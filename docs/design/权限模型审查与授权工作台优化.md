# 权限模型审查与授权工作台优化

日期：2026-11-09；状态：代码与设计审查结论、目标模型和本批页面改进。目标能力未实现前不得作为已交付能力描述。

2026-11-10 更新：独立成员授权快照、字段强制限制、菜单资源关联、旧授权退出、方法级端点契约及统一 `/api/**` 权限拦截已经完成并通过全量自动交验。本文记录的“本批未实现”仅描述 2026-11-09 当时状态；当前状态以《授权中心开发交接记录》最新结论为准。

## 1. 结论与基线冲突

当前实现为角色功能权限、角色级基础数据范围和主体角色分配的子集，不是完整权限中心。租户成员与全局账号分离、稳定权限码、事务审计、乐观锁、服务端可信租户边界应保留。

《管理权限中心与菜单详细设计》第 1 节把字段权限排除在局部第一阶段之外，且角色级数据策略与《设计讨论记录》“独立授权记录”存在偏差；不得据此削减《第一期交付范围与验收基线》的整体交付范围。局部实现批次不改变完整一期要求。本文补充菜单、功能、数据、安全脱敏、API 集中管理及共享草稿页签要求。

## 2. 审查发现

| 优先级 | 发现与代码依据 | 影响及处理 |
|---|---|---|
| 高 | `RolePermissionManagement.DataPolicy`、`access_role_data_policy` 按角色与权限配置范围；`SubjectRoleManagement` 仅保存角色 ID | 同角色不同成员无法有不同范围；角色策略变化影响全部成员。增加独立授权记录，不继续给角色堆叠成员例外字段 |
| 高 | `MyBatisDataScopeAuthorization` 对混合范围类型返回 DENY，而 `MyBatisEffectiveAuthorizationQuery` 仅按角色分支判定有效 | 本人 + 指定组织可能全部被拒绝，解释却显示分支生效。保持现有失败关闭，后续使用同一决策器产生条件树与解释，禁止直接把枚举集合并为 ALL |
| 高 | `DataScopeMapper.legacyAll` 在无角色策略时按旧直授权回退 ALL；旧组织能力分支按权限码最后一段匹配 capability | 回退未把 resource 与旧授权业务资源显式绑定；应增加固定资源/权限映射及负向测试。当前目录下的实际越权可达性仍需专项验证，不能把潜在扩大写成已证实漏洞 |
| 高 | 当前功能判定与数据策略执行并非完整 AccessPlan，字段、强制限制、委派、临时授权与客户端授权缺少统一闭环 | 不能宣称字段安全、API 范围授权已交付。后端先实现同条授权分支，再做页签配置；所有读取、计数、写入、导出保持同一边界 |
| 中 | 有效权限查询不包含旧直授权，且没有记录/字段上下文 | 定位问题时不等于最终决策；页面保留来源解释提示，最终预览需输入资源、操作及业务对象，复用运行时决策器 |
| 中 | `platform_menu` 有权限字符串，admin 路由仍有静态角色条件 | 菜单目录维护不等于菜单授权闭环；动态路由、菜单和标签清理应消费统一有效权限，后端独立执行鉴权 |
| 中 | 原工作台只读前 100 个角色、角色切换无草稿保护、请求结果无过期隔离、读取失败后无写入就绪状态 | 本批改为完整目录、搜索选择、丢弃确认、过期响应隔离及失败关闭写入口；写失败后重新读取版本 |
| 中 | 功能和范围逐行混排，缺少筛选与分组选择，原因缺失被误报为范围未完成 | 本批拆分共享草稿的功能/数据页签，增加筛选、仅已选、当前筛选结果资源批选和待配置数量；范围缺失与原因缺失分开处理 |

## 3. 目标模型

角色定义可授予的功能集合；授权记录绑定可信管理域、主体、角色、操作子集、数据条件、字段策略、有效期、来源与状态。角色级现有策略只作为兼容数据及迁移输入，不作为最终成员范围权威。

一条记录表达一个完整授权分支：操作、数据、字段必须在同一分支满足。普通分支取并集，随后应用强制限制、租户边界、开通能力与领域条件；默认拒绝。不得把 A 公司审核分支与 B 公司查看分支组合成 B 公司审核。

角色增权不能自动扩展历史授权记录：记录保存明确的操作授权边界或受审版本。角色减权立即限制分支；角色恢复仅恢复未撤销、未过期且来源有效的记录。使用角色版本、主体授权版本、限制策略版本等共同失效，不能只依赖 TTL。

| 对象 | 职责与边界 |
|---|---|
| 资源与操作目录 | 领域登记稳定资源、操作、字段、数据维度、可查询能力和执行支持；未实现能力不展示为可配置 |
| 角色 | 功能集合与生命周期；不拥有成员列表与全局数据范围权威 |
| 授权记录 | 平台账号/租户成员/集成客户端的完整授权分支；不同主体类型显式区分，不冒充用户 |
| 字段策略 | 独立控制查看、修改、展示及精确/模糊/范围查询、排序、分组、统计；按记录条件决定 |
| 强制限制 | 作用于普通分支合并之后，普通授权、模板及管理员角色不能隐式绕过 |
| 授权委派 | 管理员可授予的操作、数据、字段和期限上限；管理权限不等于无限授予权 |
| 策略模板 | 明确版本的配置快照；复制后修改模板不影响已有授权 |
| API 客户端 | 绑定租户、资源/操作、数据、字段与有效期，另有认证、凭据轮换、额度；凭据不进入权限配置草稿或审计 |

API 端点绑定稳定操作权限；前端菜单和按钮也关联相同目录。若确实需要“可调用 API 但不展示页面”，由独立的页面访问/导航能力表达，不重复建立角色菜单业务权限权威。目录节点可由可见子节点推导；选中目录仅是配置快捷方式，不授予未展示子节点或后续新增操作。页面访问不得自动授予导出、审批、删除等操作；必要依赖由领域声明并在确认时展示。

## 4. 减少配置负担的工作台

工作台分为“为谁授权”和“维护角色/模板”两类任务。主体可为租户成员或 API 客户端，平台账号使用平台管理域；界面始终显示目标与管理域。成员选角色只配置业务需要的差异，常见路径为：选择成员 → 选择角色/模板 → 选择数据范围 → 查看摘要并提交。

同一授权记录的页签共享草稿、目标、版本和变更原因：菜单与功能、数据范围、字段与脱敏、API（客户端适用）、预览与提交。授权对象放在固定上下文区，避免每个页签重选。角色维护和主体授权是不同聚合，不伪装为一个跨聚合原子保存；需变更角色时打开明确的角色维护任务并提示受影响成员。

- 菜单与功能默认用业务菜单树定位资源，操作按行列矩阵显示；无菜单 API 资源单独分组。菜单树与功能矩阵编辑同一草稿，不要求用户重复勾选。
- 数据范围只列出已选且确需范围的资源；同资源且元数据兼容的操作支持“应用到所选操作”，应用前列出目标、覆盖差异和不兼容项。不同资源不得仅按同名范围批量复制。首次不默认 ALL。
- 字段默认按敏感等级和领域安全模板给出明确结果；“继承模板/本条覆盖”可见，未声明字段隐藏且不可修改。普通管理员以少量方案选择为主，高级条件按需展开。
- 高风险操作（原文、导出、授权管理、删除）显式标记；批量选择不跨越筛选结果，也不隐式选择依赖。提交摘要集中一次说明撤权或扩权影响，避免逐字段确认。
- 搜索、仅已选、仅待配置、资源折叠、策略复制帮助定位；删除功能时同步移除其草稿策略并计入差异。模板复制只复制调用者有权授出的交集，缺项明确提示。
- 未接通的安全、API、菜单页签不建立可点击空入口。实际支持后逐步接入，页面优化不能替代执行能力。

## 5. 本批实现范围与组件选择

保留 BusinessWorkspace 应用工作区与已有 SubjectAuthorization；复用 Element Plus Tabs、Select、Checkbox、Form、Alert、MessageBox，没有新增组件或 UI 库。角色目录为平面列表，使用可搜索 Select；权限按真实资源分组，不编造菜单树。功能和数据在同一角色草稿中切换，共用原因与原子保存端口。

本批增加：权限名称/权限码/资源搜索、仅已选、资源内当前筛选结果批选、数据范围单独页签、未完成数量快捷定位、完整角色目录读取、角色切换草稿确认、读取失败禁写、过期响应隔离、保存影响确认。保存成功以服务端快照重建基线；失败后需重读，不自动重试覆盖。

本批未实现独立授权记录、条件树、菜单权限闭环、字段/脱敏、API 客户端授权、跨主体批量授权、兼容性批量范围应用、路由离开保护。功能/数据子页签共享草稿；主体页签仍是独立保存任务。浏览器关闭或离开路由的草稿恢复仍待统一处理，不把当前切换保护描述为全场景保障。

## 6. 后续顺序与验收

1. 先验证并收缩旧授权回退的资源映射，建立所有接口登记和未登记默认拒绝测试；完成旧授权对账与停写方案。
2. 引入独立授权记录及委派边界，追加迁移并保存旧数据来源，禁止修改已发布迁移或直接删除历史授权。
3. 建立统一 AccessPlan 条件树与字段执行，运行时和预览同源；实现数据、脱敏、强制限制，再接入管理页签。
4. 菜单消费统一权限结果；API 客户端进入相同分支模型，补授权版本失效、额度及调用审计。
5. 再实现策略模板、兼容范围批量应用和跨主体批量操作，提交预览列出每个目标的实际差异。

关键验收样例：同角色不同成员拥有不同组织；本人 + 指定组织为正确并集；A 审核/B 查看不可拼接；脱敏可见不自动可写或可查询；强制限制不可被第二角色绕过；撤权后旧 Token 拒绝；隐藏菜单后直调接口仍校验；页签切换保留草稿、冲突不覆盖、旧响应不串目标、筛选批选不影响隐藏项。真实数据库与浏览器证据需分别记录。
