# 平台总体设计基线

版本：0.1

更新日期：2026-11-05

状态：已确认需求与设计原则基线，详细设计持续讨论中。

本文是项目设计依据，依据已确认讨论整理。标注待确认、待细化及后续规划的内容不构成已批准的实施细节。第一期范围优先于各共享服务早期讨论的阶段描述。领域聚合清单、物理服务划分、表结构及接口尚未定稿。

## 工作阶段

当前处于需求与架构讨论阶段。充分讨论并经用户确认后再开始实现。

## 已确认：第一期范围

- 第一期先完成平台底座，不覆盖 SCM、WMS、巡库等具体业务场景。
- 底座范围包括租户、账号、组织、岗位、角色权限、系统开通、统一门户、公共配置与审计；日志和国际化必须纳入基础设计。
- 共享服务后续分批推进；前文能力范围不代表全部在第一期实现，各服务具体交付批次待规划确认。
- 日志分类、采集查询、追踪、脱敏、权限及保留策略待讨论。
- 国际化的语言范围、翻译资源、前后端文案、时间与数字格式及业务数据多语言边界待讨论。

### 已确认：日志与国际化范围

- 第一期支持简体中文、英文，并预留其他语言扩展能力。
- 国际化是统一方案，覆盖多语言、多时区、多币种及跨国系统操作习惯，不仅是界面翻译。
- 分为集中配置管理与运行引擎两部分，尽可能内聚配置和管理能力，各业务系统复用运行能力。
- 多语言明确覆盖 UI、主数据及异常信息。
- 运行引擎统一处理语言解析与回退、时区转换、日期和数字格式、币种精度与舍入、金额格式及按规则进行汇率折算、区域操作习惯适配、配置继承与上下文解析；各业务系统不自行实现这些国际化逻辑。
- 业务系统提供租户、公司、用户、单据币种、业务日期等必要上下文，调用统一能力；引擎可通过前端组件、公共 SDK 或服务接口提供能力，具体部署方式待定。
- 已生效单据使用其保存的规则和折算依据，避免后续配置变化改写历史结果。
- 展示语言优先级：用户偏好 → 租户默认；翻译缺失按统一回退规则处理。
- 展示时区、日期和数字格式优先级：用户偏好 → 公司默认 → 租户默认；涉及多个公司或无明确公司上下文时的解析规则待细化。
- 业务日期和业务时区按单据所属业务主体及业务规则确定；业务币种、精度、舍入和折算按业务规则确定，生效时保存必要依据。
- 个人展示偏好不改变业务计算结果，切换展示时区不改变业务日期，切换语言不改变金额币种。
- 区域配置继承规则、币种与汇率职责、主数据翻译结构、格式及交互适配等细则待继续讨论；支持范围和各能力实现深度按第一期规划细化。
- 第一期在平台内提供日志查询，包含用户登录、登出及操作日志。
- API 网关未来加入，并纳入集成日志和调用链日志能力；具体实施批次与网关方案待确定。
- 日志基础模型需预留请求追踪及跨服务关联能力，避免后续接入网关和调用链时重新定义关联方式。
- 登录失败、会话到期等事件分类，日志字段、查询权限、保留期限及追踪技术方案待继续讨论。

## 平台范围

面向大型集团公司，集合 SCM、WMS、巡库等约十个业务系统。

共享能力包括用户、消息、定时任务、编码服务、字典、组织、权限配置，以及审批、打印、报表。客商、仓库、单据等业务基础模型存在重叠，具体边界待继续讨论。

主数据先统一管理，按需授权编辑和审核。跨系统业务链路暂未确定，希望支持灵活编排，具体方案待讨论。

## 已确认：租户与组织

- 支持多租户、多公司；租户数据强制隔离，租户间不可共享数据。
- 无多租户需求时提供默认租户。
- 租户作为组织树顶层，租户根节点下构建组织。
- 组织类型可自定义，包括业务组织、法人组织、财务组织及其他组织；未声明类型时默认为业务组织。
- 同一组织允许具备多种能力。
- 组织间关系用于配置业务归属、财务归属等关联，可连接不同类型树的组织单元，不改变各树上下级。
- 组织负责人单独配置，并关联本组织的有效成员任职，不根据岗位名称推断负责人。
- 审批选人区分组织负责人与某岗位任职人员两种规则。
- 负责人人数、任职失效后的处理及变更生效方式待进一步设计。

### 已确认：按组织类型独立建树（替代此前单一主树定义）

- 每个租户下按组织类型分别维护独立组织树，各树顶级组织单元统一挂载租户根节点；不采用单一主组织树或仅按类型筛选视图的方案。
- 每个组织单元只属于一种组织类型，在所属类型树内最多有一个组织上级。
- 允许租户内有权用户自定义组织类型，不限定为内置的业务、法人、财务组织类型；未声明组织类型时仍默认使用业务组织。
- 组织类型用于分类及划分树，不等同于组织能力；原有同一组织具备多种能力的决定继续有效。
- 数据范围明确组织类型、组织单元及是否包含下级；下级仅沿所属类型树计算，不沿跨树组织关系自动扩展权限。
- 各领域声明法人组织、业务组织、财务组织等业务归属维度，由授权规则明确组合。
- 组织类型作为独立聚合；管理权限、生命周期细则及跨类型迁移机制待详细设计。

### 已确认：组织类型变更规则

- 组织类型编码在租户内唯一，创建后保持稳定，名称允许修改。
- 已有组织单元引用的类型不能直接删除。
- 停用组织类型前，检查组织、任职、授权及业务引用并展示影响范围；具体依赖处置和停用效果待详细设计。
- 组织单元不能直接修改所属类型；跨类型调整通过专门的迁移操作完成，校验上下级、岗位、组织关系及授权影响。
- 跨类型迁移的标识保留、历史归属兼容及事务机制待详细设计，须遵守已确认的历史保留原则。

### 已确认：业务数据的多组织归属

- 业务数据可分别关联法人组织、业务组织、财务组织及自定义组织维度。
- 各业务模型声明需要的组织维度、是否必填及允许的组织类型，不要求所有业务具有相同维度。
- 组织间关系可辅助带出默认值，但不自动产生权限。
- 授权规则明确组合不同归属维度，例如法人组织属于 A 公司且业务组织属于采购总部及下级。
- 单据保存实际选定的组织标识，组织关系调整不自动改写历史单据归属；仍遵守已确认的历史快照原则。
- 自定义组织维度的注册、数据存储与查询适配、默认值冲突及归属校验待详细设计。

### 已确认：组织领域聚合

- 组织类型、组织单元、组织关系、岗位、任职作为五个独立聚合，通过标识关联。
- 组织类型聚合管理类型编码、名称、状态及类型树约束；组织单元通过类型标识引用。
- 新增组织节点须校验类型有效；存在上级组织单元时，上级必须属于同租户、同类型，顶级节点挂载租户根节点。
- 组织单元聚合管理基本资料、唯一所属类型、能力、类型树内上级及负责人配置，整棵树不作为一个聚合加载。
- 组织关系聚合管理业务归属、财务归属等关联，不用于改变类型树内上下级。
- 岗位聚合管理所属组织、编码、名称及状态。
- 任职聚合管理租户成员、岗位、任职状态及有效期。
- 移动组织、调整负责人、结束任职等跨聚合操作，由组织领域应用层协调并保证相关约束；具体事务及并发控制方案待详细设计。

### 已确认：组织调整规则

- 组织编码在租户内唯一，内部标识永久不变。
- 组织迁移不得跨租户，不得形成循环。
- 迁移不改写历史单据的组织归属与快照。
- 按所属类型树动态计算的数据权限会受树内迁移影响；迁移前展示影响范围，确认后生效并记录审计。
- 停用组织后禁止新增任职和新业务引用；存在下级组织、有效任职或未完成业务时，先检查并处理依赖。
- 影响分析的具体范围、依赖检查及生效机制待详细设计。

### 已确认：租户领域聚合

- 租户、租户成员、租户开通配置作为三个独立聚合。
- 租户聚合管理基本资料、状态及生命周期，不将所有成员加载为聚合内集合。
- 租户成员聚合管理账号关联、租户内成员资料及状态；成员授权和组织任职由各自领域管理。
- 租户开通配置聚合管理已开通系统、功能及额度，具体内部结构待详细设计。
- 租户停用时统一阻止该租户访问及业务执行，保留数据和历史。
- 租户重新启用后，仍有效的成员资格、开通配置及授权恢复使用，不恢复已过期或撤销的权限。
- 在途任务停用处理、恢复执行策略及停用传播机制待进一步设计。

### 已确认：租户成员生命周期

- 同一账号在同一租户只有一个成员身份。
- 成员支持待激活、正常、禁用、已移除等状态，具体转换约束待详细设计。
- 禁用保留任职与授权记录，但立即停止该成员在当前租户的访问。
- 移除不删除历史关联；重新加入时复用成员标识，保持历史可追溯。
- 重新加入不自动恢复已撤销的任职和授权，由管理员重新确认。
- 禁用用于临时暂停；重新启用成员后，仍有效的任职和授权直接恢复，已过期或撤销的除外，继续受租户状态、开通范围、委派及强制限制约束。
- 移除用于正式退出租户：结束有效任职、撤销其授权并保留历史；重新加入时复用成员身份，但须重新安排任职和授权。

## 已确认：账号与操作范围

- 同一登录账号可以选择进入不同租户。
- 用户在当前租户内可以直接操作所有已授权业务，无需通过切换任职身份来限制日常操作范围。

## 已确认：审批

- 审批流程剥离为独立审批服务，所有审批流程的发起统一通过审批服务。
- 审批服务与业务系统的具体接口、状态及权限衔接方案待继续讨论。
- 审批人定位默认以单据归属组织为依据，流程可以显式选择提交人组织等其他依据。
- 被选为审批人后，获得该审批任务所需的受限查看与处理权限，仅限对应单据、字段及审批操作，不要求预先拥有整个业务模块的权限。
- 审批任务权限仍须遵守强制脱敏及访问限制；具体字段范围和任务结束后的权限有效性待细化。

### 已确认：审批默认规则

- 找不到审批人：暂停并告警，由授权人员处理，不自动通过。
- 审批人与提交人相同：默认转交上级或指定替代人；允许自审须由流程明确配置。
- 多人审批：支持会签、或签、依次审批，由节点配置。
- 转交、委托、加签：分别配置是否允许，记录实际处理人及完整流转。
- 驳回：支持退回提交人或指定前序节点，由流程限定。
- 撤回：结合审批进度及业务是否已生效判断，不仅撤回审批记录。
- 超时：支持提醒、催办、升级处理，默认不自动通过。
- 待办结束后收回任务处理权；已办人员保留受限历史查看权，可见字段和保留期限由租户策略控制，继续遵守强制限制。
- 以上作为默认行为，特殊流程可在受控范围内单独配置，具体配置约束待设计。

## 已确认：统一审批工作台

- 作为平台统一入口，汇总当前租户内各系统的审批事项，涵盖待我审批、我已审批、我发起的、抄送我的。
- 支持按单据类型、公司、发起人、时间及审批状态等筛选，通过单据中心进入详情及审批时间线。
- 查询与操作遵守授权范围、字段权限及脱敏规则。
- “我发起的”展示本人提交审批的单据；包含未走审批单据的“我的单据”由单据中心承接，两处可关联跳转。
- 单据、审批实例及审批任务分别关联；驳回重提保留各次审批历史，不覆盖原处理意见。
- 汇总尚未提交单据的“我的草稿”为可选建议，尚未确认。

## 已确认：岗位与角色

- 岗位表达组织中的任职职责，角色表达系统操作权限。
- 当前阶段岗位与权限授权独立，角色单独授予；岗位不自动带出角色或权限。
- 岗位归属组织，租户成员通过任职关系关联岗位；支持一人多岗、同岗多人。
- 当前不对岗位分类，不引入公共岗位与组织专属岗位的分类机制。

### 已确认：任职失效后的处理

- 离岗后，不再被新的审批任务按该岗位或组织负责人规则选中。
- 已分配但未处理的审批任务进入待重新分配状态，保留原分配记录；重新分配的执行方式待详细设计。
- 单独授予的角色不随离岗自动撤销，系统提醒授权管理员复核，维持任职与授权独立的原则。
- 成员被禁用或移出租户时，其在该租户的访问立即失效。

## 已确认：账号、租户成员与授权对象

- 账号是跨租户的统一登录身份；租户成员是账号在某个租户内的身份，成员资料、状态、任职及授权由各租户独立管理。
- 一个账号可以关联多个租户成员身份；移除某租户成员不影响其在其他租户的成员资格。
- 业务角色属于租户，授予租户成员，不直接授予全局账号。
- 授权以独立关系维护：租户成员 + 角色 + 数据范围 + 字段与脱敏策略；角色不直接包含全局账号列表。
- 角色定义功能权限，数据范围限定适用公司、组织或记录，字段与脱敏策略控制相应字段的查看、修改及展示。
- 登录选择租户后，通过账号定位当前租户成员，仅计算当前租户内有效授权，继续遵守强制限制。
- 单租户场景仍保留账号与默认租户成员的关联；授权界面可直接展示人员信息，内部使用租户成员标识。

## 已确认：细粒度权限与脱敏

- 基础授权采用“用户 + 角色 + 数据范围”，角色定义操作能力，数据范围限定适用数据。
- 授权粒度支持到单元格，即特定记录的特定字段，并支持在授权过程中配置数据脱敏要求。
- 普通授权可以累加；强制限制优先，不能通过其他普通角色授权绕过强制脱敏或访问限制。
- 支持申请临时查看原文，通过审批后，在限定时间、限定数据范围内查看完整值。
- 临时查看原文不应默认绕过强制限制；哪些限制允许经审批例外放行，需另行明确。

### 已确认：数据范围与规则引擎

- 数据范围支持指定组织、组织及下级、与本人相关、指定业务对象、条件组合及指定记录。
- 与本人相关可涵盖本人创建、本人负责、本人所在组织等；指定业务对象可涵盖仓库、客商、项目等，具体维度由领域声明。
- 平台统一提供权限规则引擎，各领域声明可参与授权的字段及关系；管理员通过受控条件配置，不直接编写数据库 SQL。
- 字段及单元格权限可在数据范围条件上继续细化，实现按记录条件控制字段查看、修改与脱敏。
- 条件组合语义、执行与查询适配、规则版本及性能边界待详细设计。

### 已确认：授权组合与执行规则

- 单条规则内部支持且、或、非及条件分组。
- 多条普通授权取并集，但功能、数据范围及字段策略必须在各自授权内匹配，不得拆开跨授权拼接。
- 强制限制对普通授权结果统一收口，优先于普通授权。
- 默认拒绝：未匹配有效授权、缺少必要上下文或规则执行失败时，不得放行。
- 权限由后端统一执行，列表、详情、修改、导出、打印和报表遵循相同规则。
- 示例：A 公司采购审核权与 B 公司采购查看权组合后，不产生 B 公司采购审核权。

### 已确认：字段权限与脱敏模型

- 字段规则分别配置可见性（隐藏、可见）、可编辑性（只读、可修改）、展示方式（原文、部分遮盖、替代值等）及记录级生效条件。
- 字段可见或脱敏展示不自动获得修改权；允许修改也不自动获得原文查看权。
- 开发人员声明字段类型及可用脱敏方式，管理员在授权范围内选择配置。
- 内置手机号、邮箱、证件号、银行账号等常用脱敏策略，预留自定义策略接口。
- 无权查看的原始值不返回前端。
- 有修改权但无原文查看权时，提供独立的替换值操作，不回显原值。
- 未修改字段不提交，不得将脱敏占位值写回数据库；接口须明确表达字段未变更与主动清空的区别，具体协议待设计。
- 后端同时校验操作权限、记录范围、字段修改权及业务条件。
- 校验提示和操作日志继续脱敏，避免间接泄露原值。
- 敏感字段的精确查询、模糊查询、范围筛选、排序、分组及统计能力分别授权；脱敏可见不自动包含这些查询能力。
- 开发人员声明字段支持的查询方式，管理员在授权范围内配置；后端统一校验。
- 查询条件及相关日志须保护敏感值，避免通过查询过程或日志泄露。
- 脱敏策略参数及多策略冲突的确定性规则待详细设计。

### 已确认：权限领域聚合

- 权限领域包含角色、授权记录、授权委派、强制限制策略、策略模板五个独立聚合。
- 角色管理功能权限集合及角色状态。
- 授权记录管理租户成员、角色、数据范围、字段策略、有效期及授权来源。
- 授权委派管理管理员可授予的范围、期限和撤销方式。
- 强制限制策略管理不可被普通授权绕过的访问及脱敏限制。
- 策略模板管理可复制复用的数据范围、字段及脱敏规则，修改模板不自动改变已复制的授权。
- 临时查看原文经审批后形成有期限的授权记录，复用统一权限机制；仍遵守强制限制，允许例外的边界另行明确。
- 聚合内部结构、跨聚合一致性与具体接口待详细设计。

### 待细化的权限规则

- 单元格权限的条件配置、指定记录例外授权及管理方式。
- 查看、编辑、导出、打印、报表等操作的字段规则和脱敏执行方式。
- 强制限制的配置主体、作用范围与策略冲突处理细则。
- 临时查看原文的审批人、最长有效期、撤销机制及审计要求。

### 已确认：角色变更与停用

- 角色增加功能权限时，展示受影响成员，审核确认后生效；审核方式和审核权限待详细设计。
- 角色减少权限时，确认后及时生效。
- 各条授权的数据范围、字段权限及脱敏策略不随角色修改自动扩大，继续遵守强制限制。
- 已被授予的角色不能直接删除，可以停用；停用后相关授权失效，保留历史记录。
- 角色重新启用后，原授权直接恢复生效，无需逐条重新确认；仍须满足成员状态、授权有效期、有效委派来源及租户开通范围，并遵守强制限制。已撤销或已过期授权不因角色重新启用而恢复。
- 已过期授权允许由具有相应授权管理权的管理员调整过期时间；调整后满足生效条件即可重新生效，无需重新创建授权。变更须在其授权管理范围内，记录修改人、变更前后有效期及时间；不得突破有效委派期限或绕过撤销状态、强制限制等约束。
- 角色版本、缓存失效和影响分析机制待详细设计。

### 已确认：授权管理体验

- 角色配置集中选择功能权限。
- 提供授权向导：选择租户成员、角色、数据范围，再配置字段及脱敏策略。
- 支持复用数据范围和字段规则的策略模板；默认复制后使用，修改模板不自动改变已有授权。
- 提供权限预览：按成员及业务对象查看最终权限与授权来源。
- 变更前支持影响分析，展示受影响人员、范围及权限差异。
- 预览与影响分析的使用权限、可见内容及技术实现待详细设计。

## 已确认：分级授权管理

- 支持租户内集中管理与分级授权。
- 租户管理员可以将指定系统、组织和数据范围内的授权管理权委派给下级管理员。
- 下级管理员只能在委派范围内授予权限。
- 业务操作权与授权管理权独立，拥有业务操作权限不代表可以将其授予他人。
- 撤销操作区分两种方式：仅撤销管理资格时，已有业务授权保留，由上级接管管理；收回整个委派范围时，依赖该委派产生的授权同步失效。
- 用户通过其他有效途径获得的授权仍保留，但继续受强制限制约束。
- 每笔授权需要记录来源及委派依赖，以支持准确撤销和责任追溯。
- 再委派、委派到期及授权变更审批等细则待继续讨论。

## 已确认：主数据分层治理

- 采用“公共资料统一管理，公司和系统分别扩展”的方式。
- 租户公共资料：统一维护主数据身份与公共属性，例如客商编码、名称、统一社会信用代码；不跨租户共享。
- 公司使用关系：管理各公司是否可以使用、是否启用该主数据。
- 公司业务属性：分别维护结算方式、账期、业务负责人等公司合作信息。
- 系统扩展属性：由对应系统维护专用属性，例如 WMS 作业策略、巡库检查配置。
- 公共资料修改按授权审核；不同公司的业务属性允许采用不同审批规则。
- 草稿与生效版本分开：修改审核期间继续使用当前生效版本，审核通过后新版本生效。
- 历史单据保存关键数据快照，避免主数据变更改写历史内容；快照字段按单据类型确定，历史快照仍须遵守访问和脱敏规则。
- 主数据停用后禁止新增业务引用，历史引用仍可查询；未完成业务能否继续处理由业务规则决定。
- 已被引用的主数据不直接删除，通过停用或归档管理。
- 各类主数据的适用层次、唯一性规则及具体生命周期待继续讨论。

## 已确认：单据中心与业务服务边界

- 建设平台级单据中心，以统一编码和标识管理单据入口、查询、操作及配套能力、生命周期追踪与问题定位。
- 单据中心统一保存单据索引、生命周期记录和能力声明；具体单据内容由各自业务服务存储和管理，不集中保存所有单据完整数据。
- 后续希望围绕单据扩展出统一开发模式。
- 业务服务是单据状态的权威来源；单据中心将操作请求交由业务服务执行，并根据执行结果同步索引和生命周期记录。审批、编排通过业务服务提供的操作推进单据。
- 单据接入采用“代码声明业务契约，管理界面配置运行规则”：代码声明类型身份、页面入口、查询字段、状态、操作接口及配套能力；管理界面配置审批、模板、授权等运行规则。
- 状态同步需要支持失败重试、核对和修复，具体一致性机制待设计。

### 待细化的单据设计

- 单据类型编码、稳定唯一标识、业务单号的职责及编码规则。
- 单据类型注册、状态与操作声明、查询索引字段及统一入口。
- 业务服务与单据中心的状态同步、事件顺序、失败补偿及一致性检查。
- 来源与下游单据关系、审批和编排实例、调用追踪及诊断信息的关联方式。
- 统一开发模式的接入规范与自动获得的平台能力。

## 已确认：可视化业务编排

- 支持租户管理员通过可视化界面组合已开放的业务动作、条件及审批环节。
- 开发人员声明可用业务动作及输入输出契约，编排在这些契约范围内配置。
- 审批可以作为编排中的等待环节，业务单据也可以直接发起审批；两种方式均统一经过审批服务。
- 编排调用已注册的单据操作或业务动作，不直接修改业务数据库；业务校验和执行仍由对应业务服务负责。
- 编排定义、配置和执行遵守租户隔离及授权边界。
- 编排设计、发布、停用及运行异常处理交由被授权的运维角色，在其授权范围内完成。
- 业务流转中，人工节点记录实际处理人；后续自动节点沿用最近一个已完成人工节点的处理人，直到新的人工节点完成，并标明自动执行。
- 人工触发时从发起人开始沿用；定时或外部事件触发且尚无人工处理人时，显示“系统自动”。
- 自动执行权限依据流程获授的业务动作和数据范围，不因沿用人员展示信息而继承该人员全部权限。权限具体承载与校验机制待设计。
- 底层审计保留真实执行来源，包括流程实例、节点和自动执行标记；运维重试、跳过、终止等干预记录实际运维人员。技术审计放在诊断详情，业务流转展示经办信息。

### 待细化的编排设计

- 触发方式、节点类型、数据映射和条件表达方式。
- 流程版本、发布权限、运行实例与版本绑定。
- 重试、幂等、超时、补偿、取消和人工干预机制。
- 执行身份、数据权限、脱敏要求及跨公司动作的授权方式。
- 运行监控、单据关联和问题诊断。

### 已确认：发布与运行控制

- 已发布版本不可直接修改；在途实例继续使用启动时的版本。
- 发布时校验节点配置、数据映射、动作授权及必要的异常处理配置。
- 失败处理支持自动重试、人工重试与终止；业务动作须防止重复执行。
- 跳过与补偿仅在业务动作明确支持时开放，不得任意跳过必需审批或业务校验。
- 运维干预须填写原因并留痕；重试使用原节点输入，修改数据后执行须单独受控。
- 发布权限独立配置，允许同一运维人员设计和发布，也允许租户启用设计与发布人员分离。
- 上述已确认原则对应的节点配置、接口和运行机制仍需进一步设计。

## 已确认：编码服务

- 租户内统一业务编码服务供单据、客商、仓库等对象使用，内部唯一标识独立生成。
- 编码组成可配置，支持固定文字、业务字段、日期、流水号和分隔符等，并预留未来扩展和自定义规则能力。
- 编码组成部分支持通过表达式过滤，预留号码保留及动态组合编号能力；表达式语义和预留方式待细化。
- 用户确认表达式用途涵盖组成段启用条件及候选号码过滤。
- 动态组合需要预留有序远程取值、函数计算及前序结果引用能力；远程调用默认限定为查询取值。
- 高级规则能力（表达式过滤、预留号码、动态组合、远程取值与函数计算）作为后续扩展，当前不实现；基础设计预留扩展点，具体分期边界待实施规划确认。
- 默认在“租户 + 编码对象类型”内唯一，流水计数范围与唯一性范围分开配置；分公司计数仍须避免唯一性范围内重复。
- 正式取号时机可配置，默认创建草稿时生成；同一业务对象重试取号返回原号码。
- 生成后不变、不回收，允许断号；严格连续编号作为特殊需求单独设计。
- 规则变更形成版本，后续取号使用新规则，已有编码不变；发布前校验、试生成并检查冲突。
- 默认系统生成，历史导入和手工编码作为单独授权能力，执行唯一性校验并记录来源。

### 待细化的编码扩展设计

- 表达式控制组成部分的启用条件、取值及组合方式，以及候选号码过滤的具体语义。
- 禁用号码、预留号码和号段的管理、用途、授权使用及冲突处理。
- 表达式可访问的数据、执行约束、规则验证与并发取号机制。

## 已确认：打印范围与模板制作方式

- 打印范围包括各类业务单据、交接单、合同，以及仓库标签、条码、二维码和专用标签打印机。
- 模板由开发人员提前制作，业务人员选择使用；当前不要求业务人员可视化设计模板。
- 同时支持预览后打印和静默打印；静默打印支持直接向预设设备提交任务，具体设备接入方案待技术设计确定。
- 支持按仓库、作业站、单据或标签类型配置默认打印设备，用户可在已授权设备中切换。
- 自动触发打印使用流程配置的设备选择规则。
- 设备离线、缺纸或打印结果未知时，任务进入异常状态，避免盲目重试造成重复打印；具体回执与恢复机制待设计。

### 待确认的打印设计

- 模板、数据绑定、版本、输出任务及打印记录的统一管理方式。
- 业务服务提供打印数据，打印服务适配文档、标签等不同渲染与设备的职责边界。
- 按公司和业务条件选择模板、预览/下载/打印权限、脱敏、补打控制。
- 正式文件归档与快照、设备回执及合同业务能力边界。

## 已确认：报表设计器

- 提供可视化报表设计器，开发人员进行数据分析、处理后完成可视化设计，发布给业务用户查看使用。
- 同时包含固定格式明细报表与交互式分析看板。
- 固定格式报表覆盖分组、合计、分页及打印场景；交互分析看板覆盖图表、联动、下钻及大屏展示场景。
- 数据时效按报表和数据集分别配置，不要求全部实时；作业查询可实时或近实时，跨系统运营分析可分钟级，集团历史分析可小时级或每日更新，具体目标按场景确定。
- 报表展示数据更新时间。

### 待确认的报表设计

- 受控数据集、字段与指标口径、跨系统数据整合及更新时间说明。
- 数据权限与脱敏落地、发布授权、版本管理及导出控制。
- 大数据量异步查询与导出、实时性及缓存策略。
- 与打印服务的模板、渲染和任务职责衔接。

## 已确认：消息渠道

- 消息服务的目标渠道包括站内消息、邮件、短信、企业微信、钉钉及飞书；第一期已收敛为平台底座，消息渠道具体接入批次另行确认。
- 各外部渠道的实际启用依赖租户配置及相应平台接入条件，具体接入方案待设计。

### 已确认：消息默认规则

- 统一消息事件，多渠道分别配置模板。
- 渠道配置及成员手机号、邮箱、办公平台账号映射按租户管理。
- 普通通知允许用户选择渠道及免打扰时间；关键待办和告警由管理员配置必须发送的渠道。
- 发送失败支持有限重试、备用渠道及人工排查，记录投递结果并避免重复发送。
- 外部消息默认只包含必要摘要，敏感详情登录平台查看；跳转时重新校验租户及权限。
- 消息已读与任务完成分离，发送成功不等于用户已读。

### 待确认的消息设计

- 待办提醒、业务通知及运维告警的分类和关联跳转。
- 消息已读与业务任务完成状态分离。
- 租户渠道配置、成员账号映射、模板及脱敏规则。
- 渠道选择、必达策略、用户偏好、免打扰、失败重试、去重及投递记录。

## 已确认：定时任务服务

- 定时任务决定何时触发，业务编排决定执行步骤，业务服务负责具体操作。
- 调度支持指定时间、固定间隔、Cron 及业务日历。
- 任务通过已注册业务动作或启动编排接入。
- 支持暂停、恢复、手动触发、超时及有限重试。
- 上次执行未结束时，支持跳过、排队或允许并行；默认不允许同一任务重叠执行。
- 停机期间错过的任务按配置跳过或补执行。
- 提供执行记录、失败告警，并关联单据及编排实例。
- 按租户隔离，由授权运维人员配置和操作；业务写入动作须防止重复执行。
- 时区、业务日历定义、补执行边界及具体调度机制待技术设计细化。

## 已确认：字典与公共配置

- 区分系统枚举、业务字典及业务参数，统一提供清晰的管理入口和边界。
- 系统枚举由开发定义，业务人员不能任意增删编码；业务字典由租户内授权人员维护，支持分级、排序和停用。
- 业务参数声明类型、取值范围及生效范围。
- 编码保持稳定，修改显示名称不改变编码；已引用字典项不直接删除。
- 支持租户默认值及按需开放的公司、组织或系统覆盖，每个配置项明确是否允许覆盖。
- 配置变更记录修改人及变更内容，关键参数支持审核后生效。
- 客商、仓库、物料等仍作为主数据管理。

## 已确认：独立业务异常信息管理

- 业务异常信息管理作为独立功能，不仅作为普通字典项管理。
- 同时包含业务校验提示的统一管理（错误码、提示文案、处理建议）及业务异常处理闭环（分派、处理、跟踪）。
- 异常定义、异常实例、处理闭环，以及与技术故障、告警、单据的关系待继续讨论。

### 已确认：异常管理默认规则

- 异常目录与异常工单分别管理，通过异常编码关联；目录包括文案、参数、等级、处理建议及是否生成工单。
- 并非每次校验失败都生成工单，按异常定义的处置规则决定。
- 开发人员声明异常编码和参数，授权人员维护文案、处理建议及处置规则。
- 文案支持参数化和多语言，不直接展示技术堆栈或敏感信息。
- 同一业务问题重复触发时，可合并至未关闭工单，并保留发生次数和记录；具体合并条件待设计。
- 工单支持分派、转交、处理、解决、关闭及重新打开，复核要求按异常类型配置。
- 全程遵守租户隔离、数据权限和脱敏规则，关联单据中心追踪。

## 已确认：附件与文件服务

- 统一存储并关联具体业务单据或任务，按租户隔离。
- 文件访问权限跟随业务，上传、查看、下载、删除分别授权，不允许仅凭文件地址越权访问。
- 正式合同、审批材料保留历史版本；已归档或有业务引用的文件限制删除。
- 支持图片、PDF、常见办公文档预览，可按需配置水印。
- 上传限制类型及大小，进行安全检查；大文件支持分片及断点续传。
- 记录敏感文件的查看、下载及删除操作。
- 字段脱敏不自动遮盖附件内容，附件须独立控制可见范围；自动识别及遮盖作为后续扩展方向，具体分期待定。
- 存储接入、保留期限、归档与清理、预览格式及安全检查方案待技术设计细化。

## 已确认：门户与系统入口

- 同时支持统一网页门户内切换业务系统，以及各业务系统通过独立地址进入。
- 统一认证、租户上下文、导航与独立入口的衔接方式待进一步设计。
- 系统与功能采用三层控制：平台提供范围 → 租户已开通范围 → 用户获授权范围；下层授权不得突破上层范围。
- 开通与授权由具有相应管理权限的指定角色执行，不因系统已开通而自动向所有用户开放。
- 管理职责分为平台开通管理员、租户授权管理员及下级授权管理员，通过角色配置承载；分别负责租户系统/功能/额度开通、租户内授权及受委派范围内授权。
- 创建租户时指定首位租户管理员，由其建立组织、邀请成员并分配管理权限。
- 平台管理员负责租户开通与维护，不默认获得租户业务数据访问权；平台开通权限不自动包含业务数据访问权限。

### 已确认：租户管理员保护

- 租户必须保留至少一名有效的租户管理员。
- 禁用、移除最后一名有效租户管理员，或撤销其管理员权限前，必须先完成管理权交接，防止租户无人管理。
- 管理权交接的验证、审计及并发一致性机制待详细设计。

## 已确认：身份认证领域聚合

- 身份认证领域划分为账号、会话两个独立聚合。
- 账号聚合管理统一登录身份、认证资料及账号状态；停用账号影响其在所有租户的登录与访问。
- 会话聚合管理一次登录的有效期、撤销状态及当前租户，支持单独下线。
- 租户成员禁用仅影响当前租户；全局账号停用对所有租户生效。
- 全局账号管理权与租户成员管理权分开，租户管理员不能直接停用全局账号。
- 认证资料保护、会话撤销传播及与租户策略的协调机制待详细设计。

## 已确认：认证扩展范围

- 企业单点登录与多因素认证纳入整体认证设计。
- 第一期提供相关接口契约及验证逻辑，暂不实现完整认证能力及外部身份提供方接入。
- 接口校验与完整功能的具体边界、验证方式及后续实现批次待设计明确；预留接口不得被视为已完成认证或允许绕过认证。
- 基础账号密码、密码策略、会话控制等认证清单仍待逐项确认。

### 已确认：基础会话规则

- 会话有效期及空闲超时由租户配置。
- 管理员可在授权范围内查看在线会话并强制下线。
- 用户禁用或移出租户后，对应访问立即失效。
- 权限变更及时生效，无需退出重新登录。
- 多设备登录可配置，默认允许；不同会话的当前租户独立，避免相互干扰。
- 统一账号与租户策略间的作用范围、撤销及缓存失效机制待技术设计细化。

## 已确认：部署前提

- 优先支持私有化部署。
- 当前不要求支持完全离线环境。
- 技术方向见下节，具体版本及配套组件继续讨论；不因先私有化部署而取消既定多租户隔离设计。

## 已确认：技术方向与服务粒度

- 前端桌面优先，保留 vue-pure-admin 主要布局交互，先统一部署并支持独立地址；未来允许独立部署。
- 前端须按领域模块化，与后端命名保持一致，隔离模板内部依赖以支持升级、替换及低成本应用拆分；具体结构见前端工程详细设计草案。

- 前端采用 vue-pure-admin，后端采用 Spring Cloud + DDD，数据库暂选 MySQL；具体版本及配套组件待确认。
- 服务部署粒度可以更大，不按每个功能拆服务；服务内部须清晰区分领域及聚合边界。
- 此前提出的认证、平台管理、审计日志三个独立服务仅为讨论建议，未确定采用。
- 领域划分、聚合与数据归属、跨领域调用及后续服务拆分边界待进一步设计。

## 后续规划

### 按岗位批量授予角色

- 用户已明确要求后续增加此能力，当前不实现。
- 用于根据岗位批量授予角色。
- 批量授权的数据范围、适用人员、变更同步、撤销和审计等细则，留待该功能设计时讨论确认。
- 本条不代表启用岗位与角色的自动绑定，也不改变当前单独授权的规则。
## 已确认：跨领域协作原则

- 需要立即得到结果的校验通过领域公开接口执行，例如新增任职前检查成员有效性。
- 状态变化后的跨领域联动使用领域事件，例如成员移除后结束任职、撤销授权。
- 访问立即失效直接依据成员状态判断，不等待事件联动完成；同时遵守租户、账号及其他既有有效性约束。
- 跨领域禁止直接访问对方的表或仓储；跨领域查询通过专门查询接口或读模型完成。
- 事件须可靠投递，支持重试、幂等及失败排查。
- 上述契约可先在同一部署服务内部执行，后续拆分服务时保留契约。
- 事件持久化、事务边界、顺序及失败补偿的具体实现待详细设计。
## 已确认：租户数据库隔离

- 第一期采用每个租户独立 MySQL 数据库，不采用共享库共享表作为第一期租户数据存储方案。
- 租户数据在各自数据库内管理，继续遵守租户之间不可共享业务数据的原则。
- 平台库管理全局账号、租户目录、账号可进入的租户关联及数据库连接配置；连接凭据的安全存储方式待技术设计。
- 租户库管理成员资料、组织、岗位、角色、授权、租户配置及租户内业务数据。
- 平台账号与租户关联用于确定可进入的租户，具体成员资格及业务权限仍由租户侧校验；关联同步和撤销机制待详细设计。
- 数据库路由由后端验证后的租户上下文确定，前端不得直接指定数据库连接或以未经验证的租户值决定路由。
- 每租户独立数据库不要求每租户独立 MySQL 实例；多个租户库可部署在同一实例，后续按需迁移。
- 独立数据库不替代应用层的认证、权限及租户上下文校验。
- 数据源凭据管理、连接池、建库初始化、结构升级、备份恢复及跨领域数据归属待详细设计。
## 已确认：租户自动创建

- 由平台自动创建租户及其独立数据库，不要求运维逐租户提前手工建库。
- 创建流程：填写租户资料并指定首位管理员 → 创建数据库 → 初始化结构和基础配置 → 关联管理员 → 启用租户。
- 初始化完成前不开放租户访问；失败保留进度与原因，支持重试，避免重复建库或重复创建管理员。
- 数据库管理凭据、流程状态、步骤幂等及失败恢复的具体机制待详细设计。
- 数据库升级、备份与恢复原则见对应章节，具体技术机制待详细设计。
## 已确认：数据库升级原则

- 平台库与各租户库分别记录结构版本。
- 数据库变更通过版本化脚本执行，已发布脚本不得直接修改。
- 支持分批升级；单个租户升级失败不阻塞其他租户，失败租户限制不兼容功能。
- 优先使用兼容性变更；破坏性变更需备份并安排维护窗口。
- 提供升级进度、失败原因及重试入口，操作留痕。
- 迁移工具、应用与数据库版本兼容矩阵、执行锁及失败恢复方案待详细设计。
## 已确认：备份与恢复原则

- 平台库、单个租户库支持分别备份，备份周期及保留期限可配置。
- 恢复前暂停目标租户的写入及后台任务，不影响其他租户。
- 恢复范围须考虑数据库、附件及平台侧关联信息的一致性。
- 恢复后检查结构版本、成员关联及授权状态，避免旧备份恢复已撤销权限；撤销记录保留与核对机制待详细设计。
- 恢复操作单独授权、全程审计，并定期验证备份可恢复。
- 备份频率、允许丢失的数据时长、恢复时长及具体工具在容量与运维要求明确后确定。
## 已确认：工程与组件选型基线

- 内部 ID 默认采用应用侧 UUIDv7，MySQL 使用 `BINARY(16)`，API 使用 UUID 字符串；业务编码与分片路由独立。生成接口及约束见后端工程详细设计。

- 使用成熟开源组件组合，建立轻量平台骨架，不直接裁剪整套后台框架。
- Maven 多模块按领域组织；第一期部署一个平台基础应用，领域模块边界保持独立。
- Java 21，采用兼容且受维护的 Spring Boot、Spring Cloud 版本组合；确切版本须核查后锁定。
- 数据访问使用 MyBatis，领域模型与持久化模型分开。
- 数据库版本迁移使用 Flyway，分别管理平台库及各租户库。
- Spring Security 承担认证安全基础，业务权限引擎依照已确认的平台权限模型建设。
- Redis 用于缓存与会话，明确缓存失效与会话撤销机制。
- 可靠事件先采用本地事件表（Outbox），支持重试与幂等；事务、投递及消费细节待设计。
- 使用结构化日志，预留 OpenTelemetry 调用链接入。
- API 契约采用 OpenAPI，统一错误码、分页及校验规范。
- API 网关后续接入；不为使用 Spring Cloud 而提前引入注册中心、配置中心或消息队列全套组件，按实际需要引入。
- 动态数据源作为路由工具，平台统一控制租户验证、凭据保护及连接池生命周期，不以组件注解代替隔离设计；具体路由组件待选。
- DDD 按复杂度应用：权限、租户生命周期等严格建模，简单字典配置保持简洁。
- 在正式锁定版本与实现方案前，进行技术验证：登录选择租户 → 独立数据库路由 → 数据和字段权限校验 → 审计记录 → 语言切换；不覆盖具体业务场景。
- 当前仍为设计阶段，本次确认不代表开始代码实现。组件版本、许可证、兼容性及验证结果尚未核查。
