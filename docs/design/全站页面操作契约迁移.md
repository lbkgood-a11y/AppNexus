# 业务对象与操作架构现状

本文是本次不兼容重构后的代码现状，取代此前按阶段追加的进展描述。开发要求见《业务服务统一开发规范》，验收与环境边界见《架构重构查缺补漏审查》。历史 Flyway 文件用于升级及追溯，不是运行时兼容协议。

## 统一模型

业务对象表达管理的实体，分类为 MASTER_DATA、TRANSACTION、CONFIGURATION、LEDGER、SYSTEM。账号、租户、租户成员、组织类型、组织单元、岗位、人员任职、组织关系、打印模板、打印场景、打印设备、流程定义、流程实例、流程任务等分别登记，不再使用 PlatformAdministration、OrganizationDomain、Print 等控制器分组作为对象身份。

对象编码 + 对象内操作编码形成全局 operationId，例如 Account.update、Position.create、PrintTemplate.publish、LeaveRequest.submit。权限码仍采用 resource:action，表达授权要求；它不是操作身份。多个操作可以共享权限，操作也可以声明 OR-of-AND 要求。共享组织管理权限是既有组织数据执行策略，不等于把岗位登记为组织单元对象。

## 唯一声明与聚合

- BusinessObjectType 在所属模块唯一声明对象名称、分类和模块；同一对象在不同声明位置重复，即使内容相同也拒绝启动。
- OperationBinding 关联真实 MVC 方法。平台接口的权限唯一来自 EndpointOperation，不能再重复声明 permissions。
- 具备审批/打印能力的业务对象通过 BusinessObjects.Provider 声明操作与能力；接口使用 reference=true 引用，不重复填名称、页面或权限。配置解析、字段和结果契约从该声明投影。
- OperationRegistry 聚合真实方法、路径和操作。OperationContractValidation 验证对象归属、全局身份、页面、名称及完整授权表达式。未知、重复、空授权和不完整 AND 分支失败关闭。
- 目录缓存仅为不可变构建元数据；用户操作准入不跨请求缓存，不能跨账号或租户复用。

## 页面与接口

| 入口 | 职责 | 来源 |
|---|---|---|
| 功能清单 /platform/features | 按页面或真实对象查看操作、权限、接口和约束，只读 | /bff/platform/menus/features、/bff/platform/operation-catalog、/bff/platform/object-catalog |
| 业务对象目录 /platform/business-objects | 只管理已声明可配置能力的对象，不为账号/岗位虚构审批配置 | BusinessObjects.Provider 与持久化目录状态 |
| 业务配置 /business-objects/workbench | 当前租户已开放对象的行为策略、发布和就绪检查 | /api/business-objects |
| 授权中心 | 角色、成员授权和指定主体分层诊断 | 权限、导航、数据与字段的真实执行端口 |
| 菜单管理 | 导航分组、名称、排序、启停和显隐 | platform_menu；不创造权限或业务能力 |

菜单、字典、组织、打印、工作流的页面分组，以及平台账号/租户入口，均从 /bff/operation-decisions 或 /api/operation-decisions 投影。已删除独立 /capabilities、/operation-capabilities 和 /bff/platform/access 展示协议。原业务服务继续逐请求执行身份、功能、数据、字段、归属与业务规则。

v-operation 只绑定操作 ID；@role 是固定管理域到真实角色操作的薄适配，不再拼权限码。135 个绑定控件的静态身份和动态分支由检查脚本核对。非授权交互例外只允许刷新、导航、复制、取消、草稿编辑、认证上下文和公共委托，不提供批量自动放行功能。

## 诊断及能力边界

OperationDiagnosticsController 先复核对目标主体的管理权，再读取角色来源、目标数据范围、强制字段限制和真实页面准入。菜单可见与路由可访问分开，未知来源的要求明确显示缺失。字段限制不返回原值。

ObjectDiagnostics 是具体记录的只读扩展，使用当前认证账号和可信租户，不接受客户端指定操作者。业务服务负责先授权对象再检查状态；无提供者明确 NOT_CHECKED，无权对象返回统一不可见结果，存储故障返回服务不可用。请假提交和打印已通过该端口复用本人归属、业务状态、绑定匹配及依赖预检。新的业务对象需要提供自身规则，底座不猜测任意对象的状态机。

配置预检与正式解析共用 matchingBindings；预检不创建解析、流程、打印输出或租约。审批只检查发布绑定固定的定义/版本。打印对象预检检查场景、模板、发布契约；输出选项确定后，再按 PREVIEW/SILENT 检查渲染节点和设备站点队列。检查结果是瞬时事实，正式执行必须再次校验。

## 数据与授权迁移

公开模块为 business-object-contracts、business-object-client、business-object-service，前端为 @appnexus/business-object。旧包、类型、DTO 字段和路由不保留。

V73 改名八张 doc_* 表为 business_object_*，将 type_code/action_code/operation_key 改为 object_type/operation_code/operation_id，并转换当前配置与执行快照 JSON。外部 scope 为 business-object:resolve，客户端授权版本推进。历史审计原文保留。

V74 引入 business.object.catalog:manage（平台）和 business.object.configuration:manage（租户），一次性迁移对应角色与成员授权快照并推进角色版本。运行时不再借用 tenant:read/update 或 organization.permission:grant 作为对象配置管理许可。

## 验证入口

后端使用 clean test，防止删除的类残留进入产物；旧能力路由存在性、对象唯一声明、跨管理域、目标主体数据范围、字段限制、失效会话、对象不可见和打印预检均有回归。前端执行全部 workspace 类型检查与测试、生产构建和 operation 引用检查。浏览器证据与最终部署指纹在忽略目录 .local/closure-evidence、.local/runtime，验收结果统一记录在《架构重构查缺补漏审查》。
