# 附件管理详细设计

2026-11-24 · 首期

## 1. 范围

首期实现附件上传安全策略、附件资料、附件管理工作台及可复用的附件组件。组件按业务 ID 查询附件清单并提供上传入口。附件管理负责保存关联 ID，不接入任何具体业务对象、业务页面或业务表。

每套部署配置一个私有对象存储连接。配置包含服务类型、地域、端点、桶及部署侧凭据来源。服务类型支持阿里云 OSS、华为云 OBS、AWS S3。连接由部署环境选择，应用启动校验必填项。首期无需存储管理页面、存储配置表、探测任务、路由、切换或迁移功能。变更连接前由运维保证已有对象路径仍可读取。附件原件由服务端上传，凭据和存储路径均不向普通调用方开放。

## 2. 上传安全策略

系统管理中的「附件配置」维护文件类型启停和每个类型的最大文件大小。类型键、扩展名、MIME 和硬上限由服务端检测器目录提供，管理人员可在硬上限内调整生效值。所有附件上传共用同一规则。初始值沿用此前设计，TXT 和 CSV 由管理员按实际需要启用。

| 类型 | 扩展名 | 初始状态 | 默认及硬上限 |
| --- | --- | --- | --- |
| JPEG | jpg、jpeg | 启用 | 10 MiB |
| PNG | png | 启用 | 10 MiB |
| PDF | pdf | 启用 | 20 MiB |
| Word | docx | 启用 | 20 MiB |
| Excel | xlsx | 启用 | 20 MiB |
| PowerPoint | pptx | 启用 | 20 MiB |
| 纯文本 | txt | 停用 | 10 MiB |
| CSV | csv | 停用 | 10 MiB |

1 MiB 为 1,048,576 字节。允许恰好达到上限的非空文件。白名单外格式默认拒绝，包括可执行文件、脚本、HTML、SVG、含宏文档、独立压缩包及加密文件。服务端流式计数，核对扩展名与实际内容。对图片解码、OOXML 解压、PDF 解析及临时文件设置资源限额。上传内容通过服务端安全检查后才写入正式存储并在清单中可见。规则当前状态保留最后操作者、版本与修改时间，停用只影响后续上传。

## 3. 数据表清单

| 表名 | 职责与关键字段 | 约束 |
| --- | --- | --- |
| platform_attachment_upload_policy | 附件配置。type_key、enabled、max_bytes、version | type_key 为主键。限额为正且不超过该类型硬上限。使用版本控制并发修改 |
| platform_attachment | 附件资料。id、tenant_id、business_id、file_name、size_bytes、media_type、storage_path、upload_status、idempotency_key | id 为主键，storage_path 唯一。按 (tenant_id, business_id, created_at, id) 查询关联清单。对 (tenant_id, created_by, idempotency_key) 建唯一约束，重试沿用原记录 |

两张表均在 CREATE TABLE 声明带中文列注释的 created_by、created_at、updated_by、updated_at。账号为可信上下文产生的 BINARY(16)，时间为数据库按 UTC 生成的 TIMESTAMP(6)。配置变更及适用操作复用统一审计。

business_id 是本租户内用于关联的一枚不透明标识。附件服务不解析它所属的业务类型、不联查业务表。调用方必须使用租户内全局唯一、稳定的关联 ID。业务 ID 用于筛选，不能充当权限凭证。storage_path 为应用生成的桶内对象键，不保存公共 URL，不使用原文件名拼接路径。管理台仅向授权的管理员展示对象路径。

上传先完成准入、限额、格式及安全检查，再登记待写入记录与随机路径。写入对象并确认成功后，将记录更新为可用。重复请求使用原记录，并校验请求的业务 ID 和内容一致性。失败记录保留可诊断状态。同一幂等请求可在原写入失败或五分钟租约过期后接管，继续使用原路径和相同字节。写入令牌限制状态提交，避免旧请求覆盖新请求的结果。清单只返回可用记录。

## 4. 页面和通用组件

| 界面 | 首期提供 |
| --- | --- |
| 附件配置 | 格式、扩展名、启停、有效最大大小及审计信息。可修改限额和启停 |
| 附件管理工作台 | 按业务 ID、附件名称、文件类型、上传人和上传时间分页筛选。显示名称、大小、业务 ID、上传状态及审计信息，支持查看详情 |
| 通用附件组件 | 输入业务 ID，自动加载附件清单，并提供上传入口。列表显示名称、大小和上传时间。支持只读、进度、失败和重试。上传成功刷新清单并返回附件 ID |

工作台可录入业务 ID 以使用通用组件。切换业务 ID 时清空旧清单并忽略旧请求返回的结果。组件复用 Element Plus 上传控件及平台表格、权限指令和错误反馈。有效策略用于前端提示，服务端执行最终限制。浏览器通过统一 API 上传，不持有存储凭据。首期工作台和组件仅提供上传、查询与资料展示。

## 5. 权限、API 与验收

附件配置和附件资料分别由各自唯一的 BusinessObjects.Provider 声明。配置属于平台管理域，配置查看与更新独立授权。附件按可信租户隔离，查询本租户本人上传的附件。平台跨租户元数据查询独立授权，列表、总数和详情采用同一范围。按业务 ID 查询仍执行附件范围。首期未接入任何其他业务对象的权限判断。

对接现有版本化 API 风格，定义有效上传规则、配置读取与修改、单文件上传、按业务 ID 分页查询、台账分页和详情等真实操作。Controller 引用统一操作，前端绑定同一操作。附件 ID 和关联 ID 由数据契约声明，工作流、打印和业务编码首期无场景。操作状态、版本、租户及字段保护按实际端口落地。

实施验收覆盖边界字节、伪装格式、规则停用、扫描失败、存储失败、失败记录恢复及并发重试。验证附件清单按业务 ID 筛选并防止跨租户或越主体访问。真实浏览器核验上传、刷新、错误反馈和全局布局继承。实施阶段在 docs/validation 逐项留存 D01–D12、声明同步和适用门禁证据。

### 实际入口与权限

| HTTP | 操作 | 统一权限 |
| --- | --- | --- |
| GET /bff/platform/attachment-policies | AttachmentUploadPolicy.list | configuration.attachmentpolicy:read |
| PUT /bff/platform/attachment-policies/{typeKey} | AttachmentUploadPolicy.update | configuration.attachmentpolicy:update |
| GET /bff/platform/attachments | ManagedAttachment.ledger | configuration.attachmentledger:read |
| GET /api/configuration/attachments/rules | ManagedAttachment.rules | configuration.attachment:upload |
| GET /api/configuration/attachments | ManagedAttachment.list | configuration.attachment:read |
| POST /api/configuration/attachments | ManagedAttachment.upload | configuration.attachment:upload |

浏览器上传以 application/octet-stream 传输单个原件。X-Attachment-Business-Id 和 X-Attachment-Name 使用 UTF-8 百分号编码，Idempotency-Key 为本次请求的 UUID。写操作复用平台 CSRF。GET 附件列表使用必填 businessId，offset 缺省 0，limit 缺省 20，最大 100。平台台账可进一步按租户、名称、类型、上传人、开始及结束时刻筛选。

部署连接和扫描的配置键、默认及必填行为见 [application.properties](../../backend/applications/monolith-app/src/main/resources/application.properties)。OSS 配置官方 S3 兼容端点，OBS 配置区域 HTTPS 端点，AWS S3 使用 SDK 默认凭据链。上传必须配置私网 clamd。云厂商状态、区域端点和版本兼容按目标环境验收。

## 6. 租户凭证中心与附件存储选择

后续实现采用租户级凭证中心。租户管理员在「租户设置 → 凭证中心」维护对象存储连接，登记名称、厂商、地域、HTTPS 端点、私有桶和该连接的凭据。附件设置从本租户的已启用连接中选择一个默认写入目标。全局上传白名单和大小限制继续由平台统一维护。

| 操作 | 权限和行为 |
| --- | --- |
| 查看连接 | 仅查看本租户的名称、厂商、桶、状态和最后验证时间。密钥原文不可回显 |
| 登记与轮换 | 单独授权。秘密交给服务端密钥管理设施，业务记录只保存受限引用。更新后记录操作人与结果 |
| 验证连接 | 单独授权。由服务端使用专用测试对象验证配置所需的权限，验证请求只允许访问支持厂商的受控地址 |
| 选择附件连接 | 仅可绑定本租户已启用连接。上传服务从可信租户上下文解析默认值，客户端不能指定其他租户或连接 |
| 停用连接 | 有历史附件引用时保留读取所需配置，禁止选作新写入目标。连接目标发生变化时生成新标识 |

连接标识和对象键共同定位附件。切换只影响新上传，在途请求与同幂等键重试沿用原连接。历史文件按记录中的连接读取。凭据轮换可复用连接标识，桶或对象命名空间变化使用新连接标识。未设置默认连接时上传返回明确错误。历史记录缺失连接标识时，从原部署配置建立受控兼容映射，再按实际归属核对回填。

凭证中心复用平台统一权限及审计，跨租户查阅和测试默认拒绝。密钥不进入响应、日志或导出。若支持租户录入端点，服务端校验地址及出站网络，避免任意 URL 连接。首个消费者仅为附件管理。实现前需盘点现有密钥管理能力，确定配置存储、秘密引用、附件连接字段和存量迁移方案。凭证中心仍处于设计阶段。过渡期的文件装配规则见下一节。

## 7. 凭证中心上线前的配置文件

设置 APP_ATTACHMENT_STORAGE_TENANT_FILE 指向 UTF-8 Properties 文件的绝对路径。文件由运维管理，应用启动时读取。租户键使用服务端租户 UUID，每个租户当前只配置一个连接。文件直接保存连接凭据，由运维限制文件访问权限并保持在版本控制之外。文件模式无需配置凭据环境变量。修改文件或轮换凭据后重启应用。

```properties
# 下列 UUID 是示例，须替换为实际租户 ID。厂商取 oss、obs 或 s3。
tenant.00000000-0000-0000-0000-000000000001.provider=oss
# 目标为私有桶；桶、端点或地域变更会改变固定写入目标标识。
tenant.00000000-0000-0000-0000-000000000001.bucket=appnexus-wms-test
# S3 签名地域，OSS 和 S3 必填。
tenant.00000000-0000-0000-0000-000000000001.region=cn-beijing
# HTTPS 服务端点，OSS 和 OBS 必填，S3 可省略以使用官方区域端点。
tenant.00000000-0000-0000-0000-000000000001.endpoint=https://s3.oss-cn-beijing.aliyuncs.com
# 当前租户专用凭据，必填，无默认值；部署时替换示例占位符。
tenant.00000000-0000-0000-0000-000000000001.access-key=<有效的 AccessKey ID>
tenant.00000000-0000-0000-0000-000000000001.secret-key=<有效的 AccessKey Secret>
```

开启文件模式后，仅按可信租户目录选连接。缺席租户拒绝上传。新记录的对象键包含不含密钥的目标指纹。轮换同一目标的凭据不改变指纹，改桶、地域或端点后旧目标的待完成写入拒绝继续，避免错误写入新桶。启用文件模式前的部署级待完成记录保持原键，在文件模式下拒绝重试。未设置文件路径时沿用原部署连接，便于原有部署继续运行。
