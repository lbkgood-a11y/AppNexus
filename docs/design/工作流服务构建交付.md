## 服务端执行约束

1. 业务代码注册WorkflowBusiness，描述能力、功能权限、构建内路由、允许输入与非敏感输出。不接受任意URL、SQL、脚本、表达式或Java类配置。
2. 发起只接收对象类型、ID、审批依据版本、单据组织、用途及接入能力。snapshot从业务存储重读权限、组织及审批依据；客户端不能提交选人条件值。
3. 按类型、用途、能力和匹配条件选中唯一启用发布版本。找不到或冲突返回409。同单据同用途仅一个活动实例，驳回重提新建实例并按对象关联历史。
4. 任务创建时解析有效人员；默认剔除提交人。无人保留不可办理占位任务并写审计告警，不跳过。扫描复核离岗人员，处理入口也实时复核。
5. 暂存不推进。每次处理复核审批依据与提交快照；依据变更返回APPROVAL_BASIS_CHANGED。普通评分、评价等必须由业务端维护独立办理版本，不能静默替换依据。
6. 实例锁后重读任务，防止两个请求沿用同一OPEN快照。业务确认成功后完成任务，业务失败不推进。或签剩余任务取消；驳回终止本次实例，不执行后续生效动作。
7. APPROVAL终态和交付记录同事务保存，结果交付失败不改审批结果。业务状态变更和下游事件须由业务服务同事务保存；复杂下游可通过WorkflowStarter发起关联业务编排。
8. ACTION/WAIT建立接收节点与交付记录，Worker在事务外调用业务，确认和引擎推进同事务。异步回调仅暴露Java公开契约，外部HTTP签名/身份验证由具体业务适配器实现；浏览器不能声明执行成功。
9. 撤回必须配置业务校验能力并获得同步确认；撤回不自动回滚已发生业务。恢复必须有原因，不提供任意跳过关键节点入口。
10. 任务结束立即收回任务字段处理权。历史接口只返回工作流事实，业务原文仍需业务侧授权；不因已办身份开放整个业务模块。

## HTTP契约

统一前缀 `/api/workflow`，第一方认证沿用平台Cookie/CSRF或有效Bearer及可信租户上下文，不向合作方API自动开放。
写入必须携带 `Idempotency-Key` UUID；同租户同账号同键不同内容409。办理意见为独立comment字段，缺省空，最长2000字符，不作为业务输入或脚本执行。读写均no-store，稳定错误码不含SQL/引擎异常原文。

| 接口 | 能力/对象约束 |
| --- | --- |
| GET /capabilities、/businesses | 有效成员，能力目录仅展示本人可配置能力 |
| GET /definitions、/definitions/{id}/versions | workflow:read |
| PUT /definitions/{id} | workflow:edit；revision首次-1、后续为当前版本 |
| POST /validate、/preview | workflow:edit；preview只计算样本路径 |
| POST /definitions/{id}/publish、/disable | workflow:publish；发布时再校验能力权限；停用原因必填 |
| POST /instances | workflow:start及接入业务能力权限；条件来自可信快照 |
| GET /tasks?view=todo/done/started/copied | 有效成员，只查本人当前租户事项 |
| GET /tasks/{id}、POST /tasks/{id}/actions | 任务归属；写操作再校验任职、依据及受控字段；动作SAVE/SUBMIT/APPROVE/REJECT |
| GET /instances | workflow:operate；仅工作流事实，不含原文 |
| GET /instances/{id} | 发起人、任务参与者、抄送人或运行管理员；历次实例逐项过滤 |
| POST /instances/{id}/withdraw | 本人发起且运行中；必须配置并通过业务校验能力 |
| POST /tasks/{id}/reassign、/jobs/{id}/retry | workflow:operate；原因必填，重新分配仅允许当前规则内有效人员 |

动态OpenAPI随引擎启用登记这些控制器，既有app分组覆盖/api/**；此表记录新增API的权限及事务约束。
