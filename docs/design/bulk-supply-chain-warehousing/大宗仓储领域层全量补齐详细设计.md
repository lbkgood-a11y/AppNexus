# 大宗仓储领域层全量补齐详细设计

状态为待评审。设计日期为 2026-11-22。

## 1. 范围与交付单元

在 `backend/services/bulk-warehousing-service` 内一次补齐现有写用例的领域实现，由 `monolith-app` 沿现有方式装配。迁移以现有仓储生产入口和业务事实为基线，涵盖进仓、库存、货权、出仓、冲销及返仓。提交可以按职责拆分，整套调用链通过验收后统一切换。本轮生产迁移仅覆盖现有钢卷用例。玉米、大豆、废钢、煤炭和消费品用于验证领域模型及模板边界。这五类货物的生产 API、模板管理界面和新增持久化模型另行交付。

设计基线见[多品类仓储系统设计方案](多品类仓储系统设计方案.md)、[仓储服务与平台集成设计](大宗供应链仓储服务与平台集成设计.md)、[进仓流程详细设计](进仓流程详细设计.md)和[钢卷控吨出仓详细设计](钢卷控吨出仓详细设计.md)。工程边界执行[后端工程标准](../../development/后端标准工程结构与AI生成约束.md)及[架构与分包边界](../../development/架构与分包边界.md)。

## 2. 多品类领域模型

| 归属包 | 权威事实与业务责任 | 需要验证的不变量 |
|---|---|---|
| `domain.receiving` | 通知行、接管、收货确认 | 实收累计受通知和有效批准上限约束。接管、确认和过账均关联对应货物、位置和来源。一个确认行对应一次有效入账 |
| `domain.stock` | 库存身份、位置、质量状态、余额及占用 | 序列身份至多有一个有效实物占用。数量型占用累计受可分配余额限制。移位及状态转换数量守恒。库存过账可追到来源 |
| `domain.title` | 身份货权、份额货权、权利版本及监管限制 | 过户平衡且实物位置保持原值。混储实物余额等于货主份额与获准暂挂份额之和。暂挂份额不可配。过户、冻结和解除均保留依据 |
| `domain.dispatch` | 通知、提货授权、车船次、配货及交接 | 子额度和范围受父单约束。预占、已配、释放、核销及余量按同一授权口径对清。交接校验授权、配货和额度，并根据库存、货权与证据领域的决定给出履约及额度变化 |
| `domain.evidence` | 计量证据版本、分摊、质检覆盖和结论 | 分摊量之和等于采用量。复磅引用新版本，失效证据不可交接。质检放行仅作用于覆盖范围及数量 |
| `domain.returns` | 原交接引用、冲销、返仓在途、接管和损失 | 可冲销或可退量取决于原交接及后续事实。发运量与有效接管、批准损失及在途余额对清。改仓保留线路历史 |
| `domain.process` | 版本化进出仓模板、步骤及策略选择结果 | 步骤的前置事实与必需证据必须满足。适用策略确定且可追溯。模板可达成必经业务节点 |

库存身份采用两种有类型的语义。序列单元以稳定身份引用单卷或单件，批量库存以品规、批或堆批及位置引用对应余额。分切、混批和粒度转换将来通过有来源和目标身份的显式转换实现。货权按身份或份额表达，可分配实物与可使用货权分别核验。

数量模型持有数值、单位及口径。区分计划量、批准量、计量值、实收实发量、库存过账量和额度核销量。钢卷保留整数卷数、账面重量及实测重量各自的语义。散货用基础单位核算库存和可用份额。换算、舍入和尾差归属以确定的规则版本为依据，采用十进制定点计算。既有钢卷单位、精度和错误行为从实际入口固化为兼容用例。

各业务记录保有独立生命周期。跨库存、货权、额度的判断以同一事务中锁定的权威事实为输入，产出有类型的业务决定，包含受影响标识、数量变化、结果状态和证据引用。库表版本及应用授权留在执行边界。领域代码仅依赖 JDK 和允许的纯计算构件。需要跨领域校验时，由用例传递必要事实，保持包间依赖单向。

### 2.1 领域依赖与事实归属

七个领域包之间通过应用用例协调，各包独立计算本领域的决定。应用将上游决定映射为下游定义的最小输入，例如把计量有效性和确认量传给出仓规则，把质量结论及覆盖数量传给库存规则。实现阶段禁止七个业务包互相导入、持有对方聚合或调用对方仓储。仅在出现实际跨包复用时，才提取标识、基础计量和精度等稳定值类型，由各包单向依赖。

| 领域 | 跨领域协作时提供的事实或决定 |
|---|---|
| `receiving` | 提供签发范围、接管与确认结果。应用据此请求库存入账，货权登记和质量放行按其各自前置条件执行 |
| `stock` | 提供库存身份、位置、可发状态、账面量和占用决定，持有库存质量状态。加工转换及批次谱系归库存 |
| `title` | 提供当前权利、份额与限制决定。出仓的当前权利核验与授权内保存的权利版本比较由应用组装，货权变动归本领域 |
| `dispatch` | 提供通知、授权、车次及配货事实和额度决定。复磅审核的暂停或认可属于出仓履约，原始计量与分摊校验归证据 |
| `evidence` | 提供有效计量、分摊和检验覆盖。业务完成条件及入账效果由消费该证据的领域决定 |
| `returns` | 以原交接快照及后续事实判断可冲销、可返仓、改仓和损失，输出返仓决定。实物恢复、货权影响、额度变化分别由各权威领域计算 |
| `process` | 提供流程版本、可执行步骤及策略选择结果。应用绑定具名步骤与真实操作，流程规则保持纯计算 |

## 3. 流程模板、策略和领域命令

| 机制 | 输入与输出 | 执行边界 |
|---|---|---|
| 流程模板 | 方向、模板身份与版本、已完成事实、允许的下一步骤、必需证据及异常转移 | 描述接管、计量、检验、交接等步骤的依赖，可表达跨车组批、分批和拒收。模板给出允许执行的具名步骤，应用调用对应领域命令并提交业务过账 |
| 领域策略 | 规范化事实和策略版本，返回身份粒度、候选与占用要求、计量分摊、验收覆盖或交接证据要求 | 按规则种类组合。整卷独占与批量数量占用是不同策略。同一运输方式可配置不同证据，权限和监管复核由固定执行链承担 |
| 领域命令 | 当前领域状态、实际证据及选定策略，返回接受、业务拒绝，或如复磅暂停这类需保存的业务结果 | 固定实现接管、确认、放行、占用、核销、过户、冲销等不变量。任何模板到达关键转换时均通过相同命令门禁 |
| 应用及平台工作流 | 可信身份、操作上下文、审批结果、读写端口及事务 | 平台统一准入和审批承接。应用重新读取授权后的业务事实，按操作完成事务。任务完成或审批回调只有经过实际领域命令才会改变仓储事实 |

### 3.1 代表性流程

| 模板 | 正常路径 | 分支与恢复 |
|---|---|---|
| 钢卷进仓 | 签发 → 接管 → 收货确认与过账 → 按现行条件登记货权及质检放行 | 拒收、重复接管或超量按原规则处理。货权与质检分别依赖各自的事实，按源用例定序 |
| 钢卷汽运出仓 | 通知与授权 → 建车配货和占用 → 车辆限额核验与复磅 → 门岗交接 | 撤配、换车、复磅超额暂停、交接冲销、同仓或跨仓返仓。建车前预占由原授权用例处理 |

### 3.2 选择、版本和生效

选取维度为进出仓方向、仓库、品规或品类、业务类型、作业方式。合同确定允许的接管点、计量证据、超收批准和交接条件，并用于校验候选模板。候选按预定义优先级选择，精确仓库和品规优先，品类默认仅在明确登记时生效。同优先级冲突或缺失适用策略时，签发或开始执行受控拒绝。发布校验步骤可达、关键门禁和证据齐全、单位兼容、策略组合有效。

每个执行对象绑定其采用的模板和策略版本。已进入执行的记录原版本续办。确需切换时须有批准记录、已完成事实映射和证据重验。交接仍读取当前货权版本、监管限制、授权撤销和有效期。此次迁移由代码目录发布固定钢卷模板，通知持久化版本。V161 为既有通知保留 V1，现有入仓与钢卷汽运新通知绑定 V2。后续新增策略管理入口时，另行设计发布权限及真实执行。

### 3.3 五类货物的进出仓模板与策略

下表是领域验证用模板。每行给出可组合的步骤和规则。实际启用由仓库、品规、业务类型、作业方式及合同共同决定。合同决定适用阈值、计量依据及交接点。

| 品类 | 进仓模板 | 出仓模板 | 策略差异 |
|---|---|---|---|
| 玉米 | 按车计量与采样 → 卸入隔离区并接管 → 按验收批部分或全部放行。需要烘干或清杂时，转入仓内加工作业，按 §3.6 完工过账 | 按已放行筒仓批及货主份额占用 → 装车复核及计量 → 按确认行交接并核销 | 追溯至筒仓批和投入批。配置水分、杂质等质量条件、可混储范围、转换损耗和库存量与合同折算量的口径 |
| 大豆 | 按来货批计量和采样 → 在指定库区隔离接管 → 按合同要求核验等级及批次属性 → 按覆盖范围放行 | 校验订单要求的等级及来源等属性 → 锁定符合条件的批次和可用份额 → 按批拣取或装运 → 计量交接 | 按订单和合同控制批次兼容性及混配许可。需要来源隔离时，批次属性进入分配资格。允许混配时保留投入批和数量 |
| 废钢 | 入场计量及查验 → 卸货分拣 → 按等级分行计量或按批准规则分摊 → 分别确认接收、待复核或拒收 | 按等级、堆批和可用数量占用 → 装车计量并确认等级分摊 → 按交接行扣减库存并核销 | 同车可有多个等级及拒收行。毛皮净重、扣杂、实际入账量与适用计价量独立留痕。复核改判走有依据的批次调整 |
| 煤炭 | 汽运按车称重、卸货接管、多车组验收批。船运按舱或卸货段计量与分摊、分段接管。均支持待检入账和按覆盖量放行 | 按堆批可用量、货主份额和额度占用 → 按车或船舱装运并确认计量分摊 → 按合同交接点分段核销 | 按运输方式选择过磅、水尺或皮带秤等合同认可的证据。设置混储兼容、份额核销、跨车或跨舱质量覆盖及分摊尾差规则 |
| 消费品 | 按托盘、箱或件扫描收货 → 核对品规、批次、适用效期及包装版本 → 按基础单位入账，按仓库规则质检放行 | 按订单和效期要求选批 → 整托、整箱或拆零拣选 → 按箱件复核交接并核销 | 支持批次追溯、包装换算和效期优先分配。有效期、最低剩余效期及混批限制按品规和订单执行。物流包装标识可随拆装变化 |

### 3.4 需要补齐的通用领域能力

| 能力与归属 | 设计要求 |
|---|---|
| 批次与资格条件 · 库存、计量质检 | 库存事实记录批次、品规、可用等级及适用的生产日期、效期和来源属性。占用和交接均核对批次资格。有效期及剩余效期计算由用例传入可信业务日期 |
| 计量、分级与覆盖 · 计量质检、收发履约 | 保留原始计量值及有效证据版本。支持一个计量结果覆盖多行、一车多等级、跨车组批和部分放行。同口径分摊守恒。过账量、合同折算量和额度核销量各自可追溯 |
| 转换与谱系 · 库存、货权 | 拆批、混批、改级和加工产出使用显式库存转换命令，记录投入、产出、批准损耗、处理依据及来源标识。按相同基础单位核对投入等于产出与批准损耗之和，分别核对库存和份额，按审批依据处置原占用并延续适用限制 |
| 混储与份额 · 库存、货权 | 库存按堆批管理，权利按货主及适用范围核算。分配同时校验堆批可用量、货主可用份额与额度。增减、转移、自然损耗及差异暂挂形成可对账事实 |
| 包装层级与拆零 · 库存 | 包装单元可表达托盘、箱、件及父子关系，商品库存身份和基础件数独立记录。按包装版本换算，拆装保留追溯且基础件数守恒 |

### 3.5 领域验收场景

| 品类 | 正向场景 | 必须拒绝或保留的结果 |
|---|---|---|
| 玉米 | 两车同批接管后按检验覆盖量部分放行。对获准数量烘干、清杂，核对新旧批数量、份额、批准损耗和来源链，再按新批出仓 | 批次转换缺少损耗依据时拒绝。待检余量不可分配。合同折算量变化不能直接改变实物库存 |
| 大豆 | 同一品规两个来源批分别接管。订单指定来源与等级时仅从合格批占用、装运并交接 | 非兼容批次混配、替换为未放行批或超货主份额均拒绝，原占用保持可核对 |
| 废钢 | 一车实测净重分为两个接收等级和一个拒收行，计量分摊对清。后续仅按已接收等级分配和出仓 | 分摊不守恒、拒收量入账或改判缺少有效依据时拒绝。原始磅单及首次分级可追溯 |
| 煤炭 | 汽运跨车验收批部分放行，船运跨舱分摊后分段交接。在混储堆批按货主份额占用和出仓，实物、份额及额度可对账 | 实物余额充足但货主份额不足时拒绝。证据重复使用或当前冻结时拒绝交接 |
| 消费品 | 按版本以 10 箱 × 24 件入账。效期优先选择合格批，拆箱发 7 件，剩余 233 件，并可追溯批次与箱托变化 | 过期批、剩余效期不足或包装换算版本不符时拒绝。拆箱本身不减少库存 |

### 3.6 仓内加工作业与完工过账

仓内加工作业是独立业务对象，用于表达已经接管的货物在仓内经历的烘干、清杂、分选、分切或配料。作业模板规定工序、证据和完工条件。进仓模板可在接管后安排加工，出仓模板按产出批次的实际质量状态决定是否可分配。当前以独立对象定义作业职责，独立加工领域包待出现跨班次续办、多工序或在制品核算等需求时评估。

| 职责 | 权威事实与边界 |
|---|---|
| 加工作业 | 保存作业及模板版本、投入批次及实投数量、加工记录、主副产出、计量和验收证据、损耗及批准依据。作业从计划、执行、待完工确认推进至已过账。执行期间对计划投入建立受控占用，完工确认提供过账事实 |
| 库存转换（`domain.stock`） | 校验原批次余额、加工占用和转换条件，扣减实际投入，生成产出批次及库存流水，记录来源与目标谱系。按相同基础单位核对投入量等于全部可计量产出与批准损耗之和。产出依据有效验收证据确定质量状态，适用待检规则时保持待检 |
| 货权与监管（`domain.title`） | 核对原货主份额和当前限制是否允许加工，按批准依据分配产出份额及损耗归属，记录限制向适用产出继承的关系。完工时复核当前权利和监管版本 |
| 应用用例 | 通过统一权限模型校验操作准入、仓库及货主记录范围和适用字段保护，读取并锁定作业、投入库存、占用和监管事实。协调库存与货权决定，在同一事务提交过账 |

#### 品类加工模板

| 品类 | 加工模板与产出 | 计量与追溯重点 |
|---|---|---|
| 玉米、稻谷、小麦和大豆 | 按批领用 → 烘干、清杂或筛选 → 确认合格粮、可回收筛下物及批准损耗 | 追溯投入批及前后检验。配置含水率与杂质证据，区分实测重量、库存过账量和合同折算量 |
| 废钢 | 按堆批领用 → 剪切或破碎分选 → 按等级确认产出 → 登记可回收残料与损耗 | 逐等级记录实测或经批准的分摊量及去向。单纯复检改判执行质量或等级调整 |
| 成品钢材 | 母卷领用 → 纵剪成子卷或开平定尺成板 → 按规格确认产出及余料 | 记录母卷、子卷或板材批及适用炉批来源。按重量对账，卷数与件数按各自口径记录 |
| 煤炭 | 多堆批计量领用 → 按批准方案配煤 → 实测并确认产出批。也可按粒级执行破碎筛分 | 配煤记录批准配比与实际投入、各来源批和产出检验。筛分分别保留各粒级和残余物流向 |

#### 多投入、多产出及监管规则

1. 完工确认记录投入行、产出行及损耗行。每个投入行引用来源库存身份、占用、实际数量和计量证据。产出行区分主产出、副产物及可回收余料，分别记录目标库存身份、实际数量、质量状态和去向。可回收余料进入产出合计，每笔批准损耗独立关联证据。
2. 在共同的实物计量口径下核对投入合计等于产出合计加批准损耗。不同单位须按有效规则版本换算。尺寸、品规、卷数、件数及合同折算量分别保存。仅改变外包装的打包沿用包装作业。加工形成新库存身份时走库存转换。
3. 每个完工过账组关联投入至产出的来源关系与分配依据。可实测归因时记录对应数量，物理混合后按批准规则记录贡献，并区分实测与分摊。支持由目标身份向上查询来源，也支持由来源向下查询全部产出、余料及损耗。分摊精度与尾差归属随规则版本记录。
4. 单一货主的投入按批准依据核算产出和损耗。多货主混配须验证混储许可、各来源份额及明确的分配依据，逐货主核对投入份额、产出份额与承担损耗。发生货权转移时须有独立授权依据和对应货权记录。加工前及完工时校验当前限制。禁止加工、禁止混配或限制无法落实到适用产出范围时拒绝。允许加工的限制按批准范围继承至相应产出与余料，后续分配和交接复核。

完工过账按作业和完工确认的稳定标识去重。应用重新读取实投、产出和批准证据，校验其范围及版本。领域通过后，在同一事务内消费投入占用、扣减来源批次、登记产出及损耗、更新货权和限制、保存谱系与审计，并把作业推进为已过账。相同确认重放返回原过账结果，内容不一致时返回冲突。任一写入失败时整笔回滚，保留可续办的原作业状态。实际投料即需单独入账的多工序模式应另行设计在制品余额和各工序的过账时点。

**玉米烘干示例。** 同一质量计量口径下，原批次实投 100 吨，烘干后实测产出 96 吨，4 吨损耗有有效批准。完工后原批次扣减 100 吨，新批次增加 96 吨，同时记录 4 吨损耗、对应货主份额变化和批次谱系。若有单独确认的可回收副产物，其数量纳入产出合计。合同折算量按独立口径留痕。

| 验收场景 | 预期结果 |
|---|---|
| 正常完工及追溯 | 按 100 吨投入、96 吨产出及 4 吨批准损耗对账。由产出批次可追到原批、计量和批准记录。产出质检未放行时不可出仓 |
| 计量与批准异常 | 投入和产出计量口径不一致、数量不守恒或损耗批准缺失时拒绝过账，库存和货权余额保持原值 |
| 监管与份额 | 加工期间新增禁止加工的限制或源份额不足时拒绝。允许加工且限制需延续时，目标批次保留限制，后续占用和交接受其约束 |
| 废钢分级 | 同一堆批投入 10 吨，产出两个等级分别为 6 吨、3 吨，可回收余料 0.8 吨，批准损耗 0.2 吨。各行可双向追溯。重复归集余料或缺失等级依据时拒绝 |
| 钢卷分切 | 母卷实投 20 吨，两个子卷分别为 11 吨、8.5 吨，余料 0.5 吨。原母卷扣减，两个新身份及余料可追到母卷，适用限制按范围继承。占用冲突或重复生成子卷身份时拒绝 |
| 煤炭配煤 | 两个来源批分别投入 60 吨、40 吨，确认 100 吨产出。按获批的实际投入贡献记录 60 吨、40 吨货主份额及来源，产出按检验结果放行。任一来源份额不足、禁止混配或缺少多货主分配依据时拒绝 |
| 幂等与失败 | 重放同一确认只产生一个过账组。模拟货权写入失败时，库存、谱系及作业状态一并回滚 |

本轮将上述场景纳入领域及用例事务边界验证。生产迁移仅覆盖现有钢卷用例。钢卷分切与其他加工场景均用于设计验收。加工对象投入生产前须按 D01–D12 完成独立声明、权限与实际运行接入，并用真实数据库验证过账和回滚。

## 4. 应用执行和一致性

调用方向为 Controller → 公开 API → 应用用例 → 领域。应用通过自身输出端口读取主数据和仓储事实，集成适配器调用主数据公开契约，MyBatis 负责锁、固定 SQL、映射、版本条件和必要的数据库约束。仓储表由仓储服务拥有。

每项写命令沿真实入口取得可信主体并完成统一功能准入、行范围及适用字段保护。在现有本地写事务中，按核对过的锁顺序锁定所需通知、授权、车次、货权监管范围、库存或返仓记录。复核关联对象范围与版本后构造领域事实，取得领域决定，再提交业务流水、余额和审计。冻结、过户与交接沿用相交控制范围。改仓同时校验原出仓仓、原接收仓及新接收仓的适用记录范围。

保留各现有入口的幂等适用范围、请求指纹、原结果及冲突语义。已有同键成功重放时，仍执行适用准入与范围检查，按既有契约返回原结果。业务拒绝、需保存的暂停事实以及技术失败分别映射到现有返回、错误码和提交行为。失败整笔回滚，可信账号取自认证上下文，审计时间由数据库以 UTC 生成。

### 4.1 出仓授权额度、货权与实物库存

“货主额度”在出仓语境中指货主签发的**出仓授权额度**。领域输入和余额展示应明确使用下列三个名称，分别说明适用范围、单位和数量口径。

| 口径 | 权威领域 | 业务含义 |
|---|---|---|
| 出仓授权额度 | `domain.dispatch` | 通知单、提货授权和车次约束下可预占、占用、释放及核销的数量。通知和授权可在选定实物前预占 |
| 货主可用货权 | `domain.title` | 指定货主、仓库和货物范围内，可用于本次操作的整卷权利或混储份额。按当前权利版本和冻结等限制判定，份额型分配还需扣除适用的有效占用 |
| 实物可用库存 | `domain.stock` | 指定身份或堆批中，质量已符合出仓条件且可分配的实物。整卷按身份独占，数量型库存按有效占用计算可用量 |

| 操作 | 三个领域的协作 |
|---|---|
| 授权预占 | `dispatch` 核对通知和授权有效性及上限，登记未分配预占。此时尚未选定库存，实物占用和货权余额保持原值。这笔预占只代表额度保留 |
| 实物配货 | `title` 校验所选库存的当前货主、权利版本及限制，份额型场景同时占用货主份额。`stock` 校验可发状态并锁定整卷身份或堆批数量。`dispatch` 使用已有未分配预占，按规则补占差额并登记车次占用。三个决定在同一事务提交 |
| 释放 | 撤配按原配货明细解除实物占用及适用的份额占用，`dispatch` 释放相应通知、授权和车次额度，并使该配货对应的复磅审核失效。钢卷撤配释放量回到可再分配额度，未分配预占保持原值。授权短结释放其未分配预占，仍存在车次占用时拒绝短结 |
| 交接核销 | 在同一写事务内，`title` 复核当前货主、权利版本和限制，确定交接影响的货权；份额型场景核减对应份额。`stock` 校验实际身份或批次数量与有效占用，扣减库存并消费占用。`dispatch` 校验有效计量、当前授权和三级占用，按适用口径把占用转为已核销量。交接、库存、货权及额度变化按同一交接标识追溯 |

应用用例按既有统一准入和范围执行取得业务事实，按固定次序锁定相关记录，协调三个领域的决定。冻结、过户和交接共用相交的控制范围。任一约束失败时不产生部分过账，重复交接沿用原有幂等契约。钢卷实物扣账采用账面量，授权核销采用有效复磅确认量，两种数量分别记录。混储份额占用和核减用于多品类领域验收。

### 4.2 钢卷事务分组与适配器写入

应用用例是业务事务边界。同一命令内的子步骤使用组合应用同一数据源事务；事务由装配和出站适配器提供，领域判断不持有事务、锁或技术端口。迁移时逐操作记录现行事务、锁的获取顺序及锁覆盖范围，包含仓级栅栏、通知及授权链、车次、货权版本及卷号库存锁，以及跨仓返仓使用的仓库集合。新增或调整锁须通过对应并发回归。

| 命令组 | 同事务提交的结果 |
|---|---|
| 进仓与入仓处置 | 每次签发、接管、收货、货权登记及质检放行各自完成其既有事务。收货一次提交累计量、确认和库存过账；独立登记或放行按原前置条件提交 |
| 配货、撤配与复磅 | 实物占用、额度、配货及适用审核失效同时提交。超额复磅保留实际计量及暂停结果，验证原占用维持既有契约 |
| 门岗交接、过户与冻结 | 按现有共同控制范围串行复核。交接写入交接及明细，按账面量同时扣减实物和在库货权，按复磅确认量核销三级额度，消费配货占用。过户和冻结各按原操作事务提交 |
| 冲销与返仓 | 整笔冲销、同仓返仓、跨仓发运及接管、改仓、损失结清或重开、返仓质检放行按原命令分别提交。每条命令内联动写入适用的返仓事实、余额、货权、额度及证据；跨仓流程在各命令之间以已提交的在途事实续办 |

`MyBatisCoilOutboundStore.dispatch` 当前把多类写入集中在同一适配器操作。迁移时可沿用同一原子写入端口，由应用传入各领域已确认的结果。固定 SQL 的行数、版本及唯一约束继续承担并发兜底，条件更新失败映射至既有错误并回滚。每组需保存的业务拒绝与技术失败分别按现行语义验证。

### 4.3 库存身份、批次谱系与追溯查询

`domain.stock` 持有稳定库存身份、库存流水和批次谱系。钢卷沿用现有收货记录 ID 作为追溯入口，卷号作为业务标识同库存身份关联。过户、位置变化、质量放行和原卷返仓沿同一库存身份追加事实。拆批、混批或加工转换产生新身份时，按过账组记录从投入行到产出行的来源关系、数量口径、计量证据及分摊依据，关联余料和批准损耗。更正或冲销保留原记录及其有效状态。谱系按转换事件建立，来源必须早于相应产出，避免循环追溯。

| 业务记录归属 | 跨领域关联 |
|---|---|
| `receiving` | 通过库存身份关联通知、接管和确认行，保留源仓与接管位置快照 |
| `dispatch` | 通过配货明细关联库存身份、通知、授权和车次，通过交接及交接行标识关联卷的实发量、库存扣账量和核销量 |
| `returns` | 通过原交接及交接行关联冲销、返仓批次、在途发运、改仓、接管和短损记录，保留原仓和实际接收仓快照 |
| `title` | 通过库存身份或份额记录关联货权登记、过户双方及权利版本、冻结和解除；转换时通过同一过账组追溯份额变化和限制继承 |
| `evidence` | 通过业务行保存的有效计量或检验引用追溯当次采用的证据版本和覆盖范围，复磅、复检时保留原引用 |

由应用查询用例按可信租户、库存身份和上述记录键汇总。现有钢卷追溯沿用 `BulkWarehouseStockBalance.trace` 的统一功能准入及现行租户级计划要求，核对当前库存的仓库、货主和品规，以及历史明细涉及的所有仓库、货主和过户对方。取得同一库存锁内的一致视图后完成范围和适用字段保护。有任何历史关联不可读时整体拒绝，避免从响应推断其他仓库、货主或单据。现有查询契约和错误语义纳入回归。

未来批次谱系查询沿用统一权限模型。向上查来源、向下查产出时，对请求范围内的节点、关系及关联记录逐一执行可信租户、仓库、货主及适用字段检查。请求范围内存在无权记录时采用整体拒绝语义，返回内容、错误详情及数量汇总均不得泄露被拒绝的信息。谱系写入与库存转换同事务，查询按一致视图读取已提交的转换与关联事实。

## 6. 迁移与切换

1. 从现有入口建立逐操作基线，固化请求、错误、锁和事务、持久化数量及相关读模型。覆盖在途、已占用、已暂停、待检、已冻结和历史幂等数据。记录可能由 SQL 条件隐含的业务语义与数据库并发保护。
2. 按领域职责建立模型、纯规则和钢卷流程绑定。通过既有输出端口快照映射与现行错误契约接通全部用例。数据库约束继续承担原子性和并发兜底，业务判断迁入单位明确的领域规则。
3. 以现有 API、声明、记录标识、业务流水和历史状态为兼容目标。流程版本采取 V161 增量迁移，在既有入仓、出仓通知上增加版本列。存量按 V1 续办，新签发记录按当前目录写入 V2。授权、车次及返仓引用原通知时沿用该绑定。历史业务数量保持原值。部署前验证带旧记录的续办及回退时的版本兼容。
4. 在部署组合中一次替换对应执行链，清除应用层重复的领域规则。禁止同一命令对新旧路径双写。上线前以同一存量夹具比较新旧结果及对账；回退以前后读写契约兼容为前提，保留部署前产物并用既有流程确认健康及在途可续办。

## 7. 验收及声明复核

| 验收层次 | 必须提供的证据 |
|---|---|
| 钢卷领域行为 | 逐操作映射到实际命令和测试。验证非法状态、数量精度、重复占用、分摊守恒、超额暂停、过户版本、退回、冲销和短损等边界 |
| 多品类与流程 | 按 §3.5 验证五类货物的正反向场景，按 §3.6 验证加工完工、库存转换、货权监管及重复和失败行为。另覆盖同品类不同模板、旧版本续办、候选冲突及缺失、跳过必经步骤失败，以及证据齐全但当前冻结或授权已失效时拒绝交接。以上为领域验收，生产入口和真实数据库迁移验收覆盖现有钢卷用例 |
| 正式装配与真实数据库 | 从原 HTTP 路由进入组合应用。29 个写操作逐项覆盖正常与适用拒绝路径。检查跨租户、无权限、无策略、跨仓及跨货主、撤权、字段保护、失败回滚、版本冲突、并发抢占及交接与冻结竞争。验证同键同内容、同键异内容和业务级重复过账。校验已存在数据的余额、流水与四个审计字段 |
| 出仓额度、货权与库存 | 钢卷预占只改变通知和授权的额度。配货消费已有预占并锁卷，撤配释放原占用并使复磅失效，短结拒绝仍有车次占用的授权。账面量与复磅量不同的交接分别核对库存扣减和额度核销。额度不足、冻结或过户后权利版本失效、实物待检或被其他配货占用时分别拒绝。并发抢卷至多一笔成功，交接写入失败时核对三类事实及流水整体回滚，同键重放只核销一次 |
| 混储份额协作 | 领域验证使用统一吨口径。货主可用份额 60 吨、授权剩余 40 吨、实物可用量 80 吨时，申请 50 吨因额度不足而拒绝。另分别构造份额不足与实物不足的情况。成功配货后复核份额和库存的占用、释放，交接后复核三类账目及关联标识 |
| 查询与页面回归 | 复查准出、续办、余额、追溯及在途读模型的结果、范围与分页。用现有页面走通进仓、整卷交接、撤配续办、过户及跨仓返仓。若实施会修改前端代码，执行 C07 全局布局浏览器验收 |
| 钢卷单卷全链路追溯 | 从同一库存身份核对入仓接管、实收、货权登记、质检、过户及监管记录，再核对配货、有效复磅和交接。用各自合法分支验证交接冲销与再次出仓，以及跨仓在途、改仓、接管、待检放行及再次出仓。核对当前库存与历史数量、证据引用及仓库货主快照。分别撤销历史仓库、历史货主或过户对方的读取范围，验证整体拒绝。并发交接或返仓查询仅返回一次提交前或提交后的完整视图 |
| 多品类批次双向追踪 | 领域验证废钢拆批和煤炭混批。由一个来源向下追到各等级产出、余料及损耗。由混配产出向上追到每个来源批的贡献、货主份额、计量和批准依据，再从任一来源反查对应产出。复核数量守恒及实测与分摊标记，验证循环关联、重复过账及无法对账的转换被拒绝。查询接入方案验证跨租户及任一来源或产出范围越权时整体拒绝 |
| 存量续办与异常闭环 | 验证同授权撤配换车、多卷多车续办、已暂停复磅恢复、冻结后撤配及解除、过户后旧授权失效、完整冲销和分批退回的互斥。跨仓验证部分接管、改仓后旧仓拒收、损失结清后重开、返仓待检放行及再次出仓。每项对照旧执行链的返回、错误、余额、流水及权限 |
| 竞争与中途故障 | 覆盖交接与冻结及过户的竞争、跨仓改仓与原计划仓接管的竞争。模拟交接写入后库存或货权条件更新失败、仓路变更中途失败，核对所有适用表及审计一起回滚。基于既有组合应用 `ProductV1IntegrationTest` 场景补齐缺口，并记录操作与具体测试方法的对应关系 |
| 架构与工程 | 扩展 `ServiceLayerBoundaryTest`，正向命中每个新增领域生产包中的类型，验证领域向内依赖和公开边界。运行适用 `ArchitectureRulesTest`、`PackageDocumentationTest`，每个实际源码包维护中文包说明。逐操作复核应用仍有实际领域调用 |

复用 `InboundReceivingDeclaration`、`OutboundStockDeclaration`、`CoilOutboundDeclaration`、`CoilTitleDeclaration` 和 `WarehouseStockBalanceDeclaration`。按[D01–D12](../../development/业务对象完整声明规范.md)逐对象从实际差异反查。D01–D03 对照身份、操作、页面和路线。D04–D06 对照准入、范围和字段保护。D07–D10 对照现有能力、契约、编码和运行接入，逐项说明适用性。D11–D12 核对状态、事务、版本及真实证据。仅内部重构且声明语义经验证一致时，可记录维持声明版本的依据。发现契约或安全语义变化时，记录声明同步、版本升级及存量迁移依据。

实现阶段在 `docs/validation/` 按[功能交付门禁](../../development/功能交付门禁要求.md)记录 G01–G09 和适用 C01–C10，附命令、退出码、测试数量、失败和跳过项、真实装配数据与部署状态。既有[进仓门禁记录](../../validation/大宗仓储进仓写入门禁检查.md)、[交接记录](../../validation/大宗仓储出仓复磅与交接检查.md)和[返仓改仓记录](../../validation/大宗仓储钢卷返仓在途改仓检查.md)用于提取回归场景。本次设计评审通过后，验收证据由新执行链产生。
