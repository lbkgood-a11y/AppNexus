# 商品属性模板用途可维护化

## 业务边界

由主数据商品配置维护租户级用途，使用稳定编码和可编辑名称。预置 BASIC、SPEC、QUALITY、EXTENSION，升级保留模板和分类配置的现存引用。新增 PACKAGING 可与 EXTENSION 同时绑定，属性值归商品主档。SPEC 保留规格归属，其余用途归商品主档。用途编码及取值归属创建后固定。

## 发布与兼容

- 现有商品仍读取所持有的分类配置版本。迁移保留既有配置 ID、模板版本 ID、模板项和属性值。历史响应继续保留内置空槽，新增用途只有在相关配置实际绑定时进入历史响应。
- 发布沿用整版提交和分类版本冲突校验。服务端拒绝未知用途、跨租户模板版本、用途不匹配及跨槽重复属性。旧调用方仍可提交原四槽。已有自定义绑定参与防误清校验，避免旧客户端遗漏字段时删除自定义绑定。
- 模板列表、模板维护表单和分类发布对话框使用同一授权用途目录。商品主档的属性分组显示用途名称，历史用途仍能被解释。
- 新增迁移需覆盖模板和分类绑定历史 CHECK 约束、用途编码列长度、存量与新租户的系统用途初始化、租户级唯一约束及四项审计列。不得修订历史 Flyway 文件。
- 后台新增、维护使用统一业务对象与操作准入。读取目录仅提供当前租户允许查看的用途。授权和数据库迁移需用真实环境验证。

## 现状核对

ProductTemplateService 创建校验和 ProductCatalogService 发布校验均限制四个用途。V115 延续数据库四值 CHECK。分类读取、配置快照和部分前端类型也包含固定枚举。规格归属在 V116 根据 SPEC 计算，非 SPEC 自定义用途可以沿用商品主档归属。

当前仅完成调用链与迁移风险梳理。没有实现新接口、迁移、管理页面或验收，不作为交付记录。
