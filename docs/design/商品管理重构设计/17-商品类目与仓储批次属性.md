# 商品类目、货号与仓储批次属性

## 业务边界

现有商品类目、商品主档与货号页面分别复用 CatalogManagement、ProductManagement、ProductSkuManagement。菜单使用现有路由和权限标识，按类目、商品、货号排序。原商品编码、货号、规格及其外键关系继续使用。类目发布商品属性模板并可提供下游模板默认值，SPU 分别确认规格轴和普通货号属性，SKU 确认批次规则及计量配置，仓储保存实际批次值。

## 属性与单位配置

| 归属 | 配置 | 实际值 |
|---|---|---|
| 商品类目 | 发布商品属性模板，可提供规格、货号属性及批次模板的默认版本 | SPU 保存商品属性值 |
| 商品（SPU） | 分别确认规格轴与普通货号属性模板的生效版本 | 规格轴值沿用原规格记录，普通货号属性值由 SKU 保存 |
| 货号（SKU） | 确认批次模板的生效版本、库存单位、计价单位及多档包装换算 | 仓储实收时保存批次值，库存以 SKU 生效库存单位过账 |

类目默认值用于带出初始配置。SPU 和 SKU 保存确认的版本，避免上游发布覆盖已采用规则。批次模板复用现有属性类型、选项和校验规则，使用独立用途。QUALITY 继续承载商品级质检属性。仓储从授权的 SKU 引用获取生效规则，并在首次实收固定版本。历史单据免于迁移、补录和换算回溯。

SKU 库存单位可以继承已有商品基础单位。计价单位和各包装档位分别确认至有效库存单位的换算依据；同一个包装单位可以有多个稳定包装编码。实收按已验证的 SKU 计量配置过账。未配置 SKU 专属单位时继续使用现有默认行为。SKU 已用于库存后，库存单位变更须受到库存业务约束，避免把原余额按新单位解释。包装换算保留档位编码和生效版本，供新单据过账校验。

## 收货与查询

- 从通知行获取商品和 SKU，使用已授权的主数据公开端口验证归属及版本。仓储不直接查询商品表。
- 有批次规则的 SKU 在首次实收时填写规范化批次号及属性值。服务端校验规则版本、字段白名单、类型、范围、选项和必填。非 SKU 实收沿用原契约。
- 仓储按租户、SKU 和批次号固定采用的规则版本与属性值。同一批次后续实收使用既有快照。并发首次创建用唯一约束和同事务复核防止同一批次出现不同值。收货、库存过账、关联及审计同事务保存。
- 单次实收和批量实收均进入同一业务校验。属性采用稳定顺序参与幂等摘要，旧请求缺省值保持原摘要语义。重放时复核当前可见性。
- 批次查询复用收货可见性。跨仓分批时只通过当前账号有权读取的实收记录返回批次信息。查询条件为 SKU 和批次号，字段通过公共投影执行只读、脱敏和隐藏约束。

## 声明与实施边界

| 对象 | 现有入口 | 计划中的声明变化 |
|---|---|---|
| 商品类目与模板 | 主数据商品配置发布、模板版本维护 | 在原 Provider 维护商品模板及下游模板默认值，核对写入与读取保护 |
| 商品与货号 | 商品主档和结构用例 | 沿用原标识和关系，在原 Provider 对应操作接入 SPU 模板绑定、SKU 批次规则和计量配置，通过授权的公开端口提供仓储引用 |
| 仓储入仓 | 实收及实收单查询 | 在既有 Provider 同步批次契约、主从范围、字段保护和运行接入，核对旧客户端兼容 |

批次值不引入新的平台发号、审批或打印入口。新建自有仓储表须直接包含四个审计字段，以可信账号及数据库 UTC 写入。计划使用原收货事务，明确规则版本冲突、批次值冲突及失败回滚。当前已实现模板用途分离及类目默认模板发布、SKU 专属计量和批次模板采用，以及批量实收批次号。实收 API 已接入批次属性校验和单笔快照存储。普通货号属性模板由 SPU 确认，类目只提供默认值，SKU 维护生效模板的属性值。规格轴版本由 SPU 独立确认，规格按自身固定版本保存和回显。仓储页面录入及按 SKU 和批次号查询和一致性执行尚未接通。
