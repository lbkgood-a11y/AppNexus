# 商品管理R3.1契约修订与一致性说明

日期：2026-11-17；状态：设计建议，待V1正式评审。本次仅修订六项指定契约，不批准实施、不执行实验。09为V1基线，本文件给出其规范性细节；01现状及08历史整改记录保持原有证据，不将新契约写成已实现。

## 1. 草稿创建与分级完整性

POST商品只创建DRAFT，不能携带目标ENABLED，不提供原子“新建并启用”；先create，再以返回version调用setStatus，两次独立事务，启用失败时已保存草稿保留。后续若要单事务创建启用需另立契约。本版不要求create同时满足启用完整性。

| 层级 | 要求 |
|---|---|
| 最小创建 | code/name必填且格式合法；其他普通字段可选；productForm、categoryId、categoryConfigId、baseUnitId可省略或NULL；specificationMode由V1服务端固定NONE，客户端省略或显式NONE均可，其他模式拒绝；version不入创建请求，初始由服务端返回0 |
| 已填字段 | 引用同租户且可选；categoryConfigId非空时categoryId必填并匹配；可先选分类而未绑配置；未绑配置时attributeValues必须缺省或空数组；绑定后值必须属于该版本，类型/精度/选项始终合法；可缺required项 |
| 草稿普通修改 | 必须version；仅普通资料及已绑定义下值，不能偷改结构；可继续不完整，返回completionIssues而非把缺项当保存失败 |
| 草稿结构设置/切换 | 已保存DRAFT仍走预览+结构命令；目标可不完整，但已填引用/值必须合法，退出值显式确认；不要求停用；保存后保持DRAFT |
| 启用 | 未归档、结构状态COMPLETE，显式PHYSICAL/SERVICE、分类与发布配置、单位规则和主档必填齐全；NONE无规格；失败保持原状态/版本/审计 |
| 停用记录结构迁移 | DISABLED目标必须完整，不能以迁移把已有完整档案降成不完整；LEGACY_PENDING转COMPLETE亦须完整且旧规格已明确处置 |

completionIssues是计算结果不是生命周期状态；不泄露未授权候选。完整性不阻断合法草稿保存；未知属性、跨租户引用、非法值仍直接拒绝。

## 2. 旧enabled与新ENABLED的兼容语义

新增建议字段structure_state=LEGACY_PENDING|INCOMPLETE|COMPLETE；这是结构准入状态，与status三态正交。新草稿根据当前校验计算INCOMPLETE/COMPLETE；enabled旧true/false只映射status=ENABLED/DISABLED，全部存量初始LEGACY_PENDING，绝不因旧true宣称符合新完整性。结构状态持久化与数据同事务更新，服务每次启用/关键写仍重验，不仅信任标志。

有效新商品 = status=ENABLED且structure_state=COMPLETE且未归档。旧true+LEGACY_PENDING在列表显示“旧档启用／结构待确认”，不显示“已通过新模型启用”。查询状态与结构筛选分开；下游未来不在本阶段设计，但任何新模型候选读取不能仅按ENABLED放行。

| 存量组合 | 允许 | 禁止 |
|---|---|---|
| ENABLED+LEGACY_PENDING | 已授权查看、列表、历史；单独停用 | 普通编辑、原地确认COMPLETE、重复启用请求绕过校验 |
| DISABLED+LEGACY_PENDING | 查看；先预览并显式完整迁移 | 直接启用、伪造NONE、只改标志放行 |
| DISABLED+COMPLETE | 普通维护、完整迁移、校验后启用 | 自动恢复旧true标志代替启用 |

存量通过迁移转COMPLETE时保持DISABLED，随后独立启用；保留原始enabled到legacy_enabled_snapshot（可空，新商品NULL）作为历史证据，不继续双写旧布尔状态。旧列保留迁移期但停止业务写入。新status和structure_state由新服务唯一维护。

## 3. 结构迁移版本绑定、幂等和失败恢复

### 3.1 预览契约

POST /{id}/structure-preview只读，使用唯一OpenAPI operationId productPreviewStructureMigration；业务operationId Product.previewStructure，建议复用migrate_structure权限但声明独立操作。CSRF按宿主POST安全链要求执行。

请求固定sourceVersion、sourceStructureRevision、sourceCategoryConfigId（允许NULL），目标categoryId/categoryConfigId（草稿可NULL）、productForm/baseUnitId/NONE、完整目标attributeValues、退出项处置、legacySpecificationDisposition。服务重读源和目标确定版本，不接latest。响应包含source状态、目标确定配置链与四槽、diff、completionIssues、canonicalPayloadDigest及previewToken、expiresAt。

previewToken为服务端签名的无持久化预览凭据，建议有效15分钟（设计参数，UTC数据库/服务可信时钟，需G1确认）；绑定租户、账号、商品ID、源version/structureRevision/config、目标固定配置和元数据准入摘要、完整规范化载荷摘要及协议版本。签名复用宿主公开能力；能力不可用则G1选择受控持久化预览方案并另审表，不伪称已可用。token不入URL/日志，客户端任意改目标值/处置需重预览。token不承诺执行可用，不代替授权；源/目标准入变化时拒绝并重预览，不自动追新配置。

### 3.2 执行与幂等契约

PUT /{id}/structure的唯一OpenAPI operationId为productMigrateStructure，业务Product.migrateStructure。请求包含与预览完全相同的规范载荷、sourceVersion/sourceStructureRevision/sourceCategoryConfigId、previewToken；必填Idempotency-Key，建议UUID，作用域为tenant+account+Product.migrateStructure+productId+key。普通create/update不因此宣称支持幂等重放。

新增建议md_product_structure_request表：id/tenant_id及四审计字段；account_id（真实会话账号）、product_id、operation_code、request_key、payload_digest BINARY(32)、result_product_version、result_structure_revision、change_id、result_json（最小成功结果）、completed_at TIMESTAMP(6)、expires_at TIMESTAMP(6)。唯一索引覆盖tenant/account/product/operation/key，字段长度和索引字节G1验证；无可信账号的结构迁移接口拒绝，系统批次另审。该表与商品/值/审计/change同一数据库事务提交，成功结果不可改，不缓存整份敏感商品详情。

同key同digest已成功：重新认证、复核当前租户及迁移权限和对象可读后返回原结果，标replayed=true；不再次验旧CAS或preview过期、不再次写历史。若权限已撤销则拒绝，不因幂等记录绕过授权。返回resultVersion与当前version可能不同，需重新GET当前商品，不能覆盖页面为旧状态。同key不同digest返回409 IDEMPOTENCY_KEY_REUSED。并发同key由唯一键/事务锁串行；有界等待超时返回409 MIGRATION_IN_PROGRESS，客户端只能查询或手动重试同key同载荷。

幂等成功记录建议保留7天，成功响应明确replayUntil；这是待确认技术窗口。窗口外返回409 IDEMPOTENCY_WINDOW_EXPIRED（仍在记录时）；物理清理后key无法识别，服务必须先检查原source CAS，已成功请求因版本已变而409，不宣称永久重放。客户端窗口外先GET历史核实，不复用key执行新业务命令。payload摘要含规范化值/目标/退出处置与source版本，不含可重新签发token的字节；但首次执行必须用有效且摘要匹配token。

### 3.3 执行顺序与失败恢复

每次先认证/CSRF/授权，再查询已提交幂等结果；无结果时校验token及源/目标准入，按05锁序锁定资源和商品，做CAS，插请求占位、撤当前值/choice、切配置及结构状态、写目标值、before/after快照和完成结果，同事务提交。请求占位不以独立事务提交；并发冲突回滚后读取胜者已提交结果。业务值错误、CAS过期、审计/change写失败、死锁或超时均整事务回滚（包括请求记录），不留下可误认为成功的记录。

响应丢失：先GET商品/changes按changeId或版本核实；在有效窗口内用户手动重试同key同载荷，可获得同结果，前端不自动重放写请求。若首请求回滚，无结果且源未变，同key可重新执行；token过期或准入改变则重预览。改变载荷需新key；源已变则409 SOURCE_VERSION_CHANGED，保留输入、重新读取并预览。失败后不通过写旧快照“撤销”；更改必须新命令/新version。读取未发现结果不是允许无条件覆盖的证明。

## 4. 旧规格文本保留与V1处置

新增建议legacy_specification_original TEXT可NULL、legacy_specification_disposition=UNREVIEWED|CONFIRMED_NONE|DEFERRED_SPEC可NULL；存量迁移时逐字保留旧specification（包括空串/空白），不得trim/自动解析/覆盖。新商品三字段NULL。原列保留到单独数据收缩批准，不以切换代码为由DROP。原文在详情独立“历史规格原文”只读区展示，访问跟随Product.read，不作为当前属性、搜索规格或SKU。

UNREVIEWED初始适用所有存量，即使原文为空也不能据此证明无规格。结构迁移必须带明确处置与reason；有迁移权限的操作者执行，并由G1指定数据负责人批准批次/逐项确认规则。CONFIRMED_NONE表示业务确认不需要结构化规格，目标可NONE且原文仍保留在详情及before/after快照；不把原文复制成可编辑描述然后删除来源。DEFERRED_SPEC表示需要真实规格，维持LEGACY_PENDING且不得V1转COMPLETE/启用；登记为待后续规格切片处理的清单。处置可作为独立迁移预览的阻断项，DEFERRED_SPEC确认只记录原文审查事件和处置、不伪造已完成结构迁移；具体审核记录写入受CAS保护的历史命令，见09接口。

旧原文确实错误需要纠正时不改original，使用独立更正说明进入change快照；本版不新增任意历史编辑入口。幂等载荷与预览摘要绑定处置和reason，重试不得丢原文确认；G2逐字/长度/摘要对账，不只比较非空行数。

## 5. OpenAPI与配置槽位规范

OpenAPI operationId是每个HTTP method+path唯一的SDK方法名；业务operationId是平台唯一对象操作标识，两者不混用。建议：productList→Product.list、productRead→Product.read、productCreateDraft→Product.create、productUpdate→Product.update、productSetStatus→Product.setStatus、productPreviewStructureMigration→Product.previewStructure、productMigrateStructure→Product.migrateStructure、productReadChanges→Product.readChanges、productArchiveDraft→Product.archiveDraft、productRestoreDraft→Product.restoreDraft、productReviewLegacySpecification→Product.reviewLegacySpecification（仅存量处置审查，建议共用migrate_structure权限）。配置端点也须逐方法全局唯一命名，G1导出全接口清单验证，不以“同业务操作”重复OpenAPI operationId。

配置集发布请求必须包含四个槽位：templates:{BASIC:版本UUID或null,SPEC:null,QUALITY:版本UUID或null,EXTENSION:版本UUID或null}；键缺失/未知/重复拒绝，不能把缺失当“保留原值”。这是全量发布不是PATCH。V1的SPEC非NULL即拒绝。数据库binding仅为非NULL槽写行，purpose唯一，NULL槽不写伪关联，读取/快照始终展开四键（旧schema历史缺键按旧适配显示未记录，不改原快照）。

全四键NULL且service_unit_required明确的已发布配置集称“空配置集”，有真实id/revision，允许无动态属性商品建档启用。不等于categoryConfigId=NULL：后者仅草稿/存量待确认可用。零模板项的模板草稿可保存，但V1禁止发布零项模板，提示使用空槽；退役版本不变成空槽。完整配置迁移按四槽固定版本一次切换，不要求造四个空模板，也不根据最新分类指针重解析。

## 6. R3.1评审与验收增量

G0必须确认：分级草稿校验、结构状态正交语义、存量原文审查、四槽/空配置、幂等7天及预览15分钟设计参数和唯一OpenAPI映射。未确认不得宣称这些已获业务批准。

G1新增证据：真实样本enabled与LEGACY_PENDING映射/原文逐字对账；17表建议DDL（原16加幂等请求表）及UTC/四审计；全OpenAPI operationId唯一；预览签名公开能力；key唯一索引字节/并发、同事务请求结果、失效窗口及恢复方案。DB10验证响应丢失、同key同/异摘要、并发等待、回滚不留请求记录、成功重放在token过期时仍可读、撤权重放拒绝、源CAS失效不再执行；DB11验证旧true不满足新启用、原文空白不丢及DEFERRED阻断；DB12验证最小草稿、required缺项仅启用失败、四槽缺键与零项模板发布拒绝。核心DB01–03/05–12是准入证据（DB04规格生成列仍延期）。

G2新增验收：create成功→启用失败草稿保留；旧true显示结构待确认且不可普通编辑；显式停用/原文确认/完整迁移/独立启用全程；同key重复最多一条成功change且父version只推进一次；写超时界面不自动重试，读取/手动重放恢复；空配置与未绑配置页面不同；原文详情与快照可读且未丢字节语义。所有数据库实验与业务验收仍未执行。
