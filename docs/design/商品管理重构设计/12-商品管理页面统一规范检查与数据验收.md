# 商品管理页面统一规范检查与数据验收

日期：2026-11-18。范围：商品档案、商品分类、属性管理、属性模板、计量单位。依据：仓库AGENTS.md、《前端UI与代码生成规范》及其截至2026-11-17的覆盖修订、《业务服务统一开发规范》。本记录只陈述本轮实际证据，不以此前实现或构建成功替代界面验收。

## 1. 发现与整改

| 检查项 | 发现 | 本轮处理 |
|---|---|---|
| 工作区与层级布局 | 分类只有逐层钻取列表，缺少统一层级导航 | 复用TreeListTemplate和Element Plus懒加载树；左树选择限定右侧直属分类，根节点显示根分类。移动端沿用公共模板堆叠/折叠。树每次加载完整同级分页，不拆散父子关系或递归预取全树；父选择也读完同级分页 |
| 查询操作 | 缺重置、按钮混排 | 五入口统一查询/重置右对齐，使用management-filter-actions。商品重置全部条件；分类重置保留当前节点；搜索回第一页 |
| 表格引擎 | 弹窗、模板项及历史仍使用el-table | 改用@appnexus/ui公开VxeTable/VxeColumn，保留真实行、操作权限和列宽拖动；主列表继续复用ManagementTable |
| 操作列 | 只读用户保留过宽空列；窄屏固定操作列遮住数据 | 根据实际获准操作计算宽度；768px以下取消操作列固定，保留表内横向滚动，业务列不再全部被遮住 |
| 详情网格 | 自动列宽不满足明确断点 | 主档详情桌面4列、1100px以下2列、600px以下1列，列距24px；复用已有详情壳，无新设计系统 |
| 版本与状态 | 原始英文枚举；模板名称列空白 | 版本状态使用双语标签；版本号独立列，属性显示修订名，模板显示description；模板用途本地化，启停状态保留文字及标签 |
| 时间显示 | 历史及预览到期时间直接显示ISO | 与RecordAuditDetails使用相同Intl语言/浏览器时区格式；未知值不补当前时间 |
| 分组维护 | 两个连续prompt代替字段表单 | 复用ManagedDialog、el-form和字段校验；保存loading防重，错误保留输入。取消仅关闭内存草稿，已逐项登记界面例外 |
| 语义与校验 | 退役/启停/归档确认按钮含糊；模板可勾不适用标志 | 确认按钮使用具体动作与取消；文本禁止搜索、非枚举禁止自定义输入，切换候选清空不适用标志。基础表单启用scroll-to-error；动态属性继续字段就地校验 |
| 分页/文案 | 主档历史/对账自配分页；配置说明暴露实现边界 | 列表分页改为AppPagination，Select候选保留紧凑prev/next；说明改为实际配置任务。无新增依赖、主题变量或模拟接口 |

修改集中于CatalogManagement.vue、ProductManagement.vue、ProductEditor.vue、zh-CN.yaml/en.yaml和operation-ui-exclusions.json。未修改数据库结构、后端接口、认证流程或其他模块业务；保留此前工作区修改。

## 3. 实际浏览器检查

- 五入口真实加载、新增单位/分类/分组/属性/模板/商品及保存刷新；必填空提交在对应字段出现错误。
- 分类树新增后刷新，父节点选择限定直属子列表；查询重置保持当前节点，商品不存在编码返回0条后重置恢复真实列表。
- 属性修订及模板发布有具体动作确认和不可变说明，历史表显示“草稿/已发布”而不是原始状态码；模板用途正确翻译。
- 商品选择分类动态生成“验收材质”，必填标记明确；超过20字符在字段旁报错且拒绝保存，恢复原值后未写入非法数据；条码前导零再次读取保留。
- 商品完整启用和停用成功，历史含创建/启用/停用；草稿归档后变只读、无保存/启用按钮，仅可恢复；恢复后重新出现编辑/归档，再次归档保留历史。数据库只读核对最终状态与版本。
- 浅色、深色、系统入口及英文详情真实检查；深色状态/表单/按钮可辨，英文操作、形态、状态及时间格式正确；恢复中文与跟随系统。
- 当前实际内容视口567px宽：分类页document/body scrollWidth均567，查询动作右边界与表单同为550px；表格内部可滚动，操作不遮住全部业务列。截图.local/product-v1-deploy/ui-category-verified.png。

浏览器遇到一次改码热更新期间属性页临时不可用，读取公开接口返回真实[]，重载后正常并完成后续写入；归档后一次自动化读取超时，先只读核对落库，再读取确认成功，没有重放不确定写入。发布前应使用构建产物，不能将HMR中间状态当正式产物。

## 5. 列表操作语义漏检整改

用户截图指出“详情 / 维护”不符合全站查看、编辑分离规范，且商品列表没有统一审计查询。此前检查覆盖了组件和布局，却没有逐项对照相邻主数据的操作语义，也没有验证商品列表响应是否包含audit；不能将第1至4节视为操作一致性全部通过。

本次ProductManagement拆分“查看”（Product.read）和“编辑”（Product.update），向ProductEditor显式传入view/edit模式。view模式即使当前用户是可写管理员也只读，不渲染输入框、保存、启停、归档、结构迁移或旧规格审查操作。编辑保留既有业务状态和权限限制；归档/旧档保护不解除。

商品分页Controller通过已有RecordAuditSource(table=md_product_v1,path=rows)接入公共审计投影：只对原查询已授权、同可信租户的行批量补齐四审计字段，公共ManagementTable自动显示“审计信息 / 查看审计”，复用统一弹窗，不新增任意表名/ID审计接口。历史变更页签与四字段审计查询保持各自职责。

验收补充：前端类型检查和生产构建通过；ProductV1IntegrationTest 2项与GlobalRecordAuditTest 5项真实数据库测试通过。新增HTTP断言核对非空商品列表audit.createdBy、createdAt及no-store，不仅检查注解存在。实际浏览器验证同一admin分别进入查看与编辑，前者无写控件、后者有保存和真实输入；本轮不改动商品数据。正式本机后端已重新打包启动，Flyway校验112项且无新迁移；首次重启窗口查询失败后手动查询成功，再次完整刷新稳定显示查看/编辑及公共查看审计。实际打开审计弹窗核对四字段，截图.local/product-v1-deploy/product-actions-audit.png。运行日志runtime-actions-fix.log；未重置数据库或降低权限。

后续页面自检增加强制逐行核对：查看、编辑各自操作标识及只读行为；有权列表行是否返回audit；统一审计按钮是否实际出现并能打开四字段。不能以详情已有审计或变更历史页签替代列表审计入口。
