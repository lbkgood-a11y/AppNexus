## 3. 存量迁移方案比较与推荐

一次性重建全部商品并换ID实现简单但会破坏旧身份，不推荐。长期双写新旧模型能灰度但容易出现两个权威来源，也不推荐。建议“扩展结构→显式映射→受控窗口切换→稳定后收缩旧字段”，商品ID/编码不变；兼容是限时数据迁移过程，不新增永久旧协议运行时回退。

1. 只读盘点md_product行数、启停分布、编码大小写碰撞、单位稳定值、空值/规格长度、审计NULL；输出聚合统计，不在报告泄露敏感正文。
2. 备份并在隔离库演练；新增所有表时首次CREATE TABLE直接包含四审计字段及中文注释；原md_product增列用新迁移。
3. 通过字典公开契约导出单位和值，逐租户生成唯一映射；未知维度/精度保持待确认，不能把所有单位默认为质量或件数。箱/件不默认建立换算。明确谁批准清理旧product_unit写入口。
4. 商品新增状态按旧enabled映射，缺分类/形态/规格模式保留未知，标为待完善；不伪装新建草稿或自动从规格文本推断STANDARD/CUSTOM。
5. 用户显式选择分类和模式后迁移，旧specification/barcode/unit原文保留；SKU仍按需创建，商品条码不自动提升成SKU编码。创建时间和账号保留原值，未知NULL不补造。
6. 同事务记录迁移前后快照和当次真实操作者；批次迁移可无账号时NULL，不能拿管理员或零UUID伪造责任。每条商品有源version条件，失败项单独报告且不半迁移。
7. 切换窗口冻结旧商品写入，完成一致性核对后发布新接口和页面；schema扩展与新写入能力启用必须兼容部署顺序，不允许旧执行器把动态值清空。
8. 稳定后才新增后续迁移移除旧字段/旧商品分支，需备份与验收证明；不要将legacy原文未经确认销毁。

回退分界：尚未产生新模型写入时可回退旧应用并保留扩展结构；一旦产生新属性/规格/SKU，不可直接启动旧CRUD继续写。应停写并修复前进，或在隔离环境验证备份恢复与增量导出后受控恢复；DROP新表或简单enabled回写不能称无损回退。任何生产破坏性恢复均需单独明确批准，本次不执行。

| SKU尚未建设 | 指定规格创建独立唯一编码并启停 | 跨商品规格、重复码、停用码复用、SKU重绑拒绝 |
| 单位只有字典（E11/E12） | 单位精度/维度及明确同维度系数；存量映射对账 | 箱件/质量体积自动换算拒绝；跨租户单位拒绝 |
| 只有enabled（E07） | 保存草稿、显式启用、停用再启用 | 缺必填不能启用；编辑权限不能代替启停/迁移权限 |

| 复杂数据事务未建设 | 主档+值+规格+SKU+变更一次提交 | 子项错误/审计错误全回滚；并发只有一个version成功 |
| 全局审计（E09） | 新建/改明细同步父与子审计，时间数据库UTC | 客户端伪造主体/时间拒绝；回滚不推进；历史NULL保留 |
| 页面与授权 | 管理员及授部分权限用户真实操作；菜单按钮投影一致 | 直接API绕过按钮仍拒绝；撤权、过期、停用成员失败关闭 |

### 6.2 新增反向验收场景

- 同一稳定attribute_id跨四模板重复或固定品牌副本发布失败；QUALITY不能写规格值表。
- category_id与category_config_id错配、模板项不属于商品配置、枚举项修订错配均被服务和数据库相应层拒绝。
- 标量全空/多列非空、选项类型带标量、整数溢出/小数过scale拒绝，不能由数据库静默舍入。
- 父商品配置切换时旧退役规格仍能读旧定义；事务失败回滚完整配置，不允许半升级。
- 普通质量数值修正不要求停用；配置/单位变更按05矩阵停用；已有SKU关键值不允许原地改义。
- 服务NULL单位显示合法，实物NULL或service_unit_required要求下服务NULL不能启用。
- 深度9及互相迁入形成环被拒；归档草稿不可编辑、恢复保留旧绑定；30天不执行永久删除。
- 多个SPEC筛选条件分散在不同规格时不返回该商品；无匹配与无权限不混淆。
- 旧快照由对应schema_version解释，未知版本给只读摘要；退役不冒充缺失。
- 无文件服务时核心无图建档照常完成；有服务时验证上传授权、临时清理、失败引用补偿和文件权限，不做模拟接口。
