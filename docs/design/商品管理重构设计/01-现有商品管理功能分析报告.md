## 2. 已有功能与实际流程

菜单为“主数据 → 商品管理”，路径 /master-data/product，页面键 master-data/product，租户权限 masterdata.product:read。不是独立的五菜单商品子系统。

列表：keyword 对编码或名称做字面包含查询，enabled 筛选全部/启用/停用；页码默认 1，页容量默认 20，服务端 1–100；真实 total；ORDER BY code,id。字段为编码、名称、规格型号、单位、条码、状态、操作。没有分类、类型、规格模式筛选，也没有动态属性筛选。LOCATE 包含查询不能假定利用普通名称 B-tree 索引。

新增：统一弹窗填写编码、名称、规格文本、字典单位、条码；后端校验后同事务写入、记录字典引用与审计；默认已启用、版本 0。编辑：复制列表行到草稿，并以原 version 提交；编码不可修改。保存失败保留草稿；409 不覆盖，重新打开以获取最新值。启停：单独权限和确认框，CAS 成功后刷新。没有删除 API、删除按钮、审批或完整变更历史。

商品没有独立只读详情入口（客商和仓库有专用编辑/详情组件，不能误算成商品能力）。编辑弹窗可显示 RecordAuditDetails，只证明最后创建/修改信息，不是历史事件列表。

## 3. 现有数据模型与契约

md_product 为一租户一套公共档案；没有 SPU/SKU 二层关系。

| 列 | 实际定义/约束 |
|---|---|
| id、tenant_id | BINARY(16)，主键 UUID、可信租户 |
| code | VARCHAR(64)，同租户唯一，创建后不可改；首位字母数字，其后字母数字点下划线短横线 |
| name | VARCHAR(200)，去首尾空白后必填 |
| specification | VARCHAR(500)，默认空文本，单一规格描述 |
| unit | VARCHAR(500)，DDL 默认空；服务校验必填且最多32字符、字典引用有效性 |
| barcode | VARCHAR(500)，默认空，按文本保留前导零；未见唯一/GTIN校验 |
| enabled、version | BOOLEAN 默认 TRUE；BIGINT 默认0，修改及启停递增 |
| created_by、updated_by | BINARY(16)，实际账号，历史未知允许 NULL |
| created_at、updated_at | TIMESTAMP(6)，数据库 CURRENT_TIMESTAMP(6) 写入；UTC约束沿用宿主 |
| 索引 | PK(id)、UNIQUE(tenant_id,code)、INDEX(tenant_id,enabled) |

Input(code,name,attributes,version,contacts,bankAccounts) 和 Row 为多个主数据对象共用；商品只能使用三个字符串属性，非客商不得传 contacts/bankAccounts。Map 在 API 层，落库仍是固定列，不存在“已支持任意 JSON 属性”的事实。没有独立商品实体/DTO/VO层，主要使用嵌套 Java records 与 JDBC。

已读取单位字典，只维护稳定值、名称与启停，不表达单位维度、精度或换算。预置件、箱、吨、千克、克、升、米；不能据此假设箱和件存在通用换算。

## 4. 问题、保留与重构判断

| 问题与影响 | 判断 |
|---|---|
| 只有规格文本，无法类型校验、筛选、规格去重 | 保留原文作迁移依据；增加规格和类型化属性，不猜测拆分 |
| 无分类/模板，扩展要改前后端字段白名单和列 | 新建配置驱动领域；分类与模板独立 |
| PRODUCT 与其他档案共享字符串 Input/执行器，复杂规格加入后条件分支膨胀 | 抽出商品专用 DTO、应用服务、持久化，通用安全能力继续复用 |
| 单位字典无精度、维度和换算 | 独立单位实体；通过公开端口迁移，避免两套可编辑单位来源 |
| 只有 boolean 状态和最后审计 | 显式草稿/启用/停用和追加历史；审批并非当前刚需 |
| 编辑依赖列表快照，无商品只读详情 | 增加授权单条读取及结构化详情，保留并发校验 |
| 共用页面根据 kind 分支，难承载动态属性和规格交互 | 增加商品领域页面，复用公共模板，不重写应用壳 |
| 未区分标准/非标 | 新增规格管理模式；不用两个模块或表体系 |

可保留：现有商品ID与编码、文本条码语义、租户归属、固定路由入口、独立启停权限、安全会话/CSRF、服务端参数绑定、唯一约束、版本CAS、统一准入与审计组件。原记录审计与历史未知 NULL 不应重写。

当前不存在两套标准品/非标品重复实现，不能把“尚未建设”写成“已存在重复”。现有重复风险是多个对象共用小型 CRUD 并不断增加 kind 分支，而非已经存在多套商品系统。
