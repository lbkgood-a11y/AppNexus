# 商品管理正式实施评审材料（V1）

日期：2026-11-17；版本：R3.1评审修订稿；状态：待评审、未批准、未实施。本轮只整理材料，不运行可行性实验，不修改业务代码或数据库。R2的01–05仍为领域设计依据；本材料重新划定V1范围，将原V1与原V2的基础能力合并，不代表批准原V1–V5。

## 1. 本次请求批准的范围

只评审V1“商品主档＋主档动态属性＋不可变配置版本＋生命周期”完整闭环。V1支持实物与服务、BASIC/QUALITY/EXTENSION、NONE无规格；保留SPEC用途的总体设计，但V1不得发布/绑定含SPEC槽位的配置集，不提供标准组合、自定义规格、SKU维护或相关表。旧规格文本只读保留，不强制转换为NONE。图片、单位换算、审核和组合商品排除；不能据此阻塞核心交付。

正式评审分为业务选择、技术可行性、实施准入、上线验收，不能用一次签字同时代替所有关口。后续规格/SKU需独立范围、数据及接口评审，不继承本次授权。

## 3. V1实施基线

### 3.1 功能边界

V1交付五个真实维护入口：商品档案、商品分类、属性管理（含分组/修订/选项）、属性模板（含版本/发布）、计量单位（不含换算）。配置不是孤立CRUD：必须完成“定义→模板发布→分类配置发布→商品建档→启用→修改→新版本发布→显式迁移→读历史”全流程。无模板的空配置合法，BASIC/QUALITY/EXTENSION各零或一个确定模板版本，SPEC槽明确为空。

新商品模式固定NONE；product_form草稿可未选，启用前显式选择PHYSICAL/SERVICE。启用校验固定分类/配置、名称/编码、单位规则和主档必填属性。草稿允许缺配置/形态/单位但不能写未知动态值或启用；已选值始终做格式校验。生命周期、归档、普通编辑和结构迁移依05§7.2，V1不允许把未支持的规格模式写入接口。

### 3.2 数据表基线

建议17张逻辑表，其中原md_product扩展、其余16张新建；最终DDL与命名需G1审定。各新表首次CREATE直接包含四审计列、中文列注释、可信主体与数据库UTC。不可变表也不例外。

| 聚合 | V1表 | 必须实现的约束/版本语义 |
|---|---|---|
| 分类与配置 | md_product_category、md_product_category_config、md_product_category_template、md_product_category_config_item | category_id/config一致复合FK；配置集只存发布结果；跨模板attribute_id唯一；service_unit_required固化；SPEC禁止绑定 |
| 属性 | md_product_attribute_group、md_product_attribute、md_product_attribute_revision、md_product_attribute_option | 稳定ID＋不可变修订；类型、单位、选项与修订一致；分组快照 |
| 模板 | md_product_template、md_product_template_version、md_product_template_item | V1只发布BASIC/QUALITY/EXTENSION；绑定确定revision；发布不可改正文，退役仍可读 |
| 商品和值 | md_product、md_product_attribute_value、md_product_attribute_choice | category_config_id固定、类型列恰一或枚举子行、选项修订一致、父version CAS、structure_revision、草稿归档 |
| 单位和历史 | md_product_unit、md_product_change | 单位维度/精度有引用不可改；主档单位可NULL按形态校验；快照schema_version=1及差异历史 |

上表加下述结构请求表共17张逻辑表（md_product原表＋16张新增），最终DDL应逐表对照。V1不建md_product_specification、md_product_sku、两类规格值/选项、md_product_unit_conversion、md_product_image。旧specification/unit原文及barcode保留只读迁移证据，历史创建审计保留NULL。候选键、冗余字段及精确元组遵03§8.2；应用归属不等于直接SQL跨模块读字典表。

R3.1新增md_product_structure_request：结构迁移成功幂等请求、载荷摘要、结果版本/change引用及7天重放窗口，和商品事务原子提交；四审计列必备。md_product新增structure_state、legacy_enabled_snapshot、legacy_specification_original/disposition，字段/约束及状态定义见10§2–4。表清单不是已执行DDL。

### 3.3 核心接口建议

以下均是待定OpenAPI，不是现有可调用接口。写操作Cookie/CSRF、可信租户、no-store、固定路由、稳定错误码；不接受tenant/operator/audit、任意JSONPath或SQL。所有ID按字符串，数值用精确十进制字符串；查询page默认1、size默认20范围1–100。

| 接口建议 | OpenAPI operationId → 业务operationId | 关键契约 |
|---|---|---|
| GET /api/master-data/product | productList → Product.list | code/name/category/form/status/archived及单categoryConfigId+最多3属性条件；真实total |
| GET /api/master-data/product/{id} | productRead → Product.read | 当前固定引用完整详情、version/structureRevision、只读四审计 |
| POST /api/master-data/product | productCreateDraft → Product.create | 只建DRAFT；code/name必填，形态/配置/单位可空；模式服务固定NONE；未绑配置值为空，已填必合法但required可缺；返回id/version=0及completionIssues；完整启用是独立命令 |
| PUT /api/master-data/product/{id} | productUpdate → Product.update | version必填；只允许普通资料与现有定义下值；不接分类/单位等结构字段 |
| PUT /api/master-data/product/{id}/status | productSetStatus → Product.setStatus | 目标状态+version；合法三态迁移；仅目标ENABLED完整校验并要求COMPLETE；旧LEGACY_PENDING可停用不可启用；不默认已启用 |
| POST /api/master-data/product/{id}/structure-preview | productPreviewStructureMigration → Product.previewStructure | sourceVersion/sourceStructureRevision/sourceCategoryConfigId、完整目标与原文处置；返回固定配置链、diff/completionIssues、payloadDigest、previewToken及expiresAt；10§3绑定15分钟有效期，不写库 |
| PUT /api/master-data/product/{id}/structure | productMigrateStructure → Product.migrateStructure | sourceVersion/sourceStructureRevision/sourceCategoryConfigId、完整目标与处置、previewToken和Idempotency-Key；新执行拒ENABLED；成功重放独立处理；10§3为完整契约 |
| GET /api/master-data/product/{id}/changes | productReadChanges → Product.readChanges | 原read权限内分页历史，按to_version倒序、schema版本读取 |
| PUT /api/master-data/product/{id}/draft-archive；PUT /api/master-data/product/{id}/draft-restore | productArchiveDraft → Product.archiveDraft；productRestoreDraft → Product.restoreDraft | version必填；DRAFT且符合操作准入；固定两路由不依客户端任意operation执行 |
| 固定 /api/master-data/product-category、product-attribute、product-template、product-unit资源 | 对应对象list/create/update/setStatus、revision/version发布及分类publishConfiguration | 补充树分页、选项/修订读取、发布前预览；G1逐个方法/路由绑定operationId，不复用泛型SQL执行器 |

OpenAPI每个method/path唯一operationId；预览Product.previewStructure与执行Product.migrateStructure为不同业务操作，可共用migrate_structure权限，不能同名导出SDK。具体映射见10§5。属性/模板DRAFT可编辑，发布后只复制新版本；分类配置发布必须显式四键BASIC/SPEC/QUALITY/EXTENSION，V1 SPEC=null；无绑定为null、不造空模板，禁止发布零项模板；全NULL为合法已发布空配置集，未绑配置NULL仅草稿/存量可用。V1禁用SPEC及SKU所有写入，不能仅隐藏按钮。

### 3.4 页面与权限

列表复用BusinessWorkspace/ManagementTable/AppPagination；复杂编辑/详情沿人员样板TabbedDetailTemplate masterData；小配置编辑ManagedDialog，动态表单只组合Element Plus。固定字段/动态属性、质量/扩展分区展示；零/false不判空；未保存分类切换有差异确认。多语言、深浅/System及三视口执行04规范。

| 对象/操作 | 权限建议 | V1验收重点 |
|---|---|---|
| Product.list/read/readChanges | 现masterdata.product:read | 只读成员能看详情与历史，无update也可读；跨租户不泄露 |
| Product.create/update/setStatus | 现create/update/set_status分开 | create不隐式给启用权；update不能改结构或启停 |
| Product.previewStructure/migrateStructure/reviewLegacySpecification | 新masterdata.product:migrate_structure | 迁移与启停分权；无权不产生预览明细/写入 |
| Product.archiveDraft/restoreDraft | 新masterdata.product:manage_draft | 归档非删除，保留编码和历史，父CAS |
| 分类/属性/分组/模板/单位 | 新独立资源及发布、维护、读取权限 | 业务建档者在Product.read下读取必要候选，不被迫授配置维护权；新维护权限不自动给普通角色 |

新权限精确编码和初始化范围由安全负责人G1签署，沿现OperationBinding/BusinessObjectType唯一声明；按钮用operationId，菜单只导航。图片/SKU/审批无空入口。主档读取所需的候选接口不是免鉴权目录，必须复核租户与原宿主读取权。

## 4. 数据库可行性验证方案（尚未执行）

### 4.1 环境、授权与证据

G0通过并明确批准“隔离技术验证”后，在一次性MySQL环境执行，版本/字符集/排序规则/sql_mode、事务隔离级别、时区UTC与目标环境一致；当前仓库测试曾用MySQL8.4，不能据此假定生产版本。只用最小合成租户/账号/属性样本，不连接共享库，不改历史迁移。优先现有Testcontainers/测试运行时，缺环境先报告，不安装新依赖绕过。

验证期间的临时表也须首次包含四审计列及中文注释，不放宽GlobalRecordAuditTest。实验脚本/测试实现与执行是后续经批准工作，本轮仅定义用例。证据要含DDL、SHOW CREATE TABLE/约束和索引元数据、每次预期与实际错误、事务前后快照、版本/审计对比、MySQL版本及执行日期；不记录凭据。

### 5.2 旧数据保护与V1支持边界

保留md_product ID/code、条码前导零、specification/unit原文、原审计NULL与历史enabled含义。enabled只映射历史ENABLED/DISABLED，structure_state=LEGACY_PENDING，不满足新启用准入；不推断形态、分类或规格模式，显示“旧档启用／结构待确认”；新V1记录只支持NONE。旧记录可查看/查询/停用；重新启用或结构迁移须由业务负责人确认是否确实无规格并补齐V1资料。旧文本若代表真实规格，保留只读并延期后续规格切片，不强造NONE、不删原文、不创建默认SKU。普通文字编辑对未完成结构旧记录暂不开放，以避免将旧商品当新完整模型。

单位由BusinessValueCatalog公开端口受控导出/映射，不能跨模块直改字典表；新单位成为商品唯一写源，旧product_unit商品用途停止维护，其他字典不受影响。旧商品原文迁移期保留；重复名称/未知维度人工确认，不能按显示名模糊匹配。所有自动过程不伪造实际账号。

旧规格逐字保存original，审查UNREVIEWED/CONFIRMED_NONE/DEFERRED_SPEC；空文本也不能自动确认无规格。CONFIRMED_NONE后仍在详情/快照保留原文；DEFERRED_SPEC维持LEGACY_PENDING，不转NONE。新增建议PUT /{id}/legacy-specification-review：productReviewLegacySpecification → Product.reviewLegacySpecification，仅受CAS审查原文处置，建议共用migrate_structure权限；非结构完成、不推进structure_revision，追加审查历史；转换COMPLETE仍走完整结构命令。详见10§4。

1. G1盘点调用者与所有源数据，冻结最终接口和角色映射；备份/隔离恢复演练。
