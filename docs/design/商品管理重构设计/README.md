## 推荐决策

- BASIC、QUALITY、EXTENSION归主档，SPEC归规格；QUALITY仅商品档案指标。按稳定attribute_id跨完整配置去重；品牌等固定字段只写主档，不实现动态映射副本。
- 商品固定category_id/category_config_id；配置集四用途各至多一个确定模板版本（未配置槽位明确为空），模板项固定属性修订；发布正文不可改、退役仍可读。结构迁移一次切完整配置集，历史规格留原配置。
- 采用类型化值表与不可变配置项投影，复合FK保障租户、配置、模板项、修订、类型、枚举和父子归属；必填/状态等跨行规则在领域事务校验。
- 普通资料和定义不变的属性值允许启用态编辑；分类、形态、模式、基础单位、配置集变更先停用。已有SKU的规格关键含义不原地改写，SKU不改码/重绑，替代使用新身份。
- 实物基础单位必填，服务可空；配置集service_unit_required可显式收紧。单位变化不自动换算属性。
- 草稿保留，人工归档可恢复；30天仅闲置提示，默认无定时永久删除。父商品version统一控制规格/SKU/图片写入，structure_revision只随结构迁移递增。
- 图片保留产品设计，真实文件服务授权与临时清理核实后才交付上传；无图不阻塞核心商品。
- 沿用master-data-service、vue-pure-admin及共享UI，本次仅评审V1“主档＋动态属性＋配置版本＋生命周期”；原V2基础属性能力合并到V1，其余切片仅作方向，未经本轮授权。评审后允许删除并替换旧商品实现，不保留两套执行器；保护存量数据及其他共享主数据能力。

## 执行边界与用户确认

本轮只修订六份设计、README并生成08整改报告，未改业务代码、接口实现、迁移、依赖或运行库。用户追加允许推翻旧商品功能、删除相关代码，随后明确选择“先完成设计，评审后删除”。因此旧代码替换列入06清单，本轮不执行删除，不清理或重置其他未提交改动。

正式评审需签署上述决策、批准具体V切片、最终迁移/OpenAPI/验收方案；提交评审不等于通过评审，也不授权本轮开始代码实施。

## R3.1本轮修订

V1草稿只要求code/name及已填值合法；新建模式服务固定NONE，形态/配置/单位可缺，启用另命令完整校验。旧enabled与新status仅保存历史标志，新增structure_state阻断LEGACY_PENDING被误当新完整商品。结构迁移绑定源版本、目标确定配置和完整载荷，15分钟签名预览及7天幂等结果窗口均为待确认设计参数，成功记录与业务原子提交；同key异载荷拒绝，超时读取或手动同key恢复，不自动重放。

旧规格original逐字保留，CONFIRMED_NONE与DEFERRED_SPEC显式审查，不因原文空白自动NONE；新四槽全量键/null表达、零项模板不可发布、空配置集合法。OpenAPI operationId逐端点唯一，不与平台业务operationId混淆。G0确认新增契约，G1补17表与DB10–12/签名能力验证，G2补草稿/兼容/超时恢复/原文验收；当前全部仍待评审、未实验、未实施。
