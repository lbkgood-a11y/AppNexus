## 2. 关键代码和数据约束

- 后端位于master-data-service的product子包：ProductController（唯一正式商品Controller）、ProductV1Service（内部实现类名，非第二对象）、ProductCatalogService、ProductAttributeService、ProductTemplateService及ProductAttributeRules。
- 类型化主档与值表仍使用已建md_product_v1命名，不能为视觉改名重建存量ID。旧md_product仅为历史保留/对账源，原通用PRODUCT枚举、执行器商品分支、旧ProductController、旧前端字段/操作/API映射及临时product-v1页面已移除。
- 前端位于modules/master-data/src/product，通过公开包入口组合BusinessWorkspace/ManagementTable/TabbedDetailTemplate/ManagedDialog/RecordAuditDetails及Element Plus；apps/admin只装配真实HTTP/CSRF。无新增UI/数据库依赖。
- 新表首次CREATE直接具备四审计列及中文列注释；实际账号来自VerifiedTenantContext，UTC时间由数据库生成；未知历史NULL保留。
- tenant_id前导复合FK固定商品→分类/配置、配置→用途模板、配置项→模板项/属性修订/类型、枚举→父值/修订选项。数据库互斥CHECK与唯一键兜底；跨行必填/发布状态/父聚合状态由领域服务事务校验，不交给前端。
- 商品修改、动态值、子项审计、历史、结构幂等成功结果同事务；父version CAS，structure_revision仅结构迁移递增。缺失version拒绝，不能被默认0放行。

### 切换约束

旧enabled=true/false只映射历史status，全部旧档初始LEGACY_PENDING；不能用旧true声明新模型完整。旧ID/code/barcode前导零、规格/单位空白原文和四审计逐列保留。UNREVIEWED需人工确认，CONFIRMED_NONE仍须停用后完整迁移；DEFERRED_SPEC保留历史并阻止V1强造NONE/启用。审查仅推进商品version和追加历史，不虚构结构完成。

源码已经只保留一个正式入口；共享环境要在维护窗口停旧写实例/后台任务，备份后执行迁移，V111对账成功才允许启动新实例。对账失败停止部署并核查源差异，不启用outOfOrder/忽略校验，不覆盖新档。不能让旧实例在V111完成后继续写旧表；此为发布Runbook硬约束，不假称一条SQL可以阻止任意旧二进制。

新模型产生写入后，旧CRUD不能表达动态值/配置/草稿历史，不能直接回旧应用继续写；优先停写修复前进，必要时保留增量并在隔离环境验证备份恢复后受控恢复。代码替换不等于删除历史数据。

## 4. 结构预览与幂等

复用OperationPreviewProof公开端口和宿主持久RSA密钥，15分钟无持久化预览绑定可信租户/账号/商品、源CAS/结构修订/配置、完整目标/退出处置/理由及目标准入。不是JWT或认证令牌，不写URL/日志/浏览器持久存储。

执行必须同一载荷和UUID Idempotency-Key；md_product_structure_request成功结果与商品/值/change同事务。父锁串行后重查同键，同键同摘要返回原成功结果且不写历史；同键不同摘要409，7天窗口到期拒绝。重放重新认证/授权，撤权不能恢复旧结果；请求响应丢失先读取、可手动同key恢复，前端不自动重放。任何CAS、值、审计、历史、请求结果故障都回滚，失败不保留成功占位。
