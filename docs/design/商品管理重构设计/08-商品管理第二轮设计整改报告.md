## 5. 数据模型与业务规则冲突检查

| 发现的风险/冲突 | 本轮解决方式 | 剩余验证 |
|---|---|---|
| 只用item_id FK无法证明来自商品固定配置 | config_item物化完整绑定链，值携带config/修订/类型/owner_scope复合FK | 实施时验证伪造配置/项无法插入 |
| 配置切换可能让历史规格旧值外键失效 | 规格捕获自身category_config_id，旧值与该配置绑定；只有当前规格要求等于商品当前配置 | 完整事务与历史读取测试 |
| MySQL不能延迟FK，改父配置前子值仍指旧配置 | 事务先保存before并撤下当前值，再切父配置、重建目标值；保留未变项创建审计 | 失败注入/回滚和并发测试 |
| 退役规格永久占组合唯一空间，无法替代错误SKU | 生成current_combination_hash仅约束未退役规格（含停用）；旧SKU代码仍永久唯一，新规格新码 | 生成列/唯一索引真实DB测试 |
| “最多一列非空”会放过标量空行 | 按value_type要求正确标量恰一；枚举只存choice、单选计数由服务验 | CHECK与服务共同验证 |
| 所有属性变化被算作迁移 | 普通质量数值/BASIC值/无SKU规格值按原定义修改不迁移；变定义/配置/已编码语义才迁移 | 操作矩阵真实权限/状态测试 |
| 同维度换单位被假定无语义影响 | 推荐统一停用迁移，不能自动换算属性 | D03决策；真实单位样本 |
| QUALITY可规格级但值表仅支持SPEC | 本版推荐QUALITY仅主档，未开放备选scope | D01如选择规格级需重新审查 |
| 服务可空却DDL/UI全商品必填 | 可空base_unit_id+配置集service_unit_required+形态启用规则 | D02签署及NULL正反测试 |
| 草稿自动删除与禁止删除/历史保护冲突 | 默认只归档恢复，不执行定时清除，30天不作保留期 | D05归档授权/回滚测试 |
| 退役模板被误当缺失/套新标签 | 退役完整保留，快照schema按版解析；真正缺失告警 | 历史兼容fixture与UI |
| 多个SPEC筛选分别命中不同规格 | 同规格单EXISTS承载所有SPEC条件 | SQL正确性与分页/性能 |

本版未发现上述推荐规则之间仍有相互否定的约束；不将此人工逻辑结论当成可执行DDL或并发实现已经正确。
