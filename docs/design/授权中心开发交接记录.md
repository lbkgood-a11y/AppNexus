## 2. 已完成能力

### 2.1 数据库与迁移

- V20：将 V17 组织专用 `access_permission` 演进为统一权限目录，保留并重编码已有成员直授权。
- V21：增加 `access_role_permission`、`access_account_role`、`access_member_role` 和授权审计表，通过复合外键限制平台/租户管理域及租户归属。
- V22：账号和租户成员增加 `authority_version`，用于主体角色覆盖写的乐观锁及后续缓存版本校验。
- V23：增加权限数据范围元数据、角色数据策略和组织范围值表。
- V24：初始化固定平台超级管理员角色和每租户独立管理员角色，并迁移现有过渡管理员关系。

所有新迁移均为追加迁移；没有修改已发布的 V1–V19。

### 2.2 后端领域与用例

- `PermissionCatalog`：平台/租户权限目录。
- `AccessAuthorization`：统一功能权限判定。
- `RolePermissionManagement`：功能权限与数据策略完整快照原子保存。
- `SubjectRoleManagement`：平台账号角色和租户成员角色完整快照保存。
- `DataPolicyMetadataCatalog`：范围类型和受控资源元数据。
- `DataScopeAuthorization`：`SELF / ORGANIZATION / ORGANIZATION_SUBTREE / ALL / DENY` 解析。
- `EffectiveAuthorizationQuery`：按权限码解释来源角色、数据范围及未生效原因。
- 授权覆盖写、角色/主体版本推进和审计均处于同一 MySQL 事务。
- 需要数据范围的权限未配置策略时返回 `DATA_SCOPE_REQUIRED`，不能保存半成品授权。
- 组织范围值在保存时复核当前租户及启用状态；`DENY` 不能作为持久化策略。

### 2.3 系统角色与旧授权过渡

- 平台固定系统角色：`PLATFORM_SUPER_ADMIN`。
- 租户系统角色编码：`sys_tenant_admin`；`system_key` 包含租户 UUID，保证全局唯一。
- 新建平台管理员或租户管理员时，会原子补齐系统角色、权限、数据策略和主体关系。
- 租户管理员的数据范围权限初始化为当前租户 `ALL`，不表示跨租户全部。
- 迁移期鉴权采用三路双读：
  1. 统一 RBAC；
  2. V17 `access_member_permission`；
  3. `organization_capability_grant`。
- 旧授权仍保留用于对账和回滚，尚未停止旧写入，也尚未切换为仅 RBAC。

### 2.4 组织仓储数据范围

- 组织列表、修改和删除开始在 SQL 中应用数据范围。
- `ALL`：当前可信租户全部组织。
- `ORGANIZATION`：指定组织。
- `ORGANIZATION_SUBTREE`：通过递归 SQL 限制指定组织及其后代。
- `SELF`：现有组织模型没有可靠的创建人或负责人语义，当前失败关闭。
- 创建组织缺少明确父级授权上下文，当前仅允许 `ALL`，避免扩大权限。
- 迁移期旧组织直授权按原有语义解析为当前租户 `ALL`。

### 2.5 HTTP API

已提供以下真实接口：

```text
GET/PUT /bff/platform/roles/{role}/permissions
GET/PUT /bff/platform/users/{account}/roles
GET/PUT /bff/platform/tenants/{tenant}/roles/{role}/permissions
GET/PUT /bff/platform/tenants/{tenant}/members/{member}/roles
GET     /bff/platform/permissions
GET     /bff/platform/data-policy-metadata
GET     /bff/platform/users/{account}/effective-permissions
GET     /bff/platform/tenants/{tenant}/members/{member}/effective-permissions

GET/PUT /api/access/roles/{role}/permissions
GET/PUT /api/access/members/{member}/roles
GET     /api/access/permissions
GET     /api/access/data-policy-metadata
GET     /api/access/effective-permissions
```

写接口逐次获取并验证 CSRF，租户自助接口不接受客户端 `tenantId`。

## 6. 关键安全约束

- 菜单、路由和按钮可见性不是安全边界。
- 平台角色不能授予租户成员，租户角色不能跨租户分配。
- 租户接口的租户和成员只能来自 `VerifiedTenantContext`。
- 数据范围必须进入 SQL 查询或条件写入，禁止查全量后在 Java/前端过滤。
- 未配置、未知范围、缺少上下文和无法无损合并的策略均失败关闭。
- `ALL` 永远只表示当前可信管理域或当前租户。
- 不得把密码、Token、会话凭据写入授权审计、注释或示例。
- 不得修改已发布迁移；所有演进继续新增 V25 及后续迁移。
