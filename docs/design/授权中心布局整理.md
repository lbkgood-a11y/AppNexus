# 授权中心布局整理

日期：2026-11-09。

## 选型与调整

沿用 BusinessWorkspace、ManagementTable、Element Plus Tabs/Form/Select，未新增组件或 UI 库。角色配置属于同一对象编辑，采用上下布局：任务页签、角色上下文、筛选与分组配置、统一授权摘要与保存。原三栏布局使角色选择和摘要长期占用大量宽度，改为顶部角色选择和底部保存区。功能权限按资源分组，桌面使用两至三列，手机单列；已知资源使用业务名称，未知资源保留原标识。功能、默认范围、字段规则继续共享原草稿与原子保存。

主体角色页保留列表与编辑两个任务区，优化列宽、筛选背景与间距；有效权限解释用分隔线与编辑区区分。成员数据权限页将成员、角色选择并排，操作范围横跨内容区，期限和变更原因明确排列；手机单列。

未修改接口、权限规则、角色快照、有效期或草稿确认逻辑。保存失败禁写、角色切换确认、路由离开保护保持原实现。本批没有向真实账号写入授权。

## 2026-11-19 角色用户页签

右侧新增“角色用户”页签，当前左栏角色作为加入目标。显示当前管理域真实用户目录、检索、统一 AppPagination 分页及当前角色加入状态；已加入显示状态，其他有效用户提供“加入角色”。此页为角色导向的用户加入目录，保留原主体角色页签用于完整角色维护。

复用 SubjectAuthorizationApi 的目录、快照读取及覆盖接口；加入前填写原因并重新读取用户完整角色和 authorityVersion，仅追加当前角色，不丢弃其他角色。并发冲突不自动重试写入。写入及确认过程中阻止角色切换、工作区刷新和路由离开。平台、租户分别绑定 AccountRoleAssignment.replace、MemberRoleAssignment.replace，不新增授权端点或放宽后端约束。

RoleUsers.vue 是领域组合组件：已检查 SubjectAuthorization，但其主体导向完整角色编辑及诊断不适合单角色用户加入任务；因此组合现有 ManagementTable、Element Plus、AppPagination 和原因确认框，不增加基础 UI 或另一套设计体系。中英文文案同步。

## 2026-11-19 应用壳 scoped 间距修复

前两次仅修复 class 传递仍未解决问题：lay-content 的 `.main-content` 位于 scoped 样式内，多层及 Fragment 路由组件下实际工作区缺少壳的 scopeId。现将外边距规则改为 `.viewport-page-host :deep(.main-content)`，匹配壳内真实内容节点，继续引用 --app-page-gap，不设置页面局部常量。此前“确保实际生效”的结论缺乏浏览器验证，本条更正；本轮仍需真实页面验证。
