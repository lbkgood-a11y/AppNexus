# 认证与会话详细设计

版本：0.3；日期：2026-11-06；状态：总体架构与轻量化第一期范围已确认；已进入正式功能开发，精确安全参数随集成和性能验收锁定。

## 当前实施状态（2026-11-06）

2026-11-10 增量：已增加 Web 绝对会话寿命、单会话撤销审计、管理员强制下线、TOTP/恢复码、平台管理写入强制 MFA、step-up 和恢复码/受权管理员凭证找回，并完成一个隔离企业 OIDC 身份源 PoC。当前实际接口、安全边界、部署配置、自动验证与剩余项见[第一期收尾执行记录](第一期收尾执行记录.md)。下文早期“绝对寿命、MFA、密码恢复未实现”的描述是历史状态，以该增量为准；移动端 Token、生产企业 SSO 管理、邮件找回和完整设备管理仍未交付。

正式实现位于 services/platform-service，poc-app 仅保留历史验证。账号通过 MyBatis 存储在 MySQL，Flyway 管理平台级 identity_account、identity_bootstrap 和 OAuth 表。账号使用 UUIDv7 不可变标识及 Argon2id 哈希；首次管理员通过事务内单例初始化标记创建，重启或修改初始化变量不会覆盖已有凭据。

内嵌授权服务器与机密 BFF 使用 Authorization Code + PKCE S256；客户端注册、授权及同意记录通过框架 JDBC 实现持久化。Access Token 使用不透明格式，BFF 授权客户端状态只存服务端会话。签名材料从持久 PKCS12 密钥库加载，不在应用启动时临时生成。客户端密钥和回调与数据库注册不一致时启动失败，要求显式迁移。

Web 会话由 Spring Session 存入 Valkey；各实例共享 Cookie 会话。默认 HttpOnly、Secure、SameSite=Lax、Path=/，只有 local HTTP 配置关闭 Secure。初始空闲超时 30 分钟。BFF 及授权/用户信息入口核对账号启用状态；Valkey 按来源地址及账号+地址共享计数，默认每分钟分别允许 60 和 10 次登录尝试，超限返回 429，限流存储不可用时拒绝登录。当前使用直连来源地址，可信反向代理策略待部署时配置。

前端使用 vue-pure-admin 风格的账号密码页，浏览器通过受 CSRF 保护的标准表单向授权服务器提交凭据；登录和注销均不向 JavaScript 暴露 Access/Refresh Token。/bff/session 直接返回展示 DTO，不含 Token/密码哈希，并禁止缓存；roles/permissions 当前为空，不因登录自动授予业务权限。

正式集成测试使用真实 MySQL 8.4 和 Valkey，覆盖授权码交换、PKCE、会话 ID 轮换、第二实例读取共享会话、注销失效、密码错误/CSRF、初始化幂等、账号停用和共享限流。浏览器已验证账号密码登录、完整后台布局、刷新恢复会话、顶部菜单注销、注销后访问拦截及浏览器存储不含 Token/密码。账号管理/密码恢复、MFA、审计、设备管理、绝对会话期限、租户及业务授权、故障回源、密钥轮换和生产参数基准仍待后续实施；本节不表示整个第一期认证功能已完成。开发启动方式见 [backend/README.md](../../backend/README.md)。

## 个人中心与凭据变更（2026-11-06）

- GET /bff/account：查询当前账号标识、登录名和显示名称，禁止缓存且不返回凭据。
- PATCH /bff/account：仅允许本人修改显示名称，服务端裁剪首尾空白并限制为 1 至 100 个 UTF-16 代码单元，拒绝控制字符；不允许修改账号标识、用户名或权限。
- POST /bff/account/password：CSRF 保护并校验当前密码；新密码为 12 至 128 个 UTF-16 代码单元，拒绝空白、与当前密码相同、等同账号名及内置常见弱密码。完整泄露密码字典仍待后续接入；不以此简单名单代替完整账号安全验收。
- 密码以 Argon2id 哈希保存，按预期凭据版本进行条件更新；更新与该账号 OAuth 授权撤销处于同一 MySQL 事务。并发修改只允许与当前版本一致的请求提交，冲突返回 409。
- identity_account.version 当前用于凭据版本；修改显示名称不递增此值。登录成功时将版本写入 Valkey 会话；BFF 和授权入口核对其与数据库是否一致。改密成功注销当前会话，其他旧会话在下一次请求时被拒绝，不删除全局缓存或其他账号会话。
- 密码认证成功可绑定最新凭据版本；OAuth 回调不可将旧凭据会话自动升级为新版本。已有但缺少版本标记的会话默认拒绝，因此首次部署此变更需要重新登录。
- 改密采用与登录相同的共享来源地址/账号组合限流，防止反复猜测当前密码。权限管理、设备会话列表、完整安全审计及 MFA 不属于本批自助资料功能。
- 个人资料接口同时返回邮箱、E.164 手机号及各自验证状态；本人修改联系方式时服务端归一化并原子清除发生变化字段的验证状态，未变化字段保留原验证结果。资料响应禁止缓存且不返回凭据或权限。验证码投递、验证和将已验证联系方式用于登录或找回仍待后续实现，页面不提供虚假验证入口。

## 1. 设计目标

- 使用 OAuth 2.0 Security BCP、OpenID Connect 1.0、PKCE 和标准浏览器会话机制，不自定义一套 Token 协议。
- 统一支持 Web、原生移动端、外部系统、未来多应用 SSO 及企业身份源，同时保持第一期部署轻量。
- 认证只证明主体是谁与认证强度；租户成员、系统开通、操作、数据和字段权限继续由统一 `AccessPlan` 管线决定。
- 默认拒绝；账号、租户、成员、会话、客户端或权限权威状态无法验证时不放行。

## 2. 总体架构

第一期在平台基础应用内嵌轻量授权服务器，使用 Spring Authorization Server + Spring Security，实现 OAuth 2.1 方向的安全流程和 OpenID Connect 1.0。逻辑边界独立，物理上不拆分服务；未来可替换为独立 IdP，业务 API 只依赖标准协议与平台主体契约。

```text
账号/凭据/MFA/外部身份绑定
              ↓
OAuth 2.1 / OpenID Connect 授权服务器
       ├─ Web BFF 客户端 → 服务端会话 Cookie
       ├─ 原生 App 公开客户端 → Code + PKCE
       └─ 集成客户端 → Client Credentials
                              ↓
                应用 API / AccessPlan
```

## 3. 客户端类型和标准流程

| 调用方 | OAuth 客户端 | 流程 | API 凭证 | 关键限制 |
|---|---|---|---|---|
| 浏览器 Web | 机密 BFF 客户端 | Authorization Code，建议同时使用 PKCE | HttpOnly 服务端会话 Cookie | Token 不进入浏览器 JavaScript |
| 原生 iOS/Android | 公开客户端 | Authorization Code + PKCE (`S256`) | Bearer Access Token | 使用系统浏览器，App 不保存客户端密钥 |
| 外部/系统集成 | 机密客户端 | Client Credentials | Bearer Access Token | 固定租户，可选 mTLS，无用户身份 |
| 未来第一方独立 Web 应用 | 机密 BFF | Authorization Code + PKCE | 各应用自己的服务端会话 | 不共享跨域 Cookie |

明确禁止：

- OAuth Resource Owner Password Credentials（密码模式）。
- Implicit Flow 及将 Access Token 放在 URL fragment/查询参数。
- 原生应用内嵌 WebView 作为 OAuth 主要登录容器。
- 浏览器将 Access/Refresh Token 持久化到 `localStorage`、`sessionStorage` 或可被 JavaScript 读取的 Cookie。
- 移动端使用 Client Credentials 冒充用户。

## 4. 标准端点与契约

授权服务器使用标准端点语义，不按 Web/Mobile 自定义多套登录 API：

```text
/.well-known/openid-configuration
/oauth2/authorize
/oauth2/token
/oauth2/revoke
/oauth2/introspect       只向已授权机密客户端开放
/oauth2/jwks             只在采用签名 JWT 时提供
/userinfo
/connect/logout          按 OIDC 登出支持能力锁定
```

登录页、MFA、找回密码是授权服务器的用户交互，不作为公开业务 API 暴露密码验证能力。

## 5. Web 会话

- Web BFF 完成授权码交换，服务端保存授权/会话状态，浏览器只持有高熵、无业务含义的会话 ID。
- Cookie 设置 `HttpOnly`、`Secure`、`SameSite=Lax`、`Path=/`；生产优先 `__Host-` 前缀且不设置 `Domain`。
- Cookie 认证的状态修改请求必须使用与会话绑定的 CSRF Token；`GET`/`HEAD`/`OPTIONS` 无业务副作用。
- CORS 默认关闭；必须跨域时使用精确来源白名单，不允许通配来源携带凭据。
- 登录成功、MFA/权限提升、密码修改和其他身份强度变化时轮换会话 ID。
- Spring Security 显式装配 `ChangeSessionIdAuthenticationStrategy`，不仅依赖框架默认值；真实 Servlet 容器/浏览器 E2E 须校验登录前后 Cookie 会话 ID 已变更。
- 同一 Cookie 会话的标签页共享当前租户。第一期不支持同一会话在不同标签页并行使用不同租户。

## 6. 移动端

- 授权请求使用系统外部用户代理：iOS `ASWebAuthenticationSession`、Android Custom Tabs。
- PKCE 必须使用 `S256`，同时校验 `state`；OIDC 流程校验 `nonce`、issuer、audience 与授权码回调。
- 回调优先 Universal Links/App Links，普通自定义 URL scheme 作为受控兼容方案。Redirect URI 必须精确注册匹配，不使用通配。
- Refresh Token 存放于 iOS Keychain 或 Android Keystore 支撑的加密存储；Access Token 尽量只存内存。
- Refresh Token 每次使用后轮换，旧 Token 立即失效；检测到已使用旧 Token 再次使用时撤销该设备会话的 Token 族并告警。
- Refresh Token 轮换在权威存储中使用“当前 Token 哈希 + ACTIVE 状态”条件更新/CAS，不使用无锁的先查后写。并发刷新只允许一个成功，其他请求视为重放并撤销整个 Token 族。

## 7. Token 与会话状态

- 第一期 Access Token 优先使用不透明随机 Token，便于在单体/少量实例下即时撤销和集中管理；不因“无状态”盲目使用长效 JWT。
- 未来多资源服务需要本地验签时可切换短效签名 JWT，但仍通过会话/成员/租户/授权版本检查实现安全收紧。
- Token 和会话只携带主体、客户端、当前租户、认证强度、会话/授权版本及协议 scope 等最小声明，不嵌入完整角色、数据范围和字段策略。
- 会话具有绝对有效期、空闲超时、最后活动时间、当前租户、上下文版本、认证方法/强度、设备会话和撤销状态。
- Valkey 保存会话/Token 热状态，共享数据库保存必要权威状态、设备会话、撤销与审计依据。Valkey 故障时可受限回源；两者都无法验证时拒绝。

Token/会话精确 TTL 不在设计文档中凭经验写死，由风险等级、私有化运维能力和容量测试确定；平台提供安全上限，租户只能在允许范围内收紧或配置。

## 8. 租户切换

- 登录证明全局账号身份；进入业务 API 前必须选择租户并校验有效成员资格。
- 切换租户由受控用例完成：验证账号、租户、成员和开通状态，然后更新当前租户并递增会话上下文版本。
- Web 轮换服务端会话上下文；移动端签发绑定新租户/版本的新 Token。旧请求和旧 Token 不得被重新解释为新租户。
- 客户端不能通过任意 `tenantId` 请求头或参数直接改变数据行级边界。

## 9. 本地账号与密码

- 登录识别符与账号分离，可按产品配置支持用户名、已验证邮箱或已验证手机号；内部使用不可变账号 ID。
- 账号资料保存可选邮箱和 E.164 手机号，并分别记录验证状态。新建或修改联系方式默认未验证，不得因管理员录入就开放登录、找回或通知信任。邮箱归一化为小写，邮箱和手机号在全局账号目录唯一；后续启用多登录方式时，只能将已验证值绑定到独立登录识别符。
- 密码使用 Argon2id，每个密码独立随机 salt；参数由目标服务器基准设定并可版本化升级。必要时的 pepper 保存于 Secret/KMS，不与哈希同库。
- 允许长密码/密码管理器生成密码，不强制无安全价值的周期更换或复杂字符拼凑；拒绝常见、已泄露和与账号明显相关的密码。
- 密码修改要求当前凭据或足够强的重新认证。找回/管理员重置使用一次性、短有效期、可撤销凭证，成功后撤销相关会话并通知用户。
- 登录、找回和注册响应避免泄露账号是否存在。限流结合账号、IP、设备和风险信号，不使用可被恶意触发的长期全局账号锁死作为唯一防护。

## 10. MFA 与重新认证

- 认证上下文记录 `auth_time`、认证方法 `amr` 和认证强度 `acr`，业务用例可对高风险操作要求 step-up authentication。
- 第一期轻量 MFA 支持 TOTP 和一次性恢复码；恢复码只保存哈希且单次使用。短信/邮件验证码可用于恢复或风险校验，不作为高安全 MFA 的首选。
- 管理员、平台作用域、破窗访问、密钥管理与敏感原文临时查看默认要求 MFA/重新认证。
- WebAuthn/passkey 作为后续无密码和抗钓鱼能力，插件边界在第一期保留，不为其自定义协议。

## 11. 企业 SSO 与身份联合

- 优先作为 OIDC Relying Party 对接企业 IdP；只有客户明确需求时增加 SAML 2.0 适配。
- 外部身份以 `(issuer, subject)` 绑定全局账号，不以可变邮箱作为唯一持久标识。首次绑定、自动建账和租户加入使用受控策略，不因 IdP 登录成功自动授予业务权限。
- 企业 IdP 宣告的 MFA 只在 issuer、`acr`/`amr` 映射和信任策略明确配置时等价为平台认证强度。

## 12. 撤销与安全事件

- 账号停用撤销其全部会话/Token；租户成员禁用只撤销该租户上下文；租户停用阻止该租户所有访问。
- 用户可查看并撤销自己的设备会话，授权管理员可按范围强制下线。
- 密码重置、MFA 恢复、Refresh Token 重放、可疑登录、管理员强制下线和客户端密钥撤销写入安全审计并产生受控告警。
- 权限变化不要求重新登录，通过授权版本立即对新请求生效；认证强度不足时通过 step-up 提升，不通过扩大普通会话权限解决。

## 13. 已确认：轻量化第一期范围

第一期实现：

- 本地账号密码、登录/注销/修改/找回和登录防护。
- OIDC/OAuth 标准发现、Authorization Code + PKCE、Client Credentials、Token 撤销和用户信息端点。
- Web BFF 会话/Cookie/CSRF、原生移动 Token/Refresh Token 轮换、集成客户端。
- TOTP、恢复码及敏感操作 step-up。
- 会话/设备管理、强制下线、撤销、审计和租户切换。
- 一个标准 OIDC 企业身份源的可验证 PoC，用于证明可扩展性，不作为完整企业 SSO 管理产品交付。

第一期不实现：

- 通用 SAML 管理平台、SCIM、社交登录市场和自动风险评分引擎。
- WebAuthn/passkey 完整产品化。
- 独立高可用 IdP 集群、跨地域会话复制和完整开发者门户。

## 14. 集成与功能验收

- Web：授权码登录、Cookie/CSRF、会话固定防护、租户切换、注销和管理员下线。
- Mobile：系统浏览器 + PKCE S256、App Link 回调、Refresh Token 轮换/重放检测和安全存储。
- Integration：Client Credentials、租户绑定、双密钥轮换、授权版本失效、限流和幂等。
- 账号安全：Argon2id 性能基准、账号枚举防护、限流、密码找回、TOTP/recovery code 与 step-up。
- 故障：Valkey 故障受限回源，无法验证会话时默认拒绝。
- 审计：成功/失败登录、MFA、找回、Token 重放、强制下线和密钥撤销不泄露密码、Token 或恢复码。

## 本人安全日志实施（2026-11-06）

正式 audit 模块公开 SecurityLogRepository 端口，持久化适配器使用 MyBatis 访问平台级 account_security_log 表，由 V3 迁移创建。记录不可变账号标识、稳定操作类型和服务端 UTC 时间；不保存密码、Token、请求正文、未经验证的设备或地理位置。

已接入成功登录、主动注销、资料修改和密码修改。登录仅在密码认证成功阶段记录一次，OIDC 回调不重复记录；登录日志写入失败时终止该次认证。资料/密码修改日志与业务更新同一 MySQL 事务提交，防止回滚操作被记录为成功。注销记录追加后才完成主动注销响应。尚不包括失败登录、被限流请求、会话超时/强制撤销、平台管理查询及完整合规审计，不据此宣称完整安全审计交付。

GET /bff/account/security-logs 只从认证主体取得账号，客户端不能通过 accountId 扩大查询范围；page 默认 1、范围 1–100000，size 默认 10、范围 1–50。响应直接返回 items/total，按递增日志 ID 倒序并禁止缓存。日志从功能启用后开始积累，不回填虚构历史。

日志保留期限、归档清理及防篡改存储仍需后续运维设计；当前应用不提供修改和删除入口，不等于数据库级不可篡改。

## 本人登录会话管理

GET /bff/account/sessions 使用 Spring Session 的 Valkey 主体索引，仅查询认证账号的未过期且凭据版本有效的会话。返回创建时间、最近访问时间、当前会话标记与 SHA-256 摘要管理标识，不返回真实 Cookie 会话 ID。最近访问包括后台探测，不等同于用户最后主动操作。

DELETE /bff/account/sessions/{handle} 要求会话认证与 CSRF，仅允许撤销本人的其他会话。跨账号、已失效与不存在的标识统一返回 404；当前会话返回 409，要求使用正常注销。撤销直接删除目标共享会话，后续请求必须重新认证；已在执行的请求不保证立即中断。其他账号的会话不受影响。

使用 spring.session.data.redis.repository-type=indexed 与主体索引，禁止通过全库键扫描查询在线用户。切换仓储类型后，部署前已有会话不保证自动进入索引，需要重新登录；生产需规划切换窗口。该功能不是完整设备管理，不记录或推断设备型号、IP 地理位置，也未提供管理员强制下线、批量撤销或会话撤销审计。

登录会话新增“退出其他登录”：POST /bff/account/sessions/revoke-others，必须携带 CSRF；服务端按主体索引取快照并排除当前会话，删除目标后记录 OTHER_SESSIONS_REVOKED。无目标时返回 revoked=0，不追加成功日志。并发新登录不在快照范围，执行中请求不保证中断；Redis 删除与 MySQL 日志不是原子事务，故障时可能部分完成，界面提示失败并允许刷新重试，不承诺事务回滚。前端使用模板确认弹窗和危险操作按钮，保留当前会话。


租户选择首批实施：V4 迁移建立 platform_tenant 与 tenant_member，同账号同租户唯一；TenantAccess 公开端口仅返回租户与成员同时启用的关系。GET /bff/tenants 查询本人列表，POST /bff/tenants/current 以 CSRF 保护首次选择，校验成员后轮换会话 ID 并存入租户、成员及上下文版本；GET /bff/tenants/current 每次重验状态。不存在或无成员的选择返回 403，未选择或失效上下文返回 409。

前端进入工作台前探测当前上下文，单租户自动选择、多租户显示列表、无租户显示真实空态；个人中心仍允许无租户账号访问。不会自动为初始化管理员创建业务租户，也不会因登录赋予平台租户创建权限。租户创建/成员管理页面在后续管理权限实现后交付，本批不增加公开建租户接口。

当前仅完成选择及上下文存储/重验入口，尚未接入业务 API 的统一租户执行过滤器、SQL 行级隔离、上下文响应版本校验及多标签同步。已选租户之间切换返回 409，不宣称完整租户隔离交付。后续业务接口在上述执行边界完成前不得仅依赖前端路由守卫。


租户执行边界增量：/api/** 第一方业务入口经过账号/凭据版本校验及 TenantExecutionFilter，按服务端会话绑定重新查询有效租户成员。客户端 tenantId 参数及 X-Tenant-Id 不参与边界决定。上下文 VerifiedTenantContext 为不可变请求属性，finally 清理，不用 ThreadLocal，不向异步线程自动传播。异步用例须显式重新验证，当前不支持异步业务上下文继承。

GET /api/workspace/context 已接入此边界；成功响应包含 X-Tenant-Context-Version。缺少登录返回 401，缺少或失效租户返回 409，无法验证数据库状态返回 503。前端工作台准入改为调用该业务入口。此过滤器只建立请求身份边界，不代替业务操作授权、系统开通校验或 SQL 行级隔离；后者尚待实施，不能宣称租户业务数据已完整隔离。个人中心和 /bff/tenants 选择流程不需要预先建立租户上下文。
旧会话授权恢复（2026-11-06）：授权服务在 SecurityContextHolderFilter 之后、授权端点之前检查真实 FactorGrantedAuthority 认证时间。缺少证据时只清除旧认证上下文、凭据版本并轮换会话 ID，保留 BFF 已发起的 OAuth state/PKCE 请求，引导重新认证；不伪造 auth_time，不整会话清除待完成授权请求。真实浏览器验证 admin 重复授权、重新认证与平台管理进入成功。
