# 粮食与钢材入仓通知字段设计

入仓通知表示预计到货与收货计划。沿用大宗仓储的通知主从模型，由仓库和货主确定单据归属。通知可包含多个品规，每行分别记录计划量、批准上限和实收进度。入场、接管、实收继续以原通知及行标识关联。

| 截图字段 | 归属及规则 | 实施情况 |
|---|---|---|
| 通知单号、预约单号、入库单号 | 通知单号沿用现有业务编号。外部预约号是可重复的参考编号。入场与实收编号来自各自单据，使用已有关系追溯。 | 新增预约单号，沿用通知号和既有单据关系 |
| 仓库、货主、供货方、收货单位 | 仓库和货主沿用主数据。供货方、收货单位是独立客商角色，可能与货主相同，须经相应角色及租户授权校验。 | 仓库和货主已有。独立客商角色待接入 |
| 通知时间、预计到货、车／船号 | 通知时间用服务端签发时刻，预计到货独立记录。计划车牌或船号可选，实际到场车牌由入场单记录。 | 新增计划车牌或船号 |
| 司机、联系电话、证件号 | 按运输联系人和现场核验数据建模，按业务需要采集并执行字段保护。 | 在通知主单的新增、编辑与查看接入司机姓名、联系电话、证件号，均选填；沿用统一字段保护，验证范围见司机信息检查记录 |
| 货号、品名、分类、单位、通知数量、合同号、备注 | 引用商品及品规。通知数量对应计划量，批准上限独立控制实收。合同号按明细记录，允许同一单不同合同。 | 新增行合同号，沿用现有品规、单位、数量与备注 |
| 钢卷号、产地、材质、规格 | 品规决定稳定的商品属性。具体钢卷及产地按实际追踪需求分别进入单件标识或批次属性，保持签发与实收来源清楚。 | 品规已有，通知阶段的钢卷或批次预报待接入 |
| 件数、重量、总件数、总吨数 | 件数与重量是不同度量。按行维护来源，服务端只在同量纲或存在受控换算时汇总。总量只读。 | 已有基础单位数量，双计量和汇总待接入 |
| 库位、明细照片 | 实际库位沿用入场与接管分配。照片采用受控证据或附件引用。若需提前指定计划库位或上传预报照片，独立保存计划信息。 | 实际库位及证据标识已有，通知阶段的计划库位与附件待接入 |
| 状态、版本、审计、创建来源与方式 | 沿用系统状态、流程版本和可信审计。暂存需要真实草稿状态与操作权限，来源和方式由服务端按可信调用渠道确定。 | 现有签发与审计保留，暂存及来源和方式待接入 |

预约、计划车船号和合同号为可选文本，最多 64 字符。司机姓名和证件号最多 64 字符，联系电话最多 32 字符，均选填，历史单据留空。预约单号和合同号仅为业务参考，继续按原通知单号查单。单据关系、权限和流程版本沿用现有链路。

## 单据生命周期与入库确认

- 单据头使用入仓通知单号和可选业务单号。前者标识本单并用于查单，后者记录预约单或其他上游单据编号。继续复用现有 API 字段 noticeNo 和 appointmentNo。业务组织、经办人和运输工具标识按各自业务语义建模。业务组织和经办人在受权组织／人员档案下选择，可信登录账号仍独立用于审计。
- 单据状态目标为 10 准备、30 待审、70 执行。提交后待审，审核通过后执行，退回后回到准备。计划数量与实收数量独立，执行状态和收货进度独立。现有签发和履约进度字段在此轮明细变更中沿用，目标状态和组织人员字段尚未接入。
- 通知明细使用稳定 UUID。接管及入库明细由该标识反查来源行，临时展示序号只按当前视图生成。暂存和入场登记均不产生实收数量，入库确认与库存入账及累计实收量更新同事务，拒收和幂等重放不增加累计量。后续入库冲销需关联原确认记录并扣回同一来源行，尚未接入。
- 通知主单和明细的审计展示均取数据库中的可信创建／修改账号与 UTC 时间，页面只读。历史未知账号保持空值。
