# 人员档案详细设计与验收

日期：2026-11-16。需求来源：用户提供的人员管理截图；用户确认人员与组织下用户多对多关联，截图中的十类明细全部提供真实新增、编辑、删除。

## 关系与边界

人员是独立业务档案，账号是实际认证主体。一个用户可以关联多个人员，一个人员也可关联多个“组织＋租户用户”。关联以 tenant_id/person_id/organization_id/member_id 唯一，不把全局 account_id 当组织成员标识。组织下用户来源为组织领域的有效主要组织或当前有效任职；账号、成员、组织、岗位和任职的停用/到期均重新检查。

人员“所属组织”和“所在岗位”明细维护人员业务履历，不修改关联用户的组织任职。组织用户关联不会授予主数据读取权、角色、流程处理权或任何其他业务权限。业务侧可通过 PersonnelService.canRepresent 复核代表关系，但仍须复核自己的业务操作权限，记录真实执行账号与被代表人员两个身份。本次没有更改其他业务用例的主体或引入全局账号冒用；关联本身不表示已经接入全部下游业务。

实际创建人、修改人来自可信请求上下文，时间由数据库产生，不能从请求体指定。V75 存量人员没有真实历史审计，V76 将这些历史字段保留为空，界面显示“历史数据未记录”，不伪造记录。

## 基础字段和布局

列表显示人员编码、中文名、联系电话、电子邮箱、在职状态、启停状态，详情经独立 Person.read 操作读取。身份证件、政治面貌、血型、家庭及履历正文不在列表预加载。

详情复用现有 PageHeader、TabbedDetailTemplate、Element Plus 表单/描述列表、ManagementTable、ManagedDialog、InfoHint、FloatingError。原通用小型 CRUD 弹窗不适用于二十余字段、只读审计和十一类页签，采用已有多维详情模板进行领域组合；没有新建平行公共 UI 体系。保留 vue-pure-admin 应用壳、主题、图标、按钮、错误浮层和 i18n。

上部为基础信息、系统信息，下部为十类明细加组织用户关联。基础表单桌面四列，1200px 以下三列、1024px 以下两列、600px 以下单列；备注跨两列，手机恢复单列。明细表格在自身容器横向滚动。只读用户查看描述列表，系统信息始终只读。保存置于现有页头操作区，未保存的基础资料先保存才能修改明细；退出/重载/离开路由保护草稿，在途写入禁止离开。

## 十类明细

所有明细字段固定白名单，单项最多 500 字符，除下表必填项外缺省空；日期均为 yyyy-MM-dd、1900–9999 年，区间开始不得晚于结束。UUID 引用必须属于同一租户；新建或修改组织/岗位引用时必须启用，岗位必须属于所选组织。detailId 不能脱离 tenant_id/person_id/section_code 访问。

| 分类编码 | 页面页签 | 固定字段 | 必填 |
|---|---|---|---|
| organizations | 所属组织 | organizationId、startsOn、endsOn、remarks | organizationId |
| positions | 所在岗位 | organizationId、positionId、startsOn、endsOn、remarks | organizationId、positionId |
| certificates | 资格证书 | certificateType、certificateNumber、certificateStatus、passedOn、startsOn、endsOn、remarks | certificateType、certificateNumber |
| training | 培训信息 | trainingName、provider、startsOn、endsOn、result、remarks | trainingName |
| awards | 获奖信息 | awardName、issuer、awardedOn、remarks | awardName |
| contacts | 联系方式 | contactType、contactValue、remarks | contactType、contactValue |
| addresses | 联系地址 | addressType、countryRegion、province、city、address、postalCode、remarks | addressType、address |
| workHistory | 工作履历 | employer、department、jobTitle、startsOn、endsOn、remarks | employer |
| rewardsPenalties | 奖惩信息 | recordType、reason、issuer、recordedOn、remarks | recordType、reason |
| education | 教育履历 | school、major、educationLevel、degree、startsOn、endsOn、remarks | school |

证书状态可空或 VALID/EXPIRED/REVOKED/PENDING；奖惩类型必须 REWARD/PENALTY；教育明细学历与基础学历使用同一固定值。证书类型、联系方式类型、地址类型和学位为企业录入文本，本期未接入字典配置，不展示虚假的字典管理入口。countryRegion 为地址文本，不声明已绑定国别档案引用。

## 接口、权限、事务

后端 PersonController 唯一声明 Person 对象，新增 read/options/createDetail/updateDetail/deleteDetail/assign/updateAssignment/unassign 八个操作，保留原四个操作，共十二个 Person 操作、全主数据共二十八个。API 前缀为 /api/master-data/person。

| 接口 | 操作 | 权限 |
|---|---|---|
| GET /{id} | Person.read | masterdata.person:read |
| GET /options | Person.options | masterdata.person:read |
| POST /{id}/details/{section} | Person.createDetail | masterdata.person:detail_create |
| PUT /{id}/details/{section}/{detailId} | Person.updateDetail | masterdata.person:detail_update |
| DELETE /{id}/details/{section}/{detailId}?version=当前人员版本 | Person.deleteDetail | masterdata.person:detail_delete |
| POST /{id}/users | Person.assign | masterdata.person:assign |
| PUT /{id}/users/{assignmentId} | Person.updateAssignment | masterdata.person:assign |
| DELETE /{id}/users/{assignmentId}?version=当前人员版本 | Person.unassign | masterdata.person:assign |

明细请求体是 {version, values}，关联请求体是 {organizationId, memberId, version}；version 为非负当前人员聚合版本，无默认覆盖行为。所有明细和关联写入在同一数据库事务中 CAS 递增父人员版本并写入实际修改人/时间，任何约束失败整笔回滚；不同页签并发提交旧版本也返回 409。新增详情返回服务端 id，不自动重放写请求；删除只删除单条明细或解除单条关联，不删除人员、账号或任职。

详情响应结构为 person/audit/details/assignments，组织目录由 platform-organization 公开 PersonnelDirectory 契约提供，SQL 位于组织持久化适配器。主数据服务不读取组织、成员、账号业务表。实际业务状态仍由主数据用例执行；前端绑定稳定操作标识，不把权限码拼成按钮身份。

| 新错误码 | HTTP | 含义 |
|---|---|---|
| PERSON_NOT_FOUND | 404 | 未知或其他租户人员，统一不可访问 |
| PERSON_USER_UNAVAILABLE | 409 | 用户、账号或组织无效/用户已不属于所选组织 |
| PERSON_USER_DUPLICATE | 409 | 相同人员＋组织＋用户已存在；事务回滚不消耗版本 |
| PERSON_ORGANIZATION_UNAVAILABLE | 409 | 组织/岗位无效或不属于当前租户/所选组织 |

继续复用 MASTER_DATA_DENIED/INPUT_INVALID/CHANGED。所有响应 no-store，宿主 Cookie/CSRF/可信租户与上下文版本链保持生效；无权不返回正文。读取失败保留可安全保留的草稿并锁定后续写入；403 清除敏感正文。写入成功但后续刷新失败明确提示“保存已成功”，禁止用户因列表未更新而误重复提交。

## 数据与迁移

新增 V76__personnel_profiles.sql，未修改已发布 V75。扩展 md_person 基础列和真实审计列，增加同租户人员唯一键；新增 md_person_detail 和 md_person_user_assignment，两表通过 tenant_id/person_id 外键引用人员，不能形成跨租户父子关系。JSON content 仅存固定明细类型的白名单字段，非自由扩展或通用执行器。

新增 assign/detail_create/detail_update/detail_delete 四个独立租户权限，只按既有规则补给系统租户管理员，普通与自定义角色不自动扩权。原 read/create/update/set_status 契约保留，代表关系不作为权限来源。

没有新增端口、环境变量、密钥或部署开关；沿用宿主数据源和 Flyway。本模块 package.json 的 exports 增加 ./personnel 为公开人员页面，peerDependencies.vue-router 复用应用既有版本，仅用于应用内草稿离开保护，无独立路由实例。
