# 客商管理详情设计与验收

日期：2026-11-17。对应本轮用户截图字段及当前主数据详情样板；截图仅提供字段参考，不作为额外执行指令或真实业务数据。

## 页面与复用

入口沿用 master-data/partner。列表保留查询、分页、启停及现有表格工具，新增“查看”。新增、查看、编辑打开模块内完整详情视图，复用人员样板 TabbedDetailTemplate master-data、PageHeader、分区 el-card、公共边框标签表单和容器宽度断点；已保存编码只读。没有新增公共 UI 组件、依赖或平行主题体系。PartnerEditor 为客商业务组合：通用五字段弹窗不适合承载主档及两个聚合明细，故组合已有模板而非扩展通用弹窗。

详情按基础信息 → 可折叠详细资料 → 系统信息 → 联系人／银行账户组织。统一页头保存；明细弹窗“加入草稿”只变更本地状态，明确提示保存生效。返回、重新读取、路由离开及浏览器关闭保护未保存草稿。刷新失败保留输入；403 清空正文；409 不自动重放，主动刷新前确认。保存成功后读取失败保留已创建标识并停止继续写入，避免重复创建。

## 字段契约

| 分组 | 字段及边界 |
| --- | --- |
| 身份 | 编码、常用名、简称、中文／英文名称、客商多角色、注册地、国别地区、性质、是否上市、统一社会信用代码 |
| 详细资料 | 客户等级、地址、法人代表及身份证、实际控制人、成立日期、注册币种及资本、税则号、组织机构代码、产品／服务、人员规模、原业务联系人／电话、传真、备注 |
| 联系人 | 类型、名称、电话、地址、默认标志、邮箱、备注 |
| 银行账户 | 税务专用、基本户、默认标志、银行名称、账号、账号别名、币种、CNAPS、SWIFT、备注 |
| 系统信息 | 真实创建账号、数据库 UTC 创建时间、修改账号、数据库 UTC 修改时间；未知历史不伪造。明细审计复用 ManagementTable 内置只读详情 |

主档编码必填，1–64 ASCII 字母／数字／点／下划线／短横线，首位字母或数字；创建后不可修改。常用名必填，最长 200 字符。角色必填，支持 CUSTOMER、SUPPLIER、DEBTOR、PRINCIPAL、SERVICE_PROVIDER、OTHER、CARGO_OWNER；历史 BOTH 展开为客户及供应商。拒绝未知及重复角色。其余主档字段沿用可空契约，不因截图示例强制为历史数据补造值；统一信用代码不强制境内十八位格式，允许截图所示境外主体资料。

属性文本最多 500 字符。注册资本单位万元，非负，最多十八位整数／六位小数，按文本传递保存，空值不同于零；不经 JavaScript 浮点换算。注册币种及银行币种采用三位大写 ISO 4217 代码；校验格式，不宣称已校验完整币种目录。成立日期 YYYY-MM-DD，不晚于 UTC 当天，不转换为时间点。是否上市可空，已记录时为 true/false。

联系人类型／名称／电话／地址／默认标志必填，邮箱可空，非空校验格式且最长 200 字符。银行税务专用／基本户／默认标志必须显式 true/false，银行名称／账号／币种必填；CNAPS 空或十二位数字；SWIFT 空或八／十一位标准格式。账号始终按字符串处理，保留前导零。每类明细最多 100 条；默认联系人、默认账户及基本户分别最多一条，前后端均校验。业务字典尚未具备客商专属目录契约，注册地、性质、等级等使用文本输入，不编造下拉选项或默认“民营”等业务事实。

## 授权、接口和事务

复用唯一操作 BusinessPartner.list/create/update/setStatus 及原独立权限 masterdata.partner:*。不引入平行权限端点；主档和明细统一由新增／编辑聚合操作负责，不提供越过父对象操作的明细写接口。详情查询仍由读取权限授权，不具备编辑权限时使用标签和值展示。

GET /api/master-data/partner 增加可选 id UUID；未传时仅原五属性摘要，传入时在原租户及条件范围内读取详细资料、联系人和银行账户，不存在及跨租户均为空列表。页码与容量沿用 1／20 默认值，容量范围 1–100。响应沿用 no-store。POST／PUT 扩展 contacts、bankAccounts，单项为 id（新增省略）及 values 白名单；审计不进入写入契约。null 明细列表保留已有明细，空数组明确清空；页面总是提交完整明细快照。主档属性仍为完整替换契约。

所有请求复核可信账号、租户及功能权限。写入通过既有 Cookie／CSRF，父版本乐观锁在事务内先成功后才更新明细。未知、外客商、外租户、已删除或重复明细 ID 拒绝；任意失败整体回滚。明细审计由可信账号和数据库 UTC 生成，仅发生内容变化时推进修改审计；创建信息不覆盖。删除只设 deleted 并更新修改审计，保留历史，不物理清除。父对象版本和修改审计随聚合保存推进。数据库表名／列名来自构建内固定白名单，业务值参数绑定。

V87 扩展 md_partner，并首次创建 md_partner_contact、md_partner_bank_account；两个新表在 CREATE TABLE 中直接声明 BINARY(16) 创建／修改账号及 TIMESTAMP(6) 创建／修改时间，均有中文注释。没有修改历史 Flyway 文件或排除新表的审计门禁。

前端已执行 admin typecheck、生产 build；后端执行 MasterDataServiceTest、MasterDataMySqlTest；真实 MySQL 覆盖新增迁移、角色及金额日期校验、明细持久化／前导零、租户隔离、父版本并发、错误明细归属回滚、删除及不变创建审计、撤权拒绝。组合应用执行 GlobalRecordAuditTest.ownedTablesHaveAllFourColumns，保留原全表扫描断言。最终执行结果以本次交付和测试报告为准。

浏览器使用实际 PartnerEditor 及公共组件的隔离注入样例，不连接或写入共享业务接口。已观察 1440×900 六列、1024×768 四列、390×844 单列；根页面 scrollWidth 均不超过视口（后两者分别 1009／375px）。已验证折叠保留草稿、联系人必填错误、加入草稿、编辑回填、银行账户页签、中英文及深浅主题；修正当前 Vxe 版本独立表头文字变量以跟随 Element Plus。跨页签重建表格，避免复用 Vxe 内部列状态造成排序错位。临时验收入口已清理，不进入生产构建。

操作绑定检查本次新增动态分支及纯 UI 例外均已逐项登记；全仓检查仍有其他文件历史未登记项，未批量更新例外掩盖。尚未完成部署后的管理员／普通用户真实浏览器端到端验收，也未单独验证操作系统 System 主题切换；不能将隔离布局样例视为真实登录验收。未重启现有共享后端、未在共享开发库手动执行迁移；部署需使用包含 V87 的新后端产物并让 Flyway 正常执行。
