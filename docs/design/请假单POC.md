# 请假单审批 POC

请假单作为工作流首个验证单据，验证真实业务存储、可信审批依据、条件路由、人工审批和结果回写。POC 不计算年假余额、法定工作日或工资，不产生考勤扣款。

## 单据和流程配置

| 配置 | 约定 |
| --- | --- |
| 业务对象 | `LeaveRequest`，用途 `approval` |
| 业务能力 | `leavePoc`；原文和原因保留在业务存储 |
| 单据字段 | 请假类型、开始日期、结束日期、请假原因、归属组织 |
| 请假天数 | 起止日期均计入，按自然日计算；1—365 天；日期不进行 UTC 转换 |
| 条件字段 | `requiresHr`，由后端以天数 >3 计算为 `true`，否则 `false` |
| 流程 | 开始 → 主管审核 → 条件分支 →（超过 3 天：人事审核）→ 结束 |
| 主管 | 使用单据组织的 `LEADER` 规则；必须先配置有效负责人任职 |
| 人事 | 使用真实租户成员 `MEMBER` 规则；配置时选择有效成员，不创建模拟账号 |
| 自审 | 禁止；解析不到审批人时保留异常待办，不自动通过 |
| 结果 | APPROVED / REJECTED / WITHDRAWN 通过可靠交付回写；交付尚未成功时单据保留审批中 |
| 修改 | 提交后冻结审批依据；POC 不提供编辑、驳回重提和在途修改 |

## 接入边界

业务实现只依赖 workflow-contracts，不访问工作流表或引擎。租户及操作者来自可信会话，每次访问复核有效成员。本人可以读取自己的单据；审批人只在有效待办范围内读取单据原文，待办结束立即收回原文访问权。

创建单据、发起流程要求 `workflow:start`；配置和发布分别沿用 `workflow:edit`、`workflow:publish`。POC 沿用工作流权限，正式请假模块上线前需拆分业务权限。

前端选用标准列表工作区，组合已有 BusinessWorkspace、ManagementTable、ManagedDialog 和 Element Plus 表单；不新增基础 UI 组件。界面通过现有流程工作台办理，通过流程设计器查看和修改已生成的真实流程定义。

## 验收场景

1. 1 天和恰好 3 天：主管通过后结束；4 天：追加人事审批。
2. 任意一级驳回：结果为驳回，不进入后续节点。
3. 发起人不能自审；无主管、成员失效或跨租户访问应拒绝或保留异常待办。
4. 重复提交和可靠交付重试不重复创建单据或覆盖其他实例结果。
5. 只读原文不把请假原因写入引擎流转变量；审批后原任务不能继续读取原文。

本文件描述 POC 目标与配置约定；实际构建、部署和浏览器验证结果另行记录，不以设计文档替代验收。

### 使用步骤

1. 从本机账号文件取对应身份，访问 `http://localhost:8848` 登录并选择新建 POC 租户。
2. 主管进入“流程中心 → 流程工作台”，办理保留的体验单；“进入业务单据”可读取本次请假原文。
3. 主管同意后，人事账号进入同一工作台继续审批；申请人在“请假单 POC”刷新后看到可靠交付回写的终态。
4. 管理员在“流程设计器”查看已发布配置；修改草稿不会改变在途体验单绑定的版本。
