# 菜单页面操作权限对应修复

日期：2026-11-10。修复授权中心按整个资源展开导致多个页面显示相同操作、菜单目录存在未执行权限及菜单写入未逐操作复核的问题。

页面—权限来自 `NavigationPages.operations` 精确构建契约。`AuthorizationNode.operations` 返回真实操作码；`resources` 仅保留资源元数据，不参与前端整组展开。新旧页面没有 operations 时只显示基础访问权限，不能退回整资源放行。共享读权限允许出现在多个真实使用页面，保存仍按权限 ID 去重；没有映射的权限继续留在“其他功能”，不静默丢失授权维护入口。

| 页面操作 | 权限码 |
|---|---|
| 菜单查询、读取页面目录 | `configuration.menu:read` |
| 新建根节点、新增下级 | `configuration.menu:create` |
| 编辑菜单资料、表单内启停 | `configuration.menu:update` |
| 删除菜单 | `configuration.menu:delete` |
| 平台角色查询、新建、编辑、启停、删除 | 对应 `access.role:read/create/update/enable/delete` |
| 平台授权中心读取角色及配置授权 | `access.role:read`、`access.role:grant`；账号目录为 `identity.account:read` |

V45 停用没有独立执行点的 `configuration.menu:enable` 和 `configuration.menu:publish`，保留历史记录；将菜单 update 的名称说明同步为“编辑菜单（含启停）”。没有新增发布按钮或虚假独立启停入口，不更改菜单配置值或已有菜单状态。

菜单管理新增 capabilities 接口只返回真实当前操作，页面新建/编辑/删除按钮据此控制；用例逐次复核相同稳定码，平台身份不能绕过操作撤销，前端隐藏/禁用不作为安全边界。继续复用现有 TreeListTemplate、ManagementTable、ManagedDialog 及 Element Plus，没有新增组件或视觉体系。

测试覆盖资源共享但页面操作不同、目录批选去重、未关联操作保留、未实现权限停用、全部构建映射必须指向有效权限，以及管理员缺少创建/编辑/删除操作时在写入前拒绝。实际验证结果随任务更新；浏览器未完成场景不得以构建替代。

验证结果：真实 MySQL/Valkey 菜单集成 8 项、操作权限拒绝 1 项、契约生成/隔离 2 项、架构 4 项通过；前端授权模块 8 项、admin Vue/TypeScript 类型检查及正式构建通过。最新契约快照已同步。当前浏览器登录后完整撤权/按钮操作、主题和视口验收尚未完成，不以自动检查替代。
