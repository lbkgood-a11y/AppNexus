# ERP、WMS、SCM 权限场景验证

日期：2026-11-09。验证对象为当前工作区代码；已有未提交修改保留。本次不实现采购、库存业务，不以组织测试代替这些业务的端到端验收。

## 结论

现有身份、角色、稳定权限码、成员授权快照、事务审计可以继续作为基础。当前数据策略仍是组织专用模型，多维业务范围需要扩展；流程授权需要由业务模块执行。当前不能认定完整 ERP、WMS、SCM 授权已经通过验收。

## 验证方法与证据

- 静态核对 authorization 模块、MyBatis 数据范围与字段执行器、V25 授权快照迁移及组织仓储。
- 回归 RoleManagementTest 与 UnifiedFieldProtectionTest；结果以下方实际执行记录为准。
- 仓库未提供采购单、库存、仓库及货主业务链，本次对应场景是模型适配检查，不是业务运行测试。

## 场景一：采购制单与审批

设同一租户有公司 A、B：采购员只能创建 A 公司采购单；审批员可审批 A 公司采购单，但不得审批本人创建的单据，且受金额额度和单据状态约束。

| 检查项 | 当前证据与判断 |
|---|---|
| 制单、审批使用不同权限 | 稳定权限码可承载，但采购操作及其接口尚未接入，属于可复用机制 |
| 同角色不同成员范围不同 | 成员授权快照和既有组织测试支持；公司作为独立业务维度尚未支持 |
| A 公司审批权不能与 B 公司查看权拼接 | 现有 SQL 按角色、权限连接快照，具备同分支基础；公司条件未实现，不能宣称该业务场景通过 |
| 不能自审、超过额度拒绝、已过账禁止修改 | 当前通用鉴权接口不接收单据对象、金额和状态；需业务领域规则执行 |
| 多人同时审批或撤权时提交 | 有授权管理乐观锁，不等于业务审批并发控制；业务条件写入及授权一致性仍需专项验证 |
| 只读数量、成本受限 | 当前受保护字段目录仅支持 String；金额等数值字段、字段写入和导出渠道均需扩展 |

流程状态、金额和自审规则应由采购领域维护，调用统一权限与范围能力；不应通过增加大量金额档位角色或菜单节点替代。

## 场景二：多仓多货主库存

设授权分支一允许上海仓货主甲，分支二允许苏州仓货主乙。允许范围应是 `(上海仓 AND 货主甲) OR (苏州仓 AND 货主乙)`；上海仓货主乙、苏州仓货主甲均应拒绝。

| 检查项 | 当前证据与判断 |
|---|---|
| 同一角色按成员分配不同仓库 | 当前 DataScope 只有 organizationIds，不能直接承载仓库 ID |
| 仓库与货主组合条件 | V25 每个角色/权限只有一个 scope_type，值表仅关联组织；无法直接表达上述条件 |
| 同角色多条独立授权与不同到期时间 | 授权头主键为 tenant_id/member_id/role_id，同角色仅一条授权头，不能直接表达多个独立期限分支 |
| 列表、数量统计、库存修改一致受限 | 组织仓储已有范围接入，但没有库存仓储执行证据 |
| 跨仓调拨 | 应分别校验来源仓操作和目标仓接收资格；当前单资源组织范围不能证明支持 |
| 外部货主和集成程序 | 现有 Subject 主要面向账号/成员；客户端授权仍待接入 |

不得将仓库、货主编码进组织树，亦不得分别合并仓库集合和货主集合后做笛卡尔积，否则会扩大授权。

## 最小演进建议

1. 保留角色和权限目录，新增受控业务范围维度；管理员选择公司、仓库、货主等真实对象，不能输入 SQL 或脚本。
2. 同一分支内不同维度取 AND，完整分支之间取 OR，最后应用租户和强制限制；范围必须进入查询、计数与条件写入。
3. 若需同角色多来源、独立期限或独立撤销，为授权记录引入独立标识；现有成员角色关系作为归属索引。
4. 为采购声明制单、提交、审批等领域操作，并接入状态、金额、自审与并发规则。
5. 扩展字段读取、修改、查询和导出契约，区分岗位能力与强制限制。
6. 用真实采购和库存业务完成上述正向、反向测试后再认定业务适用；动态菜单消费统一授权结果，不另建角色菜单授权。

普通管理员的目标操作为：选择成员、分配岗位、选择业务范围、确认摘要。条件组合和仓储映射由底座及领域模块维护。

## 后续实现：业务范围条件契约

authorization 模块新增 `BusinessScope`，由领域注册资源与完整必需维度。分支携带独立 grantId、可信租户、操作码、维度 UUID 集合和期限；维度内集合表示允许值，分支内不同维度取 AND，完整分支取 OR。没有隐式全部范围；缺失或未知维度的分支不参与放行。此标识暂未持久化，不代表现有 V25 已支持同角色多条授权。

`resolve` 输出不可变的有效分支，供后续受控仓储编译器使用；`allows` 用于单对象领域检查与契约验证，禁止作为列表查全量后的过滤器。调用方必须先完成主体、角色、权限上限及撤销检查，目标归属必须来自服务端业务对象。本批没有新增 HTTP API、迁移或前端入口，没有把客户端构造条件接入生产鉴权，也没有替换既有组织授权路径。

新增 `BusinessScopeTest` 验证仓库/货主交叉组合拒绝、操作隔离、跨租户拒绝、到期边界、同角色可表达独立期限分支、维度缺失拒绝及集合深复制。后续需完成领域范围值校验、独立授权持久化、与既有权限判定对接、查询/计数/条件写入编译及真实业务集成测试，才能认定多维授权上线。
