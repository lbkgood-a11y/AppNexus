# 权限计划、固定聚合与策略模板实现

日期：2026-11-10。当前增量完成组织单元正式 AccessPlan、固定联表安全聚合样例和角色策略模板；授权委派、全部字段操作和缓存故障回源仍不能标为已完成。

## 权限执行计划

`AccessPlanning` 在单次权威读取事务中复核功能权限及行范围，生成不可变 `AccessPlan`。主体只接受服务端账号/租户/成员；资源与权限必须匹配，缺少权限默认拒绝。集合深复制，不允许跨请求复用计划或通过请求体提交计划。组织单元 CRUD 已接入；DENY 只能拒绝或返回空，不回退全部。

组织资源没有已登记敏感字段，当前计划字段限制为空；不能把空字段限制解释为未来业务字段自动获得编辑、排序、查询、导出或打印权。现有集中展示脱敏仍沿用原管线，其他资源和输出渠道须逐项接入。

## 固定联表与聚合样例

`GET /api/organization/summaries` 在统一可信租户上下文和 `organization.unit:read` 下返回类型、状态和数量。`ScopedOrganizationSummary` 先将租户和行范围注入固定 SQL，再执行组织单元与类型联接及分组。两表显式租户谓词，动态部分仅是绑定占位符数量，不能接受自由列、表、SQL 或排序表达式。

`OrganizationSummaryTest` 使用真实 MySQL 的 A/B 租户相同类型/组织标识，验证精确行范围只统计 1 条、ALL 只统计当前租户 2 条、DENY 为空。该样例只证明固定模型的安全聚合，不交付通用查询编译器或报表平台。

## 策略模板

V42 创建同域快照模板，平台 owner 为零 UUID，租户 owner 为真实租户。模板保存已审核角色完整功能、数据范围及字段强制限制，不存业务原值或凭据。创建模板不改变任何角色。

应用模板仍调用 `RolePermissionManagement.replaceAuthorization`，使用目标角色当前版本、变更原因以及当前目录校验，复核组织归属、权限域和字段执行支持，不能跨域套用或将模板旧版本作为目标版本。模板是复制源，后续源角色变化不修改已有模板，模板应用也不自动更新其他角色。

当前租户及平台角色提供模板列表、保存和应用 API。授权中心复用原工具栏、Element Plus、确认框和 HTTP/CSRF；新增 `PolicyTemplateActions` 只承载模板操作，已有角色编辑器不适合承载模板来源和应用确认，因此组合独立场景组件，不另建 UI 体系。未保存草稿阻止保存/应用模板；列表失败禁写，应用要求填写原因及明确完整覆盖确认。

真实 MySQL 模板测试 2 项通过，覆盖保存/应用、源角色保持、版本冲突、无权主体和外域模板拒绝；HTTP 测试补充 CSRF 和无权错误映射。AccessPlan 单元测试 2 项、固定 SQL 聚合 1 项通过。登录后模板操作、深色/英文/三视口仍需浏览器验收。

## 事件与尚未完成范围

角色权限覆盖、生命周期和主体角色变更通过 `AuthorityEvents` 在当前业务事务写 Outbox。无数据库触发器，不授予额外 MySQL 权限；新增写用例必须继续接入端口。

授权委派的两个撤销语义、来源依赖和期限上限仍未实施，不能用角色分配冒充委派。成员独立范围编辑的所有事件来源、字段按记录条件、字段修改/查询/排序/导出/打印、Valkey 权限缓存的受限回源与故障验收仍需继续。
