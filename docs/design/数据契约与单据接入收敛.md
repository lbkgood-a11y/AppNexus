# 数据契约与单据接入收敛

日期：2026-11-13。本文替代《平台单据页面关联维护》中人工接线规则；设计器内部布局不在本次范围。

## 职责与唯一来源

业务代码登记 Descriptor → Action → InteractionContract.Capability，能力引用 dataContract/dataVersion，字段列表为唯一数据结构来源。schema() 生成公共 DataContract；打印目录及工作流设计目录读取同一声明，不另建可写副本。PRINT 和 WORKFLOW 使用不同用途契约；结果回调及完成方式仍属于交互协议。

数据契约包含编码、正整数版本、用途，以及字段路径、类型、必填性、单位。当前没有隐式默认值：可选缺失保持缺失，必填缺失拒绝。已有五参数 Field 默认必填。仅支持 TEXT/NUMBER/BOOLEAN 标量及点分嵌套对象；不宣称支持任意 JSON Schema、脚本或数组审批字段。历史打印文本/明细契约维持既有结构及校验；业务登记的类型契约使用公共严格校验。

业务适配器 LeaveContractData 将已授权请假记录转为审批/打印数据，不读取数据库，不补默认值；服务继续负责租户、申请人和权限校验。审批引擎保留字符串传输，按字段声明显式解码后校验，缺失、非法布尔、非法数值、多余字段失败关闭。打印接收真实 NUMBER，不再将 days 转字符串。

公共校验抛出稳定码及字段路径，不包含原值；HTTP 返回 code/field，前端翻译并呈现路径。业务记录不会搬到平台目录。

## 发布与执行

工作流发布保存数据契约结构快照；启动先校验业务数据，再匹配策略和流程，检查发布契约兼容性，并随实例保存契约快照。单据解析仍固定业务版本、策略发布版本及依据；工作流重读依据必须与解析一致。

打印发布检查模板 field 引用并冻结契约目录快照，任务创建再次校验数据并保存同一契约快照。补打和预览确认复制原模板版本、原数据及原契约。历史无契约快照的记录保持 NULL，不用当前结构伪造历史；旧发布版本的新执行按当前可用契约验证。

## 平台与租户配置

页面与行为关系是代码接入事实，不再开放 HTTP 人工关联保存。平台只读展示已接入操作，并提供独立启停：operationKey 必须存在，reason 为必填 1—200 字（不得含敏感信息），revision 首次 -1，之后回传读取值；冲突拒绝覆盖。控制审计记录操作者、原因及时间，不影响既有结果回调。

V68 增加 disabled_operations 及控制审计表。启动装配在行锁内将旧允许列表转换为当前登记入口的禁用覆盖；未维护类型无额外禁用，新部署入口默认登记。V69/V70 分别增加工作流及打印的契约快照列。Flyway 原历史脚本不改。

租户策略以行为为单位，旧页面别名读取时规范化为 canonical operationKey；条件匹配仍按行为唯一命中，已有冲突不会静默选第一条。具体按钮执行时仍逐次校验该入口是否禁用。

## 前端组织

复用标准列表 BusinessWorkspace/ManagementTable 与 ManagedDialog、Element Plus，无新 UI 库或组件。单据类型支持名称、编码、模块关键词搜索；操作目录支持行为、页面、编码搜索及分页。工作流设计入口为“1. 数据契约 → 2. 流程设计与发布”；契约字段只读，发布后导航到单据工作台配置策略。工作流不新增行为绑定或单据录入功能；真实提交仍在业务页面。打印和工作流设计器画布布局保持现有实现。

## 验证记录

公共契约 5 项测试通过；真实 MySQL/Flowable 请假与单据集成 8 项、打印闭环 2 项测试通过。前端单据 6 项、工作流 9 项、打印 20 项测试通过；admin 类型检查和生产构建通过，后端组合应用打包通过。开发库已应用 V68—V70，组合应用正常启动。测试包含非法数值、必填缺失、未知字段、打印契约快照、管控权限/原因/乐观锁，以及原直接提交、审批回调、撤回和打印幂等链路。浏览器工具因无法验证当前 URL 是否允许而停止，页面点击、主题及响应式视觉验收尚未完成，不以构建替代。

## 内容间距与契约维护边界补充

工作流目录复用 management-filter-header 隔开查询标题及表单；数据区及契约详情采用 16px 垂直间隔。流程业务配置以单一 gap 管理提示、表单项及规则卡片，清除重复默认外边距；仍复用原组件，不新增布局体系。

工作流当前仅支持代码登记契约，页面不直接编辑字段。打印另支持新增租户自定义文本/明细契约，但创建后同样只增不改。两者契约不可原地改写的约束一致，自定义来源的接入范围不同。若要支持工作流自定义契约，须同时提供数据来源/适配、业务行为绑定与版本发布，不能仅增加编辑表单。本次在工作流契约页显式说明该边界，没有新增未接通的编辑入口。

路由页外边距修复：workflow/designer.vue 原有返回按钮和 WorkflowCenter 两个根节点，使应用壳的 main-content 类无法透传，导致整页贴边。改为单一根容器承接模板 24px 外边距，内部仅设置 16px gap，不重复硬编码页面 margin。契约来源说明使用 Alert description 并允许换行。此前内部间距调整不能替代这一根因修复。

## 请假草稿负责人检查修复

实际畅联组织没有配置负责人，原创建/编辑草稿提前检查负责人并返回通用 LEAVE_INPUT_INVALID，导致用户无法保存草稿。负责人检查移至 WORKFLOW 提交分支；有效组织、本人、权限及依据版本校验保留，直接受理不要求主管。审批缺负责人返回 LEAVE_ORGANIZATION_LEADER_REQUIRED（409），同事务回滚单据状态、策略解析及提交记录。客户端增加中文/英文稳定错误说明，并将草稿弹窗错误与列表错误分开，避免一次保存失败重复显示为列表失败。已有负责人配置未自动修改。

进一步分离表单保存与单据提交：创建/修改草稿不读取组织任职或负责人，只保留表单业务值、标识格式、租户与本人权限及版本约束。仅在 WORKFLOW 提交分支检查有效任职和负责人，BUSINESS 直接受理不增加组织路由条件。当前请假表单仍将组织作为必填业务字段；本修复不将通用表单暂存等同于已实现的任意不完整表单存储。

本轮回归：请假真实 MySQL/Flowable 7 项通过，新增覆盖无有效组织任职时草稿创建/修改成功、审批提交拒绝且状态回滚；组合应用已重启。
