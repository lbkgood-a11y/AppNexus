# 业务流 Agent 助手规划

记录日期：2026-11-06

状态：已确认后续建设方向，暂未启动。必须在权限模块构建完成后，再推进详细设计与实施；不提前纳入当前权限模块交付范围。

## 建设目标与调用方式

建设全站统一的业务流 Agent 助手，让用户通过自然语言创建单据、查询业务资料和驱动业务流程。覆盖范围随业务模块逐步接入，不代表当前已具备全站执行能力。

CLI 是网页前端所使用的后端业务 API 的命令行客户端，与网页前端复用业务应用服务，不直接访问数据库或 Mapper。不以新增 AI Gateway 或 MCP 为启动前提，具体模型、协议与执行环境待启动后详细设计。

```text
用户自然语言 → Agent 理解、查询、补齐信息和编排
→ CLI 结构化业务命令 → 网页前端共用的业务 API
→ 业务应用服务、权限管线与业务状态机 → 数据库
```

## 规划能力

- 业务能力目录：描述各类单据的动作、参数、前置状态、权限及结果，供 Agent 发现和调用。
- 资料查询与消歧：将物料、仓库、客户、供应商等名称匹配为真实且有权限的对象；不凭空生成标识、价格或业务事实。缺项或歧义需要用户决策时发起询问，采用默认值时明确展示。
- 单据创建：生成结构化草稿，通过服务端校验后保存；支持后续提交、撤回、关闭等正式业务动作。
- 流程驱动：遵守服务端状态机和审批规则，通过正式关系和事件衔接跨单据流程，不直接修改状态字段。
- 持久化任务：保存执行步骤和结果，支持审批等待、暂停、失败恢复、幂等重试及会话中断后继续；跨步骤失败通过明确的补偿动作处理。
- 结果呈现：提供真实单据编号、状态、页面链接、执行记录和待办事项；仅在服务端确认成功后报告完成。

## 权限与执行约束

- 每步执行基于已验证的用户、租户与有效委托重新授权，复用操作权限、数据范围、字段权限、脱敏和统一 `AccessPlan` 管线。模型或 CLI 输入不构成可信身份来源。
- 异步继续执行时重新验证身份、成员状态、权限与委托有效性，不永久沿用发起时权限。用户发起流程不意味着 Agent 可以代替其他审批人批准。
- 自动执行范围、确认和审批按业务动作与风险定义，不要求全部动作重复确认。必要的确认绑定具体动作、单据内容与版本，内容变化后重新判断。
- 预校验不替代执行时校验；创建和提交时服务端重新检查业务规则、权限、状态与并发版本。写操作采用稳定幂等标识，避免重复调用或网络重试产生重复单据。
- 模型仅获得已授权且经过字段处理的数据；单据、附件和外部资料中的文字不能成为执行授权。审计不得记录敏感原值或凭据。
- 凭据由受控执行环境管理，不进入模型上下文。CLI 提供明确业务命令，不提供任意 SQL、Shell 或任意 URL 执行入口。

## 启动条件与实施顺序

前置条件是权限模块构建完成并通过相应验收，包含本规划依赖的操作授权、租户隔离、数据和字段权限、默认拒绝及权限变更后重新决策能力；以权限模块正式交付与验收基线为准。

权限模块完成后，先细化业务能力目录、CLI 契约、Agent 执行协议和持久化任务模型，再选择一条完整业务链试点，之后按统一规范扩展全站。采购申请、审批、采购订单、收货可作为候选链路；试点及批次在启动时结合业务模块成熟度确定。

业务模块接入应提供稳定 API 与 CLI 命令、结构化参数及错误、前置状态和权限声明、幂等语义、单据结果链接，以及长流程状态查询或事件通知。网页助手沿用现有 vue-pure-admin 与前端 UI 规范。

当前仅记录规划，不启动 Agent、CLI 或助手界面代码建设，不调整 MyBatis 技术选型。
