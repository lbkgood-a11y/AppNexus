# 授权中心主体角色实现与验收

日期：2026-11-09。范围为授权中心交接记录的第一项“主体角色前端页签”。

## 页面与组件

平台与租户授权中心在同一 `BusinessWorkspace` 中增加“主体角色”页签。采用左右详情模板的组织方式：左侧真实主体查询列表，右侧角色快照编辑及有效权限解释；1100px 以下转为上下排列。复用 `ManagementTable` 的刷新、密度、列配置、全屏及 Element Plus 表单、分页、确认和折叠面板，没有新增基础 UI 组件或 UI 库。`SubjectAuthorization.vue` 是这组领域操作的组合组件，现有通用表格不负责角色快照和权限解释，所以由该组件组合实现。

平台目录复用 `/bff/platform/users`，每页 20 条，由后端返回总数；租户目录复用 `/api/organization/domain/members`，在已受控的完整成员目录上做名称筛选及每页 20 条切片，不改变服务端租户边界。租户目录继续受原组织读取权限限制，不宣称任意角色管理员均可读取该目录。

角色目录逐页读取，避免只读取前 100 个角色造成已有分配丢失。停用角色不能新增，但已有停用角色可移除；不在目录中的原角色以“不可用的原角色”保留，不静默剔除。角色目录不是提交授权的权威，服务端仍校验目标管理域、启用状态和数量上限。

## 写入及错误约定

- 提交完整角色 ID 集合、读取所得 `authorityVersion`、1–500 字符的中文或英文原因。空集合表示撤销全部角色。
- 每次写入重新取得 CSRF；页面不保存 Token、密码或租户凭据。
- 保存前确认目标及覆盖、撤权后果，保存中禁止切换主体、编辑或重复提交。
- 主体切换和重新加载前保护草稿；页签通过 KeepAlive 保留编辑状态。
- 列表及详情使用请求序号丢弃过期响应；读取失败关闭写入口，不能使用其他主体的旧版本保存。
- 写入失败（包括 409）保留输入并关闭提交，需重新加载后再编辑；不盲目重试覆盖写。
- 写入成功后单独刷新权限解释，解释失败不会将写入报告为失败或自动重复提交。
- 权限解释展示稳定权限码、来源角色、生效状态、失效原因、范围类型与组织数量。它仅表示已保存角色贡献，不包含迁移期旧直授权，也不替代业务鉴权。

## 新增接口

`GET /api/access/members/{member}/effective-permissions`：从 `VerifiedTenantContext` 取得租户与操作者成员；先调用现有 `SubjectRoleManagement.memberRoles` 复核管理权与目标成员归属，再读取权限解释。客户端不能指定租户。无身份返回 401，无可信租户返回 409，普通成员返回 403，外租户成员返回稳定 404。响应沿用 no-store。
