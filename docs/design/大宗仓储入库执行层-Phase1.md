# 大宗仓储入库执行层 Phase 1

## 仓库现状和实施归属

现有后端基线为 Java 21、Spring Boot 4.1.2、MyBatis Spring Boot 4.1、MySQL 8.4 和 Flyway。前端沿用 Vue 3、TypeScript、vue-pure-admin 和 Element Plus。入库执行归属 `bulk-warehousing-service`。仓库、库区、库位、商品、规格、SKU、单位、换算和商品模板经主数据受控公开端口解析。

当前工作区 V181/V182 下线旧仓储单据。V182 删除旧入场接管、实收确认、质量放行等表，并先给 `bw_stock_receipt` 补齐库存查询维度。当前 Mapper 从保留库存账读取。本方案以 V182 已应用后的结构为前提，保留 `bw_inbound_notice`、`bw_inbound_notice_line` 和 `bw_stock_receipt`。存量库存、累计实收量和历史未知值按原语义保存。新增单据仅承接新发生的执行，存量库存无须补造车次、磅单、质检或入库单。

## 对象和关系

| 业务对象 | 物理表 | 粒度和职责 |
|---|---|---|
| CommodityTemplate | `bw_commodity_template` | 每行一个可发布版本。固定策略键、流程节点、表单 Schema、参数及库存粒度 |
| InboundTask | `bw_inbound_task` | 通知下的车次或等效到货作业单元。保留到场、队列和监卸结论 |
| QualityOrder | `bw_quality_order` | 每行一次检验版本，同车次最多一个现行版本，历史版本保留 |
| MeteringOrder | `bw_metering_order` | 同车次一张独立计量单，持有物理净重、理计、件数和证据 |
| ReceiptOrder | `bw_receipt_order`、`bw_receipt_order_line` | 同车次最多一张有效入库单。冲红后以新单号重开并链接原单。单头固定计量和适用的质检版本，明细按仓位批次或 LPN 分摊 |

本期假定同车次使用一套模板和一份质检口径。同车可以关联同一通知下的多个同口径品规行，明细以稳定 UUID 指向具体通知行。实际运输混装且需要不同质检口径时，拆成各自能独立采样和定量的作业单元。共享过磅证据时必须保留可核验的独立分摊，所有分摊量之和不得超过父证据定量。散货通常一行。钢铁每卷或每捆一行，单据内 LPN 唯一，过账时还要依据现有库存身份语义检查在库唯一性。

DDL 见 [六张核心表草案](大宗仓储入库执行层-Phase1.sql)。使用租户复合主外键约束跨租户错挂，入库单与计量、质检必须同作业，入库行与通知行必须同通知。独立业务编码按租户唯一，并接入统一发号。使用 `row_version` 处理并发编辑，质检 `version` 代表业务复检版本。队列索引按租户、节点、等待起点及 UUID 支持稳定游标，车次索引按通知追溯，三单拥有独立状态索引。批次和 LPN 是追溯查找入口，索引效果在真实范围策略和代表性数据上验证。

有牌车辆登记车牌，无牌农用车登记现场临时识别号，非车辆作业两者为空。一卡通以稳定介质 UUID 绑定作业，登记发卡及回收时间。租户内同卡只能同时绑定一个作业。现场临时号采用仓点分配的追踪编号，车次 UUID 为执行关联依据。

重量列统一为千克、`DECIMAL(18,4)`。库存基础单位数量和磅差比率保留各自精度。入库单显式记录物理净重、扣量和账面重量。纯理计时物理净重可空；质检引用可空，按发布模板和入库阶段校验。退车可以记录皮重等于或大于毛重的原始读数，正常实收必须验证正净重。

## 品类规则

| 品类 | 放行条件 | 计量和过账 |
|---|---|---|
| 玉米 | 可先过毛。皮重采集前须完成保管员监卸、确认无退车并核对现行质检版本合格，生成入库单及过账前再次校验。盲检只向对应操作投影样品条码和获准指标。复检在同一作业锁下切换现行版本 | 地磅净重等于毛重减皮重。受限公式计算扣水、扣杂，现场异常扣重单独留证，保留参数、公式版本、输入、舍入和输出快照。账面重量不得小于零。退车关闭作业且不入账 |
| 煤炭 | 采样登记后可过皮或确认外部净重，允许待化验暂估入账。继续追踪原作业、样品和已过账明细 | 支持地磅、轨道衡和水尺证据。热值、硫分等结果经可靠事件更新受影响批次的质量事实，保留原入账快照、重量、单号及审计。迟到或重复事件不得覆盖较新版本。化验完成不直接授予库存放行，依最终判定执行 |
| 钢铁 | 完成外观、质保书和炉批关联核验。照片保留受控附件引用 | 件/捆数和重量并行记录，可选实重或理计作入账依据。两种重量均存在时以（实重－理重）÷理重校验绝对磅差；缺少对照值时磅差为空，若模板要求双重量核验则阻断确认。不扣重，LPN 行汇总须与计量件数及选定重量口径相符 |

商品类目可提供默认模板，执行服务按租户和已配置的商品身份选择有权采用的已发布版本，创建作业时冻结版本。具体模板选取优先级和适用配置入口在 Phase 2 确定。仓储执行模板只编排作业，引用既有 QUALITY 和 SKU 批次模板定义字段；批次内容由仓储保存。策略和字段白名单在服务端解析，前端 Schema 仅渲染已授权字段。公式采用受限规则表达式，固定变量、单位和舍入，禁用任意脚本。WMS 保留物理净重、质量、扣重及账面量等事实，ERP 消费版本化快照独立完成价格和结算计算。

## 写入与库存边界

- 单据各自拥有操作准入和状态。已确认计量、已完成质检结果及已过账快照不可原地改写。过账前发生复检时重审放行，保留原过皮依据。过账后更正采用冲红补偿或追加新质量事实，原始重量和占用记录保留。冲红成功后释放有效单据槽位；重开按原作业重审并使用新单号。库内实盘差异由独立损溢单过账。
- 过账用同一事务复核来源通知行、批准额度、有效模板及三单状态，并写入入库单、行、通知累计量、库存账和审计。批准额度默认按换算后的库存基础单位入账量占用，物理实收单独保留。待检与可用库存采用现有库存账口径。新库存行拟以入库明细 UUID 作为 `bw_stock_receipt.receipt_id`，确保一次过账；历史来源可没有对应新行。已扣至零的物理收货走拒收或异常处置，禁止生成正入账库存行。
- 磅台读数、轨衡票据、水尺报告和质保书证据均要求可信来源、原始计量单位、时间和唯一事件身份。SQL 的 JSON 保存可追溯快照。跨单据防重、共享证据分摊、重复请求摘要以及确定批次身份所需的专用约束或关联表，在 Phase 2 按实际接入端口定稿。统一事务 Outbox 已有表结构，仓储业务发布端口及消费去重仍需确认。煤炭批次质量更新使用受控机器身份，仅更新事件关联的授权范围。

## 接入设计

新业务对象各自进入唯一 `BusinessObjects.Provider`。作业单归属到场、监卸、退车和工作台队列聚合查询。质检单归属采样、盲检读取、出具结论和复检；计量单归属过毛、过皮、外部导入、抄码和确认；入库单归属生成、明细维护、过账和后续更正。独立入口与工作台写入复用同一操作。模板管理归属模板对象，发布版本固定内容，停用影响新作业。

工作台自身无业务表。聚合结果按通知的仓库、货主及各对象准入、行范围和字段保护逐块投影。无法读取的卡片不返回记录及敏感事实，禁止借助汇总、进度或算账推断受保护值。队列标签和等待起点由实际作业状态维护，三张单的编辑状态基于服务端授权。后续复用现有管理端应用壳和 Element Plus。地磅读数、抓拍、抬杆、喊号和打印需在真实能力接通并授权后开放，打印采用平台统一契约。

状态机、策略契约及下一阶段接入见 [Phase 2 设计](大宗仓储入库执行层-Phase2.md)。Phase 3 接入真实授权、独立 API、聚合、过账与事件，Phase 4 实现工作台。
