# 前端 UI 与代码生成规范

版本：1.0；日期：2026-11-06；状态：当前系统的强制执行基线。

## 1. 目标与适用范围

统一不仅是颜色相同，还包括布局、组件、信息层级、操作语义、状态反馈、权限表达、响应式、无障碍和文案。本文用于新增、修改和审查前端代码；覆盖登录、后台、个人中心及未来领域模块。用户明确提出的需求优先，例外须在实现说明中记录原因和范围。

当前技术基线为 vue-pure-admin 7.0.0、Vue 3、Element Plus、Pinia、Vue Router，以及 Iconify/Remix Icon。遵循仓库锁文件，不因生成某个页面升级或引入另一套 UI 框架。

“必须”是交付要求；“默认”用于新页面，复用已有模板组件时以其既有规格为准，不为了套数值而改写上游布局。本文是后续生成基线，不表示历史页面已完成全部一致性审计。

## 2. 组件选型与代码归属

| 场景 | 必须优先使用 | 禁止事项 |
|---|---|---|
| 后台整体布局 | 当前 admin 应用壳、侧栏、顶部导航、标签页、面包屑 | 页面重复创建顶部栏、第二个全局侧栏或路由实例 |
| 同类业务交互 | 仓库已保留的模板增强组件 | 未检查现有能力就自绘同类控件 |
| 表单与校验 | el-form、el-form-item 和相应 Element Plus 输入组件 | 手绘输入框、独立错误样式、仅靠 placeholder 作标签 |
| 按钮、菜单、选项卡 | el-button、el-menu、el-tabs、el-dropdown | 用 div/span 点击模拟已有组件 |
| 弹出框 | 统一使用 `@appnexus/ui` 的 ManagedDialog；应用壳动态弹层使用 ReDialog | 使用 Drawer，或另写弹层定位、遮罩与焦点系统 |
| 列表与分页 | 当前可用的模板列表封装；否则 el-table、el-pagination | 为了使用已裁剪的示例而重新导入整套模板演示依赖 |
| 提示与状态 | 模板 message、el-alert、el-empty、el-skeleton、v-loading 等 | 自建 Toast 系统、以空白代替故障和空态 |
| 图标 | @appnexus/icons 的 AppIcon；模板内部继续使用既有 ReIcon | 新图标库、emoji 充当操作图标、业务深层导入模板组件 |
| 主题与语言 | ThemeToggle、模板主题入口与 i18n | 独立主题存储、重复语言实例、把身份信息写入展示偏好 |

只有现有组件确实不合适时才能新增。记录“需求、已检查组件、不适用原因、最小扩展、复用位置”；通常先组合而非重写。不存在的功能不提前建空包。

业务页面属于 frontend/modules/<领域>；启动和装配属于 apps/admin；与模板相关的适配当前在 admin 内，稳定公共能力按需提取到 infra。领域模块只能经公开入口使用跨包能力。个人中心当前属于应用壳自助设置页面，后续按领域规模调整时同步设计。

## 3. 视觉基础

| 项目 | 新页面默认标准 | 当前来源与约束 |
|---|---|---|
| 字体 | 继承全站中文无衬线字体，不另设字体 | src/style/reset.scss；不得页面级替换为衬线或装饰字体 |
| 正文/标签 | 14px，行高约 1.5–1.7；说明 12–13px | 优先 Element Plus 字号变量与组件默认值 |
| 页面标题 | 20–24px，字重 600；分组标题 16px | 一个页面只有一个主标题，不把所有字段加粗 |
| 颜色 | 主色、成功、警告、危险、文字、边框、背景分别使用语义变量 | --el-color-primary、--el-color-success/warning/danger、--el-text-color-*、--el-border-color-*、--el-bg-color/--el-fill-color-* |
| 主色 | 跟随全局配置及用户主题色 | platform-config.json 当前 EpThemeColor 为 #409EFF；业务 CSS 不复制该值 |
| 间距 | 以 4px 为步进，常用 8/12/16/24/32px | 同一排工具间距 8px，内容分组 24px；模板容器不覆盖 |
| 圆角 | 使用 --el-border-radius-base/small/round | 不给普通 CRUD 页面增加登录宣传页式大圆角 |
| 阴影 | 普通内容卡片优先无阴影、轻边框 | 弹层按模板默认，不滥用悬浮效果和渐变 |
| 密度 | 后台默认组件尺寸；登录或重要独立表单可 large | 同一行控件必须尺寸一致，不全站强制放大 |

颜色不能单独表达状态，必须配文字或图标。不得使用不随主题变化的白色页面背景和黑色正文覆盖变量。登录页的双栏插画是模板登录场景延伸，不作为列表、详情和设置页的通用视觉样式。

## 4. 页面布局范式

| 页面类型 | 固定组织方式 |
|---|---|
| 登录 | 独立页面；品牌、主题/语言入口、单一凭据表单；移动端隐藏非必要插画；保留标准 CSRF 表单和 BFF 流程 |
| 查询列表 | 标题/说明 → 筛选 → 主操作工具栏 → 表格 → 分页；新增按钮在固定工具栏位置 |
| 编辑/新建 | 标题 → 分组表单 → 保存/取消；编辑默认使用统一弹出框，内容过于复杂时使用独立页，不使用抽屉 |
| 详情 | 标题和状态 → 摘要 → 业务分组/标签 → 操作；只读字段不使用可编辑输入框伪装 |
| 个人中心 | 保留外层应用壳；内部账号摘要和分区菜单 → 右侧信息/偏好/账号安全；偏好即时生效，资料显式保存 |
| 错误页 | 模板 403/404/500 页面，给出返回或重试；不展示堆栈与内部路径 |

页宽服从模板“固定/自定义页宽”能力，页面不得用任意固定宽度破坏该设置。长表格在自己的容器内滚动；页面正文不得横向溢出。

## 5. 图标与操作语义

- 新业务图标统一 Remix Icon 线性风格，构建期生成本地 SVG。主导航保留模板既有填充图标，不因本规范一次性替换上游图标。
- AppIcon 默认 20px；正文/输入框 16–18px、工具栏 18–20px、空态或头像标记可 24–40px。同一区域保持一致，不拉伸宽高比例。
- 图标名称表达业务语义，如 user、lock、settings；同一操作全站使用同一图标，不混入另一套粗细或多彩图标。
- 图标按钮必须有可访问名称；不明确的操作加 Tooltip。装饰图标 aria-hidden，不重复朗读标签。
- 同一操作组原则上一个主要按钮；主操作 primary、一般操作 default、导航/轻操作 text 或 link、破坏性操作 danger。保存、取消位置保持一致。
- 删除、停用、撤销等动作说明对象和后果并确认；确认按钮使用具体动词，不使用含糊的“确定”替代危险动作。

## 6. 表单、表格与数据展示

- 普通业务表单使用 el-form 统一校验；凭据页允许原生 form 承载标准服务端 POST，但输入和按钮仍使用 Element Plus，不能改变安全流程。
- 短字段表单统一标签宽度（默认 100px，国际化长标签可增宽）；设置和移动表单采用顶部标签。同一表单不混用两种对齐方式。
- 必填标识由组件产生；说明写在字段旁，错误放在对应字段并定位首个错误。不把所有字段错误合并为一个 Toast。
- 控件类型匹配数据；选择用 Select/TreeSelect，日期用 DatePicker，开关只用于明确的二元状态。开关必须标明是否即时保存，失败回滚。
- 提交期间按钮 loading、防止重复提交；失败保留非敏感输入。密码不进日志、URL、持久存储；完成、取消或离开分区时清空。
- 校验前后端一致；前端校验用于体验，服务端为最终权威。长度、金额精度、日期时区必须有契约，不擅自转换业务语义。
- 表格左对齐文本，数值/金额右对齐；列宽、空值占位和操作列一致。默认空值显示“—”，0 不当作空值；长文本按需省略并可查看全文。
- 表格操作统一位置，主操作可见，次要操作放更多菜单。筛选更新重置页码；删除当前页最后一项后修正分页；默认分页参数服从 API 契约，不硬造总数。
- 时间、数字、币种经统一国际化规则格式化；金额不用浮点重算后端结果，标识按字符串处理。日期与时间点不得混淆。

## 7. 请求状态、错误与会话

每个读写功能必须明确：首次加载、刷新、无数据、筛选无结果、错误、无权限、保存中、成功。已有内容刷新不闪成空白；失败提供可执行的重试入口，不能显示成功假数据。

| 结果 | 统一处理 |
|---|---|
| 401 | 使用现有 sessionLifecycle 清理展示状态、菜单与标签，回登录页给出失效原因；不循环重定向 |
| 403 | 提示权限或安全凭据问题，不能伪装成空数据或重试至成功 |
| 409 | 提示数据/凭据已变化；需要时引导重新加载，不盲目覆盖 |
| 429 | 提示频繁操作，按 Retry-After 提供等待语义，不自动连续重试写请求 |
| 网络/5xx | 保留页面与安全的用户输入，提示服务不可用并提供重试，不自动注销 |
| 字段错误 | 映射稳定业务码/字段错误并在字段旁展示，不依赖翻译后句子判断结果 |
| 成功 | 一次操作一次适当反馈；刷新受影响内容，不重复 Toast/弹窗 |

现有入口为 utils/http、api/session 和 utils/sessionLifecycle，新增页面复用这些能力。安全配置、Cookie、CSRF 和真实认证协议不得因 UI 统一而退回模板模拟 Token 方案。

跨业务穿透导航统一使用应用内上下文切换：服务端上下文更新成功后，清理受影响的标签与页面缓存，通过 Vue Router 定位目标菜单并重建内容区；禁止用 `window.location.reload` 代替内容刷新。目标路由不同则直接导航，目标相同则通过模板 redirect 路由中转重建组件。OAuth 登录等必须离开 SPA 的协议跳转不受此限制。

## 8. 权限与功能真实性

- 菜单/按钮可见性只改善体验，所有接口权限、租户和数据边界由后端校验。登录不自动产生角色或管理员业务权限。
- 无权限字段的原值不得先到浏览器再隐藏；禁用、隐藏、脱敏由业务契约决定，不自行猜测。
- 只提供已接通的功能。个人中心当前不提供模拟安全日志、无后端头像上传和未经验证的联系方式绑定；偏好不提供未接入通知系统的开关。
- 默认账号 UUID 不作为主要业务文案，放次级只读信息；生产页面不显示框架版本、数据库配置或内部调试信息。

## 9. 主题、国际化、响应式与无障碍

- 浅色/深色/跟随系统共用模板主题状态；ThemeToggle 是已有主题能力的薄适配。状态提示、图标、输入、禁用、悬浮、弹层均需验证深色模式。
- 用户可见文案进入 zh-CN.yaml/en.yaml；错误优先通过稳定码映射语言，不以中文字符串判断业务。英文变长不得截断必要操作。
- 验收视口至少包括桌面 1440×900、窄屏 1024×768、手机 390×844；移动端主要触控区域尽量达到 44×44px，小按钮通过容器扩大命中区。
- 窄屏多列表单转单列；内部导航可折行/切换为适合窄屏的布局；页面无横向溢出。不能简单隐藏核心功能来通过响应式检查。
- 使用语义标题、真实标签、按钮和链接；支持 Tab、Enter、Space 操作及可见焦点。弹窗复用组件的焦点管理，不手动破坏焦点恢复。
- 正文对比度以 WCAG AA 为目标（普通文字至少 4.5:1，大字至少 3:1），重要状态不能仅靠颜色；动画尊重 reduced-motion。

## 10. 生成代码的固定流程

1. 阅读 AGENTS.md、本文、对应领域/API 设计，并检查仓库现有相似页面及可用模板组件。
2. 明确页面类型、路由和权限、字段契约、组件选型、交互及状态；资料不全时优先检查代码与契约，不编造 API。
3. 实现最小可用功能，使用模板组件及主题变量；跨包只用公开入口，中文注释遵守仓库规则。
4. 有自定义组件时记录理由；新增配置须说明用途、单位、默认值、环境和安全影响。严格 JSON 的参数说明写入配套文档，不破坏语法。
5. 完成类型检查、构建和适当功能测试；浏览器验证主流程、错误、主题与响应式。使用独立测试账号，不修改现有管理员凭据。
6. 同步设计文档与验收证据，清理测试数据。未验证项明确列出，不用“构建成功”代替界面验收。

可复用的生成任务约束：

> 按 AGENTS.md 和《前端 UI 与代码生成规范》实现本功能。先检查当前 vue-pure-admin 相似页面与已保留组件，优先模板增强组件，其次 Element Plus；不得引入其他 UI/图标体系。复用应用壳、@appnexus/icons、主题与 i18n、HTTP/CSRF/会话入口。覆盖加载/空态/错误/权限/提交状态，保持中英文、深浅主题及移动端一致。重要参数中文注释。完成类型检查、构建、浏览器主流程和错误验证；如必须新增组件，记录现有组件不适用的原因，并同步文档。

## 11. 交付门槛

- 组件与模板同类页面一致，无平行布局、主题或图标体系；例外有明确记录。
- 页面层级、间距、按钮语义和表单/表格对齐一致，无未接通入口或模拟业务数据。
- 加载、空态、字段错误、权限、冲突、服务故障和提交反馈齐全，密码等敏感信息不落入浏览器存储或日志。
- 键盘可操作、标签可识别、焦点可见，桌面/窄屏/手机无正文溢出，深浅主题及英文可读。
- 前端 typecheck/build 通过；重要流程有真实浏览器证据；影响接口或权限的变更有相应后端验证。
- 本文作为人工及代码生成审查门槛；目前未实现自动 UI 一致性 lint，不宣称全部要求已经自动执行。

顶部快捷入口统一规范：主题与语言均使用 Element Plus Dropdown + text Button，18px 图标、40×48px 点击区域，无胶囊分组、常驻底色或阴影。当前主题用单一图标表达，点击菜单选择浅色/深色/系统；登录页与三种后台导航使用同一组件。设置页需要快捷主题入口时也使用相同组件。

内容容器一致性：普通内容页及个人中心外框统一使用 el-card shadow=never，保留组件的边框与圆角；页面外边距由模板 main-content 的 24px 统一提供，页面不得另设外框圆角或重复外边距。个人中心仅覆盖卡片 body 的内部排布与 padding，不覆盖外框视觉。验收须对比相邻路由的内容左上角坐标、边框和圆角。

登录页同样遵循全站基础圆角：外框使用 --el-border-radius-base、无额外阴影，输入框与按钮不覆盖组件原生圆角；不得将独立登录场景解释成允许 28px 外框或 9px 控件圆角。移动端全宽无外框时可取消外框边界。

## 12. 已确认的内容区参考模板与选用规则

用户提供的三个 pure-admin 页面参考确认为后续管理页面的内容布局基线。新增或改造页面必须根据管理对象与任务选择以下模板，沿用当前 pure-admin、Element Plus 组件和交互；不得仅因视觉偏好重新组织一套布局。

| 模板 | 适用场景 | 内容组织与选择依据 |
|---|---|---|
| 标准列表（系统日志参考） | 用户、租户、日志等平面数据的查询和维护 | 顶部独立筛选容器；下方数据容器按工具栏、表格、底部分页组织。不需要层级导航时优先采用。 |
| 左树右表（部门与用户参考） | 先选择组织或分类，再管理其关联成员或其他数据 | 左侧独立树容器提供树内搜索和展开、收起；右侧上方为筛选区，下方为数据区。选中节点明确限定右侧查询范围，筛选重置默认保留当前节点，查询重置页码。 |
| 树形表格（菜单管理参考） | 维护具有真实父子关系的对象，同时比较其多列属性 | 首列缩进并支持节点展开、收起，其余属性按列对齐；对象操作固定在操作列。新增下级等动作仅在真实业务契约支持时提供。完整树不得直接按普通行分页而拆散父子关系。 |

### 12.1 共用布局与操作约束

- 所有业务页面先定义 `BusinessWorkspace` 的业务身份，再组织导航、查询和数据/详情区。标准列表、左树右表、租户选择和个人中心不在内容区重复应用壳已经表达的面包屑、页面标题与描述，直接进入业务工作区；`PageHeader` 仅用于详情、创建、编辑等需要对象标题、状态或页面级操作的场景。只有下级对象上下文才在工作区显示对象名称与状态。属于同一对象的 Tab、SearchPanel、DataPanel 必须共享一个工作区表面与外边界，内部用背景层次、间距和轻分隔线表达层级；不得表现为三个互不关联的卡片。
- 业务导航位于工作区顶部；切换后工作区说明、查询标题、列表标题、数据、主操作和状态必须同步。查询标题应体现对象，如“租户查询”，不能只写无归属的“查询条件”。
- 工作区内部嵌入公共表格时使用无重复卡片边界的模式；弹出框或全屏仍保留独立表面。全站禁止业务抽屉；弹出框统一使用浅色标题栏、最大化和关闭图标，普通状态沿用 Element Plus 初始打开位置且不得在打开动画后进行二次定位，并允许拖动标题栏移动；最大化占据完整浏览器视口并覆盖应用壳。桌面端允许右下角手动调节宽高，普通状态下移动与调节不得把标题栏或关闭按钮移出内容区，移动端自动适配视口。该原则同样适用于左树右表、上下联动、详情表单、左右详情、Tab 详情、卡片网格和数据概览。

- 筛选区与数据区分为两个清晰容器；筛选条件左对齐，“查询 / 重置”按钮组统一靠筛选区右侧。窄屏换行后按钮组仍在可用行内右对齐，不隐藏必要条件和操作。
- 数据区工具栏左侧显示列表或任务标题，右侧依次放业务主操作、刷新、密度、列设置、全屏。避免在内容顶部重复大标题、长说明与相同列表标题。
- 调整布局不得减少已有业务操作或表格工具能力。原有新增、编辑、删除、成员管理、授权等入口按对象归属保留；权限校验、危险操作确认及真实接口契约保持有效。
- 刷新、密度、列设置、全屏作为表格工具标准能力，优先复用当前模板组件。列设置按模板支持列显隐、排序、固定和重置；已存在的能力不得在改版时丢失，尚未接入的能力必须实现后才展示有效入口，不以无响应按钮交付。
- 分页放在数据容器底部右侧，顺序与模板一致。桌面列表数据区可撑满可用高度，表格滚动与底部分页配合；移动端按内容自然排列，不以固定高度造成遮挡或正文横向溢出。
- 左树用于选择右侧数据范围，树形表格用于维护层级对象自身，二者不得混淆。仅有平面组织接口时不得编造层级、父子关系或新增下级能力。
- 实现前在对应前端设计说明中记录选用模板及业务理由；验收同时检查布局、查询按钮右对齐、完整业务操作、表格工具、请求状态、主题、国际化及响应式。
