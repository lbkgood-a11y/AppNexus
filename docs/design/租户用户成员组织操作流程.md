# 租户、用户、成员与组织操作流程

日期：2026-11-06。本次实现提供平台目录、租户开通、成员关联、主要组织归属与组织能力授权的完整操作链路；不代表完整组织树、岗位、任职、多组织关系、角色继承或字段权限已实现。

## 1. 对象与责任

| 对象 | 作用域与职责 | 操作入口 |
|---|---|---|
| 用户 | 全局登录账号；可以属于零个、一个或多个租户 | 平台管理 → 用户 |
| 租户 | 业务数据隔离边界，停用后禁止进入 | 平台管理 → 租户 |
| 租户成员 | 账号与租户的关联，是进入租户的前置条件，本身不授予组织操作权限 | 租户列表 → 成员管理 |
| 组织 | 租户内组织单元，当前为平面结构 | 组织管理 → 新建/重命名/删除 |
| 主要组织归属 | 成员与同租户组织单元的关联，与操作权限分离 | 组织管理 → 成员授权 → 主要组织归属 |
| 组织授权 | READ/CREATE/UPDATE/DELETE 能力及有效期；GRANT 只由受控初始化建立 | 组织管理 → 成员授权 |

平台管理员只管理账号、租户目录及成员关联；不能以平台身份读取租户业务数据。租户首位管理员具有该租户的组织 CRUD 与 GRANT，不能访问其他租户。全局账号停用、租户停用、成员停用分别校验。

## 2. 首次配置与日常流程

1. 首次部署设置 `APP_BOOTSTRAP_USERNAME=admin` 和随机的 `APP_BOOTSTRAP_PASSWORD`。认证引导先创建登录账号，平台引导随后为同一账号建立平台管理员身份并审计；任一步失败都会阻止应用完成启动。配置默认为空，不按固定用户名对存量账号自动赋权；成功后从持续部署配置移除用户名引导参数，密码由 Secret 管理且必须按首次登录策略轮换。
2. 平台管理员登录：无租户资格时直接进入平台管理，不再陷入只能联系管理员的选择租户空态。
3. 在“用户”创建其他账号：登录名 1–100 位 ASCII 字母/数字/`._@-`，首位字母或数字；名称 1–100 UTF-16 字符；初始密码 12–128 字符，仅请求内存处理并以 Argon2id 哈希入库。密码交付需组织自己的可信渠道，系统不生成或展示明文密码列表。
4. 在“租户”创建租户，明确选择首位管理员账号。单个事务原子创建租户、首位成员、五项组织能力、一次性初始化记录和审计。请求 UUID 用于网络重试幂等；同 ID 不同参数拒绝，不将平台操作者自动加入租户。
5. 从该租户“成员管理”添加现有用户，仅建立成员关系，默认无业务能力。重复添加拒绝；停用成员需显式恢复，不能用重复添加绕过历史权限治理。
6. 首位管理员登录：恰有一个可访问租户时自动进入，隐藏选择界面和顶栏切换控件。多个可访问租户时先选择，之后顶栏显示当前租户及切换菜单。平台管理中的“进入组织管理”也必须经过真实成员验证，不是模拟租户用户。
7. 创建组织，在成员授权区为成员设置主要组织，再显式授权。归属组织不产生操作权限；组织有归属成员时拒绝删除，须先解除关联。当前主要组织不代表岗位或复杂任职模型。
8. 停用账号/租户/成员使用确认与明确状态提交，不删除业务数据。成员停用会撤销组织权限，恢复成员不恢复旧授权。平台管理员账号与持有有效 GRANT 的账号/成员受保护，普通停用入口不能绕过其运维治理。

| 配置项 | 默认、约束与影响 |
|---|---|
| APP_BOOTSTRAP_USERNAME | 默认空。首次部署设置为 `admin`，与初始化密码共同创建首个登录账号并同步授予平台身份；已有初始化记录时不会创建、重置账号或恢复已撤销权限。 |
| APP_BOOTSTRAP_PASSWORD | 默认空。由 Secret Manager 生成和注入的随机初始密码，至少 12 个字符；不得写入镜像、仓库、日志或普通配置文件。 |

本地初始化脚本对全新数据库默认生成 `admin` 及随机密码，并将同一账号同步初始化为平台管理员。已有数据库不会因脚本默认值增加账号、重置密码或改变平台权限；存量环境必须通过受控迁移或已有平台管理员治理流程处理。

## 3. 租户选择交互规则

| 本人有效成员资格 | 登录行为 | 顶栏 |
|---|---|---|
| 0，且是平台管理员 | 平台管理；可创建租户并指定首位管理员 | 不显示切换控件 |
| 0，普通用户 | 清晰无资格状态、重试，提示联系平台管理员 | 不显示切换控件 |
| 1 | 服务端验证后自动选择，直接进入业务 | 隐藏选择/切换控件 |
| 多个，尚未选择 | 展示本人租户列表 | 显示选择入口 |
| 多个，已有当前租户 | 恢复有效会话上下文 | 当前租户 + 下拉切换 |

“全局只有一个租户”仍不意味着任何账号都是该租户成员。单租户系统中，有资格账号自然符合“本人恰有一个有效租户”；无资格账号依然默认拒绝。前端不读取全局租户总数来判断资格，也不泄露其他租户目录。

切换先确认未保存内容会丢失；同标签在途业务写入未完成时拒绝切换；成功轮换会话 ID、增加上下文版本、清理标签缓存并整页重载。同源 BroadcastChannel 只通知重读上下文，不发送身份或凭据。其他标签焦点恢复复核版本，业务请求携带旧版本时服务端 409 拒绝。切换后版本大于 1 的业务写入缺少版本头也拒绝。请求头不能选择租户，服务端会话与有效成员才是权威边界。

## 4. 借鉴来源

本次读取官方文档（2026-11-06）：

- [Auth0 Organizations 登录流程](https://auth0.com/docs/manage-users/organizations/login-flows-for-organizations)：多组织 Business Users 在登录后进入 Organization Picker。借鉴“先认证，再从本人组织范围选择”，未采用自动成员资格或邮箱域自动加入。
- [Azure Portal 设置：Directories + subscriptions](https://learn.microsoft.com/en-us/azure/azure-portal/set-preferences)：展示 Current directory，只列可访问目录，并提供 Switch；支持独立启动目录偏好。借鉴当前上下文可见和显式切换，本次不新增持久默认租户偏好。
- [Microsoft Entra 创建租户](https://learn.microsoft.com/en-us/entra/fundamentals/create-new-tenant)：租户创建是独立管理流程并受权限约束。借鉴开通入口与普通业务上下文区分，不照搬 Azure 订阅或付费规则。

## 5. 前端复用与参数说明

组织领域页面优化（2026-11-08）：组织管理采用“组织架构 / 任职管理 / 组织关系 / 组织类型”四个任务入口。默认组织架构使用 `BusinessWorkspace` 内嵌 `TreeListTemplate`，先选择组织类型树，再从左侧组织树确定右侧岗位、任职、负责人及关联关系的共同上下文；这是因为组织类型定义独立树边界，而岗位、任职和负责人均依赖具体组织。任职管理提供跨组织反向查询，组织关系与组织类型作为低频治理列表独立呈现。表格继续复用 `ManagementTable` 的刷新、密度、列设置和全屏能力，写入继续使用 `ManagedDialog`；现有组件足以覆盖需求，因此未新增自定义公共组件或 UI 库。

关系类型改为使用 `organization_relation_type` 字典选项，不再允许自由文本；负责人只从当前组织岗位的有效任职中选择。结束任职、取消负责人、删除关系及停用组织均提供明确后果和确认。该页面重组不改变后端 API、租户隔离、能力校验和并发版本契约。

已检查模板租户页、个人中心、ReDialog、导航及 Element Plus。列表/分页/表单采用 Element Plus，业务弹层统一使用 `ManagedDialog`，不使用抽屉；新 TenantSwitch 只是 Dropdown + text Button 的组合适配，三种模板导航共同复用，原因是原模板没有服务端租户上下文控件。没有新 UI 库或主题体系。业务平台页在 modules/tenant，宿主注入公开 API；平台页不依赖模板内部实现。

管理入口拆分增量（2026-11-08）：平台用户与租户已分别使用 `/platform/users` 和 `/platform/tenants`，不再在同一页面以 Tab 切换两种安全影响不同的对象。旧 `/platform/manage` 仅作隐藏兼容重定向；无租户平台管理员默认进入租户管理。租户成员仍是租户管理的下级上下文，不归入全局用户管理。

本次仍选用“标准列表”模板，复用 `BusinessWorkspace`、`ManagementTable`、`ManagedDialog` 及 Element Plus；路由入口通过 `section` 固定管理对象。现有组件已能覆盖加载、筛选、分页、写入、错误和空态，因此不新建平行表格、弹层或主题组件。

用户资料增量（2026-11-08）：用户列表和创建/编辑表单增加邮箱、E.164 手机号及各自验证状态。登录名在资料编辑中不可修改；联系方式变更会重置验证状态。本增量只完成资料维护，不宣称已支持邮箱/手机号登录、验证码或找回密码；这些能力需独立的验证与登录识别符流程。

严格 JSON package.json 的新增入口在此说明：`@appnexus/tenant/administration` 导出目录类型与请求端口；`@appnexus/tenant/management` 导出平台管理组合页面。vue、vue-i18n、element-plus peerDependencies 复用宿主现有实例；admin workspace 依赖仅连接本地模块。

API 分页默认第 1 页、20 条，每页 1–100；筛选最长 100 字符。成员目录只返回必要账号摘要，不返回哈希、Token 或其他租户业务内容。变更采用 CSRF，服务端复核平台身份并原子追加审计；业务接口仍受租户过滤器与组织能力门禁。
