# 角色管理详细设计

版本：1.0；日期：2026-11-08；状态：已确认、待实现。

## 1. 范围

本期只交付平台角色与租户角色的查询、创建、编辑、启停、逻辑删除、乐观锁和审计，不交付用户角色绑定、菜单授权、数据权限、角色继承或用户直授权。页面不得展示未接通入口。

角色管理是访问控制领域的独立能力。现有平台管理员负责平台角色及平台代管租户角色；现有租户管理权威源负责当前租户角色。后续 RBAC 上线时替换集中式入口鉴权策略，不改变角色生命周期。

## 2. 模型与约束

- `scope_type` 为 `PLATFORM` 或 `TENANT`；平台角色的 `tenant_id` 必须为空，租户角色必须具有不可变租户标识。
- `role_type` 为 `SYSTEM` 或 `CUSTOM`。系统角色必须具有全局唯一且不可变的 `system_key`，自定义角色不得具有该字段。
- `code` 长度 2–64，只允许以小写字母开头的小写字母、数字和下划线；创建后不可修改。`sys_` 为系统角色保留前缀。
- 平台域内编码唯一，租户域内编码唯一。逻辑删除后编码永久保留。
- `status` 为 `ENABLED` 或 `DISABLED`。删除前必须禁用；系统角色禁止删除，受保护系统角色禁止禁用。
- `name` 长度 1–100，`description` 最长 500，`sort_order` 范围 0–9999、默认 100。
- 更新、启停和删除携带从 0 开始的 `version`；条件更新失败返回冲突，不静默覆盖。

MySQL 8.4 使用应用侧 UUIDv7、`BINARY(16)` 存储。为避免 MySQL 唯一索引允许多个 `NULL`，表中使用生成列 `scope_owner_id`：平台域映射为全零 UUID，租户域映射为真实 `tenant_id`，并建立 `(scope_owner_id, code)` 唯一索引。正常 UUIDv7 和租户标识禁止使用全零 UUID。

## 3. 生命周期

合法转换为 `ENABLED -> DISABLED -> ENABLED`。禁用原因必填，启用原因可选；同状态请求在版本仍为当前值时幂等成功且不追加审计。删除请求必须同时满足：自定义角色、已禁用、确认编码完全一致、删除原因非空、无成员或授权引用。删除记录 `deleted_at/deleted_by/delete_reason`，不物理删除。

第一期预置且保护 `PLATFORM_SUPER_ADMIN` 与每租户 `TENANT_ADMIN`；系统语义只依据 `system_key`，不得依据显示名称、普通编码或固定数据库 ID。

## 4. API

- 平台角色：`/bff/platform/roles`
- 平台代管租户角色：`/bff/platform/tenants/{tenantId}/roles`
- 当前租户角色：`/api/access/roles`；使用现有 `/api/*` 可信租户上下文和上下文版本保护。

每组提供分页查询、详情、创建、编辑、状态变更和删除操作。租户接口不接受客户端 `tenantId`；平台代管接口同时以路径租户和角色归属限定所有 SQL。创建请求不接受 `scopeType/tenantId/roleType/systemKey/status`，编辑请求不接受编码与安全字段。

分页默认 20、最大 100；关键词匹配名称和编码；状态、角色类型为可选枚举筛选；排序字段采用服务端白名单。默认按 `sort_order ASC, created_at DESC, id DESC`。

稳定错误码至少包括 `ROLE_CODE_ALREADY_EXISTS`、`ROLE_VERSION_CONFLICT`、`ROLE_SYSTEM_DELETE_FORBIDDEN`、`ROLE_SYSTEM_DISABLE_FORBIDDEN`、`ROLE_NOT_DISABLED`、`ROLE_CONFIRMATION_MISMATCH`、`ROLE_IN_USE`、`INVALID_ROLE_INPUT` 和 `ROLE_SCOPE_NOT_FOUND`。跨域目标统一按不存在处理，不泄漏其他租户数据。

## 5. 持久化与事务

平台角色、当前租户角色、平台代管租户角色使用分离的仓储入口，禁止 Controller 选择 Mapper，禁止通过通用 `scopeType` 参数切换安全边界。每条租户 SQL必须包含可信 `tenant_id` 与 `scope_type='TENANT'`；平台角色 SQL固定 `scope_type='PLATFORM' AND tenant_id IS NULL`。

角色变更与追加式 `access_role_audit` 在同一本地事务提交。审计包含角色、管理域、操作者、操作、原因、必要前后快照、时间与请求追踪标识；不保存凭据或 Token。审计失败时业务变更回滚，失败请求不得记录为成功。

## 6. 前端

页面采用《前端 UI 与代码生成规范》的标准列表模板，复用 `BusinessWorkspace`、`ManagementTable`、`ManagedDialog`、Element Plus 和 `@appnexus/icons`，不新增 UI 组件库。查询条件为关键词、状态和角色类型；表格展示名称、编码、类型、状态、描述、排序、更新时间和操作。

新增和编辑使用统一弹窗；编码在编辑时以只读文本展示。启停弹窗收集原因。删除弹窗要求输入完整角色编码和删除原因。操作可用性由后端返回的动作能力与原因码改善展示，后端执行时仍重新校验。覆盖加载、刷新、空态、无结果、无权限、冲突、服务故障和提交状态；提供中英文、深浅主题及桌面、窄屏、手机适配。

## 7. 验收

领域测试覆盖编码、不可变字段、系统角色保护和生命周期。真实 MySQL 8.4 测试覆盖生成列唯一性、逻辑删除后编码保留、乐观锁及审计回滚。使用 A/B 租户相同角色 ID 验证查询、编辑、启停和删除隔离，并验证缺少租户上下文时失败关闭。HTTP 测试覆盖认证、CSRF、字段白名单、分页、重复编码和并发冲突。

前端完成组件测试、类型检查和生产构建；真实浏览器验证三类入口、并发冲突、系统角色保护、中英文、深浅主题、1440×900、1024×768 和 390×844。未通过真实接口验证的场景不得标记为完成。
