# 单据工作台初步设计

日期：2026-11-12。

成熟度：产品边界已确认；本文中的模型、执行约定和分期属于设计草案，尚未实施，不作为已交付能力。接口、数据库结构及工程归属待后续详细设计。

后续细化见[单据类型与行为契约详细设计](单据类型与行为契约详细设计.md)，覆盖版本、投影、执行器、租户覆盖、流程及打印绑定、幂等与请假迁移；仍为待评审草案。

架构修订（2026-11-12）：单据模块已确认为能力配置与关联中心，不承接业务行为执行；下文公共行为执行记录及协调职责由实际业务/专业服务拥有，单据模块仅保存配置与关联投影。平台决定单据目录并授予租户配置范围，租户在授权内维护通用服务关系。统一后端契约见[单据服务集成契约设计](单据服务集成契约设计.md)。

## 1. 已确认的定位

建设单据工作台，用于登记业务单据类型，配置单据对象与流程契约、打印对象、权限及其他操作的关联。单据行为可以连接背后的工作流与打印能力。

业务模块通过代码提供单据结构、业务页面、专业规则与受控动作；工作台配置已声明能力的运行关系。本期不建设动态建表、表单拖拽、自动 CRUD、用户脚本或通用动作编排平台。

沿用《平台总体设计》“单据中心与业务服务边界”：业务服务是单据内容和业务状态的权威来源，公共层保存契约、配置、索引及关联。功能管理与单据工作台职责区分已确认，界面整合程度待细化。

## 2. 三个入口的职责

| 入口 | 使用对象 | 职责 |
| --- | --- | --- |
| 单据工作台 | 接入开发者、获授权的配置人员 | 查看代码登记契约，配置行为与流程、打印、权限的关联，校验并发布 |
| 单据中心 | 业务人员 | 查询有权访问的单据实例，进入业务详情，查看生命周期及关联任务；后续建设 |
| 业务单据页面 | 业务人员 | 由业务模块提供录入、专业校验和业务操作，通过统一行为执行约定接入公共能力 |

工作台发布权不自动授予查看业务原文、审批或打印权限。单据中心查询索引不是访问业务详情的授权凭证。

## 3. 概念模型草案

| 概念 | 关键内容 | 权威来源 |
| --- | --- | --- |
| 单据类型 DocumentType | 稳定类型编码、名称、所属模块、受控详情入口、支持状态与行为 | 业务代码登记 |
| 单据引用 DocumentReference | 租户、类型编码、对象 ID；调用时附带所需业务版本 | 可信上下文和业务存储 |
| 单据契约 DocumentContract | 契约版本、稳定字段标识、类型、用途、敏感性、能力提供器标识 | 业务代码登记 |
| 行为声明 ActionDescriptor | 行为编码、用户或系统触发、权限引用、输入契约、执行器及幂等约定 | 业务代码登记 |
| 行为配置 ActionConfiguration | 是否启用、已声明条件、流程用途绑定或打印场景引用 | 租户配置并发布 |
| 单据能力配置版本 | 契约依赖、行为配置、流程与打印引用、发布人及审计原因 | 工作台发布 |
| 执行记录 ActionExecution | 单据引用、行为、请求键、配置版本、结果及流程/打印关联 | 执行端持久化 |

对象 ID 与业务单号分离；业务单号用于展示和检索，不作为跨能力唯一键。对象版本用于并发控制，审批依据版本用于检测审批基础变化，二者不能未经约定混用。单据内容不集中复制到公共表。

同一单据可有多个用途的流程关联、多次历史审批和多个打印任务。具体关联须保存用途、实例或任务 ID、版本及执行记录，不能只在单据上设置一个通用 workflowId 或 printJobId。

## 4. 契约与可配置范围

通用身份共用，流程依据、打印数据、列表摘要分别声明投影契约。字段在不同投影中可有不同授权与敏感性约束；不能因注册到单据目录便向所有渠道开放。

| 业务代码声明 | 管理界面可配置 |
| --- | --- |
| 类型编码、适配器、字段类型、合法状态及业务动作 | 名称覆盖、启用状态及受控选项，具体覆盖范围待定 |
| 哪些字段可用于条件、哪些数据可用于打印 | 从已声明字段选条件，从兼容打印场景选绑定 |
| 行为输入、权限资源、执行方式、强制业务限制 | 引用现有权限资源，收紧可执行条件与选择绑定 |
| 允许的流程终态处理动作 | 将流程结果关联到已声明的结果处理动作 |

配置不得新增任意接口地址、Java 类名、SQL、脚本、任意字段路径或绕过业务状态机的状态写入。条件配置只能收紧业务允许范围，不能放开代码强制约束。

## 5. 单据行为与执行约定

| 行为示例 | 触发方 | 执行责任 |
| --- | --- | --- |
| 提交 | 用户 | 业务校验与冻结依据，解析绑定，发起流程并建立关联 |
| 撤回 | 用户 | 业务校验与流程允许性检查，请求撤回，可靠结果交付后改变业务终态 |
| 打印 | 用户或明确授权的系统事件 | 校验数据与打印权限，由业务提供器取数，交给现有打印场景处理 |
| 批准、驳回结果处理 | 可信工作流交付 | 复核实例、依据版本及终态，以稳定调用 ID 幂等执行业务动作 |
| 作废 | 用户 | 业务服务校验合法状态与关联流程约束，执行自身状态机 |

行为采用预定义执行类别及受控业务动作，不提供任意步骤拖拽编排。按钮是行为的展示入口，系统回调行为不生成普通用户可调用的按钮。

执行前服务端复核可信租户、有效身份、功能权限、记录范围、字段限制、对象版本和业务状态。可执行操作查询用于界面提示，不能替代执行时鉴权；自动打印也不得继承配置人的数据权限。

幂等键至少限定在租户、单据、行为和请求键范围，同键异参数拒绝。配置解析结果首次执行后固定，重试不重新选择流程或模板。单据状态、流程状态、结果交付状态和打印状态分别保存；打印任务创建成功不代表实体出纸成功，流程结束不代表业务结果已回写。

### 一致性边界

同库、同事务管理器的提交与流程创建可沿用当前 POC 原子事务。跨服务时必须单独设计提交中状态、事务 Outbox、关联幂等、失败恢复与对账，不能把本机原子性假设扩展到远程调用。终态结果沿用可靠交付机制，失败可重试或人工恢复，不直接改业务库修复状态。

流程批准后自动打印属于业务成功事件触发的独立行为；默认不启用，启用后应在业务结果成功提交后投递。打印失败不得撤销已完成的审批或伪造业务失败。

## 6. 复用现有功能、流程与打印

### 功能与权限

功能目录继续维护页面、操作码及授权资源；单据行为引用已有操作码，不建立第二套角色授权表。普通系统设置、查询页等无需成为单据。工作台可关联已有功能入口，功能详情可反向跳转单据配置。正式单据需独立业务权限，不能长期沿用请假 POC 的 workflow:start 代替单据提交权限。

任务临时授权沿用工作流任务边界，仅限当前任务所需对象、字段和操作，仍受租户、强制限制和业务校验约束。现有字段脱敏不自动覆盖打印文件流，打印提供器必须接入同一授权与字段处理约定。

### 工作流

现有 WorkflowBusiness 同时承载业务元数据、可信快照及动作执行。建议逐步将通用单据描述提取为独立契约；工作流仍保留自身快照和调用约定，通过适配引用单据目录，兼容旧能力注册。

绑定以单据类型、用途、触发行为及受控条件确定流程。流程匹配要求恰好一条，不采用打印规则的优先级回退语义。要求审批的行为未命中或多重命中时拒绝，不静默跳过审批。

当前 WorkflowRuntime.start 按已发布模型自行匹配；若工作台提供显式流程绑定，需要扩展可信启动契约，由服务端解析并固定实际定义及发布版本。不能只新增配置页面而让运行时继续忽略绑定。第一阶段建议发布时引用具体流程版本，新版本须重新校验发布绑定，历史实例保持原版本。

### 打印

单据打印行为引用现有打印场景及兼容的数据提供器，不另建模板选择和打印队列。模板、数据契约、设备授权、预览确认及任务执行继续归打印服务。

现有场景绑定单模板；《打印场景与模板匹配规则》的多模板规则仍为待实现方向，工作台不可提前宣称已具备。后续场景按优先级匹配并默认回退，继续由打印服务负责。任务创建时固定实际场景配置、模板发布版本和授权数据快照，已有任务不随工作台配置变化重新生成。

## 7. 工作台信息结构草案

采用单据类型列表与详情配置区，详情分为：基本信息、契约、行为、流程关联、打印关联、权限引用、发布记录。代码登记项只读展示来源与版本，配置项展示草稿与已发布差异。

新增类型必须先部署合法业务声明，管理人员从已登记目录启用，不能创建不存在的业务实现。发布前检查执行器存在、契约兼容、操作码有效、流程用途与结果处理完整、打印场景可用；运行时仍复核动态依赖，失效时明确拒绝并记录原因。

前端实施必须先读取《前端 UI 与代码生成规范》，复用 vue-pure-admin 应用壳、BusinessWorkspace、ManagementTable、ManagedDialog 及 Element Plus 表单。本文未新增组件或实现页面；是否需要领域组件在详细设计时说明复用不足的原因。

## 8. 请假单最小试点

1. 保留现有请假表、页面、自然日计算与原文权限，登记 LeaveRequest 单据类型。
2. 显式登记提交、撤回、打印及系统结果处理行为；打印需先实现真实数据提供器与兼容模板，缺少依赖时不可展示可用入口。
3. 工作台配置提交审批绑定、结果处理和打印场景；发布时固定依赖版本。
4. 用真实单据验证提交、主管/人事办理、可靠结果回写及授权打印。
5. 验证无匹配、多匹配、契约变化、并发修改、重复调用、跨租户、任务过期、打印失败和配置升级后的历史稳定性。

试点不同时建设通用单据中心、动态表单、通用编排或 Agent。附件、消息、来源/下游关系先保留能力扩展边界，不提供空功能入口。

## 9. 下一轮需要细化的事项

- 配置工作台放在现有功能管理的关联详情，还是独立菜单；不改变两类模型职责。
- 发布配置是否允许租户覆盖，以及平台声明、租户配置的具体覆盖清单。
- 流程版本升级和绑定重新发布操作；依赖停用、删除与兼容性变化的处理策略。
- 通用契约端口、业务适配接入方式、执行记录与单据索引的最小持久化模型。
- 首期是否包含真实请假打印；若包含，补齐打印字段、脱敏、模板及授权验收。

上述待决事项不代表已确认实施方案，详细设计完成后再确定开发批次。
