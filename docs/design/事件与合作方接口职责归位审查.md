# 事件与合作方接口职责归位审查

日期：2026-11-19。状态：基于当前工作区的静态职责审查与迁移建议，尚未实施代码迁移。范围：平台事件、合作方接口、security 混合职责及前次识别的空模块。遵循[开发规范](../development/README.md)、[后端标准](../development/后端标准工程结构与AI生成约束.md)和[架构边界](../development/架构与分包边界.md)，本文不新增或隐式修改强制规范。

## 1. 审查结论

当前不是“事件和合作方能力不存在”，而是已有实现未按既定职责落位。platform-eventing-adapter 与 platform-partner-api-adapter 应优先承接完整边界改造，不再作为第一批直接删除项。platform-events 没有独立跨进程契约消费者，暂不应为填充目录而集中所有事件；observability 和 building-blocks 仍是空骨架。

重点不是把 security 的类整体搬到其他适配器，而是将用例、业务规则、存储、协议和装配拆开。尤其不能让 API 依赖 security 的具体 Service，或让 persistence 反向依赖 Web 适配器。

## 2. 发现与影响

### F1：事件语义、存储和调度混合，Outbox 写入路径分散（P2）

[AuthorityEvents](../../backend/services/platform-service/authorization/src/main/java/com/appnexus/platform/authorization/AuthorityEvents.java) 已是授权上下文的公开输出端口。授权变化通过 [TransactionalAuthorityEvents](../../backend/services/platform-service/adapters/persistence/src/main/java/com/appnexus/platform/persistence/platformscope/TransactionalAuthorityEvents.java) 直接写 platform_outbox；[IntegrationClients](../../backend/services/platform-service/adapters/security/src/main/java/com/appnexus/platform/security/IntegrationClients.java) 的 update/rotate 则调用 [ReliableEvents.publish](../../backend/services/platform-service/adapters/security/src/main/java/com/appnexus/platform/security/ReliableEvents.java)，后者也直接写同表。

两条路径共享存储协议，但分别维护事件类型、平台边界和写入实现；后续扩展容易产生不一致。ReliableEvents 还同时负责发布、领取、租约、消费幂等、失败、查询和人工重试，security 因此拥有非认证基础设施职责。

建议保留 AuthorityEvents 的业务语义与公开边界；事件技术写入、租约和调度实现归 eventing，现有平台表迁移仍归 persistence。平台客户端授权变化的事件端口归其身份用例，而不是让身份核心依赖 ReliableEvents。通过公开端口和组合装配连接，共用受控 Outbox 存储实现，不建立 security ↔ eventing 循环。

注意当前授权用例大量仍在 MyBatis 实现中；迁移 event 不能据此宣布授权用例层已经完成整改。业务变化、审计、版本推进、旧 Token 撤销和 Outbox 必须保持同库同事务。

### F2：当前消费机制不是跨模块广播协议（P2）

[AuthorityEventWorker](../../backend/services/platform-service/adapters/security/src/main/java/com/appnexus/platform/security/AuthorityEventWorker.java) 消费后主要记日志；注释明确当前鉴权查询权威库，没有已投入使用的权限缓存。ReliableEvents.consume 虽有 consumer 去重键，但完成一个消费者后即把 Outbox 全局状态置 DONE，不能据此声明多个独立消费者都能收到同一事件。

结论：已有可靠事件落库和单一处理路径；未证明多个业务上下文的订阅投递或跨进程广播。若未来需要“授权变更同时刷新缓存、通知会话、同步外部 IAM”，应另行定义消费者投递状态与幂等、重试、终态和补偿，不能只新增 consumer 名称。当前 consume 的 effect 仅允许可回滚的同库副作用，短信和企微 HTTP 调用不得塞进该回调假装事务原子性。

### F3：合作方 HTTP Controller 同时承担业务与存储（P2）

[PartnerDictionaryController](../../backend/services/platform-service/adapters/security/src/main/java/com/appnexus/platform/security/PartnerDictionaryController.java) 在 Web 层直接联表查询与计数。[PartnerReferenceController](../../backend/services/platform-service/adapters/security/src/main/java/com/appnexus/platform/security/PartnerReferenceController.java) 在 Web 层编排客户端权威锁、字典项锁、幂等摘要、请求回执及引用写入，并直接依赖 IntegrationClients 和其他 Controller 的错误构造方法。

建议 HTTP DTO、路径、状态码、分页与协议映射归 partner-api；字典查询/业务引用规则归 configuration 的公开用例及内部应用；固定 SQL、锁和回执读写归 persistence。客户端凭据、scope、启停和版本归身份用例公开契约，不能让 configuration 访问 OAuth 仓储或 security.Service。

引用登记涉及字典引用与集成请求回执两类数据，应在设计中明确各自所有者及窄端口，由完整用例/事务装饰器使用同一事务协调，保留现有锁顺序与撤权并发语义。不得拆成两个先后提交的 Service，也不得把跨表 SQL 原样搬入新的 Controller 包。

### F4：安全公共契约与实现耦合，迁移前须解决依赖（P2）

EndpointPolicy、EndpointOperation 目前声明在 security；PartnerReferenceController 等复用 AccountSettingsController.problem。若新 API 模块直接依赖整个 security 来取得注解、异常助手和 IntegrationClients，将继续把传输与技术实现绑在一起。

建议先盘点当前已有 operation-contracts 可承载的传输声明，或选择既有公开安全入口，形成唯一、无环的边界；不在本审查中自动创建新 contracts 模块。中立接口/注解不能依赖 Spring Security、JDBC 或 Controller。保留注解身份与扫描行为的可控迁移，避免复制两套同名注解。安全链继续由 security/组合装配配置。

### F5：运维业务、审计与观测不能混为一谈（P2）

[TaskManagementController](../../backend/services/platform-service/adapters/security/src/main/java/com/appnexus/platform/security/TaskManagementController.java) 位于 security，负责 /bff/platform/tasks 的列表和人工恢复，并直接执行管理审计 SQL。建议传输入口归 platform-api；人工重试的状态判断、授权、审计和事务由明确的任务运维公开用例承载，eventing 仅执行队列技术操作。其业务所有权在迁移设计中明确，不能未经分析塞入 configuration 或新建任务微服务。

[PartnerCallFilter](../../backend/services/platform-service/adapters/security/src/main/java/com/appnexus/platform/security/PartnerCallFilter.java) 混合可信机密主体识别、Redis 限流、调用审计和 trace 日志。安全门禁保持 security，通过窄端口访问限流与持久审计能力；MDC/日志未来可以接观测适配。integration_call_audit 是业务/安全审计，不能因为有 traceId 就整体迁进 observability，也不能删成普通日志。

## 3. 职责归属与边界表

| 能力/对象/操作 | 业务归属与公开入口 | 适配器/数据归属 | 事务与可信主体 |
|---|---|---|---|
| 授权失效事件 | authorization；沿用 AuthorityEvents | eventing 实现发布/消费技术；platform_outbox 与消费记录保持平台持久化管理 | 与授权写入同事务；租户来自用例可信上下文，平台 NULL 映射为明确边界 |
| 客户端启停、scope 调整、密钥轮换 | identity 的机密客户端用例；建议公开输入/输出端口，名称实施前确定 | OAuth/SAS 注册适配留 security；integration_client* 数据访问归持久化实现，事件写入归 eventing | 可信平台操作者；保留锁、版本、撤 Token、密钥过渡和同事务事件 |
| 字典项对外读取 | configuration 的授权查询用例 | partner-api 映射公开 DTO；persistence 固定双租户谓词和 COUNT | 已验证客户端固定租户与 scope；不可接受客户端传 tenantId |
| 字典引用登记/查询 | configuration 的引用用例，协调身份公开权威校验端口 | partner-api 协议；persistence 字典引用与幂等回执端口实现，分别记录表所有者 | 客户端权威锁→请求回执→字典项等现有顺序须审查保持；跨客户端/租户拒绝，重复键参数冲突 |
| 外部 Bearer 认证/机密主体门禁 | 身份、安全公开能力 | security 的安全链/过滤器/Token 适配 | 无状态、固定客户端租户，Cookie 不能借用外部接口面 |
| 任务查询与人工恢复 | 明确平台运维用例；不自动新建业务上下文 | platform-api 输入；eventing 队列执行，持久化管理审计 | 保留平台权限、MFA、CSRF；重试和审计同事务 |
| 短信验证码、外部 IAM、企微 | 分别归身份、组织或通知实际业务；当前不声明已实现 | 后续按具体供应商提供输出/回调适配，不统归 partner-api | 验证码规则归身份；外部副作用独立幂等与重试，不沿用数据库回调原子性 |
| 地图代理 | 当前 AmapProxyController 是已有外部调用实例；需明确地图能力及配置归属 | API 入口和固定上游客户端应拆分；不是合作方调用我们的 partner-api | 保留可信租户 Key、固定 HTTPS 上游、密钥目录和并发限制；本轮仅登记扩展差距 |

所有实现由 applications/monolith-app 组合，迁移不新增独立部署单元。建议的公开用例名称和包路径须在实际编码前按命名规范定稿，不能把本表当作已存在接口。

## 4. 空模块重新判定

| 模块 | 本次建议 |
|---|---|
| platform-eventing-adapter | 保留为事件技术实现的迁移目标；下一批承接真实用例链路，不保持长期空挂。 |
| platform-partner-api-adapter | 保留为已存在 /v1 合作方入口的迁移目标；先建立用例/存储边界，再移入口。 |
| contracts/platform-events | 暂无独立跨进程事件契约需求证据；目前 AuthorityEvents 已归授权。可移除空壳或待实际集成协议设计时复评，不以装满公共事件为目标。 |
| platform-observability-adapter | 仍为空，可移除构建占位；已有调用日志、traceId 不等于独立观测实现。 |
| building-blocks | 仍为空，无需要提取的稳定技术构件证据，可移除；业务模型不迁入。 |
| 前端 identity/audit 常量包 | 无实际消费，维持移除建议；不连带删除真实登录、审计页面或后端领域。 |

以上修正前次“7 个占位都优先删除”的建议；没有执行删除，也不代表空模块已承载相应实现。

## 5. 建议实施批次与验收

1. 先处理共享安全声明、可信机密主体及领域错误契约。检查 Maven 依赖图与扫描，不让 API/security 相互依赖；本次不预设新增物理模块。
2. 迁移字典只读合作 API 完整链路，建立 configuration 查询输入端口与 persistence 输出实现，partner-api 保留路径及公开 DTO。先用小边界验证接线，再迁移更复杂引用登记。
3. 迁移引用登记和客户端管理。保留同库事务、权威锁和请求幂等；客户端管理入口本身归 platform-api，不因管理合作客户端而放入 partner-api。
4. 统一 Outbox 技术实现与声明，接通 AuthorityEvents/身份事件端口及现有单消费者 Worker；分别验证发布回滚、过期租约、多实例领取、去重、失败转人工、人工恢复和撤权立即生效。多消费者投递若另加，单独设计验收，不在本次归位中自动扩展。
5. 迁移任务运维入口及审计；最后删除确定无用途的空模块，同步 POM、锁文件、文档和扫描，避免把空目录清理当成分层交付。

可复用的测试入口已确认存在：IntegrationClientTest、ReliableEventsTest、ApiContractTest、AllOperationAuthorizationTest、GlobalRecordAuditTest，以及 backend-architecture-tests 的 ArchitectureRulesTest、ServiceLayerBoundaryTest、PackageDocumentationTest。实际实施时按最终影响补充测试，不能只列名称宣称通过。

架构门禁需增加：partner-api Controller 不依赖 JdbcTemplate/Mapper/其他 Controller；eventing 不依赖 Web/security 实现；领域/应用不依赖适配器；新迁移类实际在组合产物被扫描。当前 ServiceLayerBoundaryTest 对 Web 禁存储主要列举已迁移对象/商品入口，不能覆盖本次合作方问题；ArchitectureRulesTest 的 Controller 声明检查存在 security 包限定，迁移时需扩大到实际 API 入口并正向断言命中，不能靠移出扫描通过。

业务反向验证：Cookie/普通用户 Token 调 /v1 被拒绝；缺 scope、失效 Token、跨租户同值、跨客户端引用、并发撤权、同键不同参数、字典删除/停用竞争、回滚审计及 Outbox 均保持。API 对比不得泄露内部字段，不改 URL、错误码与分页。MFA/CSRF 仅按原接口面的协议保留，不将 Web 会话机制套到机密客户端接口。
