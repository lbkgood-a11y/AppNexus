# 全局统一异常处理方案

日期：2026-11-14。状态：设计基线，待实施与验收；本文不代表现有页面已完成迁移。

## 1. 目标与边界

全站业务异常通过浮动图层展示，不向页面、表单或弹窗插入错误横幅，不改变原内容的位置、尺寸和滚动布局。统一错误解析、反馈入口、去重、生命周期和安全边界；领域服务继续负责业务规则和事务。

适用范围包括登录与个人中心、平台管理、租户管理、组织、授权、配置、业务对象、工作流、打印及后续业务模块。后台异步任务失败属于任务状态，保留状态记录；用户当次触发产生的异常通过本方案反馈。静态说明继续使用 InfoHint。

## 2. 当前实现与差距

- `frontend/apps/admin/src/utils/http/index.ts` 的 requestErrorMessage 统一转换部分错误码，但请求层继续抛出异常，不统一展示。
- 各领域通过 errorText 接收转换函数，自行维护 error、dialogError 和 el-alert，导致错误插入内容区、挤压布局。
- 已有模板 `utils/message.ts` 封装 ElMessage，应复用其样式；Element Plus Notification 满足持久浮层需求，无需新增 UI 库或自绘 Toast。
- 后端已存在 ProblemDetail 和 code 扩展，但不能据此认定所有服务已采用完整统一契约。

## 3. 展示规则

| 异常类别 | 统一反馈 | 行为 |
|---|---|---|
| 普通业务拒绝，如编码重复、状态不允许、存在引用 | 模板 Message，error 类型 | 视口顶部居中，默认 5000 毫秒，提供关闭按钮 |
| 需要补救操作、多个错误或较长说明 | Notification，error 类型 | 右上角，默认不自动关闭，提供关闭按钮及受控操作 |
| 409 并发冲突 | 持久 Notification | 提示数据已变化；按页面能力提供“重新加载”，不得自动覆盖草稿 |
| 403 权限不足 | Message；需要安全验证时交由现有验证流程 | 保留上下文，不自动注销，不泄露无权对象是否存在 |
| 429 限流 | Message；需要等待操作时使用持久 Notification | 合法 Retry-After 可用于等待提示，禁止自动重放写请求 |
| 网络、超时、5xx | Message；结果不确定的写入使用持久 Notification | 查询允许显式重试；写入提示先核实结果，不宣称一定失败 |
| 页面首次加载失败 | 浮层 + 原内容容器内的不可用状态和重试入口 | 不添加顶部横幅；状态占用原有数据区域，不显示成无数据 |
| 401 会话失效 | sessionLifecycle 统一处理 | 清理旧上下文后在登录场景提示一次；不叠加业务错误提示 |
| 主动取消、过时响应、路由离开 | 静默 | 不作为业务失败；过时租户响应不能污染新页面 |
| 未处理的运行时异常 | 通用故障浮层，必要时进入模板错误页 | 不直接呈现原始 Error.message 或堆栈 |

字段必填、格式等前端校验继续使用 el-form-item 的标准校验能力，属于输入辅助，不作为业务异常横幅。服务端字段错误统一进入浮层摘要，可同时标记对应字段并定位首个错误；不得再重复弹第二条提示，也不得新增挤压布局的服务端错误块。

只有业务确实要求用户确认或选择才使用 ManagedDialog/ReDialog；异常本身不自动打开阻塞式对话框。成功反馈沿用统一成功提示，与失败互斥。

## 4. 浮层生命周期与可访问性

- 浮层挂载到应用级容器，脱离文档流，沿用模板和 Element Plus 主题、弹层层级管理；必须覆盖普通、最大化弹窗及全屏表格，禁止逐页硬编码 z-index。
- 同时最多展示 3 个独立异常浮层；超过时合并为一个可关闭摘要，不无限堆叠。相同请求异常对象仅消费一次；跨请求仅在同账号、租户、操作和错误码相同的 2000 毫秒窗口内合并，不能吞掉不同对象的失败。
- 路由离开清理该页面浮层，账号退出或租户切换清理对应上下文；应用级会话提示由会话生命周期负责。过时请求不产生新浮层。
- 默认不抢占表单焦点；关闭和补救按钮可通过键盘操作，使用组件可访问语义通报错误。移动端按视口限宽，长内容可滚动，不遮住全部操作区；深色、系统主题和中英文均需验证。
- 时长、数量和去重窗口是本方案的前端缺省策略，不是现有系统配置。实施时集中声明并提供相邻中文注释，说明单位、默认值及调整影响。

## 5. 前端职责与接入契约

采用“纯解析 → 统一调度 → 组件适配”三层结构，以下为待实现接口约定。

1. normalizeError 将未知异常转为 AppError：包含 category、code、messageKey、受控插值参数、字段错误、可选关联编号和结果确定性。解析过程不展示 UI、不修改业务状态。
2. reportError(error, context) 是唯一反馈入口；context 提供页面生命周期、可信租户版本、操作及对象标识、表单字段映射和允许的本地补救回调。标识仅用于内存去重，不作为用户文案或持久化业务正文。
3. 应用壳注入 reporter；领域包通过公开契约接收能力，不深层导入 admin 实现。errorText 在迁移期间仅作兼容转换，迁移完成后删除重复链路。
4. HTTP 层负责协议、会话、取消识别和规范化，不直接无条件弹消息；操作边界负责调用 reporter。查询/提交公共包装统一接入，并在 finally 中恢复 loading。
5. Vue errorHandler 和未处理 Promise rejection 作为兜底，复用同一 reporter；已消费异常不得再次提示。兜底不能吞掉异常或代替操作边界处理，预期取消必须被识别。
6. 补救动作只能来自本地注册的可信回调，点击后重新校验上下文与权限。后端错误不得携带可执行脚本、任意 URL 或自动提交指令。

业务操作失败保留弹窗、选择项和非敏感输入，乐观更新按契约回滚。取消确认不报错。任何自动重试必须区分只读与写入，写入不自动重放；提交超时也不自动生成新幂等键再次提交。

## 6. 后端错误契约与文案安全

继续采用标准 HTTP 状态及 ProblemDetail，禁止将业务失败包装为 HTTP 200，也不引入另一套平行响应包装。

| 字段 | 契约 |
|---|---|
| status | 与实际 HTTP 状态一致；业务输入、冲突、权限、系统故障按实际语义区分 |
| code | 必填的稳定业务错误码；由所属领域唯一维护，不使用翻译文案判定业务 |
| type、title、detail | 按 ProblemDetail 表达；detail 仅为服务端受控说明，不拼接原始数据库或第三方异常 |
| field | 兼容已有单字段路径；前端只能映射到当前表单已声明字段 |
| errors | 目标可选批量字段错误扩展，包含字段路径、稳定码和受控参数；待各服务明确契约后接入，不视为当前已支持 |
| traceId | 目标可选关联编号；按日志链路实际能力接入，不在前端伪造；不得暴露内部路径或凭据 |

文案优先级为已登记业务码的中英文映射、经明确允许的安全服务端说明、通用失败提示。未知业务码及未知运行时异常使用通用文案，不能原样显示任意 detail/message。服务端参数须经过白名单和长度限制，不回显密码、Token、个人敏感值、SQL、堆栈或内部地址。所有文本按纯文本渲染，禁止开启 HTML 字符串渲染。

业务码按领域登记，不在全局拦截器不断增加业务分支；HTTP 分类和具体业务码联合判断，不能只凭 403 覆盖 MFA 等需要专门流程的安全码。服务端事务回滚、幂等和授权规则不因提示统一而改变。

## 7. 迁移顺序与验收证据

1. 建立纯解析与 reporter 公开契约，复用模板 Message 和 Element Plus Notification；验证去重、取消、会话和跨租户生命周期。
2. 选择角色管理作为样板，覆盖加载、新增、编辑、启停、删除及并发冲突；删除业务异常 el-alert，保留真实业务操作。
3. 迁移组织、字典、菜单、授权、业务对象、工作流、打印，再覆盖登录与个人中心的安全流程；逐项记录代码位置和未迁移项，不能只登记即关闭。
4. 收敛后端错误码、字段错误及关联编号契约；补齐国际化，移除直接渲染不受控 detail 的路径。
5. 更新公共组件和代码生成接入约束，检查新增页面没有绕过 reporter 的业务异常展示。

验收必须包含：同一次异常只展示一次；浮层前后页面与弹窗关键元素坐标、尺寸及滚动位置不变；错误不被遮罩或最大化容器遮挡；失败不清空草稿；写入超时不重放；取消静默；会话失效提示一次；租户切换后旧错误不出现；未知码和敏感 detail 安全降级；桌面、窄屏、手机、深浅主题、中英文与键盘操作通过。

交付证据包括解析和调度的针对性测试、前端类型检查与构建、真实浏览器失败流程截图及布局测量；涉及后端契约时补充真实接口正反向验证。当前仅完成方案编制，运行时实现、迁移和浏览器验收均待执行。

## 8. 全局展示迁移记录（2026-11-14）

已实现 `@appnexus/ui` 的 reportError、clearErrorFeedback 和 FloatingError。复用模板 Message 样式及 Element Plus Notification：短文案默认 5000 毫秒，长于 100 字符或含补救插槽时保持显示；最大 3 条，超出关闭最早提示。同文案活动浮层共享实例，调用方卸载后释放，不产生页面 DOM 布局。保留原页面的 errorText 文案解析和加载、草稿、权限处理，不重新设计业务接口。

已将组织、租户、配置、业务对象、打印、工作流、授权及应用壳登录、个人中心等共 30 个 Vue 文件的明确 error 类型 Alert 替换为公共浮层，组织关系类型加载错误同步迁移。原有重试按钮在 Notification 内保留。静态警告、任务状态、设计器校验结果、字段校验和成功状态不属于本次业务异常替换范围。登录错误提示移到凭据表单条件之外，避免非凭据入口隐藏错误。

路由切换、租户上下文变化及会话清理关闭旧浮层；Axios 取消及 401 不再生成业务错误文案，会话失效由登录场景负责。删除公共反馈区域旧固定定位样式，空反馈区不占布局空间。

验证：管理端类型检查通过；Vitest 10 个测试文件、24 项测试通过，包含共享提示、释放、持久提示、上下文清理和数量上限；生产构建通过。浏览器在本地登录页通过 `error` 参数确认浮层实际出现。尚未完成有认证会话的所有领域失败操作、最大化弹窗、深浅主题、移动端及坐标测量验收，不能据此宣称全站浏览器验收完成。

实施边界：本轮完成全局展示适配，尚未完成第 5、6 节的完整 AppError 规范化、按操作/对象的精细去重、后端批量字段错误和 traceId 收敛、运行时异常兜底。当前去重范围为同一应用上下文内的活动同文案，数量超限采用关闭最早提示而非摘要。以上为后续工程缺口，不以展示迁移代替完整方案验收。
