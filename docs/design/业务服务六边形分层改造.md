# 业务服务六边形分层改造

日期：2026-11-19。状态：实施中；本记录只对列明的源码边界及验证结果负责，不代表全仓库重构完成。

## 1. 目标与依赖

执行《后端工程详细设计》《业务服务统一开发规范》和《业务对象数据权限声明标准》。按业务对象分离领域规则、应用用例、输出端口及技术适配器。应用用例依赖端口，JDBC、JSON、事务等技术实现依赖应用定义的端口，由组合装配注入。领域规则不能依赖 Web、数据库、Spring、Flowable 或适配器。

模块化单体的部署方式不变；本次不引入新 UI、新业务协议或数据库迁移。不能用增加空包、转发接口或扩大例外清单代替职责迁移。

## 2. 已实施边界

### 2.1 编码器

`business-object-service` 的编码用例现位于 `application/coding/CodingService`。`domain/coding/CodingRules` 负责规则校验、周期选择、文本渲染及流水耗尽判定，不读取时钟或外部状态。数据库时间经 `CodingStore.now` 提供，一次发号只使用一个时间点，保证跨午夜日期与流水周期一致。

`CodingStore` 定义配置、行锁、流水和幂等回执操作，不开放 SQL、表名或客户端时间；`adapter/jdbc/coding/JdbcCodingStore` 承担固定 SQL、JSON 映射、Spring 事务和唯一约束异常转换。`CodingObjectAccess` 只表达对象配置与页面操作准入，由 `ExistingCodingObjectAccess` 桥接原执行器。应用用例不再直接依赖原 JDBC 对象执行器。

配置行锁覆盖重新授权、启用检查、重放、流水与回执写入；唯一约束失败回滚整笔事务。管理与发号仍使用原权限路径；撤权及停用后不得依靠历史回执绕过检查。可信租户、账号、UTC 审计、创建信息保持不变及取消录入不回收号码的契约保持一致。原 HTTP 路径、输入 JSON、错误码和公开 `BusinessCoding` 契约不变。

### 2.2 主数据记录写入

`MasterDataRecords` 是固定档案的记录输出端口，`JdbcMasterDataRecords` 执行新增、版本更新、启停、客商归属、旧字段读取和审计。新增记录首次 INSERT 同时写入四项审计，账号来自可信主体，时间由数据库 UTC 生成；更新不覆盖创建信息。父子、字典、客商行范围与字段限制仍在原业务事务执行，不新增绕过入口。

`MasterDataService` 已移除 JDBC、Spring 事务及技术实现构造入口，改由 `MasterDataConfiguration.create` 统一装配。`MasterDataRelations` 隔离分页、租户地理关系及客商明细；`PartnerAccess` 保留真实行范围、字段合并与目标组织复核；`RecordTransaction` 保证父对象、明细、字典引用及审计同事务。

`MasterDataRules`、`PartnerRules`、`WarehouseProfile`、`StorageRules` 提取纯字段业务约束；客商日期检查使用应用提供的 UTC 自然日，不在领域读取系统时钟。固定字段白名单在领域与持久化之间共享。

`JdbcMasterDataRelations` 暂留原内部协作者包，原因是地理图和明细协作者原为包私有，迁包会扩大其公开 API；它是明确的输出适配器，只由装配层依赖，应用不得引用。主数据应用用例已纳入技术依赖门禁。地理图的纯父链算法仍可继续从租户读取适配器细分，不把应用层无 JDBC 等同于所有领域建模已经完善。

### 2.3 商品父记录与生命周期

`ProductRecords` 和 `JdbcProductRecords` 隔离父记录读取、行锁、CAS 及最后修改审计。`ProductLifecycle` 提取普通修改、启停及草稿归档规则，`ProductStructurePolicy` 使用类型化源事实和切换意图检查审批冻结、源版本、规格退出及历史处置，保持归档、历史结构待处理、草稿不能停用及重复转换拒绝的语义。Spring 装配显式注入父记录端口，现有同领域扩展共享父锁和业务事务。

**尚未完成**：`ProductV1Service` 仍包含结构迁移、属性值、快照、审批事实读取、历史事件及其 SQL；原内部构造入口仍保留。因此商品聚合整体分层尚未闭环，不以父记录端口代替完整商品仓储设计。

## 3. 架构门禁

`ServiceLayerBoundaryTest` 在正式组合应用的测试类路径扫描 `com.appnexus`，覆盖各自有服务实际加载的领域、核心及新应用端口；不再只扫描平台领域包。领域和核心不得引用技术框架或外层；编码应用及新主数据应用端口不得引用 JDBC、Spring、JSON 实现和适配器。已迁移边界须存在于生产产物，删除或改包不能让检查静默失效。

此门禁不会自动证明其他未迁移 Service 已完成分层。平台根 `application` 是启动装配模块，不能与领域内用例混为一谈；新功能应进入对应领域用例层。现有未迁移类不得靠重命名为 adapter 宣布完成。
