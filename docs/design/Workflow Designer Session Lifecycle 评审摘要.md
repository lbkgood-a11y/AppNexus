# Workflow Designer Session Lifecycle 评审摘要

日期：2026-11-15；状态：待架构评审。完整内容见[架构设计方案](Workflow Designer Session Lifecycle 架构设计方案.md)。仅新增文档，无实现。

## 可确认

独立Demo普通及单关联连线shape.move精度恢复限定通过；九例故障通过会话隔离，完整回滚0项。公开Modeler.destroy会触发内部销毁并移除容器；不能取消全部外部任务。现有服务端有revision条件更新、请求幂等记录和同键内容冲突检查。

## 不能确认

方案A整体、任意handler内部异常恢复、完整命令历史安全、所有输入通道封锁、销毁与未完成importXML竞争、正式服务端不确定写结算及真实重载。bpmn-js仍仅用于Demo，正式设计器未迁移。

## 推荐状态与竞争处理

生命周期为CREATED→LOADING→ACTIVE，失效后INVALID→DISPOSING→DISPOSED；正常关闭也可进入DISPOSING。SAVING是独立操作状态，首期保存期间冻结编辑。RELOADING为控制器创建新会话的流程，旧会话不复活。

每次新sessionId/generation；旧回调只能结算原请求，不能更新新会话。销毁立即封锁并释放画布，在途写交给控制器确认。AbortController不撤销已到达服务端的保存。恢复只读取服务端最新已提交的原子文档信封，不读取故障画布或诊断XML。

## 必须解决的风险

现有前端每次write生成新幂等键，不能直接实现稳定请求重试；当前没有已核实的公开请求结果查询/终结屏障。一次GET当前revision不足以证明迟到保存不会随后提交。结果不确定时必须保持新写封锁，不能盲目重新加载后开放编辑。

需评审WorkflowDocumentService的受授权结算契约、迟到请求终结语义、幂等保留及请求指纹。销毁失败、外部订阅、多标签和身份切换均需独立测试；不能把按钮禁用当作可靠隔离。

## 是否实施与技术选型

建议批准后仅进入隔离Demo的生命周期最小实现及可控请求竞态验证；完整恢复链路受服务端契约阻断，不批准完整DesignerAdapter或正式接入。

本设计不改变bpmn-js方向，不支持据此引入X6，也不作最终引擎选型。会话/异步/保存竞态属于编辑器通用问题，切换图引擎不能自动消除。完成评审前停止编码。
