# 技术版本与许可证基线

版本：0.3；核查日期：2026-11-05；状态：版本选择原则、候选基线及 Valkey 选型已确认，精确版本仍须通过技术验证锁定。

## 锁定原则

- 以受维护的稳定版为起点，构建必须通过锁文件和 BOM 可重现，不在生产构建中浮动到新版本。
- 下表中的补丁版是核查日的验证起点，不是永久固定值；正式开发前再做一次安全与兼容性复核。
- 后端由 Spring Boot BOM 和 Spring Cloud BOM 统一管理可管理依赖；前端提交 `pnpm-lock.yaml`，并通过 Corepack 固定 pnpm。
- 所有直接与传递依赖生成 SBOM，扫描漏洞和许可证；引入 AGPL、SSPL、RSAL 或商业限制组件前必须单独审批。

## 许可证与分发边界

| 组件 | 初步结论 | 后续动作 |
|---|---|---|
| Spring 主要项目 | Apache License 2.0 | 保留 NOTICE/版权要求，最终以实际依赖 SBOM 复核。 |
| vue-pure-admin | MIT | 可修改和分发，分发时保留许可声明；仍需分别扫描其传递依赖。 |
| MySQL Community | GPLv2 | 私有部署与对外分发的义务不同；产品打包、连接器和镜像分发方式需在发布前由法务/合规复核。 |
| Redis | 当前版本采用 RSALv2/SSPLv1/AGPLv3 多许可选项，不能沿用早期 BSD 印象 | 第一期不选用；保留本条作为当时选型和许可证判断记录。 |

## 缓存方案比较记录

| 方案 | 许可证 | 兼容性与定位 | 本项目结论 |
|---|---|---|---|
| Valkey | BSD-3-Clause | 从 Redis 开源版分叉，保留数据结构、持久化、Sentinel 和 Cluster 能力 | 首选；最适合会话、权限缓存、撤销信号和分布式协调，可继续使用 Spring Data Redis/Lettuce 抽象，但必须以本项目使用的命令集实测兼容。 |
| Memcached | BSD 类许可 | 简单的内存 key/value 缓存，能力和数据结构较少 | 只适合可丢弃的普通缓存；如果会话撤销、原子协调和稳定过期语义都需要另行实现，不建议作为平台唯一组件。 |
| Microsoft Garnet | MIT | 高性能、兼容 Redis 协议的存储，服务端基于 .NET | 许可证友好，但引入新运行时和较新运维生态；可作性能 PoC 候选，不作默认。 |
| Apache Kvrocks | Apache-2.0 | Redis 协议兼容、基于 RocksDB 的磁盘存储，偏大容量和较低内存成本 | 适合大容量持久化场景，不是低延迟会话/权限缓存的默认首选。 |
| DragonflyDB | Dragonfly Source-Available License | 兼容 Redis/Memcached 协议，强调多核性能；当前许可对生产 vCPU 规模设限 | 不纳入默认基线；只有在明确接受许可条件并有性能需求时再评估。 |

不建议为了“不用 Redis”而在 MySQL 中自行模拟所有会话、缓存、锁和撤销机制。MySQL 可作最终状态权威源和降级兜底，但高频短生命周状态仍应由专用组件承担。

## 启动前验证门槛

1. 建立最小后端验证工程，确认 Java 21 + Boot 4.1 + Cloud 2025.1 与 MyBatis、Flyway、Spring Security、OpenAPI 和测试工具兼容。
2. 完成“登录选租户 → 已验证上下文 → 共享表 SQL 强制租户条件”，覆盖 CRUD、联表、分页、批处理与异步任务。
3. 从 vue-pure-admin 锁定标签创建最小壳，验证 workspace 拆包、`infra/pure` 适配、单模块构建、中英文切换及租户状态清理。
4. 输出 SBOM、漏洞扫描和许可证报告；任一关键组件存在不可接受许可证或高危漏洞时不进入实施基线。

## 尚待确认

- 是否接受 Spring Boot 4 作为第一期基线，或回退到兼容生态更成熟的 Boot 3.5 系列。
- OpenJDK 发行版、MySQL 的交付形态，以及产品是否会将数据库/缓存镜像随软件一同对客户分发。
