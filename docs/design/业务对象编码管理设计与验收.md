# 业务对象编码管理设计与验收

日期：2026-11-19。编码是业务对象通用能力，配置归属现有业务对象管理，不新增独立菜单、UI 库或平行权限体系。

## 功能与接入边界

租户管理员在“业务对象管理 → 已获授权对象 → 编码管理”维护对象内的多个编码器。业务模块在同一 `BusinessObjects.Provider` 的 `Descriptor.codingFields` 中明确字段、目标操作和最大长度；未接通的字段不展示入口。当前真实页面接入客商新增的 `code` 字段，长度上限64字符；已有单据/档案的其他字段不会仅凭命名自动接通。新模块应复用 `@appnexus/business-object/coding-input`，通过应用壳注入公开 API，不深层导入实现。

编码器支持有序 TEXT、DATE、SEQUENCE 分段，最多10段，恰好一个流水段。可新增、移除和上下调整分段；预览只用示例日期2026-11-09和流水1，不访问发号接口。固定文本 PU + 日期 yyyyMMdd + 6位流水，示例为 `PU20261109000001`。

| 参数 | 中文约定 |
| --- | --- |
| encoderKey | 对象内唯一，1–40位字母数字或下划线，必须以字母开头；新建后不可改键 |
| field | 同一对象声明的编码字段，必填；不能填写任意属性路径 |
| name | 名称，去首尾空格后1–100字符，必填 |
| enabled | 启用状态，界面缺省true；停用会阻止新发号及旧请求重放 |
| revision | 首次-1，已有记录使用读取版本；每次修改加1，冲突后重载，不覆盖 |
| segments.kind | TEXT、DATE、SEQUENCE；每种段仅使用对应参数 |
| segments.value | TEXT为1–32位字母数字或._-；DATE为yyyy、yyyyMM或yyyyMMdd；SEQUENCE必须空字符串 |
| segments.width | 流水补零位数1–12，界面缺省6；其他段为0；容量耗尽拒绝，不截断、不循环 |
| reset | NEVER、YEAR、MONTH、DAY；初始示例DAY，改周期必须配套相应精度日期段，避免重置后编码重复 |
| zoneId | 必填IANA时区，界面缺省Asia/Shanghai；日期和重置统一使用此时区，审计时间仍为UTC |
| maxLength | 业务代码声明1–128字符；规则输出不得超限，不允许配置人员扩大业务字段容量 |
| Idempotency-Key | 本次主动发号请求的UUID，作用域为租户+实际账号；同键不得更换对象或编码器；不作为身份凭证 |

所有输出只允许首位字母数字，后续字母数字及._-。首次发号后规则和字段冻结，名称和启停可继续修改；需变更规则时新建编码器。该约束避免旧周期与新规则共享流水造成历史歧义或重复。

## 录入、事务与唯一性

业务字段保留自由输入，协助录入主动打开选择框；读取候选、打开页面和预览均不消耗号码。用户选定编码器后点击“发放并填入”，有手工值时先确认替换。请求超时保留原幂等键，只有用户显式重试才发请求；服务端每次重新鉴权，不自动重放业务写操作。

发号使用数据库时间点，按配置时区计算日期和周期。事务锁定编码器配置，再锁定租户/对象/编码器/周期的计数行；跨进程并发共享同一数据库锁。流水更新、发号保留和审计同事务，唯一约束按租户/对象/字段/编码兜底，忽略ASCII大小写。失败回滚流水和审计。号码发放成功即消耗，取消、离开或未保存业务记录也不回收，允许断号。

编码发号不代表创建业务记录，也不授予业务保存权。手工输入仍由原业务服务校验格式和唯一性；编码器不跨模块读取业务表，因此手工值已占用生成值时，业务保存仍会返回重复编码，需要用户再次发号或调整输入。不会暗中覆盖已有单据。

## 权限与模块职责

`CodingDeclaration` 为编码器配置的唯一 Provider，Controller只reference引用 `CodingEncoder.list/save`。配置复用业务对象配置管理权限，并复核目标对象的租户授权。普通用户的候选与发号由目标对象 `codingFields.operationCode` 派生原操作权限，经宿主可信成员和功能权限桥接复核，并复用 `verifyPageOperation` 检查平台页面控制；不授予编码器管理权，不增加无关权限码。

动态候选/发号端点不接受客户端权限码、操作者或租户；只从可信 WorkflowContext 读取身份。请求键仅用于幂等。服务端实际发号前复核，撤权、停用不能借已发请求重放绕过。业务保存继续执行自己的数据范围、字段、状态和唯一性约束；本能力不开放任意SQL、脚本、事实数据或URL。

## 数据与前端复用

V123首次建表直接包含全部四个审计字段：账号BINARY(16)，时间TIMESTAMP(6)，数据库UTC生成；系统无可信账号可空。配置修改保持创建信息不变。配置详情复用 `RecordAuditDetails`，不提供任意表/账号查询入口。

编码器编辑器组合 Element Plus Form、Select、InputNumber、Card和现有对象配置页面；检查过现有配置表单，其不具备有序分段编辑能力，因此新增最小领域组件 `CodingConfiguration`。`CodingInput`组合既有Input及ManagedDialog，补充服务端候选、发号幂等和覆盖确认；不复制主题、不新增基础控件。中英文文案和错误码纳入既有语言与统一错误反馈。窄屏通过自动网格和换行保持表单可用，审计保持只读。
