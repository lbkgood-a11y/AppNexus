# 契约驱动工作流与打印执行抽象

日期：2026-11-20。状态：公共执行器、专业能力驱动及请假/商品对象迁移已实现，最终门禁验收进行中。

## 目标与验收口径

开发者在唯一对象声明中定义数据契约、操作、权限及能力，管理员配置已发布流程或打印场景绑定后，即可使用公共入口。新增一个符合公共模型的对象，不需要编写 WorkflowBusiness、打印数据 Provider、启动流程接口、结果回调接口、实例关联及重复交付处理代码。仅统一接口或增加抽象基类不满足目标。

已有 Descriptor → Operation → InteractionContract 继续作为唯一来源，流程设计投影、打印目录和授权目录均从其派生。不新增独立的审批对象登记表或打印字段声明。

用户确认的接入模型为：**业务对象契约 + 关联配置 + 通用能力配置**。该模型同时覆盖工作流、打印、编码及后续通用能力；不能为每种能力要求业务开发者重新定义对象、字段、数据来源或另一套接入契约。专业服务内部接口可以保留，但只能作为公共执行层的实现细节。

| 唯一来源 | 维护内容 | 禁止重复定义 |
|---|---|---|
| 业务对象契约 | 对象身份、字段、操作、权限、受控记录访问及适用状态约束 | 独立审批业务登记、独立打印数据结构、能力专用对象适配器 |
| 关联配置 | 对象操作与能力、规则及已发布版本的关联，适用条件和结果映射 | 任意 SQL、URL、脚本或另一份对象字段目录 |
| 通用能力配置 | 打印模板及场景、编码规则、流程模板及发布版本 | 业务正文、另一份对象操作或授权策略 |

同一个对象的数据访问和业务操作只接入对象契约一次，由所有通用能力复用。新增能力时不再向每个业务对象增加一套 Provider、Handler 或回调实现。契约缺少运行信息时扩展既有声明及公共对象执行能力，不建立平行模型。

## 执行职责

| 环节 | 公共执行层职责 | 契约提供的信息 |
|---|---|---|
| 入口 | 从可信会话建立主体，解析已登记对象和操作 | 对象、操作及管理域 |
| 授权 | 调用统一功能准入、AccessPlanning、RowAccessControl 与字段保护 | 已真实支持的资源、操作范围及字段 |
| 读取 | 在事务内读取授权记录及依据版本 | 数据来源的受控标识与字段映射 |
| 审批 | 解析唯一绑定，校验依据，启动精确发布版本，保存执行关联 | WORKFLOW 契约、用途、结果集合 |
| 结果 | 校验租户、对象、实例、审批轮次及版本，原子去重并落地状态 | 允许的结果及状态转换 |
| 打印 | 重读并投影授权字段，解析绑定场景，提交统一输出任务 | PRINT 契约及字段映射 |
| 恢复 | 复用工作流可靠投递、打印回执和未知结果处理 | 稳定请求键及执行关联 |

审批状态与业务生效分别表达。公共审批结论不自动代表扣库存、支付或发货；需要这些副作用时必须绑定代码登记的业务命令，不能允许流程配置直接执行任意 SQL、类名、URL 或脚本。

流程启动及其回读快照需要读取同一事务中的冻结记录，装配使用延迟公开端口解决循环依赖，不得以绕过快照核验的方式解决。跨进程情况下采用持久化交付及对账，不承诺本地事务覆盖远程调用。

## 记录访问与业务所有权

保持现有业务记录所有权，不以本次抽象要求改为平台托管业务正文。统一对象契约及其公共执行能力负责受控访问；字段结构、版本、归属和操作约束只声明一次，审批依据、打印数据和编码字段均由其派生。

当前仓库尚无可覆盖商品与请假的统一记录访问能力，这是需要落实的公共能力缺口，不能转为要求用户选择存储模式。实现须沿用对象唯一声明补齐受控记录读取、版本校验和已声明操作执行；底层持久化映射不能由浏览器或租户配置提供任意表名及 SQL。

对象专有的库存、支付等领域规则仍由原业务用例负责；关联配置引用其已声明操作，公共能力不能另建同义业务操作或绕过业务用例写表。不能用客户端传入的打印数据或审批事实替代服务端重读。

## 架构归属

| 能力 | 所有者与公开入口 | 实现边界 | 数据及事务 |
|---|---|---|---|
| 能力契约与绑定 | business-object-contracts 与 platform-business-object 的既有公开入口 | 唯一声明及公共执行协调，核心不依赖 Spring/JDBC | 配置表仍只保存配置及执行依据 |
| 工作流 | workflow-contracts / workflow-service | 通用桥接实现 WorkflowBusiness，业务对象不分别实现 | 工作流拥有实例、任务和可靠交付 |
| 打印 | print-contracts / print-service | 统一授权数据投影后调用 BusinessPrinting | 打印拥有输出任务、模板及回执 |
| 业务记录 | 原业务上下文，经统一对象契约访问 | 禁止跨上下文读表，禁止任意 SQL 端口 | 记录、版本、结果去重及审计原子提交 |

## 实施切换与删除策略

本次按全量收敛处理，不保留旧 Provider、旧数据契约、旧能力字段或运行时兼容分支。现有工作流、打印和编码配置一次性转换到对象操作关联配置；旧字段和旧配置表由新版本迁移删除，历史执行记录只保留审计和追溯所需的不可变快照。已执行的迁移脚本不修改，通过新迁移完成删除和转换。

业务对象先实现 `BusinessObjectRuntime`，再由 `CapabilityDriver` 统一驱动。迁移完成后，工作流运行时不再接收对象专用 `WorkflowBusiness` 列表，打印运行时不再接收对象专用数据 Provider，编码运行时不再按对象注册规则处理器。缺少运行端口的对象在装配期失败，禁止降级为旧路径。

## 必须证明的结果

- 用两个不同契约接入同一运行时，第二个对象仅新增声明及绑定，不新增专用启动、回调或打印执行代码。
- 真实工作流发起、通过、驳回、撤回、重提及重复交付；旧轮次、错误实例及过期依据不能改变记录。
- 打印使用授权后的真实记录，绑定失效、字段受限及非法契约失败关闭；未知物理打印结果不盲目补打。
- 无功能权限、无数据策略、跨租户、撤权、字段保护及直调公共入口均不能绕过统一模型。
- 真实数据库验证并发、事务回滚、幂等键异内容冲突和四审计字段；迁移不修改历史脚本。
- 在统一应用中验证实际装配及公开边界，不以纯模型测试或构建通过代替业务闭环。


## 本轮实际实现

- `BusinessObjectExecution` 不接受浏览器提供事实、模板或流程标识；对象操作、真实入口及读取版本决定执行。
- `ObjectExecutionService` 在REQUIRED事务内依次复核统一`operationAllowed`、页面关系、对象运行快照与版本、事实契约、关联结果身份及能力字段白名单。
- `StandardCapabilityDrivers` 统一BUSINESS、WORKFLOW及PRINT执行。编码已有对象字段/规则绑定与公共执行器，继续复用CodingService，其准入改为同一operationAllowed，无codingAllowed旧别名。
- 对象通过已有唯一Provider.runtime暴露一次自身记录存取。请假和商品不再实现WorkflowBusiness，不再维护第二份能力元数据、审批快照或终态判断。
- `ObjectApprovalService` 位于workflow-core应用层，统一审批身份、任务、实例、组织、版本、受控结果及幂等判断；`ObjectWorkflowAdapter` 只提供Spring事务装饰。
- V129把请假旧交付回执搬入本轮记录及轮次表，然后DROP旧表。旧实例不能污染已重提记录，历史未知完成时间保持NULL。运行代码不再查询旧表；历史迁移脚本保持不可变。

实际边界：本轮支持现有标准审批生命周期、直接受理和预览打印；业务正文仍由业务拥有。对象真实持久化及特殊业务规则并未由元数据自动生成；现有对象存量行范围/字段策略也不能因本轮公共接线而视为全量整改完成。真实测试及未完成门禁见[本轮检查](../validation/对象公共执行与审批回执迁移检查.md)。
