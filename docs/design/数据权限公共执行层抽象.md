## 职责

- AccessPlanning 保持功能权限、目录和策略解析的唯一入口；公共执行层不重新查询权限，不缓存计划。
- RowAccessControl 提供组织范围的参数化 SQL 条件及目标组织准入判定；列映射只允许业务存储代码中的固定标识符，不得从 HTTP 或授权配置读取。
- MySqlRowAccessControl 负责 MySQL UUID 绑定、稳定排序及失败关闭，不访问业务表，不执行 SQL。
- PartnerDataAccess 继续负责客商事务内锁定、目标组织真实性/启用状态、字段保护和主从业务约束；组织 SQL 编译及范围判定调用公共接口。
- 返回的条件仅为附加行范围，不含租户谓词；ALL 仅省略附加条件，不能省略业务 SQL 的可信租户边界。列表、总数及锁定共用此条件。

## 效率与扩展边界

保持原有 `organization_id IN (UUID_TO_BIN(?),...)` 形状和绑定值，组织子树仍先由现有平台能力展开。不增加业务查询、权限查询或 JOIN，保留现有组合索引。此轮不代表已证明生产数据规模下的性能。

该抽象是显式调用的执行能力，不是自动 SQL 拦截器。新增对象仍需声明能力并接入查询、总数和写入路径；复杂关联及归属变更不能由公共类自动推断。未来增加维度时再评估规则模型与索引，不将任意 SQL/属性路径作为扩展点。
