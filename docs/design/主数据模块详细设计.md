# 主数据模块详细设计

日期：2026-11-16。首期范围由用户确认：人员、客商、仓库、国别地区、商品五类基础管理。

## 范围与治理边界

首期实现租户公共档案的分页查询、新增、编辑和独立启停。每个对象分类均为 MASTER_DATA，使用固定 API 和独立权限；不提供删除、导入导出、模拟数据或没有真实后端的入口。

人员是业务档案，不创建登录账号，不变更组织任职，不授予登录或业务权限。本期未实现账号关联选择器。客商以 CUSTOMER、SUPPLIER、BOTH 表达客户、供应商及兼具，不使用两个重复档案表达同一客商。仓库只维护档案，不计算库存；商品只维护档案，不承载公司价格、库存和成本。

总体设计的公司使用关系、公司结算与账期、系统专有扩展、草稿/生效版本和按授权审核属于后续治理阶段。本期用户确认的是直接维护基础档案，保存即生效，乐观锁版本不等于审批生效版本。未接入审批、打印或消息，不登记这些能力，也不展示配置入口。停用保留历史资料；未来业务接入必须重新读取并检查 enabled，历史单据需保存所需快照。本期尚无下游引用执行器，不能把停用接口视为已完成全系统引用阻断。

## 字段契约

| 对象 | 编码 | 专有字段 | 约束 |
|---|---|---|---|
| Person 人员 | 业务人员编码 | 英文名称、联系电话、电子邮箱 | 邮箱可空，非空校验格式；不采集身份证或凭据 |
| BusinessPartner 客商 | 客商编码 | 客商类型、统一社会信用代码、联系人、电话、地址 | 类型必填 CUSTOMER/SUPPLIER/BOTH；信用代码为可选文本，本期不自动校验官方登记身份 |
| Warehouse 仓库 | 仓库编码 | 地址、联系人、电话 | 不承载库区、库位、容量或库存 |
| CountryRegion 国别地区 | ISO 3166-1 两位大写字母代码 | 英文名称、三位大写字母代码、三位数字代码 | 三位字母和数字必填；数字保留前导零；校验格式，不声称已核验标准映射，不自动植入完整国家目录 |
| Product 商品 | 商品编码 | 规格型号、基本单位、条码 | 单位必填，1–32 字符；条码保留前导零，不强制 GTIN 校验或唯一 |

共同字段：服务端 UUID、编码、名称、启用状态、乐观锁版本。编码创建后不允许修改，同租户同类唯一，1–64 位 ASCII 字母、数字、点、下划线、短横线，首位为字母或数字；国别地区覆盖为两位大写字母。名称去首尾空白后 1–200 字符。新建默认启用、版本 0。其余属性缺省空文本、最长 500 字符，邮箱最长 200 字符；不接受未知字段或控制字符。名称与业务属性不使用任意 JSON 扩展编辑。

编码的大小写等价规则沿用宿主 MySQL 默认排序规则，本期不提供区分大小写编码空间。联系电话、条码和数字代码始终按文本处理，无金额、数量和时间参数的隐式换算。

## 模块与数据归属

后端位于 backend/services/master-data-service，组合应用显式 Import。只依赖 platform-tenant、platform-authorization 和 operation-contracts 的公开契约，不依赖其他服务实现或读取其业务表。AccessAuthorization 负责有效账号、租户、成员、角色和权限，主数据 SQL 只读写 md_person、md_partner、md_warehouse、md_country_region、md_product。

每类一个固定 Controller，在类上唯一声明对象，在方法上声明 list/create/update/setStatus 四个操作，共 20 个。未重复声明 Provider，也不伪造可配置审批能力。统一操作目录、功能清单、按钮准入与导航由这些真实声明投影。

前端模块 frontend/modules/master-data 对外公开类型、固定映射和 management 入口，应用壳注入 HTTP API 和错误转换。复用 BusinessWorkspace、ManagementTable、ManagedDialog、AppPagination、InfoHint、FloatingError 及 Element Plus 表单、标签和确认框；底层表格使用公共 VxeTable 实现。不新增通用 UI 组件、主题或图标库。package.json 仅声明包标识、公开入口及已有依赖，不包含系统级运行参数。

## 操作与接口

| 对象路径 | 对象编码 | 权限资源 |
|---|---|---|
| person | Person | masterdata.person |
| partner | BusinessPartner | masterdata.partner |
| warehouse | Warehouse | masterdata.warehouse |
| country-region | CountryRegion | masterdata.countryregion |
| product | Product | masterdata.product |

各类固定接口前缀 /api/master-data/{表中对象路径}。GET 前缀对应 Object.list / resource:read；POST 前缀对应 Object.create / resource:create；PUT /{id} 对应 Object.update / resource:update；PUT /{id}/status 对应 Object.setStatus / resource:set_status。

| 参数 | 中文含义与限制 |
|---|---|
| keyword | 编码/名称包含查询，缺省空，最多 200 字符；百分号和下划线为字面字符，不是通配符 |
| enabled | 缺省查询全部，true 查询启用，false 查询停用 |
| page | 页码，从 1 开始，缺省 1，最大 1000000 |
| size | 每页条数，缺省 20，范围 1–100；前端提供 20/50/100 |
| version | 更新/启停必需的非负当前版本，成功递增 1；创建传 0；不接受无条件覆盖 |
| id | 服务端生成的档案 UUID；客户端仅能在当前租户内引用 |

POST 返回新档案 id，PUT 返回空成功响应；GET 返回 rows 和相同筛选下的真实 total。所有成功及业务拒绝响应为 no-store。更新不自动重放；重复创建由唯一编码返回冲突，版本 CAS 保证同一版本仅一次更新成功。此机制不是“相同幂等键返回相同结果”的业务幂等接口，本期不宣称支持该能力。

可信身份仅来自 VerifiedTenantContext 请求属性，浏览器不传租户或操作者。宿主认证/CSRF/上下文版本链继续生效。表名与列名来自枚举白名单，其余参数使用 JDBC 绑定。启停与编辑分别授权，无编辑权限绕过启停控制的路径。跨租户 ID 与不可更新 ID 使用统一 409，避免存在性探测。

| 错误码 | HTTP | 行为 |
|---|---|---|
| MASTER_DATA_DENIED | 403 | 拒绝数据访问，不返回档案 |
| MASTER_DATA_INPUT_INVALID | 400 | 字段不符合固定契约 |
| MASTER_DATA_CODE_CONFLICT | 409 | 编码已存在，不重复新建 |
| MASTER_DATA_CHANGED | 409 | 版本已变化、ID 不可更新或编码不匹配，不覆盖 |

前端失败保留编辑输入，使用公共浮层和重新读取入口，不自动覆盖草稿；取消确认静默处理。启停成功后重新查询，失败不乐观改变原行。初次读取失败使用原数据区域不可用状态，禁止显示成空列表成功。

## 迁移与部署

新增 V75__master_data.sql；不修改任何历史迁移。创建五张独立表、20 个租户权限和主数据目录及五个子菜单。现有系统租户管理员按既有规则补齐；普通及自定义角色不自动扩权。新租户管理员仍经已有受控初始化获取已发布租户权限。菜单页面键在后端 NavigationPages 和前端显式注册表对应，导航可见性不替代 API 授权。

未新增环境变量、端口、URL、密钥或部署开关。服务沿用宿主数据源、事务、认证、CSRF 和受控 Flyway 策略。生产按原部署流程先执行 V75，再部署包含服务的新产物；本期不自动重启正在运行的开发服务。
