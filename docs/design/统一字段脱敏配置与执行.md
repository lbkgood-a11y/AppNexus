# 统一字段脱敏配置与执行

日期：2026-11-09。此文更新上一批按账号字段逐项接入的实现方式。

## 管理员操作

在授权中心选择角色，进入「字段与脱敏」，统一查看该管理域的已声明资源字段。支持按业务资源、敏感类型和字段名筛选；选择多个字段后应用隐藏、脱敏或移除额外限制，填写原因后统一保存。筛选外、未选中和目录外字段不参与批量修改。移除限制不是授予原文读取权，原有功能、租户和数据边界仍须成立。

页面采用既有 ManagementTable 的嵌入模式，保留刷新、列设置、密度和全屏工具；筛选与表格共用 BusinessWorkspace。没有新增 UI 库或独立弹层。角色版本控制完整草稿保存，多个有效角色的强制限制取更严格结果。

## 开发接入

响应 record 使用 `@ProtectedResource` 声明稳定资源名与管理域，String 字段使用 `@ProtectedField` 声明中英文名称及敏感类型。业务模块不编写字段专用算法或 Controller 脱敏调用。统一目录启动扫描 `com.appnexus.platform` 下的资源声明，冲突、非 record 资源及非 String 敏感字段阻止启动；授权保存只接受目录登记项。

内置类型为 EMAIL、PHONE、PERSON_NAME、IDENTIFIER、BANK_ACCOUNT、TEXT，统一执行对应 MASKED 算法；HIDDEN 返回 NULL。字段原值不写日志，不以任意属性路径、SQL 或用户输入脚本定义算法。

`FieldProtectionResponseAdvice` 自动处理全站 Controller 响应，`FieldProtection` 递归投影分页 record、集合、数组和映射中的声明资源，单次调用按资源读取一次策略。不改变原对象；缺少可信主体、管理域不匹配、反射失败或超过 64 层嵌套时拒绝输出，不能降级返回原文。身份来自认证和可信租户上下文，不从响应目标推导。直接进程内读取或非 HTTP 输出应使用同一 FieldProtection 端口；文件流、任意 POJO、原始 Map 内未声明的字段不会自动获得保护，不得宣称这些渠道已纳入。

账号读取已移除邮箱/手机号专用遮盖实现，复用统一投影端口；写入防占位值逻辑仍按业务写入契约保留。统一响应 Advice 提供 HTTP 兜底；内置算法对已遮盖的首批值保持稳定。当前已接入平台账号联系方式、平台成员姓名及租户组织成员姓名；新业务字段声明后自动进入同一目录和执行管线，无需另建配置页面或字段专用脱敏器。
