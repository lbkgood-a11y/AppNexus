# 单据类型与行为契约详细设计

日期：2026-11-12。状态：详细设计草案，待评审，未实施。

本文细化《单据工作台初步设计》的类型、契约、行为和绑定模型；产品方向沿用已确认原则，具体名称、限制及接口是本次建议，不视为用户已确认。首期以组合应用和请假单接入为范围。

架构修订（2026-11-12）：已确认单据模块仅为能力配置与关联中心，与实际业务解耦；平台决定系统单据目录及各租户的配置授权，租户在授权内维护通用服务关系。统一接入契约见[单据服务集成契约设计](单据服务集成契约设计.md)。下文执行器表示业务或专业服务侧职责，不表示由单据服务执行。

## 1. 模型关系与管理边界

一个代码注册的单据类型包含多个版本的投影契约、多个行为声明及业务适配器。每个租户可以为该类型维护配置草稿，并发布不可变的配置版本。行为执行引用单据实例和实际配置版本，产生流程、打印及审计关联。

单据类型目录与功能目录分别存在，通过操作权限码和受控页面标识关联。平台决定目录并按单据类型授权租户，租户管理角色据此维护关系；首期不新增逐能力使用资格或订阅模型。租户已有审批流程和打印场景构建能力继续独立使用，业务操作仍检查现有权限和业务状态。

建议首期设置独立“单据工作台”菜单，功能详情提供关联入口；复用同一权限目录和授权中心。该菜单安排为建议，尚未实现。

## 2. 单据类型声明 DocumentTypeDescriptor

| 属性 | 含义与约束 |
| --- | --- |
| typeCode | 必填、无默认值，代码注册的全平台唯一稳定编码；已有 LeaveRequest 保留，不按展示名称推导，不允许租户改写 |
| moduleCode | 必填、无默认值，所属业务模块标识；不等于独立微服务地址 |
| nameZh / nameEn | 代码默认中英文名称；租户可覆盖展示名称，不改变类型身份 |
| descriptorVersion | 必填、无默认值，正整数；声明内容不可变，变更形成新版本并保留摘要 |
| detailEntry | 必填、无默认值，前端构建登记的详情入口标识；由业务路由解析对象 ID，不配置任意 URL |
| resourceCode | 必填、无默认值，现有授权资源标识；不得通过登记单据自动创建或授予权限 |
| states | 代码声明的业务状态编码与中英文名称；仅供解释、筛选和条件限制，不能驱动通用表直接改状态 |
| projections | 可用投影契约及版本；按用途读取，不统一返回完整业务实体 |
| actions | 支持行为及执行约定；允许配置的范围必须逐项显式声明 |
| providerKey | 必填、无默认值，本地受控注册的适配器标识；由装配解析，不是用户输入的类名或网络地址 |

运行时类型标识采用 typeCode；如目录存储使用 UUID，则 UUID 仅用于管理资源定位，不替代稳定业务编码。重复 typeCode、重复提供器或缺少依赖时拒绝激活，不能静默覆盖。

## 3. 单据身份、版本与状态

### 3.1 单据引用

DocumentReference 由 tenantId、typeCode、objectId 组成。tenantId 从服务端可信上下文取得；对象 ID 首期遵守项目 UUID 约定，业务单号仅用于显示。组织、申请人、状态和版本由业务适配器从存储读取，浏览器不能通过传入这些属性改变单据归属。

### 3.2 版本分类

| 版本 | 用途 | 变化时机 |
| --- | --- | --- |
| descriptorVersion | 业务类型与行为声明版本 | 代码契约变更 |
| contractVersion | 某个投影的数据结构及语义版本 | 字段类型、语义或结构变更 |
| documentVersion | 业务对象乐观锁版本 | 业务定义的内容更新 |
| basisVersion | 审批依据版本 | 影响审批判断的内容变化 |
| configurationVersion | 租户已发布能力配置版本 | 发布新的工作台配置 |
| definitionVersion / templateVersion | 实际流程、打印模板发布版本 | 对应专业服务发布 |

一次执行固定所需的上述版本，不用单一 version 混代。业务记录因回写终态发生更新，不应自动改变被冻结的审批依据版本。首期请假提交后不允许修改依据，沿用其 basisVersion=0；今后重提须显式升级依据或新建单据，并保留原关联。

### 3.3 多维状态

已确认：当前业务状态存放在原业务单据表，业务模块另存审批轮次及流程关联历史；单据中心不建设替代业务状态的通用权威状态表。无有效审批绑定拒绝提交、驳回修改后新轮次重提、提交后冻结依据及撤回修改的默认规则，以《单据业务接入闭环协议》第 5 节为准。该目标约定不表示当前请假 POC 已实现驳回重提。

业务状态由业务服务维护；行为执行、流程、结果交付、打印状态独立存在。例如流程已批准、结果交付重试中时，请假单仍为 SUBMITTED，界面展示“流程已批准，结果同步中”，不能伪装成业务已批准。

类型停用阻止新的用户行为和新实例；已启动流程的可信结果交付、既有任务处理、执行查询和人工恢复继续按各自权限与生命周期规则处理。业务原文访问不因“历史运行”而永久开放。

## 4. 数据投影契约 DocumentProjectionContract

| 投影用途 | 读取内容 | 约束 |
| --- | --- | --- |
| SUMMARY | 单号、标题、状态、组织、时间等索引摘要 | 索引最小化，不携带原因、联系方式等敏感原文；记录级授权仍需成立 |
| WORKFLOW_BASIS | 天数、金额等路由依据 | 仅声明的非敏感标量；从业务存储读取，冻结并按依据版本复核 |
| PRINT_DATA | 表头、明细及打印所需字段 | 可有结构化对象和集合，由打印契约校验；授权处理后才形成打印快照 |

业务原文继续使用业务详情 API，不增加默认返回完整对象的通用投影。SUMMARY、WORKFLOW_BASIS、PRINT_DATA 可以有各自 contractCode 和 contractVersion，不要求同名字段全部公开。

字段声明包括稳定 fieldKey、中英文名称、数据类型、可空性、单位、枚举范围、敏感分类及允许用途。首期条件字段只支持 TEXT、NUMBER、BOOLEAN、DATE、INSTANT 中已实现的操作组合；金额使用十进制并明确币种，日期不隐式转换成时刻。新增类型和比较器必须先实现与验收，不能仅在目录声明。

打印字段结构复用打印服务契约格式；工作台不建立另一套打印 Schema。语义对应通过代码登记的映射标识表达，不由管理人员录入自由字段路径。发布检查不仅比较类型，还需检查单位、枚举、必填性和语义版本。

## 5. 行为声明 DocumentActionDescriptor

| 属性 | 含义与约束 |
| --- | --- |
| actionCode | 类型内唯一稳定编码，必填、无默认值，如 submit、withdraw、print；不直接等同权限码 |
| nameZh / nameEn | 默认操作名称；允许租户覆盖显示文案，系统审计同时保留稳定编码 |
| triggerKind | 必填、无默认值：USER、WORKFLOW_RESULT、DOMAIN_EVENT；同语义多来源使用分别登记的行为 |
| executorKind | 必填、无默认值：BUSINESS、WORKFLOW_START、WORKFLOW_WITHDRAW、PRINT_REQUEST、WORKFLOW_RESULT_APPLY |
| handlerKey | 代码登记的业务处理器或提供器标识，必填、无默认值；不接收动态 URL、脚本或类名 |
| permissionCode | USER 行为必填，引用现有操作权限；系统行为使用可信服务调用与专用授权，不模拟普通用户点击 |
| inputContract | 明确允许的输入结构及版本；无输入时为空结构，不接受未知字段和任意对象 |
| concurrencyMode | 明确 EXPECTED_VERSION 或由执行器定义的冻结版本约定；写行为不得省略并发保护 |
| configurationOptions | 明确允许租户调整的开关、附加条件和绑定类别；未声明项不可编辑 |
| availability | 代码定义的状态及强制规则；仅返回结果码与安全文案，不输出越权对象信息 |

状态提示不能替代业务校验；不同状态可使用同一行为入口，由业务执行器判断合法迁移。界面确认提示不能作为服务端授权证据。需确认内容或金额的行为应由业务契约定义确认绑定，不由通用按钮自行推断。

### 5.1 五类执行器的职责

| 类型 | 固定执行约定 |
| --- | --- |
| BUSINESS | 调用已登记业务命令；业务服务负责校验、写入、幂等和事件 |
| WORKFLOW_START | 业务服务协调提交，冻结依据，解析唯一绑定，可信启动指定流程，保存关联；同库事务原子完成 |
| WORKFLOW_WITHDRAW | 复核本人/授权、关联实例和撤回规则，再调用流程撤回；单据终态由结果交付应用 |
| PRINT_REQUEST | 复核业务查看、打印及输出方式权限，调用受控打印提供器，由场景解析模板并创建任务 |
| WORKFLOW_RESULT_APPLY | 只接受可信流程交付，验证实例、用途、依据与终态，调用业务结果处理器并持久去重 |

系统行为不会出现在普通可执行按钮列表中。DOMAIN_EVENT 的自动打印必须在业务批准事务提交后通过 Outbox 投递，使用明确服务身份及该事件授予的有限能力；不沿用配置人的会话，也不永久保存用户访问权。

## 6. 配置聚合与绑定

一个租户、一个类型的发布配置作为整体聚合，包含名称覆盖、启用状态、行为配置及各类绑定。平台授权该单据后，租户管理角色可维护和发布，不再逐能力申请配置资格。首期原子发布，避免流程关联已生效而结果处理尚未生效。草稿使用 revision 乐观锁，发布生成 configurationVersion；系统保留已发布内容与摘要。

### 6.1 平台声明和租户配置

| 内容 | 租户可调整范围 |
| --- | --- |
| 类型编码、提供器、行为类别、字段类型、触发来源 | 只读 |
| 展示名称、行为启用 | 在代码声明允许范围内覆盖；新行为默认不自动启用 |
| 行为执行条件 | 只能附加 AND 限制；不能取消业务强制限制或授权检查 |
| 权限 | 引用代码允许的现有操作码，首期建议只读；角色授予仍在授权中心维护 |
| 流程绑定 | 从兼容用途、对象类型、契约的已发布流程选择 |
| 打印绑定 | 从已登记打印提供器及兼容场景选择 |
| 结果动作 | 从代码声明的合法结果处理器选择，不能直接填写目标状态 |

首次启用要求完整发布配置，无已发布配置时拒绝新行为。新旧代码部署须检查在用配置依赖；缺失处理器时禁止相关新行为并报告依赖失效，不能降级到默认处理器。部署兼容检查不代替每次执行检查。

### 6.2 流程绑定 WorkflowBinding

包含 bindingId、触发行为、purpose、启用状态、受控匹配条件、流程定义及发布版本、依据契约引用、结果到处理器的映射。均无隐式目标流程默认值；无附加条件表示该绑定覆盖本类型该用途的所有合法提交。

选择顺序：先过滤当前租户和类型的发布配置，再按行为、用途及可信快照判断，恰好一条才启动。不设置优先级。发布期检查可识别的重叠，运行时仍验证唯一性。要求审批的行为不可因未命中而直接完成业务。

工作台绑定负责“启动哪个流程”；流程内部节点条件负责“流程内怎么走”。迁移后不保留两套可独立编辑的流程选择规则，现有模型 matches 需转换或在新启动入口中限定职责，并提供旧接口兼容策略。

结果映射须覆盖流程支持的业务终态。流程发布或绑定发布进行双向兼容检查；结果处理器和配置版本跟随实例冻结，历史交付不读取最新映射。依赖停用时既有实例可继续使用冻结版本，紧急安全禁用则显式阻断并转人工，不自动切换流程。

### 6.3 打印绑定 PrintBinding

包含行为、已登记打印对象/提供器标识、数据契约版本和打印场景引用。首期每个打印行为对应一个场景，多种业务打印用途可登记不同语义行为，如 print、print-label；同场景多模板仍归打印服务。

工作台发布固定场景标识及兼容契约，不复制模板选择规则。每次首次创建打印请求时按当时有效场景配置解析，记录实际版本、模板及参数；随后重试和预览确认使用已解析结果。这样可独立维护打印模板，无需每次重新发布全部单据配置。

若未来需要“严格固定场景版本”，须先扩展打印服务版本接口，再作为显式策略提供；当前不可宣称已有。输出方式、份数与设备覆盖遵循打印场景权限，打印动作启用不表示允许任意设备、静默打印或下载原文。

## 7. 公开接入端口草案

以下是职责划分，不是已存在的 Java 接口签名；类型命名在工程详细设计中确定。

| 端口 | 职责与调用约定 |
| --- | --- |
| DocumentRegistry | 获取代码登记的类型、契约、行为及处理器；不接受浏览器动态登记 |
| DocumentBindingResolver | 接收可信上下文、类型、行为、用途及有限条件值，返回固定配置版本和能力绑定；不执行行为 |
| DocumentRelationReporter | 接收已认证来源的关联事实，以事件 ID 幂等更新关联投影；不改变业务与专业服务状态 |
| 业务侧工作流适配器 | 由业务模块拥有，读取可信依据，调用工作流并接收结果；不放入单据核心 |
| 业务侧打印适配器 | 由业务模块拥有，授权取得打印数据并调用打印服务；不跳过打印服务自身权限检查 |

可用操作查询必须以指定单据为范围，返回 actionCode、显示状态与安全原因码；可查看但不可执行可显示禁用原因，无查看权的对象返回统一不可访问响应。执行仍重新检查权限和版本。

创建、编辑、详情与行为执行均使用业务或专业服务 API，不提供单据服务通用执行入口。业务侧可复用接入 SDK，但 SDK 不拥有业务状态机或事务。行为可用性由业务服务查询并校验。

## 8. 行为执行、幂等与故障

本节描述业务服务及专业服务的接入义务，执行记录和执行状态由实际执行模块拥有；单据模块只保存配置解析记录及执行关联投影，不建设公共行为执行状态机。

1. 从会话或可信服务身份建立上下文，定位类型与对象，检查授权。
2. 将请求键与租户、类型、对象、行为绑定，计算规范化输入摘要；稳定摘要不包含凭据。
3. 首次执行解析配置、版本和绑定；同键重放核对摘要，返回原执行状态，不重新解析最新配置。
4. 业务执行器在事务内锁定或条件更新对象，复核状态与版本，再执行业务和专业服务调用。
5. 提交执行结果、业务关联及必要 Outbox；敏感快照留在对应业务或专业服务，公共日志只保存关联和安全摘要。
6. 异步执行用稳定子调用 ID 投递，技术故障有限重试，业务拒绝转人工；不把 HTTP 超时当作执行失败重新发起。

幂等重放仍检查当前调用方对原记录的读取权；不能凭请求键访问他人执行。当前版本检查只用于首次执行业务，成功后对象版本变化不应使合法重放重复执行。

执行记录建议状态：ACCEPTED、RUNNING、SUCCEEDED、REJECTED、RECOVERY_REQUIRED。首期同库同步拒绝可直接返回且不留下未提交执行；跨服务阶段的“未执行/未知/执行中”必须可区分，不能用 REJECTED 掩盖未知结果。重试次数及时间参数在实施时按现有任务机制明确，不在此虚构配置默认值。

原始行为成功边界：提交成功表示实例已建立且关联已提交；打印成功表示创建任务成功；结果应用成功表示业务终态已提交。下游长期状态通过关联资源查询。最终打印成功或审批成功不是对应原始行为持续 RUNNING 的理由。

## 9. 请假单映射与迁移

| 项目 | 首期建议 |
| --- | --- |
| 类型 | LeaveRequest，保留已有对象身份 |
| 状态 | DRAFT、SUBMITTED、APPROVED、REJECTED、WITHDRAWN，沿用业务实现 |
| 流程依据 | days：NUMBER、自然日、单位天；requiresHr：BOOLEAN 保留兼容，后续可直接按 days 配条件 |
| 用户行为 | submit、withdraw；print 仅在真实提供器、场景和模板完成后开放 |
| 系统行为 | apply-approval-result，支持 APPROVED、REJECTED、WITHDRAWN，复核原实例并幂等 |
| 权限迁移 | 从 workflow:start 拆出正式请假查看/提交/撤回/打印操作码；具体编码由权限详细设计登记，不自动扩大旧用户权限 |
| 业务规则 | 组织任职、主管有效性、1—365 自然日、原因长度及提交后冻结继续由请假服务校验 |

迁移顺序：先建立单据声明与只读目录，再引入工作台发布配置及精确流程启动桥接，随后让请假提交与结果处理使用新契约；保留旧历史实例所需适配，最后接入真实打印。旧实例继续由旧引用处理，不能修改原流程关联伪装成新版本。

WorkflowBusiness 的元数据迁出不等于删除其安全校验。当前可见能力目录按 workflow:start 过滤、设计者依赖发起权限等耦合应随迁移拆分：查看/配置契约、执行业务、办理任务分别授权。工作台不能直接复用当前 businesses 查询作为完整单据目录而沿用错误权限语义。

## 10. 最小持久化与验收草案

公共层首期只保存：类型声明版本快照、平台目录和租户配置授权、租户配置草稿与发布版本、绑定解析记录、单据与流程/打印的关联投影。行为执行记录、业务单据表、workflow 表、打印任务表由实际执行模块维护。单据全量索引及统一查询中心另行建设。

最低验收覆盖：声明冲突、未知处理器、越权目录读取、配置并发发布、契约不兼容、流程零/多匹配、精确版本启动、旧实例结果映射稳定、同键异输入、并发提交、任务临时授权失效、跨租户原文与打印拒绝、打印请求与实体结果区分、类型停用后的历史交付、业务成功后自动打印失败恢复。

详细表结构、接口 OpenAPI、事务调用时序及前端交互稿作为下一批设计。本文没有修改现有运行时、配置默认值或交付状态。
