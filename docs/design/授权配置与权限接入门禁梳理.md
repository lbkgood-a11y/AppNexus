# 授权配置与权限接入门禁梳理

日期：2026-11-20。依据：当前工作区源码静态追踪；工作区含正在进行的 MyBatis、对象执行等改动，结论不是已提交版本或部署版本验收。本轮交付为规范与改造范围，不修改业务代码、页面或策略，不代表自动门禁已实现。

## 1. 强制基线与梳理结论

所有接入业务对象必须唯一声明并接通统一权限执行，执行[业务规范 3.1](../development/业务服务统一开发规范.md#31-统一权限模型强制接入)。管理员通常只配置一次对象范围，平台仍逐操作授权；默认范围不授予功能权限。未声明、未执行、可绕过以及适用证据缺失都阻断功能交付。

现有页面按操作重复配置；已有启动校验、功能拦截、租户 SQL 门禁和对象专项测试只能提供部分保证。当前不能自动全面发现三类缺口，必须保留人工逐入口复核。以下“已有”仅表示阅读到实现或测试源码，不表示本轮运行通过。

## 2. 授权页面重复配置与理解成本

路径均相对仓库根目录。

| 位置与源码锚点 | 实际行为 | 重复或理解成本 | 改造范围 |
|---|---|---|---|
| `frontend/modules/authorization/src/AuthorizationCenter.vue`：`grouped`、`policies`、`scopeChanged`、`incompleteCount`、`permission-row` | 按资源分组，但每个已选权限各有范围、组织、规则编辑；策略按 permissionId 保存 | 同一对象多个操作范围相同时重复选择；功能、范围、字段分处页签，难以一次看懂完整授权 | 对象摘要，操作勾选，对象默认范围；差异操作才展开覆盖，保存前预览新增/撤销/变化 |
| `frontend/modules/authorization/src/MemberGrantEditor.vue`：`scoped`、`changeScopeMode`、`policy`、`scope` | 当前成员在当前角色分支整体继承或自定义；自定义后逐权限维护范围 | 同样的操作范围再次编辑；角色继承与将来的对象默认继承容易混淆 | 保留成员继承角色，新增对象层摘要及操作覆盖；明确每层来源和恢复继承，不将成员编辑变成功能授权 |
| `frontend/modules/authorization/src/DataGrantRuleEditor.vue`；上述两页均调用 | 规则编辑器已经共用，但仍按操作实例化 | 复用代码没有减少管理员需要维护的策略数量 | 对象默认规则只编辑一次，仅对实际支持 RULES 的操作生效；差异覆盖仍共用编辑器 |
| `frontend/modules/authorization/src/PolicyTemplateActions.vue`：`save`、`apply` | 保存已持久化角色快照，应用时完整覆盖并校验版本、原因及确认 | 有模板，仍不能表达对象内持续默认继承；不能称为实时模板继承 | 保留快照语义，加入覆盖差异预览和新策略版本兼容验证，不默认新增持续模板绑定 |
| `frontend/modules/authorization/src/SubjectAuthorization.vue`：`effective`、`diagnostics` | 已有有效权限解释与操作诊断 | 不能仅凭功能通过推出某条记录可读写，更不能推出最终字段可见 | 复用统一判定补充对象、操作、记录及字段结果和来源；未执行检查明确显示未检查 |
| `frontend/modules/authorization/src/index.ts`：`DataPolicy`、`MemberGrant`、`DataAccessDeclaration` | DataPolicy 以 permissionId 标识；成员仅有分支级 inheritDataScope；前端声明投影未带完整操作关系 | 缺少持久化的对象默认/操作覆盖来源，页面不能可靠还原“相同值”和“继承”的区别 | 扩展公共契约与声明投影；不得通过权限码字符串猜对象或通过值相等推断继承 |

配置规模说明：角色数 R、每角色对象数 O、每对象已授权且支持范围的操作数 A，当前范围编辑单元约 R×O×A，成员自定义另行增加。目标约 R×O 加实际覆盖项；这是结构估算，不是现场统计或性能指标。功能勾选仍独立存在。

## 4. 页面、公共模型与迁移范围

实施顺序必须先明确公共契约和执行保障，再开放配置。以下均为待实施范围：

1. **对象声明与公共授权模型**：唯一声明输出对象→操作→权限→受支持范围/维度→执行语义；定义对象默认策略、显式操作覆盖及来源。创建验证目标归属，更新验证原记录与目标，删除验证目标，规则适用性以真实能力为准。
2. **继承与安全语义**：仅有功能权限的操作才解析范围，角色功能与范围保持同分支，多有效分支 OR、字段限制保守合并及可信租户强制规则保持一致。默认缺失/不支持不回退 ALL；新增操作不因对象默认自动获得功能权。取消覆盖回到实时对象默认；成员继承角色与自定义对象策略分别建模，角色变更不得静默覆盖成员自定义。
3. **公共 API 与存储**：扩展现有授权中心角色/成员 API、决策/执行端口和版本令牌，不建业务私有策略表或接口。对象默认按 objectType 和管理域持久化，操作覆盖引用 operationCode；存储位置由现有平台授权模块拥有。扩表或新表须遵守审计与迁移规范。后端解析继承，不能只由浏览器展开成副本。
4. **存量迁移**：旧逐操作策略首先保留为显式覆盖以保持效果；完全相同也不能自动断言有持续继承意图。用户明确合并才转默认。覆盖角色、成员自定义、模板快照及声明版本，迁移前后比较已授权操作、有效记录范围和字段限制，拒绝静默扩大授权；历史迁移不改。
5. **页面**：复用 BusinessWorkspace、ManagementTable、ManagedDialog、Element Plus 和现有规则编辑器。以对象为行展示允许操作、默认范围、覆盖数量、字段限制；差异展开编辑，创建文案使用目标组织。提供未配置提示、恢复继承、批量草稿设置、保存差异及多角色实际结果；不另建权限管理入口或 UI 库。上线前执行真实页面及全局布局继承验证。
6. **诊断**：实际授权结果关联分支与范围来源，明确其他角色可能扩大范围、字段限制仍收口；记录诊断须先具备诊断准入且不泄露无权对象存在性，显示通过/阻断/未检查/不适用。

## 5. 工程门禁的实施与验收范围

| 优先顺序 | 改造项 | 验收标准 |
|---|---|---|
| P0 | 全入口反向声明检查 | 正式应用任意新增未登记 MVC 业务入口使启动/测试失败；任务、事件和回调按各自可信注册入口检查；声明不存在/重复、动态入口目标非法均拒绝 |
| P0 | 公共执行及受控存储 | 先覆盖代表性完整对象及全部读写路径，缺少/错用对象操作或租户上下文被拒绝；非 HTTP 入口有独立可信上下文；锁定/条件写入保证授权与事务一致，失败不推进审计 |
| P0 | 绕过反向测试 | 列表/COUNT/详情、创建目标、修改原记录及目标、删除、主从、批量、字段覆盖/删除、跨租户同 ID、撤权/停用/过期、并发及无策略验证；故意移除执行或替换写条件时必须失败，不能只测试拒绝桩 |
| P1 | 公共默认/覆盖模型及迁移 | 角色、成员、模板、版本冲突、迁移前后效果及继承来源全部可验证；功能和范围同分支，规则不支持时拒绝，不能只改前端 |
| P1 | 角色/成员页面简化 | 无差异对象只编辑一次范围，差异覆盖可见可恢复；普通用户理解摘要与实际执行一致；按 UI 规范完成主题、语言、视口及布局动态继承验证 |
| P1 | 全模块架构与 CI 集成 | 覆盖正式装配模块、持久化访问及受控后台入口，检查范围不依赖已声明 Provider 自证完整；输出机器可读缺口并真正阻断，禁止放宽断言或扩大例外 |
| P2 | 最终效果诊断及存量逐对象迁移 | 按实际身份、对象、操作和适用记录解释来源；每个迁移对象提交完整证据链，未迁移项如实保留，不宣布全仓完成 |

P0 是能力改造优先级；从本规范生效起，自动门禁尚未实现不能豁免交付前的人工复核与真实安全验证。页面及全部自动门禁是否完成必须另行验收。本轮不含实现、部署、共享环境策略变更或全站浏览器验收。
