# 审计中心一期详细设计

日期：2026-11-27。状态：设计稿，运行验收待实施。

## 1. 范围与归属

一期覆盖租户出仓确认单签发与冲销，以及平台账号的平台角色授予与回收。审计中心提供在线列表、详情和关联跳转。业务详情中的创建、最后更新信息继续使用[全局记录审计](全局记录审计设计与验收.md)。批量导出、告警及历史回填留待后续。

沿用唯一的 AuditEvent Provider 和现有平台审计能力。仓储用例提供已确认的交接、库存流水及范围证据，平台授权用例提供角色分配差异，审计能力负责事件接收、存储与授权查询。业务操作引用来源对象的有效声明。平台沿用现有声明，仓储须先恢复或提供真实可执行的出仓来源操作，过滤及字段投影复用统一权限执行。事件跨模块发布时遵循[统一事件信封](统一事件模型详细设计.md#4-事件信封与负载)。

## 2. 事件字段

每个操作使用已登记的稳定操作标识。以下字段是逻辑契约，实施时映射现有审计模型。

| 字段 | 约定 |
| --- | --- |
| eventId、schemaVersion | 全局唯一事件 ID、负载版本。旧事件缺失新增字段时按未知展示。 |
| occurredAt、recordedAt | 可信服务端确定结果的 UTC 时间、持久化 UTC 时间。成功按提交状态判定，页面按当前时区展示。 |
| domain、tenantId | 管理域为租户仓储、平台角色或受限安全域。租户 ID 仅取可信上下文。平台角色事件无租户 ID。 |
| initiator、executor | 主体类型及稳定 ID。分别表示发起人和执行账号或服务。鉴权前无法验证的主体留空，拒绝前未执行时执行主体留空。 |
| objectType、objectId、operationCode | 来源对象类型、经服务端核验的对象 ID、已登记操作。拒绝时无法核验的对象 ID 留空。 |
| outcome、reasonCode | 成功、权限拒绝、业务拒绝、执行失败。非成功必须提供稳定安全原因码；前端按码显示授权后的提示。 |
| attemptId、correlationId、effectId | 服务端生成的尝试标识、贯穿关联操作的追踪标识、已提交业务效果的稳定标识。effectId 仅用于实际生效事件。 |
| relatedEventId | 已知时关联原事件。签发到冲销也可通过原交接 ID 或流水 ID 追溯，兼容缺少原审计事件的历史数据。 |

| 操作 | 成功证据及粒度 |
| --- | --- |
| 签发出仓确认单 | 每笔实际交接一条。记录单据 ID 和事件时编号、交接 ID、仓库与货主 ID、适用的批次或卷号、库存流水 ID、实际库存变动量及单位。多个变动项逐项存储，金额或重量使用精确十进制，库存扣减方向明确。 |
| 冲销出仓确认单 | 每笔实际冲销一条。记录冲销 ID、原单与原交接、原流水和冲销流水、恢复量及单位、冲销原因（由命令提供时）。仍按原交接的已核验仓库和货主确定审计范围。 |
| 授予平台角色 | 每个实际新增的账号与角色关系一条。记录目标全局账号 ID、平台角色 ID 和事件时角色名称、分配关系 ID、分配状态由无到有，以及命令提供的原因。 |
| 回收平台角色 | 每个实际移除的账号与角色关系一条。记录同样的目标与角色证据、被移除的关系 ID、分配状态由有到无，以及命令提供的原因。回收详情只描述该角色关系。多角色操作共用关联 ID。 |

拒绝与失败按操作尝试记录，保留已可信解析且允许留存的目标标识及原因码。成功专属字段留空。事件快照采用字段白名单，禁止写入原始请求、凭证、令牌、堆栈或完整单据。历史快照独立于当前名称解析，授权后的当前名称可用于辅助识别。无法解析时保留已获准显示的历史证据。

## 3. 留痕时机、事务与重试

| 结果 | 持久化时机与一致性 |
| --- | --- |
| 成功 | 用例得到真实变更结果后，在业务事务内写审计事件或持久化 outbox。业务提交后对查询可见。仓储核对库存、流水及适用的占用和授权核销，平台核对角色分配关系。审计事件或 outbox 写入失败时，业务事务一并回滚。 |
| 权限拒绝 | 服务端统一准入或行范围执行作出最终拒绝后，在独立事务写入。没有可信仓库或货主范围的记录进入一期拟新增的受限安全审计入口。 |
| 业务拒绝 | 准入通过后由业务规则拒绝，例如单据状态不允许签发。待业务事务结束后独立写入。 |
| 执行失败 | 用例异常且确认事务回滚后独立写入。提交结果暂不确定时，应按效果标识对账后判定。已提交但响应丢失时沿用已持久化的成功证据。 |

同一已提交效果以来源、管理域、操作及 effectId 去重，并复用现有业务命令的幂等依据。重授同一角色后的新关系可产生新的授予和回收记录。消息重投继续使用同一事件 ID。不同的请求尝试可分别留下真实失败记录，同一尝试被多层处理时按 attemptId 去重。合法无变更操作沿用业务返回语义，不产生变更成功事件。

失败留痕在返回结果前确认审计写入或可靠补写入口已持久化。若两者均不可用，仍维持原有拒绝及业务回滚，触发运维告警并记录覆盖缺口，恢复后对账。采用异步投影时，记录积压及补投状态，并验证重启可恢复。

## 4. 查询与查看权限

| 入口 | 查询方式 | 服务端准入 |
| --- | --- | --- |
| 租户审计列表（现有 GET /api/audits） | 时间范围、操作、结果、操作者、出仓单号、仓库、货主。详情显示授权后的证据及关联签发、冲销和流水。 | 可信租户成员、现有入口的 organization.permission:grant，以及拟新增的 warehousing.audit:read。每条记录的事件时仓库与货主均须落在当前有效数据范围中。 |
| 出仓确认单详情 | 以稳定单据 ID 查询事件时间线。签发、冲销、已获准的失败按时间展示。 | 同时满足当前单据读取授权和仓储审计读取条件。 |
| 平台审计列表（现有 GET /bff/platform/audits） | 时间范围、操作、结果、目标账号、平台角色、操作者。平台账号授权页可预填目标账号筛选。 | 有效平台管理准入及 audit.entry:read。进入账号授权详情仍检查目标操作原有读取权限。授予和回收目前共用 Account.rolesReplace，要求 access.role:grant。 |
| 受限安全审计入口 | 以时间、操作、结果和关联 ID 查询范围未核验的拒绝记录。 | 要求有效平台管理准入及拟新增的 audit.security:read。普通租户审计和平台角色审计查询均排除这类记录。 |

列表先施加管理域、租户、数据范围及字段约束，再筛选、统计与分页。默认按 occurredAt 和 eventId 倒序，单据时间线按同一组合正序。筛选条件以授权内的可信标识解析，受保护字段也不得通过筛选、候选项或计数推断。列表只返回摘要，按事件 ID 取详情及关联事件时重新授权。被撤权后的请求从服务端按当前授权决定结果。详情 ID 对不可见与不存在返回一致结果。业务对象归档后，已获授权者仍可看留存的历史证据，跳转按目标接口当前准入执行。

## 5. 权限与历史事件核对

### 5.1 现有权限与一期新增权限

| 能力 | 源码核对与一期接线 |
| --- | --- |
| 仓储审计 | AuditEventDeclaration 和 AuditQueryService 共同要求租户入口具备 organization.permission:grant。AuditQueriesMapper 的租户查询只读取平台管理、字典、参数、集成四类摘要，暂无仓储分支或仓库、货主范围执行。拟在同一 AuditEvent Provider 中登记 TENANT 权限 warehousing.audit:read，保护新增仓储列表、详情和时间线。沿现有租户审计列表查看仓储分支时两个权限均需满足，既有四类记录沿用原门禁。单据时间线要求仓储审计读取及原单据读取权限。 |
| 出仓命令 | V181 退役出仓确认单、交接冲销入口及 warehousing.outbound.coil:handover、warehousing.outbound.coil:reverse_handover 等权限。旧 issue 权限也已退役。V182 移除了原交接、交接行和冲销表。当前工作树未找到前述出仓操作的有效替代入口。出仓审计的端到端交付依赖实际出仓与冲销用例恢复或重建，并在来源 Provider 中声明有效操作。 |
| 受限安全审计 | SecurityLogController 的 GET /bff/account/security-logs 绑定 Account.securityLogs，资格为 SELF，AccountDeclaration 的权限码为空，从当前认证账号读取 account_security_log。该入口只承担本人安全日志。拟在 AuditEvent Provider 中登记 PLATFORM 权限 audit.security:read 并新增专用查询，结合平台管理身份验权，显式授予安全审计职责。audit.entry:read 单独持有时无权访问。 |
| 平台角色审计 | AuditEvent.platformList 沿用 audit.entry:read。AuditQueryService 同时校验平台管理员。现有查询读取 platform_administration_audit，支持平台管理员指定租户查看既有租户摘要。新增仓储与安全事件不进入该可选租户查询。平台角色变更由 Account.rolesReplace 写入，审计读取需另接授权审计来源。 |

### 5.2 历史事件兼容映射

| 已有数据 | 映射规则 |
| --- | --- |
| access_authorization_audit 中 PLATFORM、tenant_id 为空、target_type 为 ACCOUNT、action 为 ACCOUNT_ROLES_REPLACED | SubjectRoleMapper 写入 actor_account_id、target_id、reason、before_snapshot、after_snapshot，MyBatisSubjectRoleManagement 仅在实际发生角色集合变更时写入。对两个角色 ID 数组做集合差。after 减 before 为授予，before 减 after 为回收，结果为成功。使用来源表、原行 ID、方向和角色 ID 生成确定性的投影事件标识，同一原行共享合成关联标识。沿用原时间、操作者、目标账号及受保护的原因。缺少事件时角色名称、单个关系 ID、请求追踪或执行主体时留空。保留原始审计行，异常快照进入对账清单。角色定义权限变更与租户成员角色变更保留各自原分类。 |
| 旧钢卷交接与冲销 | V182 之后无法通过原业务表直接重建。只读核查仍存的审计原行或权威归档，只有能验证操作、实际效果、可信租户、仓库及货主的记录才具备映射条件。库存流水只作为可关联佐证，四字段、库存余额及现有库存归属均不用于推导事件。缺证据标记历史未覆盖，一期不批量回填。 |
| account_security_log 与其他既有审计来源 | 本人安全日志继续以自身事件类别查询，集成调用的 HTTP 状态及其他来源摘要保留原语义。当前未核实能证明一期仓储权限拒绝、业务拒绝或事务失败的历史审计来源。一期从专用采集入口启用时开始记录。 |

一期采用读取时兼容平台角色历史事件，不批量改写存量。切换时为同事务双写确定唯一查询来源或建立原行到新事件的关联，列表、详情与计数统一去重。验收用包含新增、移除和保留角色的同一历史快照，检查差集、关联标识、未知字段及新旧切换无重复。

## 6. 一期留存策略

一期仓储操作和平台角色变更事件在线留存 **365 天**，覆盖一个年度盘点及权限复核周期。受限安全事件在线留存 **180 天**，为事件排查保留连续窗口，同时限制未核验请求的安全元数据积累。仓储和平台业务域内的失败事件与对应成功事件使用同一窗口。

按可信 occurredAt 的 UTC 时间计算到期，每天为 24 小时，时间缺失的历史记录暂不自动清理。调查、争议或保全明确冻结的事件暂停到期处理。关联签发仍需供留存期内冲销取证时，至少保留核验所需的最小关联证据至冲销到期。受限安全记录保持其独立读取门禁。

一期仅对新体系纳管的记录执行到期清理。现有源表、库存流水、本人安全日志及 outbox 各自沿用所属生命周期。历史投影可按一期窗口限制在线展示，原记录保留。清理启用前应以数据量估算、边界样本和恢复演练校验，并记录每批清理的策略版本、时间范围及数量。验收检查到期边界、冻结例外、新旧投影以及清理前后查询权限一致。

## 8. 验收场景

| 场景 | 通过标准 |
| --- | --- |
| 同一单据分批签发再冲销其中一批 | 每批成功记录与实际扣减流水、数量及单位对应。冲销指向正确的原交接与原流水，另一批库存未被冲回。 |
| 授予再回收，另一个角色仍提供同一权限 | 能按目标账号查到两笔关系变化及操作者。回收后账号的剩余权限按独立授权链路验证。 |
| 事务失败与提交后响应丢失 | 注入仓储及角色命令中途异常，业务变更、成功事件一并回滚并有失败事件。提交后断响应，再用原键请求，业务效果和成功记录仍各一份。 |
| 并发、重投与无变更 | 同一交接或关系并发提交、投影重启、消息重投都不重复记录已提交效果。已存在授予和已不存在回收按原业务语义处理。 |
| 拒绝类别及安全域 | 分别触发权限拒绝、业务拒绝和执行失败，验证分类、原因码及字段最小化。提交伪造仓库、货主和跨租户对象，普通审计列表、详情及计数均不泄露记录。 |
| 当前授权与历史范围 | 用同租户有权、缺仓库、缺货主、跨租户、撤权及过期主体验证列表、详情和跳转。账号改名或单据归档后，允许查看者仍能查询历史快照。 |
| 平台职责隔离 | 仅具授予权限、仅具审计读取权限及具备两者的账号分别验证读写准入。租户审计读者不能查看平台角色事件。 |
| 字段保护、分页和浏览器 | 验证受保护字段在列表、详情、筛选及数字统计中一致受限。实际页面走完筛选和关联跳转，验证主题、移动视口及全局布局继承。 |
| 留痕链路故障 | 验证审计写入失败阻断成功提交，失败记录可补写并保持去重。存储和补写同时不可用时能发现缺口并在恢复后对账。 |

实施验收使用真实数据库和浏览器场景，在 docs/validation 记录门禁及 D01–D12 的适用性、变更对照、证据和未验证项。部署前实测容量和查询性能，以第 6 节的留存窗口估算数据量。

## 9. 实施批次与独立交付条件

批次 A 优先交付。批次 B 可独立实施和验收，批次 C 在出仓用例满足接入条件后启动。各批次自行完成事件写入或可靠接收、授权查询、留存处理及运行验收。共用 AuditEvent Provider 和公共审计能力时，新增操作各自登记并按管理域启用，未启用批次的菜单和查询入口保持不可用。批次验收结果按实际启用的链路记录。

| 批次 | 依赖与启动条件 | 改动范围 | 独立交付门槛 |
| --- | --- | --- | --- |
| A 平台角色审计 | 现有 Account.rolesReplace、access_authorization_audit、平台管理身份校验和 audit.entry:read。 | 接通平台列表、详情及账号授权页带条件跳转。将 ACCOUNT_ROLES_REPLACED 的历史角色集合差映射为授予和回收。接通新命令的成功、拒绝及失败留痕，处理新旧来源去重，执行 365 天在线留存。 | 真实数据库验证授予、回收、多角色替换、无变更、回滚和重试。历史差集正确，缺失字段保留未知，新旧切换无重复。分别验证仅有授予权限、仅有审计权限及缺少平台管理准入的账号。完成列表、详情和关联跳转实测。 |
| B 受限安全审计 | 统一准入能提供可信操作标识和拒绝结果，具备独立的持久化或可靠补写能力。可先接入现有平台角色变更命令的权限拒绝，仓储拒绝采集随批次 C 接入。 | 在 AuditEvent Provider 增加 audit.security:read 和平台受限查询，记录受控操作、时间、可信主体（若已验证）、结果、原因码及关联 ID。平台角色命令的同一次拒绝按 attemptId 只保存一份事实，受限记录仅通过专用入口查询。执行 180 天在线留存。 | 至少以一条真实平台角色变更拒绝完成端到端验收。验证有权安全审计员可查，仅有 audit.entry:read 的平台人员、租户成员及本人日志用户均无法读取。列表、详情、筛选及计数无泄露。验证独立留痕、故障补写、去重、到期和冻结。 |
| C 仓储审计 | 恢复或重建真实可执行的出仓确认单签发和冲销，先确认有效对象与操作声明、库存流水、原交接关联、事务及幂等契约。需要将范围未核验的拒绝交给受限安全查询时，批次 B 的采集和查询能力须可用。 | 新增 warehousing.audit:read、租户查询分支、授权详情及单据时间线。接入分批签发、冲销、拒绝和失败，按可信仓库及货主执行可见范围。落实库存流水跳转、证据保护及 365 天在线留存。 | 真实数据库完成分批签发与指定批次冲销，核对库存、数量单位、原交接和原流水。实测同键重试、回滚、伪造范围、跨租户、撤权及归档后追溯。验证未核验拒绝仅在受限入口可查。实际浏览器完成单据时间线及关联跳转。 |

批次 A 与 B 的事件归属以可信管理域和允许留存的证据为准。A 先上线时，平台列表可读取归属已核验的角色事件。需要受限可见的拒绝先独立持久化，专用查询随 B 开放。B 先上线时，以现有平台角色命令作为首个真实采集入口，平台角色历史投影和业务审计列表随 A 开放。

每批在 docs/validation 独立记录 D01–D12 同步复核、适用交付门禁、真实数据库与浏览器证据、到期及冻结验证、上线和回退边界。回退时停用对应新入口或投影，保留已持久化的审计证据。适用门禁失败或未验证时，该批次不能标记交付完成。
