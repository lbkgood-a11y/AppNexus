# 打印服务设计与选型记录

日期：2026-11-10。状态：需求与接入方向已确认；HiPrint 已获准引入并完成基础适配，尚未完成生产准入。本文区分讨论结论、当前实现与待验证能力。

## 讨论结论摘要

1. 建设统一单据设计、输出与打印能力，采用“业务数据 + 发布模板”的方式；Web 设计器是核心准入条件，优先服务频繁改单的业务人员。
2. 采用开源组件二次封装路线，当前以社区维护的 vue-plugin-hiprint 为接入基础；不是直接采用停更的原始 HiPrint，也不引入商业 Web Studio 代码。
3. A4、标签/条码、面单、小票以及选择打印机、预览后打印、静默打印均保留为目标；PDF、Word、Excel 保样式导出没有被取消或降级。
4. 平台负责字段契约、模板草稿与不可变发布版本、权限和租户隔离、设备路由、打印任务、幂等、审计与人工补打；静默打印通过可访问设备的代理完成。
5. PDF 优先验证统一 Chromium 渲染路径；Word/Excel 是必须单独验证和研发的输出能力，不能假设 HiPrint 原生支持，也不默认采用整页图片交付。
6. Windows 开发测试与 Linux 部署均需支持；具体 CentOS 版本、无桌面部署方式和设备兼容矩阵尚待确定。
7. 接受对 HiPrint 进行必要安全与工程改造。关键隔离、认证、脚本约束和受支持运行时是上线条件，不全部推迟到以后；维护受控分支的具体范围以验证结果确定。
8. 商业化前核清核心 LGPL/商业许可来源及依赖义务；本地开发接入已授权，不代表生产分发许可和安全检查已完成。

当前已交付基础接入包与工程目录；完整设计器页面、模板后端、渲染服务、设备代理和多格式输出仍未实现。下一步先用真实单据完成输出、安全和目标系统验证，再收敛正式实施范围。

## 1. 需求基线

- 浏览器设计器是核心能力，面向变化频繁的实体单据，由业务人员在线调整布局和字段。
- 业务数据与已发布模板结合，支持 A4 文档/报表、标签/条码、面单、小票。
- 支持选择打印机、预览后打印、静默打印；支持 PDF、Word、Excel，要求保留单据样式。
- 优先使用开源组件进行二次封装，面向未来商业化与客户私有化交付。
- Windows 用于开发测试，Linux 为重要生产目标；CentOS 具体版本待确认，不能承诺任意发行版或驱动兼容。
- 打印代理必须部署在能访问目标设备的机器上；平台运行在 Linux 不代表客户端也必须运行在同一台机器上。

## 2. 选型结论与替代关系

| 候选 | 当前结论 | 原因 |
| --- | --- | --- |
| UReport2 | 排除 | 维护与安全风险不符合长期商业化目标，不以现成 Web 设计器抵消维护成本 |
| JasperReports Library | 保留为输出能力备选 | LGPL 允许有条件商业使用，但不等于获得 Web Studio 授权；Web 模板模型转换成本未验证 |
| JasperReports Web Studio | 商业采购候选，不作为开源设计器引入 | 官方商业套餐包含 Web Studio；外部客户设计、OEM、再分发、私有化和贴牌须书面确认 |
| vue-plugin-hiprint | 在线设计与打印优先验证候选 | 原生 JSON 模板、拖拽、动态表格、条码、预览和配套客户端贴近业务场景 |
| electron-hiprint | 打印代理改造参考 | 有跨平台与静默打印基础，运行时、权限隔离、通信认证需要实质改造 |
| node-hiprint-pdf | 隔离渲染服务参考 | 使用 Puppeteer，可生成 PDF；示例配置不能直接作为生产部署 |

不采用反编译商业 Web Studio 后包装销售的路线。独立实现能力与复制商业代码的授权边界不同。
不预设将 HiPrint JSON 转为 JRXML；先验证原生渲染链路，避免维护两套布局语义。

## 3. 已核查的能力与缺口

本轮证据为上游文档、许可证、依赖声明和部分源码，不包含真实设备、Linux 部署、性能或完整漏洞扫描。
已引入的开发依赖精确锁定为 0.0.62，更新日志包含 2026-10-08 记录；开发锁定不代表该版本已获生产准入。

| 能力 | 结论与约束 |
| --- | --- |
| Web 设计、字段绑定、JSON 模板 | 已有基础；工具库不是完整 Vue 业务组件库，平台页面需封装 |
| 动态表格、分页、多面板、标签条码 | 已有基础；长文本、跨页合计、面单定位和扫码精度待验证 |
| 连续小票 | 列为验证项；不将排版支持等同于切纸或设备原生指令支持 |
| 静默打印与打印机发现 | 依赖代理；浏览器原生打印对话框不能可靠反馈用户是否打印 |
| 浏览器 toPdf | 检查到图片写入 PDF 的路径，不作为正式归档默认路线 |
| Chromium PDF | 优先验证路径；统一字体、资源和引擎版本，仍需检查实际产物 |
| Word/Excel 保样式 | 未找到足够的内置实现依据；保留为需求，不降级为已完成或默认整页图片 |

Word/Excel 属于新增输出研发，不是简单缺陷修复。自由定位与 Office 布局差异需要转换规则和兼容约束；如调整需求，必须另行确认。

## 4. 商业许可准入

vue-plugin-hiprint 根许可证为 MIT，但核心 hiprint.bundle.js 保留 LGPL 或商业许可声明，README 也确认其上游来源。
不得据外围 MIT 将整个核心视为 MIT；必须核清 LGPL 版本、完整文本、修改与分发义务、权利来源及依赖许可证。
Electron 和 Node 参考项目的根许可证为 MIT，不自动覆盖全部依赖、二进制工具、图片和字体。
许可问题不能通过代码修复消除；允许已授权的本地开发依赖验证，完成准入前不向客户商业分发第三方核心或客户端二进制。

## 5. 架构与工程边界

| 目录 | 职责 |
| --- | --- |
| backend/services/print-service | 模板、发布版本、数据契约、打印任务、设备路由、租户权限、审计；本次仅创建 Maven 聚合骨架 |
| frontend/modules/print | 已建立 @appnexus/print 包与隔离适配；尚无业务页面或路由 |
| printing/renderer | 未来独立 Chromium 渲染进程，接收受控模板和数据，生成 PDF |
| printing/agent | 未来桌面/站点代理，适配系统打印队列与设备协议 |
| printing/validation | 真实单据、目标环境、打印设备与多格式验收矩阵 |

后端遵守 services/<name>-service 命名；正式跨进程协议明确后再建立 contracts，不提前共享数据库实体。
本次不决定打印服务独立启动还是组合装配，不注册运行时依赖、端口、数据库迁移和菜单。
UI 使用当前 vue-pure-admin、Element Plus、@appnexus/ui 和 @appnexus/icons；不照搬 HiPrint 演示的 Ant Design/Bootstrap。
新增画布的原因是现有模板基础组件不提供物理纸张布局和打印元素编辑；外围操作仍复用平台组件。

## 6. 上线前必须完成的安全与可靠性工作

- 升级受支持的 Electron/Chromium 与依赖，基于实际锁定版本及传递依赖扫描；本轮不声称发现或修复具体 CVE。
- 核心存在 eval/new Function 路径；模板应视为潜在执行输入。引入受限表达式，服务端校验并限制实际执行路径，不能只隐藏脚本入口。
- 打印/渲染窗口关闭 Node 集成、开启上下文隔离并收敛 IPC 权限；不加载业务主会话。
- 本地服务默认限制回环访问，显式站点模式另行受控开放；强制认证、来源校验和设备授权，不使用公开演示中转站或通用固定凭据。
- 渲染服务采用隔离进程、网络/文件访问白名单、超时、资源配额和故障恢复；不得直接暴露接受任意 URL 的示例接口或无隔离浏览器。
- 固定模板、数据快照、资源和渲染版本；租户归属由可信身份确定，不能信任模板传入租户标识。
- 业务幂等键与任务、代理执行关联；已提交系统队列不等于纸张完成。结果未知不自动重打，人工补打记录原因并关联原任务。
- Linux 支持按具体版本与设备验证；Electron 桌面客户端不等同于无桌面守护服务，不为旧系统长期保留过时运行时。

## 7. 分阶段验证与交付

1. 许可及供应链：锁定源码版本、权利来源、完整许可证和依赖清单，确定可分发边界。
2. 核心技术验证：复杂 A4、标签、面单、长小票；同模板导出 PDF、DOCX、XLSX，记录样式差异和不可支持能力。
3. 安全工程化：表达式、认证、隔离、运行时升级和目标系统适配。
4. 平台闭环：模板草稿/发布/回滚、数据绑定、预览、设备权限、打印任务、审计与补打。
5. 真实环境验收：Windows/目标 Linux、字体、驱动、DPI、断网、重启、重复提交和结果未知。

在许可和关键输出验证通过前，不将候选方案表述为最终定型。业务样本和设备不得以虚构验收结果替代。
此前 2—4 周技术验证、6—10 周首轮改造、再 4—8 周稳定化仅是有条件估算，不包含完整 Office 输出研发，不作为承诺排期。

## 8. 当前工程交付与后续待决

初始交付为文档、目录及后端 Maven 聚合入口。2026-11-10 增量：frontend/modules/print 已安装 vue-plugin-hiprint@0.0.62，增加独立 iframe 适配、模板基础检查、预览/快照/销毁接口。尚无业务设计页面、API、服务端渲染或打印代理实现。
后续待决：具体 CentOS 版本、代表单据与打印机、Word/Excel 样式容差、许可确认、发布版本、运行部署及团队排期。

### 接入验证记录

- Windows Edge 无头浏览器通过 A4 空白模板加载、快照（宽 210 mm）、预览/返回设计、销毁与主窗口未污染检查；不是完整业务单据或视觉验收。
- sandbox 不授予同源权限，CSP 禁止网络连接；本地资源由主窗口读取后交给独立文档，客户端自动连接在求值前锁定关闭。
- 上游 UMD 的 jQuery、JsBarcode、bwip-js 作为固定版本本地资产加载；不加载 Socket.IO、jsPDF、canvg 的运行实现，对应能力禁用。依赖树仍包含上游声明的可选能力，不能将未加载等同于依赖漏洞已修复。
- pnpm audit 检出 HiPrint 依赖链 jsPDF/DOMPurify 等告警，同时工作区已有其他告警；当前未做全量修复或可利用性结论。生产准入前审计实际锁及发布产物，不以隐藏入口替代修复。
- 内部试接入已获用户授权；原记录“准入前不导入”的范围在此明确调整为允许本地开发依赖验证，商业分发门槛保持待完成。
