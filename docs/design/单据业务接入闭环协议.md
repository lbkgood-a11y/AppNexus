# 单据业务接入闭环协议

日期：2026-11-12。状态：已确认需要统一闭环接入；本协议的字段、调用步骤与处理策略为待评审详细设计，未实施。

## 1. 目标与权威边界

统一声明、解析、执行、回调、关联上报及对账语义，使合同、请假等业务使用相同集成规则。单据服务仅管理目录、授权范围、配置、绑定解析及关联投影。业务与专业服务通过公开契约交互，不经单据服务转发原文或执行命令。

| 事实 | 权威来源 |
| --- | --- |
| 单据内容、业务状态、审批轮次、业务与实例关联 | 业务服务 |
| 系统类型目录、租户配置范围、发布绑定 | 单据服务及平台授权管理 |
| 流程实例、任务、终态、结果交付 | 工作流服务 |
| 场景、实际模板、打印快照、任务及输出结果 | 打印服务 |
| 操作授权、开通及强制访问限制 | 平台现有权限能力与业务规则 |

任何投影缺失都不代表权威关联不存在；防重复提交、判断可操作状态须查业务及专业服务权威记录。

## 2. 提供者声明与寻址

业务部署声明 ownerService、typeCode、契约版本、projectionKey、capabilityKey 和支持的输入/输出结构。业务服务标识由平台可信部署登记映射到本地适配器或远程服务客户端；租户不能填写 URL、类名或凭据，服务不能凭自报身份接管其他类型。

目录包含以下独立能力：读取审批依据、读取任务范围原文、提供打印数据、应用流程结果、查询业务关联及补发事件。不存在的能力必须明确缺省且拒绝调用，不能默认反射实体或直接查询数据库。

提供器是业务侧端口，工作流或打印通过公开协议调用，单据服务不代理数据。远程调用每次验证服务身份、租户范围、操作目的及实际用户或有限服务委托；单据 ID、任务 ID、resolutionId、链接均不是凭证。任务原文访问复核当前有效任务及字段范围；打印按独立授权投影生成文件，不能复用审批快照冒充完整合同。

## 3. 全链路关联标识

| 标识 | 语义与约束 |
| --- | --- |
| documentReference | 租户、类型、对象 UUID；业务单号不作为主键 |
| businessOperationId | 业务服务持久化的本次操作 UUID；与请求幂等键关联，重试保持不变 |
| approvalCycleId | 业务服务创建的审批轮次 UUID；一次合法重新提交流程生成新轮次，旧轮次保留 |
| purpose | 已登记用途，必填；不同用途可有独立活动轮次 |
| documentVersion / basisVersion | 内容并发版本和冻结依据版本，按业务契约分别校验 |
| resolutionId / configurationVersion | 本次固定绑定解析及配置发布版本；不授予执行权 |
| workflowInstanceId / printRequestId | 专业服务返回的资源标识；首次响应丢失可按稳定操作键查询 |
| invocationId | 工作流可信交付的稳定执行标识；重试不变 |
| eventId / causationId / correlationId | 事件去重、直接因果和整链追踪；不能用追踪 ID 替代业务幂等键 |

首期审批型业务同单据、同用途仅允许一个活动轮次。发起的唯一性由业务及工作流权威存储约束，不能依赖中心投影或 UI 按钮。

## 4. 声明、授权与发布

1. 部署流程提交不可变业务声明及契约摘要，平台审核激活类型；登记不自动纳入系统目录。
2. 平台按单据类型授权给租户，首期不拆分逐能力配置范围或独立使用资格。
3. 授权后租户管理角色可以维护、修改和发布关系配置；直接复用租户已有审批流程及打印场景构建能力。业务数据访问和普通用户操作沿用现有授权，不因配置权自动扩大。
4. 发布检查类型、行为、投影、流程版本、结果处理和打印场景依赖，并生成不可变配置版本。静态校验不保证业务数据运行时必然匹配。
5. 预演只能解析并解释命中，不发起流程或打印；使用真实样本时先由业务服务授权供数，工作台不自行读取业务库。

普通绑定升级只影响新的解析。已固定解析的操作继续使用原版本，但仍检查当前权限、业务依据和安全禁用。紧急禁用由权威服务明确标记，相关执行阻断并进入诊断，不能悄悄替换目标。配置权收回与使用停用分开，默认是否保留旧配置仍需明确产品规则。

## 5. 提交与流程启动

### 已确认的默认业务约定

- 需要审批的提交未找到有效绑定时明确失败，普通用户收到联系租户管理员的提示，不自动进入流程设计器。租户管理角色可从绑定配置进入流程创建、发布并返回绑定。
- 驳回后允许修改并重新提交，每次合法重提创建新审批轮次和实例，保留旧依据及审批关联历史；业务模块可以声明更严格限制。
- 提交后冻结审批依据字段，需要修改时先按规则撤回，再修改重提。其他字段是否允许更新由业务模块决定，不能隐式改变已冻结依据。
- 当前业务状态记录在原业务单据表，由业务服务唯一维护；流程状态、交付状态由工作流服务维护，不建立替代业务状态的公共权威状态表。
- 业务模块保存独立的审批关联历史，包含用途、轮次、依据版本、流程实例及配置解析引用；单据中心只维护可延迟的关联或状态投影。
- 查询、保存、提交、打印等操作由开发人员实现并登记，既有权限体系负责授权。提交经业务服务校验、解析绑定并启动实例；共享本地事务时实例创建、业务关联及提交状态原子生效，重复提交不重复创建实例。

上述是统一接入默认约定，不要求不同业务采用相同状态编码，也不替代单据领域自身的合法状态迁移。

### 5.1 共同步骤

业务服务验证身份、权限、单据状态和期望版本，创建稳定操作标识及审批轮次，从存储读取有限条件值，调用绑定解析。解析结果固定流程定义和具体版本、依据契约及结果映射。工作流启动必须携带业务轮次与稳定启动键并返回同键原实例，不能只以 HTTP 请求成功与否判断是否创建。

绑定解析与流程启动是两次调用：工作流需通过受信任机制校验绑定目标和来源，例如服务端查询解析记录或使用可验证的绑定证明。浏览器转交的流程 ID、版本和映射不可直接信任；证明格式及密钥治理在安全接口设计时确定，不能把普通 resolutionId 当签名。

### 5.2 组合部署

仅在确认业务、工作流共享本地事务管理器和数据源时，业务冻结、轮次保存、实例创建及权威关联一起提交。解析可先完成，再进入事务重查版本，避免把远程配置请求放进长时间业务锁。事务失败不留下半提交单据；已解析记录可保留，但不代表行为执行。

### 5.3 跨服务部署

业务事务保存提交意图、依据、轮次和 Outbox，将本次提交标记为待确认；是否映射为 SUBMITTING 等业务状态由模块决定，不强制所有单据同名状态。可靠启动命令携带稳定操作键，工作流幂等创建，业务侧接收结果或主动查询后保存实例关联并确认提交。

引擎可能先结束而业务关联确认尚未到达：业务侧依据预先持久化的轮次和启动意图识别可信结果，无法确认时暂缓交付并对账，不能按未知单据永久拒绝，也不能直接应用未核实结果。状态未知期间禁止同用途再开新轮次。

通信超时先按操作键查询；确认从未创建且不存在未决启动消息后才终止本次尝试。无法证明未创建时进入恢复，不能回到草稿任意重提。补偿需显式业务协议，不默认删除流程或反向修改业务库。该机制为未来设计，不声称现有工作流已支持远程提交协议。

## 6. 办理与结果应用

工作流处理任务；业务原文从业务提供器按任务范围授权读取。任务权限结束后原文授权失效，不影响依法留存的最小处理意见及审计；历史原文另按业务权限提供。

结果交付携带单据引用、purpose、approvalCycleId、basisVersion、实例 ID、终态、固定映射和 invocationId。业务侧先验服务身份与租户，再在本地事务内锁定关联和单据，同时检查：

- 实例确实属于该轮次与用途，且是业务当前允许应用的关联。
- 冻结依据未变化，单据处于允许处理本次结果的状态。
- 结果动作来自本轮固定配置，并是业务已声明动作。
- 已有 invocationId 的内容完全一致；同键异内容作为冲突，不当作成功重放。

旧轮次结果不修改新轮次单据：记录过期结果并返回明确不可应用原因，由交付策略归档或人工处理。幂等去重不能替代过期检查。应用成功时业务更新、去重记录及业务事件 Outbox 同事务提交；合同审批通过只表示审批结论，不能默认签署或生效。

## 7. 打印与自动行为

用户打印由业务 API 校验操作权、数据范围、打印投影及输出方式，解析打印场景后调用打印服务；打印服务仍执行设备、场景和输出授权。首次建请求时固定场景解析、模板版本和授权快照，后续预览确认及技术重试使用固定结果。

打印语义必须显式区分 CURRENT_DOCUMENT、APPROVAL_BASIS、EXISTING_ARTIFACT：分别打印当前业务版本、特定审批依据版本、读取已有文件。它们是待实现的语义选项，不意味着打印服务已有对应枚举。业务不保存历史内容时不能承诺重现审批版本；历史文件下载也必须重新授权。

自动打印以业务结果成功提交后的唯一权威事件触发，例如 ContractApprovalApplied，而不同时订阅流程结束和合同状态变化触发同一行为。子行为幂等键由来源事件、目标行为和目标单据确定；人工重印是新的显式业务请求，技术重试复用原键。

每个自动订阅声明唯一输入事件和输出事件，发布时检查已知循环；运行时记录因果链并限制循环触发。禁止无边界事件互相驱动，不能只依靠消息去重防止不同 eventId 构成的循环。首期不开放任意自动动作链，先提供受控审批结果后打印。

## 8. 关联上报与对账

业务服务上报权威单据关联，工作流与打印服务上报自身执行事实。投影按来源独立版本更新，乱序事件不覆盖新事实，不以事件时间排序替代版本。重复消息同 ID 异内容进入冲突诊断。

单据中心支持按来源水位或游标增量核对；业务及专业服务提供受控关联查询和补发能力，不要求扫描公开业务原文。对账发现目标存在而关联缺失时，从权威来源补齐；发现孤立流程时先查询原启动意图及操作键，不能自动新建、取消或改业务终态。

查询结果携带投影更新时间和同步状态；未获来源确认的缺失表示“尚未确认”，不能标为“确定没有流程”。人工恢复记录操作者、原因及原事实，修复通过来源服务或重放事件，不直接改投影冒充业务成功。

## 9. 依赖故障与升级

| 情形 | 处理约定 |
| --- | --- |
| 单据中心不可用 | 新解析明确失败；业务仍可保存不依赖解析的草稿，历史流程和打印继续运行 |
| 流程启动响应丢失 | 按稳定操作键查询，禁止换键盲目重启 |
| 结果回写暂时失败 | 使用原 invocationId 重试，流程终态与业务同步状态分开 |
| 关联上报失败 | Outbox 积压补发及对账，不阻断已完成业务 |
| 旧契约处理器下线 | 部署兼容检查阻止不安全下线；必须保留版本适配或先完成受控迁移 |
| 紧急安全禁用 | 权威服务显式拒绝相关动作，记录原因；不可用旧解析绕过 |

发布新代码前查询在用配置、活动轮次和未完成交付依赖。正常升级不能删除仍被使用的契约或回调处理器；不能因 UI 不再展示就视为可以删除。

## 10. 后续接口设计清单

需形成统一 Schema：类型声明、受控提供器寻址、绑定解析与可验证来源、精确版本幂等启动、审批轮次结果交付、打印投影及历史模式、关联事件、来源对账查询。认证、时间/数量限制、重试与留存参数必须在接口及部署说明明确，不在本协议中虚构默认值。

验收至少包含：配置与执行之间停用、解析结果篡改、零/多匹配、旧轮次迟到结果、启动成功响应丢失、结果先于关联确认、重复异内容事件、关联乱序及缺口、自动打印重复触发、打印失败不回滚审批、历史契约仍可交付、单据中心故障不阻断历史任务。

第一阶段可先实现同进程协议并以请假单验收，但公开模型须保留远程情况下的轮次、操作标识及关联事实。远程恢复协议未实现时必须明确标记支持范围，不将组合部署验证作为分布式保证。
