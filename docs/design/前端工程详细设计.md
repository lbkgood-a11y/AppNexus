# 前端工程详细设计

版本：0.6；日期：2026-11-06。

## 当前实现基线

前端已进入正式功能开发，应用壳和持久化登录接入位于 apps/admin；领域包仍以骨架为主。以下描述当前代码，后续目标能力未列入本节时不代表已经实现。

```text
frontend/
├─ apps/admin/                 vue-pure-admin 7.0.0 应用壳；BFF 登录入口
├─ modules/
│  ├─ audit/
│  ├─ authorization/
│  ├─ configuration/
│  ├─ identity/
│  ├─ localization/
│  ├─ organization/
│  └─ tenant/
└─ infra/
   ├─ icons/                  平台公共图标包 @appnexus/icons
   └─ security/               会话上下文辅助类型（尚未接入正式 BFF）
```

根目录通过 pnpm workspace 管理 `apps/*`、`modules/*`、`infra/*` 。包使用 `@appnexus/<名称>` 命名，并通过 package exports 暴露 `src/index.ts`。当前管理应用已导入 vue-pure-admin 7.0.0 的完整布局、主题、导航、标签页和设置组件，使用 Vue 3、Pinia 3 与 Vue Router 5；只注册首页和错误路由。领域模块以公开入口和单元测试为主，尚无领域页面、路由描述或分层目录。上游版本、改造记录与拟定 BFF 契约见 [UPSTREAM.md](../../frontend/apps/admin/UPSTREAM.md)。模板应用已通过类型检查与生产构建；持久化 BFF 登录已接入正式应用，真实 HTTP 测试覆盖 MySQL 账号与 Valkey 共享会话，浏览器已验证登录、后台布局、刷新保持会话与注销拦截，不表示登录交付完成。

当前未实现：`common`、`infra/http`、`infra/i18n-engine`、`infra/pure`、独立 `tests` 包；独立壳适配包、其他场景的浏览器验收及生产故障验收、依赖边界 lint/检查规则，以及租户切换时取消请求和清理路由/缓存等行为。不得将后续目标结构视为当前目录或已验证能力。

## 应用壳目录与清理规则

当前 apps/admin 的主要目录：

- src/layout：保留上游完整布局、三种导航模式、标签页、主题、设置、搜索及通知组件。
- src/router、src/store：应用壳路由与状态；用户状态只保留会话展示字段和注销动作。
- src/views：基础控制台首页、登录入口/账号密码表单与错误页。密码通过标准受 CSRF 保护的表单交给授权服务器，Token 不进入 JavaScript。
- src/api：BFF 会话接入及当前空动态路由适配。
- src/components、src/directives、src/utils、src/plugins、src/style：仅保留现有应用壳引用的能力。
- build、types、locales、public：构建配置、类型、语言资源和必要静态资源。

已删除未使用的 Mock、模板账号设置/空白演示页、手机号/二维码/注册/找回示例组件、旧密码登录与刷新 Token API、演示图表/编辑器/地图等组件，以及演示音频、WASM 和图片资源。首页不展示模拟业务数据。根目录 components 占位包已删除，跨领域组件有实际复用需求时再创建；领域模块骨架及 security 会话辅助类型保留，正式 BFF 适配当前位于 apps/admin/src/api/session.ts。

新增包、组件、依赖必须有实际使用方；模板组件保留在应用壳内，稳定跨领域组件再提取到 workspace 公共包。尚未实现的目标目录不提前创建空包。构建、类型检查与现有单元测试用于验证裁剪后的引用完整性；它们不替代真实登录和浏览器布局验收。

## 平台图标与主题

- 平台公共图标入口为 `@appnexus/icons`，以 Remix Icon 线性图标为统一图标集，复用 Iconify/unplugin-icons 编译能力。SVG 在构建期按需生成，不依赖运行时远程图标接口；不额外引入另一套图标库。
- 公共包导出 AppIcon、PlatformIconName 和 platformIcons。业务页面通过语义名引用，例如 `<AppIcon name="user" :size="18" />`。新增图标先在映射中注册；size 单位为像素，默认 20；独立表达含义的图标通过 label 提供无障碍说明，装饰图标自动隐藏。
- 模板已有 ReIcon 作为上游壳内部兼容能力保留；新平台/业务功能使用公共入口，不导入 admin 的内部图标组件。公共图标包不依赖后台模板的布局或 Store。
- ThemeToggle 提供浅色、深色、跟随系统三种模式，接入登录页及纵向/横向/混合导航。通过模板现有主题适配入口保存 themeMode 和 darkMode，复用原有偏好存储；导航与设置面板同步，不建立第二份主题配置。
- 跟随系统模式监听 prefers-color-scheme；手动选浅色或深色后不受系统变化影响。主题偏好只属于展示设置，不承载账号、Token 或租户身份。
- 登录页使用 Element Plus 主题变量和公共图标，提供中英文文案、响应式表单及语言切换。只显示已实现的登录功能，不增加未接通的验证码、注册或第三方登录入口。
- 已通过浏览器验证主题切换/刷新保持/系统跟随、语言切换、登录/后台/注销主题连续性及移动端无横向溢出。

## 个人中心与会话体验

个人中心入口位于纵向、横向及混合导航的账号菜单，路由 /account/profile 保留完整后台布局。页面展示不可修改的账号标识与登录名，允许本人保存显示名称，并刷新顶部名称；修改密码需输入当前密码、新密码及确认密码，成功后清理本地展示状态并要求重新登录。密码仅保存于当前组件内存，请求结束主动清空，不写入 URL 或持久存储。

api/account.ts 统一获取当前会话 CSRF 凭据后发送资料修改及改密请求。HTTP 错误入口区分 401、403、429、网络/服务故障及标准 ProblemDetail，禁止把密码和请求正文输出到日志。会话失效清理用户展示、菜单、标签页缓存，并在登录页提示失效原因；改密成功显示专用提示。

后台每 60 秒以及窗口恢复焦点/可见时检查服务端会话，隐藏页面或最近 60 秒没有真实键盘/指针交互时不发定时请求，避免轮询持续延长空闲会话，同一时刻只允许一次检查。该周期只决定提示时机，不放宽后端每次请求的会话验证。网络或 5xx 故障不注销用户；启动探测失败显示错误页而非误报账号失效。后续还需完善跨标签主动通知及更多故障场景体验。

## 全站 UI 与组件基线（强制）

具体执行标准见[前端 UI 与代码生成规范](前端UI与代码生成规范.md)，由根目录 AGENTS.md 纳入代码生成强制规则。本文负责架构与职责，UI 规范负责视觉、组件选型、交互状态及验收，后续修改应同步两者。

全站界面以 vue-pure-admin 为唯一布局和交互基线，前后端功能交付遵守同一视觉规范。优先复用模板现有增强组件，再使用模板采用的 Element Plus 基础组件；只有没有合适能力时才新增组件，并记录原因。禁止另行引入平行 UI 框架或仅因样式偏好重写模板能力。

后台统一复用现有应用壳、导航、标签页和主题设置。登录与个人中心沿用模板相应页面范式，使用既有表单、按钮、菜单及状态反馈，局部 CSS 只负责业务排布和响应式适配。字体与颜色沿用模板全局样式和 Element Plus 变量，不在业务页建立独立主题。

公共图标 @appnexus/icons 延续模板 Iconify/Remix Icon 线性风格，仅做语义映射与按需 SVG 导出；模板内部 ReIcon 保持兼容。ThemeToggle 是对模板既有主题能力的薄适配：用于跨登录页和三种导航统一提供模式快捷入口，复用原有存储，不替代模板设置面板。

本次收敛：个人中心分区导航改用 Element Plus el-menu / el-menu-item，返回操作使用 el-button，避免自绘菜单及按钮。其余业务页新增时必须先检查模板可复用能力，按 AGENTS.md 的规则验收视觉和交互一致性。

## 已确认的方向

- 使用 vue-pure-admin，以桌面浏览器为主，保留框架主要布局与交互。
- 第一期统一部署，支持门户与各系统独立地址，未来按需独立部署；暂不引入微前端。
- 必须模块化、结构清晰，与后端领域命名保持一致。
- 前端框架可替换、可升级，降低未来应用拆分成本；不让业务模块依赖后台模板内部实现。
- 采用 pnpm workspace、单一 `admin` 应用、领域模块化及 `infra/pure` 壳层隔离的总体结构已确认。
- 当前应用壳基于 vue-pure-admin 7.0.0；独立适配包及认证端到端验证尚未实施。

## 目标工程结构

目标采用 pnpm workspace，在同一仓库内提供显式包边界；第一期只有一个应用，不提前建立多个空应用。下列目录是目标布局，不是当前实现清单。

```text
frontend/
├─ apps/
│  └─ admin/                  第一阶段应用启动和装配
├─ modules/
│  ├─ identity/
│  ├─ tenant/
│  ├─ organization/           当前包名；对应后端组织领域
│  ├─ authorization/         当前包名；授权与权限能力
│  ├─ localization/          当前包名；国际化领域能力
│  ├─ configuration/         当前包名；平台配置领域
│  └─ audit/
├─ common/                   稳定类型与最小公共契约
├─ components/               跨领域组件与业务无关交互
├─ infra/
│  ├─ http/                  请求、错误、取消与追踪适配
│  ├─ security/              会话与权限适配
│  ├─ i18n-engine/           统一国际化前端运行能力
│  └─ pure/                  vue-pure-admin 壳层集成
└─ tests/                    架构与跨模块集成验证
```

目录名称与后端保持同义，前端不机械复制后端 DDD 四层。workspace 包名使用 `@appnexus/<名称>`，例如当前已有的 `@appnexus/organization`、`@appnexus/security`，通过作用域避免包名冲突，不重复堆叠前缀。目标目录名与现有模块包名以领域含义对应，不要求目录名缩写。

领域模块内部建议：

```text
organization/src/
├─ api/                      接口 DTO、映射与调用
├─ model/                    前端类型、校验及纯业务展示规则
├─ application/              用例、组合逻辑与模块状态
├─ pages/
├─ components/
├─ locales/
├─ routes.ts                 框架无关的页面注册描述
└─ index.ts                  显式公开入口
```

复杂业务规则仍以服务端为准。模块内部可按规模合并文件，不为简单页面建立空层。

## 依赖与框架隔离

- 应用装配模块选择领域模块、服务地址、入口、导航及布局；模块不得反向依赖应用。
- 模块通过公开入口使用其他模块的能力，禁止导入对方内部页面、Store 或私有文件。
- 业务模块不得直接导入 vue-pure-admin 内部路由、权限工具、布局、标签页或全局 Store。
- `infra/pure` 将页面注册、菜单、布局、主题、标签页等契约适配到模板；模板升级主要落在适配层和应用壳。
- HTTP、会话、权限、国际化通过统一入口使用，不在页面重复创建实例。
- Vue Router、状态管理和 UI 库的使用限制在表现层或适配层；纯类型、规则及用例不依赖模板内部。
- 不要求包装全部 UI 控件；优先封装权限字段、组织选择、金额日期、列表查询等稳定复用能力。
- 引入依赖检查和 lint 规则，禁止深层跨包导入，以检查落实边界。

这套隔离降低替换后台模板的成本，但不承诺无成本替换 Vue 或所有 UI 组件。框架迁移仍需改写表现层；接口契约、模型和部分用例可复用。

## 模块注册与权限

模块导出稳定标识、入口页面、路由描述、菜单候选项、语言资源及所需平台能力。壳层负责转换为实际路由，不让模块自己修改全局路由实例。

后端系统开通及用户授权决定可访问范围；前端注册资源不是授权。菜单和按钮仅做体验控制，直接访问 URL、API 以及字段返回仍由后端校验。

动态菜单通过受控页面标识映射到构建内页面，不加载任意远程代码。找不到注册页时显示明确错误，不绕过权限或跳转其他租户。

## 多租户状态与统一引擎

会话上下文由平台统一维护。切换租户时取消旧请求、清空租户缓存、重建路由和授权；返回的响应需核对发起时的上下文版本，不能将旧租户响应写入新租户状态。

统一封装国际化能力，模块仅声明翻译资源和必要业务上下文。展示语言、时区与币种分别处理；前端格式化不替代后端金额计算和权限脱敏。无权限的原始字段不应进入浏览器。

多标签页与会话租户的对应关系须与后端会话方案一起确认，不能仅通过浏览器本地存储确定租户身份。

## 升级与应用拆分路径

1. 第一期由 `apps/admin` 装配所有底座模块，通过不同地址进入对应功能。
2. 业务系统接入时创建对应模块与明确公开入口，不增加对壳层内部的依赖。
3. 需要独立部署时增加新的应用装配目录，选择其模块、布局与配置，复用公共包。
4. 多个应用共享会话与租户选择的方式通过认证协议明确，不假定跨域 Cookie 自动可用。
5. 替换 vue-pure-admin 时新建壳层适配器，复用领域模块；以功能、路由、权限和主题验证迁移结果。

应用拆分不同时等于仓库拆分。workspace 内先完成独立构建，确需独立仓库时再发布版本化公共包，避免过早增加发包维护工作。

建议将模板初始版本与本地改造记录分开维护，记录升级改动，避免大规模修改上游内部实现。vue-pure-admin 的实际目录、许可证和可扩展点须读取所选版本后验证，再确定最终迁移布局。

## 验收与待决事项

- 任一模块不依赖其他模块私有文件或模板内部实现。
- 可用最小壳装配单个模块进行构建和验证，检查是否隐藏依赖全局状态。
- 替换模拟的 HTTP、权限、国际化适配器后，模块用例仍可测试。
- 租户切换时旧请求、菜单、标签页及缓存不泄露上一租户信息。
- 桌面主要页面中英文切换正常，日期和金额统一格式化。
- 一个新增示例应用能够只装配指定模块独立构建，不复制领域代码；该验证不作为正式业务场景交付。

待确认：包划分细节、服务契约生成方式、测试工具、壳层实际适配点、多标签页会话语义和浏览器支持范围。当前 admin 使用 Pinia 3，状态管理限制在应用壳和表现层。vue-pure-admin 7.0.0 应用壳与正式登录接口已接入。版本候选基线见[技术版本与许可证基线](技术版本与许可证基线.md)。

本批个人中心浏览器验收已通过：显示名称保存/刷新及导航同步、当前密码错误反馈、改密后使用新密码登录、独立旧会话失效，以及模拟 503 保留页面和 401 清理会话。管理员密码未修改，验收使用独立临时账号并已清理。

个人中心参考模板设置页采用左侧账号与分区导航、右侧内容布局，已实现个人信息、偏好设置、账号安全三分区。section 查询参数仅接受固定白名单以支持刷新恢复；头像使用默认图标，不展示未接入的上传按钮。偏好复用平台主题/语言存储并即时生效，账号安全通过展开式表单修改密码。安全日志、联系方式验证和头像上传尚未实现，暂不展示模拟日志或无效操作；通知系统未接入前不提供通知开关。

## 安全日志列表

个人中心新增安全日志分区，使用现有 Element Plus el-table、el-tag、el-pagination 和加载/错误反馈，不引入额外表格依赖。每页 10 条，提供刷新、空态和失败重试；仅展示本人操作、成功结果和时间。稳定事件代码经中英文资源映射，时间点用 Intl 按浏览器时区展示，提示中保留原始时间点。

列表不展示尚未采集的 IP、地理位置和设备信息，也不模拟历史事件。对应后端契约为 /bff/account/security-logs。后端每次请求校验账号和凭据版本；分页中只接受最新请求结果，避免旧响应覆盖新页。

个人中心局部切换：路由 meta.reuseOnQueryChange=true，使模板内容视图按 route.path 而非 fullPath 保留实例；仅 section query 更新右侧分区。外框、左侧账号菜单和已加载资料不重建，不重复请求资料；密码在离开分区时仍清空。其他路由及 iframe 维持模板原 fullPath 键策略。

个人中心新增登录会话分区，继续局部切换。使用 el-table、el-tag、el-button 和 ElMessageBox，展示真实会话创建/最近访问时间，当前会话固定标记。撤销前说明后果并确认，提交期间防重复；当前会话不提供撤销按钮，使用现有退出登录。加载失败与空态区分，不显示模拟设备信息。

登录会话新增“退出其他登录”：POST /bff/account/sessions/revoke-others，必须携带 CSRF；服务端按主体索引取快照并排除当前会话，删除目标后记录 OTHER_SESSIONS_REVOKED。无目标时返回 revoked=0，不追加成功日志。并发新登录不在快照范围，执行中请求不保证中断；Redis 删除与 MySQL 日志不是原子事务，故障时可能部分完成，界面提示失败并允许刷新重试，不承诺事务回滚。前端使用模板确认弹窗和危险操作按钮，保留当前会话。
