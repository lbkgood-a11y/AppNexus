# 组织管理员初始化与授权

2026-11-06。本文覆盖组织单元 CRUD 与租户成员能力授权子集，不代表完整角色、数据行和字段权限模型已完成。

## 部署配置流程

1. 先由受控运维建立租户与有效账号的成员关联。登录账号初始化 `APP_BOOTSTRAP_USERNAME/PASSWORD` 仍只创建认证账号，不创建租户或组织权限。
2. 在可信运维数据库连接中核对目标的租户 UUID、成员 UUID 和账号状态；成员 UUID 不是账号 UUID。禁止按“首个登录者”或固定用户名推断管理员。
3. 单一受控部署先执行 V10 迁移。将下表两项环境变量成对注入后启动应用；默认不配置时不做任何赋权。
4. 初始化锁定有效租户、成员和账号，为该成员授予 READ/CREATE/UPDATE/DELETE/GRANT，并在同一事务写入五条授权审计和每租户唯一初始化标记。
5. 成功后移除两项变量。原成员重复启动无副作用，不恢复已撤销权限；改配另一成员、无效目标或存在历史 GRANT 但无初始化标记时拒绝启动。已有管理权限需继续走运维治理，不使用初始化覆盖。
6. 用该账号登录、选择指定租户，从“组织管理”菜单进入。授权区选择有效成员，可授予、续期或撤销四项 CRUD 权限；GRANT 不可通过普通接口委派或撤销。

| 环境变量 | 用途、默认与边界 |
|---|---|
| APP_ORGANIZATION_BOOTSTRAP_TENANT_ID | 现有有效租户 UUID；默认空，与成员参数成对配置；仅初始化该租户，不创建租户 |
| APP_ORGANIZATION_BOOTSTRAP_MEMBER_ID | 上述租户中现有有效账号的有效成员 UUID；默认空；首次授予五项能力并审计，成功后移除，不用于恢复权限 |

只读核对语句（经可信运维连接执行，不在前端提供全平台目录）：

```sql
-- 仅核对可初始化的租户、成员与账号；不读取密码哈希或凭据。
SELECT BIN_TO_UUID(t.id) AS tenant_id, t.name AS tenant_name,
       BIN_TO_UUID(m.id) AS member_id, a.username
FROM platform_tenant t
JOIN tenant_member m ON m.tenant_id = t.id
JOIN identity_account a ON a.id = m.account_id
WHERE t.enabled = TRUE AND m.enabled = TRUE AND a.enabled = TRUE;
```

## 页面与接口

菜单 `/organization/manage` 复用模板应用壳和卡片；无能力时展示无权限状态，按钮按实时能力显示。页面刷新重新读取权限；服务端逐请求验证权限，不将菜单可见性当作安全边界。没有租户时引导租户选择。菜单为公开导航入口，实际数据不向无权限成员返回。

- GET `/api/organization/capabilities`：本人当前租户的有效能力。
- GET/POST `/api/organization/units`、PUT/DELETE `/api/organization/units/{id}`：按 READ/CREATE/UPDATE/DELETE 校验，仓储强制租户条件；名称 1–100 个 UTF-16 字符且非空白。
- GET `/api/organization/grants/members`：仅 GRANT 成员可读的当前租户有效成员摘要。
- GET `/api/organization/grants/{memberId}`、POST `/api/organization/grants`、DELETE `/api/organization/grants/{memberId}/{capability}`：沿用已有授权、锁顺序及审计事务；不可委派 GRANT。到期时间为未来 ISO 8601 时间点，缺省/null 永久有效。
