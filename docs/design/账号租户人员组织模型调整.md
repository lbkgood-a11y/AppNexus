# 账号、租户、人员与组织模型调整

日期：2026-11-16。用户确认执行：账号加入租户后维护一个或多个人员身份；账号不直接归属组织，原用户组织和任职关系转为人员关系。

## 当前权威关系

| 关系 | 权威位置 | 约束 |
|---|---|---|
| 全局账号到租户成员 | identity_account、tenant_member | 保留登录和租户访问；同账号同租户唯一，不赋予业务权限 |
| 租户成员到人员 | md_person_account | 多对多；唯一 tenant_id/person_id/member_id，不含 organization_id；有效成员可无人员等待管理员关联 |
| 人员到组织 | tenant_person_organization | 多对多；主组织、有效期、启停、版本；最多一个主组织，由同人员事务行锁串行维护 |
| 人员到岗位任职 | tenant_person_position | 岗位属于组织；person_id 不是 member_id；起止 UTC 时间、启停与版本 |
| 组织负责人 | tenant_person_leader | 引用人员当前任职，不引用账号成员任职 |

账号停用或退出租户，不结束人员的组织归属、任职和负责人关系，其他有效关联账号仍可代表该人员；但该账号不能继续使用任何人员身份。恢复账号不自动恢复已撤销角色权限。退出租户时在同一事务内解除该成员的账号人员关联并推进对应人员聚合版本；重新加入租户后须重新关联，人员和其他账号关联不受影响。人员离职、退休、停用、人员组织/任职到期或关联解除，使后续身份复核立即失败。

“维护人员档案”和“代表人员操作”分开：关联人员不授予 Person.read/update 或其他业务权限；管理员具备人员管理权也不会自动代表未关联人员。RBAC 功能权限及显式授权的数据范围仍由真实账号租户成员承载，不因关联多个人员自动合并或提升权限。

## 模块边界与真实执行

组织公开契约 PersonnelDirectory 提供组织、岗位、租户有效账号目录及人员组织关系维护；PersonnelCatalog 由主数据提供最小在职人员目录，组织模块不直接查询 md_person。PersonnelExecution 由主数据提供可代表身份、逐次有效性及审批账号解析；安全适配和工作流只依赖公开端口，不读取主数据表。

人员页面的“所属组织”和“所在岗位”直接读写唯一权威组织关系，组织页面任职也写同一 tenant_person_position；不再维护与真实任职脱节的第二份 JSON。其他八类明细保留固定白名单 content。组织页任职创建/修改通过公开人员端口递增人员聚合版本，保留实际操作账号，避免人员详情页旧版本静默覆盖。

人员详情“关联租户账号”只选账号，不再先选组织。组织任职页选择人员，授权中心仍选择租户账号。旧 /api/organization/grants/members/{memberId}/organization 写接口已移除；/api/organization/domain/persons 为人员任职目录，旧 domain/members 不作兼容回退。组织授权目录的账号摘要不再携带单个组织字段。

## 业务身份选择

顶栏复用现有 TenantSwitch 容器、Element Plus 和 ManagedDialog 增加“人员身份 / 业务组织”选择。仅有一个有效人员与组织组合时，通过现有 CSRF 接口自动确认，顶栏只读显示人员姓名，不提供选择。存在多个候选组合时保留可搜索的选择弹窗；同一人员有多个组织时仍须明确选择业务组织，不自动合并身份或组织。

| 接口 | 用途 | 准入 |
|---|---|---|
| GET /api/master-data/person/my-identities | 自身可代表身份及组织目录 | 当前可信租户有效成员，不需要人员档案管理权限 |
| GET /api/master-data/person/identity | 当前 Cookie 会话选择；失效返回 204 并清理 | 仅自己，每次复核 |
| POST /api/master-data/person/identity | 明确选择 personId、organizationId | CSRF、可信租户、有效关联、人员/组织/任职复核 |

选择保存在服务端会话；浏览器只保留内存展示和陈旧请求保护标识，不存 Token 或授权事实。租户切换清空人员选择。原生 Bearer 客户端可提交 X-Person-Id / X-Person-Organization 选择意图，服务端仍通过相同公开端口复核，不直接信任请求头。

当前请假业务要求有效人员选择，缺失/撤销/跨租户/离职均 409；写入的新单据保存实际 applicant 账号与 person_id、organization_id。请求幂等比较包含人员；提交时核对与单据人员、组织一致。旧单据 person_id 未记录保持 NULL，不按姓名推断回填。

工作流岗位/负责人选人通过人员任职再解析有效关联账号，办理及业务字段读取还须核验当前具体人员命中该节点条件，不能借用同账号另一人员的岗位。工作流岗位/负责人选人通过人员任职再解析有效关联账号，未关联账号的人员不会产生可登录审批账号。工作流实际操作账号不被人员替换；wf_audit 新增 person_id/business_organization_id，管理或后台操作允许为空。任务写操作要求有效人员身份；流程设计、权限和其他管理操作不强制业务身份，便于管理员修复关系。固定账号选人 MEMBER 保持其账号语义，不将既有流程配置中的账号 UUID 误解释为人员 UUID。

PERSON_CONTEXT_REQUIRED / CHANGED / INVALID 分别表示缺少有效选择、请求身份已变化、标识格式无效。前端不自动重放写请求；切换前确认丢弃未保存内容，阻止在途业务写入并重建内容区。实际功能权限继续独立校验，人员选择不构成准入放行。

## 增量迁移

V77__personnel_identity_model.sql：不修改已发布 V75/V76。账号成员已有关联人员时复用；没有人员的存量成员生成独立人员 UUID 及 MIG-成员UUID 编码，通过 md_person_member_migration 留存映射。名称复制真实账号显示名，不按同名合并，不更改登录凭据。

原 md_person_user_assignment 拆为账号人员关系及人员组织关系；同人员/成员在多个旧组织的关系归并为单条账号人员关系，组织关系分别保留。原 tenant_member_primary_organization 与 tenant_organization_assignment 转为关联人员的主组织/岗位任职；负责人随任职映射迁移。一个旧账号关联多个已有人员时，其原有效组织和任职复制到这些人员，不复制或扩展账号业务权限；来源记录可按映射表核对。主组织冲突确定性保留最小组织 UUID，其余为普通归属。

原 personnel organizations/positions JSON 明细转入唯一组织关系，其他八类明细原样保留；运行时只从权威关系读取，不回退旧表。旧三类关系表及原明细作为迁移历史凭证保留，正式写接口不再写入。未直接删除历史审计或已发布表，后续归档可单独安排。

V78__leave_personnel_identity.sql 增加请假 person_id；V79__workflow_personnel_audit.sql 增加工作流审计人员与组织。存量未知身份 NULL，不伪造历史被代表人员。

未新增密钥、端口或系统环境变量。新增数据库列均有相邻中文注释；基本业务日期为 yyyy-MM-dd，主组织有效期含起止当天，岗位时间为 UTC 时间点、结束时间不包含端点。人员页日期形式的岗位无起始值映射 1970-01-02 UTC，避开 MySQL TIMESTAMP 最小值边界；新任职建议显式填写开始日期。
