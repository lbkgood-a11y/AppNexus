# 项目设计文档

- [审批服务详细设计](design/审批服务详细设计.md)：平级服务工程、组合启动、内嵌 Flowable、跨服务约束及当前交付范围。

- [平台总体设计](design/平台总体设计.md)：已确认的需求、设计原则、第一期范围及各能力边界，是当前设计基线。
- [后端工程详细设计](design/后端工程详细设计.md)：模块结构、共享库租户/权限管线、认证、事务事件及验证方案。
- [前端工程详细设计](design/前端工程详细设计.md)：模块边界、框架隔离、升级与独立应用拆分方案草案。
- [前端 UI 与代码生成规范](design/前端UI与代码生成规范.md)：全站组件、布局、视觉、交互、权限、主题、响应式及代码生成的强制验收基线。
- [技术版本与许可证基线](design/技术版本与许可证基线.md)：候选版本、兼容性、许可证风险及启动前验证门槛。
- [API 命名与生命周期管理规范](design/API命名与生命周期管理规范.md)：资源 URL、接口面、版本、契约、兼容与废弃规则。
- [认证与会话详细设计](design/认证与会话详细设计.md)：OAuth/OIDC、Web/Native/Integration 流程、会话、Token、密码、MFA 和 SSO 基线。
- [第一期交付范围与验收基线](design/第一期交付范围与验收基线.md)：平台底座交付清单、验收条件、排除范围及实施顺序。
- [技术 PoC 执行记录](poc/技术PoC执行记录.md)：已验证组合、环境差异、未完成项及可复现命令。
- [待决设计事项](design/待决设计事项.md)：尚未确认的模型、技术方案与分期问题。
- [设计讨论记录](设计讨论记录.md)：讨论过程与历史决策来源。

## 维护约定

1. 用户确认后，将决定同步到对应设计文档，不能只保留在聊天或讨论记录中。
2. 未确认方案明确标记为草案，不将建议视为定稿。
3. 已确认原则与接口、表结构等详细设计分别标记成熟度。
4. 决策变化时更新设计基线，并在讨论记录中说明替代关系。
5. 未来按领域形成详细设计文档，明确模型、聚合、一致性约束、接口及权限；在确认前不作为实现依据。
6. 后续工程与模块命名遵循[后端工程详细设计中的命名规范](design/后端工程详细设计.md)，保持简短、统一和可预测。

- [组织管理员初始化与授权验收](design/组织管理员初始化与授权验收.md)：一次性管理员配置、组织管理与成员授权的部署流程和验收记录。

- [租户用户成员组织操作流程](design/租户用户成员组织操作流程.md)：平台开通、用户/成员管理、主要组织归属、单租户自动进入与多租户切换，以及官方产品参考。
