# 前端开发规范摘要

本页汇总现有前端开发要求；必须同时阅读[前端 UI 与代码生成规范](前端UI与代码生成规范.md)、[业务服务统一开发规范](业务服务统一开发规范.md)及本次功能设计。

## 工程与依赖

- `frontend/apps/admin` 负责应用壳、启动与装配；`frontend/modules/<领域>` 负责业务页面；稳定公共能力按需归属 `frontend/infra`。
- 工作区包使用 `@appnexus/<名称>`，跨包通过公开入口访问，不深层导入模板或其他业务包内部文件。既有工程布局说明见[前端工程详细设计](../design/前端工程详细设计.md)，其中历史实现状态不能视为当前全量能力。
- 当前 vue-pure-admin 是唯一布局、UI、交互与图标基线；优先已有模板增强组件，再使用 Element Plus，最后才是有具体理由的自定义实现。保持锁文件，不因单页开发引入平行 UI、主题、图标或状态体系。

## 页面与交互

- 复用应用壳、BusinessWorkspace、ManagementTable、ManagedDialog 和已有表单、分页、校验、确认与加载能力；编辑使用统一弹窗或复杂独立页，不使用 Drawer。
- 图标通过 `@appnexus/icons` 公开入口使用，保持 Iconify/Remix Icon 风格。颜色、字号、间距、圆角和状态使用模板及 Element Plus 变量。
- 覆盖加载、刷新、空态、无权、错误、冲突、提交和成功；所有入口连接真实后端，不以模拟成功、无效按钮交付。
- 中英文文案进入 i18n，适配浅色、深色、系统主题及桌面、窄屏、手机；保证标签、键盘、焦点及状态可访问。

## 接口、安全与异常

- 复用现有 HTTP、CSRF、会话生命周期及上下文切换入口；不存储浏览器 Token，不使用整页刷新替代应用内上下文刷新。
- 按钮绑定统一操作标识；显隐不代替后端授权，disabled 不代表完整权限。敏感原值不得先发浏览器再隐藏。
- 业务异常按[统一异常方案](全局统一异常处理方案.md)使用浮层，字段校验保留组件标准能力；区分会话失效、无权、冲突、限流及网络故障，不自动重放写请求。
- 记录审计只读展示，未知值不猜测；详情与列表展示不得扩大账号目录读取权限。

## 交付

执行适用的类型检查、构建、操作绑定检查和真实页面主流程/拒绝流程验证。新增组件记录现有组件不适用的原因；主题、语言和视口验证按实际结果交付，不能用构建通过代替视觉与功能验收。统一流程见[开发流程与交付检查](开发流程与交付检查.md)。
