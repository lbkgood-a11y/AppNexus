# 功能交付门禁要求

生效日期：2026-11-20。适用于本仓库未来每次新增、修改、修复和重构功能的交付，覆盖人工开发和 AI 生成代码。纯文档、配置、数据库及基础设施变更也必须执行适用性判定和交付记录。

本文件是统一交付验收入口，具体实现约束执行[开发规范](README.md)及对应专项正文。开发过程执行[开发流程与交付检查](开发流程与交付检查.md)。本文件不替代专项要求，不表示已实现完整自动化门禁。

## 1. 执行与判定规则

1. 开始工作时建立本次交付检查记录；交付前逐项复核全部门禁，不能只挑选已通过的项目。记录放在`docs/validation/`，包含对象、操作及实际改动范围，可复制本文第5节模板。
2. 每项只允许标记“通过”“失败”“未验证”或“不适用”。“通过”必须有当前最终代码对应的实际证据；“不适用”必须说明具体理由和影响分析，不得留空、统一填写无关或仅写“本次不涉及”。
3. 任一适用项失败或未验证，结论必须为“未满足交付门禁”，不得标记功能已完成、验收通过或可发布。可以交付代码供审阅，但必须明确是待验收结果；缺少环境、时间或外部依赖不等同于通过。
4. 编译成功、目录齐全、注释覆盖、对象登记、测试名称、前端按钮隐藏、预检通过及旧版本验收均不能代替真实业务和安全验证。不得删除断言、缩小扫描、扩大排除或批量重生成例外获取表面通过。
5. 每次修改后按实际影响重跑相关检查；最终证据须关联交付版本或工作区差异及测试时间，后续变更使证据失效时必须补验。无需机械重跑无关测试，但必须解释验证范围。
6. 存量失败须记录位置、复现及影响，证明与本次功能的关系；如果导致本次适用门禁无法完成，仍为失败或未验证，不自动豁免。所有检查均须给出适用性结论，不要求无差别执行全仓所有测试。

## 2. 每次交付必审清单

下列项目每次必须判定。涉及具体技术的执行项可按证据判为不适用，需求范围、适用性、交付证据与状态不得省略。

| 编号 | 门禁 | 通过要求及证据 |
|---|---|---|
| G01 | 范围与验收目标 | 明确需求、业务对象/操作、成功与失败行为、影响模块、排除范围；对照目标逐项验证，不将阶段完成表述为全量完成 |
| G02 | 规范与架构边界 | 阅读适用规范；记录业务归属、公开入口、依赖方向、表所有权及事务范围；复用现有能力，不复制历史混层或创建平行实现 |
| G03 | 统一权限模型 | 所有新增功能创建即接入统一对象/操作及服务端准入；使用公共授权、范围执行和字段保护，无业务私有权限表/API/算法/缓存；自助、公开、系统管理操作明确管理域和准入，不适用行范围不能省略功能准入 |
| G04 | 真实业务闭环 | 按真实入口验证主流程、非法参数、业务状态及失败反馈；接口、页面、策略和实际执行一致，无模拟成功、未接通入口或只登记不执行 |
| G05 | 数据与安全边界 | 可信身份来自服务端；验证适用的未登录、无功能权限、无策略、跨租户、跨范围、撤权、停用、过期与直调请求；无敏感值泄漏或客户端自报身份放行 |
| G06 | 构建与回归 | 执行受影响模块类型检查、编译/构建、实际装配及关键业务回归；记录精确命令、退出码、测试数量、失败/跳过及日志；无循环依赖或依赖旧产物的假通过 |
| G07 | 注释与契约 | 公开接口使用标准中文文档注释，重要参数和配置说明准确；代码行为、默认值、DTO/API、错误码及文档一致；无敏感示例和凭据入日志 |
| G08 | 交付记录与运行状态 | 提供逐项结论、证据位置、风险和未验证项；明确未部署/已部署及对应产物、迁移状态，不能把本地测试视为运行环境已生效 |
| G09 | 业务对象声明完整性与变更同步 | 每个功能执行[业务对象完整声明规范](业务对象完整声明规范.md) D01–D12，逐项记录声明位置、适用性及真实执行证据；每次相关功能变更提供变更对照表，核对所有受影响对象，声明已同步或有无需修改的依据，必要版本及迁移已处理；从接口/页面/回调/后台任务反查，无遗漏、重复及未接通能力；不同步或缺少复核证据阻断交付，非业务变更说明影响分析 |

## 3. 按改动触发的执行门禁

| 编号 | 触发条件 | 必须检查的内容 |
|---|---|---|
| C01 | 业务对象、操作或权限变更 | 对象/操作唯一声明，Controller引用操作；角色与成员继承/自定义、管理域和版本冲突、保存失败不部分生效；新增对象具备实际执行接入和越权测试 |
| C02 | 行范围、条件或记录授权 | 同条规则记录与条件AND、多规则/有效分支OR；空配置不隐式放行，ALL不跨租户；列表、COUNT、详情、主从及适用写入路径一致；字段/运算白名单、参数化SQL、非法配置和未知范围拒绝，数据库故障不回退放行 |
| C03 | 字段保护或敏感数据 | 原文只读/脱敏/隐藏按实际契约执行；原文不先传浏览器再隐藏；禁止受限字段回传、清空、集合替换或整行删除绕过，失败整笔回滚；字段限制不授予行/功能权限 |
| C04 | 数据库结构、迁移或审计 | 新自有表首次CREATE TABLE包含四审计字段及中文列注释，账号BINARY(16)、时间TIMESTAMP(6)/UTC；历史迁移不改、版本唯一；验证真实数据库迁移、存量数据及跨租户边界；执行`GlobalRecordAuditTest.ownedTablesHaveAllFourColumns`，不增加排除 |
| C05 | 业务写入、并发或幂等 | 同事务业务、主从、版本和审计；验证失败回滚、版本冲突、目标归属变更及并发；存在幂等契约时验证重复请求和不一致重放；创建信息不可覆盖，失败不推进审计 |
| C06 | 查询或授权查询变化 | 明确代表性数据量/分布、过滤和排序组合；提供真实EXPLAIN及必要的EXPLAIN ANALYZE、索引命中和扫描行数，校验分页/总数/重复记录；对大范围、复杂OR、深分页或并发风险设定并验证相应指标，不将单次小样本耗时视为容量保证 |
| C07 | 前端页面、组件、交互、路由装配或公共样式 | 复用vue-pure-admin及既有组件，记录新增组件理由；每次代码交付前执行UI规范13.1.1全局布局清单，留存实际宿主/布局属性透传、全局边框/圆角/内外边距/gap的计算样式和间距0/8/24px动态继承证据，公共变更覆盖代表性页面；真实加载/空态/错误/无权/冲突/成功流程；操作引用检查、类型检查及构建；桌面1440×900、窄屏1024×768、手机390×844、浅色/深色/系统主题及中英文，适用普通/全屏及树状态，键盘、标签和焦点；静态检查、构建或组件预览不能代替真实页面验证，失败或未验证不得标记交付完成 |
| C08 | 新增或调整Java包、模块、跨模块依赖 | 真实生产类被扫描；运行适用`ArchitectureRulesTest`、`ServiceLayerBoundaryTest`、`PackageDocumentationTest`；每个自有源码包含中文package-info.java，无核心依赖技术适配器或跨上下文私表访问 |
| C09 | API、异常、配置、依赖或部署变化 | 执行对应API生命周期、统一异常、配置注释及许可证规范；验证兼容性和错误契约；配置标明单位、默认/必填、环境和安全影响；涉及发布时记录产物、迁移顺序、健康检查及恢复方案，不编造可逆回滚 |
| C10 | 审批、打印、消息或其他能力接入 | 使用统一能力契约，验证真实调用、状态/版本、身份、业务数据权限、故障及适用重试/幂等；不因能力执行扩大权限，未支持能力不展示入口 |

专项标准：[统一权限与业务规范](业务服务统一开发规范.md)、[数据权限声明标准](业务对象数据权限声明标准.md)、[后端工程约束](后端标准工程结构与AI生成约束.md)、[前端UI规范](前端UI与代码生成规范.md)、[架构边界](架构与分包边界.md)。其他触发项按[规范入口](README.md)检索，不能因未列在表中省略专项要求。

## 4. 证据要求与检查方式

- 自动检查记录精确命令、工作目录、环境/工具版本（影响结果时）、执行时间、退出码、结果数量及报告位置。跳过项、未扫描模块和被过滤用例必须说明。
- 人工/浏览器检查记录身份角色、管理域、操作步骤、预期及实际结果，必要截图放验证记录关联位置；证据不得包含密码、Token或业务敏感原文。
- 数据库检查使用隔离测试环境或已有授权环境，注明数据规模及版本；禁止为验收擅自改写共享环境授权或生产数据。
- 当前命令从实际POM及package.json确认。前端操作检查入口为`node frontend/scripts/check-operation-bindings.mjs`，但静态通过不证明后端授权有效。
- 自动化覆盖不到的要求仍须人工核验。新增或修改门禁时同步规范入口及关联检查；未实现自动检查须如实记录，不能宣称已有CI全面保证。
