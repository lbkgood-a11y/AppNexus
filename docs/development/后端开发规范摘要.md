# 后端开发规范摘要

本页汇总现有后端开发要求，不替代[后端标准工程结构与 AI 生成约束](后端标准工程结构与AI生成约束.md)、[业务服务统一开发规范](业务服务统一开发规范.md)及任务适用专项正文。

## 架构、分包与命名

- DDD 业务上下文优先划分模块，内部按六边形职责分包，再按功能细分；当前统一由 `applications/monolith-app` 组合部署。
- 普通服务使用 `api/application/domain/adapter/bootstrap`；平台使用领域公开根包、port、internal/application、internal/domain 和集中适配器。既有 core/adapters 保留明确构建边界，不创建平行实现。
- 核心向内依赖，应用通过输出端口访问外部能力；技术适配器实现端口，装配连接实现。跨上下文不得导入内部实现、跨模块读表或形成循环依赖。
- 命名与能力归属见[模块归属与命名规范](模块归属与命名规范.md)，扩包和依赖矩阵见[架构与分包边界](架构与分包边界.md)。`service` 名称不代表独立部署。

## 业务、安全与契约

- 对象、操作、交互与数据权限集中在同一 BusinessObjects.Provider；Controller 引用操作。声明必须接通真实执行器，不能以目录登记代替功能。
- 实际账号与租户从服务端可信上下文取得；功能权限、数据范围、字段、对象归属和业务状态在真实执行路径复核，缺失或异常默认拒绝。
- 数据权限按[业务对象数据权限声明标准](业务对象数据权限声明标准.md)实现真实查询/写入适配及越权测试；诊断和预检不能代替执行授权。
- URL、HTTP 方法、接口面、兼容与废弃执行[API 规范](API命名与生命周期管理规范.md)。异常契约执行[统一异常方案](全局统一异常处理方案.md)，不暴露堆栈及敏感信息。
- 字典编码与业务值执行[字典标准](字典编码与业务值标准.md)，不创造哈希编码、运行时别名或多套同义字段绕过迁移。

## 数据、事务与配置

- 完整用例定义事务；业务更新、关联、审计及需要的 Outbox、幂等回执原子提交。验证版本冲突、回滚和并发，禁止拆类后形成独立提交。
- 所有自有基础表统一使用单列 `id` 主键，租户归属统一使用 `tenant_id`。原业务键以唯一约束维护，纯平台级表无需租户列。见[表主键与租户归属](业务服务统一开发规范.md#表主键与租户归属)。
- 所有自有表要求 created_by、created_at、updated_by、updated_at；新表首次 CREATE TABLE 即具备四列及中文列注释，账号 BINARY(16)、时间 TIMESTAMP(6)，数据库按 UTC 生成时间。
- 审计主体可信、创建信息不变、历史未知值保持 NULL；第三方原始表保持边界，不能通过扩大排除隐藏自有新表。
- Flyway 新版本全仓唯一、历史校验和不变；迁移跟随表所有者，不为每个包创建迁移实例。
- 每个含自有 Java 源码的正式、测试及 PoC 包维护中文 package-info.java。注释、参数、系统配置和敏感值要求见[注释与配置规范](注释与配置规范.md)。

## 交付

按影响执行编译装配、真实扫描的架构与包说明检查、领域/用例测试、真实数据库及越权反向验证。新表必须检查首次定义并运行 GlobalRecordAuditTest.ownedTablesHaveAllFourColumns；不通过删断言、改扫描或扩排除获得表面通过。交付证据和未验证项执行[统一检查](开发流程与交付检查.md)。

后端命名与分包执行[后端类型命名与分包规范](后端类型命名与分包规范.md)。检查真实 Controller、MyBatis Mapper、仓储端口与实现的命名、落位及依赖，核对资源 namespace、组件扫描、反射和声明类型绑定；检查失败或适用验证未完成阻断交付。
