# 字典编码与业务值标准

日期：2026-11-17。状态：统一实现标准；部署及验收边界见文末。本标准覆盖租户字典及其业务引用，不改变国家地区、商品单位实体等主数据自身的 ID 契约。

## 1. 唯一职责与命名

| 字段 | 规则 | 示例 |
| --- | --- | --- |
| dictionary.code | 1–64 字符，小写英文字母开头，单词间单个下划线，允许数字；租户内永久唯一 | partner_type、education_level |
| item.code | 与字典编码相同的语法，同一字典内永久唯一；必须表达业务含义 | customer、full_time、a |
| item.item_value / API value | 1–100 字符；有明确国家、行业、协议标准的使用标准代码，否则使用大写英文语义码，单词间单个下划线；数字标准代码作为字符串保存 | CUSTOMER、CNY、FULL_TIME、01 |
| name | 用户可维护的显示名称，不承担匹配、权限或状态判断 | 客户、人民币、全职 |
| id | 系统内部 UUID，只用于关系与定位，不作为编码或业务值 | 由服务端生成 |

编码和值禁止首尾及内部空白、控制字符、UUID、32–64 位十六进制哈希及旧 `v_` 哈希形式。新增入口不自动 trim 或转换大小写，避免用户提交与实际稳定标识不一致。纯数字代码保留前导零；不把任意序号当成新的业务分类。新增有特殊标点或小写标准代码的字典前，须明确标准和专用校验，不放宽所有字典的通用门禁。

编码和值创建后不可修改，软删除后不复用；名称、排序、启停可维护。字典状态项的新增不扩展业务状态机执行语义。业务接口持有固定字段绑定，不能把客户端提供的字典编码当成任意表查询能力。

## 2. 预置与映射唯一来源

`dictionary-value-standard-v102.tsv` 为 V102 的唯一清单，列为字典编码、字典中文名称、旧业务值、新项编码、新业务值、显示名称，共 25 类 114 项。完整映射以资源为准，不在前端复制枚举。新租户开通调用 `StandardDictionaryDefaults.seed`，与开通、真实操作者及权限初始化在同一事务提交。

| 字典 | 旧值示例 | 新值示例 |
| --- | --- | --- |
| partner_nature | 民营、国有、外资 | PRIVATE、STATE_OWNED、FOREIGN_OWNED |
| partner_contact_type | 业务、财务、物流 | BUSINESS、FINANCE、LOGISTICS |
| staff_size | 1-49、1000+ | SIZE_1_49、SIZE_1000_PLUS |
| ethnicity | 汉族、回族 | HAN、HUI |
| political_status | 群众、中共党员 | GENERAL_PUBLIC、CPC_MEMBER |
| certificate_type | 职业资格、专业技术资格 | VOCATIONAL_QUALIFICATION、PROFESSIONAL_QUALIFICATION |
| person_contact_type | 电话、手机、邮箱 | PHONE、MOBILE、EMAIL |
| address_type | 家庭、居住、户籍 | HOME、RESIDENTIAL、REGISTERED |
| academic_degree | 无、学士、硕士 | NONE、BACHELOR、MASTER |
| product_unit | 件、箱、千克 | PIECE、BOX、KILOGRAM |

此处民族、政治面貌和旧商品单位是当前业务选项的语义编码，不声称是完整国家分类代码或计量换算协议。币种继续使用 ISO 4217 大写代码。商品计量实体 `md_product_unit` 的 UUID 关系、维度及精度不属于旧商品 `unit` 分类文本，不替换其 ID。

## 3. 存量转换与引用

存量标准转换由既有 V102 执行，不修改 V18/V19/V89/V91 及其不可变资源。旧初始化器仅供历史迁移及升级测试；运行时开通不再调用旧生成逻辑。

V102 遍历全部租户及字典项（含软删除占用），按清单转换已知值及项编码；已有符合标准的自定义值仅在原编码为自动 `v_` 哈希时还原语义编码。已有合规自定义项保持含义。无法确定含义的历史项保留原值与 ID、标记历史并停用，已有业务记录可按原值读取及原值保存，不能用于新选；不自动翻译、猜测或伪造标准码。后端拒绝重新启用不规范历史项；业务选项和新引用登记再次检查编码和值，防止旧状态误设为启用绕过规则。

转换覆盖客商主表及联系人、银行账户明细、旧商品分类文本、人员主表及 JSON 明细、仓库固定字典绑定。只匹配完整字段或多选 token；JSON 只转换绑定字段中的字符串，名称、备注、证件等其他正文不做全文替换。字典项 UUID、父子层级、引用登记、外部引用 ID 保持不变，无须重建外键。历史幂等请求摘要保持原样，同键重放仍按原始请求校验；外部调用方新请求改用新业务值，旧代码不增加运行时别名。

迁移全程为 DML 原子事务。目标编码或值已被另一项占用（含软删除占用）时抛出 `DICTIONARY_STANDARD_CONFLICT` 并回滚，禁止自动合并可能有不同名称、启停、层级或引用的对象。创建审计保持不变；实际发生变化的记录由数据库生成 UTC 修改时间，修改账号为空表示系统执行，版本递增，明细变化同步推进父聚合版本，阻止迁移前草稿覆盖。

从 V102 之前版本升级时，必须先停写旧版本应用，备份数据库，部署含 V102 的新产物并让 Flyway 正常执行，再启用新版本；旧前端草稿需重新加载。外部系统缓存及其自有数据库不在本仓库可修改范围，需按映射更新后使用新业务值调用；不能宣称已替换外部系统数据。失败先解决冲突原因，不修剪检查、不自动选择某一项覆盖。

## 4. 持续交付要求

字典规则和迁移变更须验证已知值与 JSON 引用转换、ID/层级/外部引用保护、租户隔离、创建审计保留、聚合版本推进、冲突回滚、重复执行不变、历史未知项和前导零；涉及界面时执行类型、构建及真实授权流程检查。

V102 是既有不可变迁移，不为新功能重复创建或重新编号。升级路径尚未执行该版本时按第 3 节执行部署要求；后续修改采用新的唯一迁移版本。历史测试结果见[历史记录](../design/字典编码与业务值标准历史记录.md)，不代表共享环境当前部署状态。
