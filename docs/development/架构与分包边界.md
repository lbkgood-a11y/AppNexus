# 架构与分包边界

生效日期：2026-11-19。本文适用于后端模块、包及依赖的新增、修改和审查，与[后端标准工程结构与 AI 生成约束](后端标准工程结构与AI生成约束.md)共同执行。

## 1. 架构与分包的统一定义

架构采用 DDD 业务边界与六边形依赖原则，当前默认模块化单体部署。分包采用：**业务上下文优先分模块，模块内部按六边形职责分包，职责内部按业务功能细分；平台技术适配器集中管理。**

这是一种业务能力与职责分层结合的混合组织方式（Package by Business Capability / Feature + Layer）。DDD、Maven 模块、Java 包及独立部署分别表达不同边界，不能相互等同：

| 边界 | 判定依据 | 扩展约束 |
|---|---|---|
| 业务上下文 | 业务语言、业务规则、数据所有权 | 先确定归属，不因页面或表增加就新增上下文 |
| Maven 模块 | 构建、依赖隔离与复用需要 | 不为每个对象或每层自动创建模块 |
| Java 包 | 职责、功能及公开边界 | 仅创建实际需要的包，不创建空层和无职责转发层 |
| 部署单元 | 独立发布、运行隔离或扩缩容需求 | 不因已有 Maven 模块就自动拆微服务 |

## 2. 业务所有权

| 平台上下文 | 负责的业务边界 | 不得混入的职责 |
|---|---|---|
| identity | 账号、凭据、身份认证业务规则 | 组织任职、角色授权规则 |
| tenant | 租户生命周期、租户成员关系、可信租户契约 | 其他业务上下文的全部租户数据 |
| organization | 组织、部门、人员与任职关系 | 登录凭据及认证会话技术实现 |
| authorization | 功能授权、数据范围、字段保护规则 | 具体业务对象的状态机与业务执行 |
| configuration | 菜单、导航、字典等业务配置 | Spring、连接池、部署环境等运行配置 |
| localization | 本地化相关业务模型与公开能力 | 任意公共工具或所有界面实现 |
| audit | 审计模型与公开端口 | 所有日志、指标和链路技术实现 |

跨上下文复用通过所有者的公开契约完成；“多个模块使用”不是迁入 `common`、`utils` 或 `building-blocks` 的充分理由。业务实体、仓储及业务执行器不得进入无业务归属的基础构件。

## 3. 普通业务服务的包结构

默认使用单 Maven 模块，Java 根包采用 `com.appnexus.<context>`：

```text
<context>/
├─ api/<feature>/
├─ application/<feature>/
├─ domain/<feature>/
├─ adapter/
│  ├─ web/<feature>/
│  ├─ persistence/<feature>/
│  ├─ integration/
│  ├─ messaging/
│  └─ transaction/
└─ bootstrap/
```

以上是职责选项，仅创建实际使用的目录。已有 `core/adapters` 多模块布局或 `adapter/jdbc` 技术命名按后端标准保留明确边界，不平行创建同职责实现。

| 位置 | 职责与允许依赖 | 禁止事项 |
|---|---|---|
| api | 公开用例接口、稳定输入输出类型；依赖 JDK 和稳定公开契约 | 返回数据库 PO、Servlet、Spring 或内部领域实现类型 |
| application | 用例协调、必要输出端口、授权协调、事务范围；依赖领域及公开契约 | 依赖 SQL、Spring、JSON 实现、技术客户端或适配器实现 |
| domain | 实体、值对象、不变量、状态转换及领域计算 | 依赖应用、适配器、Web、数据库或其他技术框架 |
| adapter/web | HTTP 请求响应映射并调用公开用例 | 直接访问数据库或自行编排业务事务 |
| adapter/persistence | 实现存储端口，固定 SQL、锁、版本条件及映射 | 承担完整业务决策，访问其他上下文拥有的表 |
| adapter/integration | 实现本侧端口，调用对方公开 API 或跨进程契约 | 导入对方内部实现或直接读写对方表 |
| adapter/messaging | 消息协议转换、调用用例、实现消息发布端口 | 用消息处理器替代业务用例及领域规则 |
| adapter/transaction | 实现窄事务端口或事务装饰器 | 自行改变应用定义的完整事务范围 |
| bootstrap | Bean、配置属性及技术实现装配 | 承担业务决策、状态机或绕过用例的业务入口 |

`api` 是模块公开业务 API，不等同于 HTTP 接口。普通服务 `application` 内的输出端口只允许本模块适配器及装配访问，其他业务模块不得导入。

## 4. 平台的固定物理布局

平台按上下文建立领域 Maven 模块，技术实现集中在服务级 `adapters`。不得在各领域再建立与其重复的 `infrastructure` 或另一套技术适配目录。

```text
platform-service/
├─ identity/、tenant/、organization/、authorization/ ...
│  └─ src/main/java/com/appnexus/platform/<context>/
│     ├─ <公开用例接口与稳定类型>
│     ├─ port/
│     └─ internal/
│        ├─ application/<feature>/
│        └─ domain/<feature>/
└─ adapters/
   ├─ app-api/
   ├─ platform-api/
   ├─ partner-api/
   ├─ persistence/
   ├─ security/
   ├─ eventing/
   └─ observability/
```

平台公开根包对应普通服务的 `api` 职责；`port` 是明确开放的输出端口，必须说明允许的实现模块。其他领域和适配器禁止导入 `internal`。若内部实现需要框架外装配，通过明确的装配契约连接，不能放宽为任意模块访问内部实现。

普通业务 HTTP 入口按调用对象进入 `app-api`、`platform-api` 或 `partner-api`。`security` 负责安全过滤器、会话及认证授权技术桥接，认证协议及会话专用入口可归属此处；普通组织、字典、租户参数业务不能因历史实现位于此处而继续堆入。

部署组合归属 `backend/applications/monolith-app`，全后端架构检查归属 `backend/architecture-tests`。平台旧 `application` 与 `architecture-tests` 路径不是新增源码或启动入口；历史产物不能代表当前构建结构。

平台另包含 `business-object` 上下文（`com.appnexus.platform.businessobject`），负责对象目录、配置和编码；不拥有具体业务对象正文。

## 5. 依赖与调用边界

- 入站适配器调用公开用例；用例依赖领域及输出端口；出站适配器实现输出端口；装配连接接口及实现。核心不得通过 `new Jdbc…`、Service Locator 或容器查询反向获取技术实现。
- 跨上下文协作由本侧用例依赖必要端口，集成适配器调用对侧公开能力。不得形成 Maven 双向依赖，不得跨模块导入内部 Service、Mapper 或访问其表。
- Java 的 `public` 不代表模块公开 API；公开范围必须由包约定、包说明及实际架构检查共同约束。
- 事务由完整用例定义，数据库实现负责同连接执行。多次业务写入、审计及需要的 Outbox、幂等回执保持原子性，不能因拆包拆类而独立提交。
- 可信账号和租户来自服务端安全边界；权限、数据范围、字段及业务状态必须在真实执行路径复核。包边界不能代替执行授权。

## 6. 扩包决策

| 变化 | 默认落位 |
|---|---|
| 同一对象增加操作 | 原上下文的公开用例、应用和必要领域实现 |
| 同一上下文增加业务功能 | 在各职责下增加同名功能包，如 `application/personnel` 与 `domain/personnel` |
| 增加 HTTP 或消息入口 | 新增入站适配器，复用原用例 |
| 增加数据库、远程协议或消息实现 | 新增必要出站适配器，保持业务端口稳定 |
| 调用另一上下文 | 本侧端口及集成适配器，对侧公开契约 |
| 出现独立业务语言、规则和数据所有权 | 先设计新上下文，再判断 Maven 构建隔离需要 |
| 只是文件数量增长 | 按功能细分包，不自动新增上下文、模块或部署服务 |

新增前须在任务设计或交付记录填写下表，简单任务无需单独创建设计文档：

| 用例及对象/操作 | 所属上下文/公开入口 | 应用与领域包 | 输出端口/适配器/允许实现者 | 表所有权/事务范围 | 可信主体/授权边界 | 依赖及验证证据 |
|---|---|---|---|---|---|---|
| 本次实际业务 | 实际模块与契约 | 实际包 | 实际接口及实现 | 实际范围或不适用 | 实际来源与拒绝路径 | 命令、测试及结果 |

每个包含自有 Java 源码的包（含测试与 PoC）提供中文 `package-info.java`，说明职责、允许与禁止依赖、公开边界及真实迁移状态。禁止创建空目录、无意义接口、平行 DTO 或仅移动类来宣称符合架构。

## 7. 存量处理

当前 `organization/personnel` 的业务与技术混层、`adapters/security` 内普通业务实现属于已观察到的存量差距，不能作为新代码模板；本说明不是平台全量审计报告。修改存量时迁移受影响的完整用例边界，保持协议、安全和事务语义；无关差距记录具体位置和未完成范围，不通过例外扩张宣布合规。
