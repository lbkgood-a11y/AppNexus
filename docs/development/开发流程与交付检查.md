# 开发流程与交付检查

适用于新增、修改、重构及代码审查。执行[统一入口](README.md)列出的适用规范；以下检查是执行清单，专项规范中的要求仍须完整满足。

## 1. 开始前

- 阅读根 `AGENTS.md`、开发规范入口和任务适用的专项规范。
- 检查当前工作区改动，保护已有工作；检查现有公开接口、组件、同类用例和实际构建模块。
- 每个功能先执行[业务对象完整声明规范](业务对象完整声明规范.md) D01–D12，建立功能到对象、操作、实际入口、通用能力及执行器的对应关系；交付时从接口、页面、回调和后台任务反查遗漏，不适用项说明理由并留证。
- 所有新增功能在设计阶段列明统一对象/操作、管理域和准入类型、适用的数据范围/字段保护及验证方案；不适用项逐项说明，不得先实现业务再补权限。当前存量改造范围不能作为未来新功能豁免。
- 后端填写[架构与分包边界](架构与分包边界.md)的归属表，明确对象、操作、公开入口、端口、数据所有权、事务、可信主体及依赖。
- 新增或重命名目录、模块与包时，按[模块归属与命名规范](模块归属与命名规范.md)记录能力分类、上下文名称、目录、artifactId、Java 根包和部署归属；检查同义命名、公开边界及扫描规则。
- 前端先检查模板及已有增强组件的适用能力；必要的新组件说明复用不适用的原因，并记录在设计或组件说明中。

## 2. 实现中

- 所有接入业务对象强制唯一声明并接通真实统一权限执行；按[统一权限模型强制接入](业务服务统一开发规范.md#31-统一权限模型强制接入)分别核对遗漏声明、遗漏执行、绕过执行，逐入口关联证据，任一缺失或未验证阻断交付。配置简化采用对象默认范围与操作覆盖的公共模型，不以省略写入校验减少配置量。

- 先确定稳定业务契约与规则，再实现用例、真实适配器、装配和声明；跨模块只使用明确公开边界。
- 对象、操作和数据权限按专项规范集中声明；Controller 只引用操作，不以目录登记代替执行器。
- 每次相关功能变更均按[声明同步复核](业务对象完整声明规范.md#4-每次功能变更的声明同步复核)对照实际差异追踪受影响对象并同步声明；提交前及交付前复核，在交付记录提供变更对照表。无需修改声明也必须说明原声明仍准确的依据，后续追加变更须补查。
- 按[统一权限模型强制接入](业务服务统一开发规范.md#31-统一权限模型强制接入)检查权限相关变更：复用统一授权管理、决策及公共执行能力，不新增业务私有授权表/API/页面、范围算法、脱敏或缓存；能力缺口先扩展公共模型，业务约束与授权判定明确区分。
- 可信账号、租户、功能权限、数据范围及字段保护在真实执行路径校验；同步处理失败、回滚、并发和幂等。
- 新自有表首次 `CREATE TABLE` 声明单列 `id` 主键，并按租户归属统一使用 `tenant_id`。存量改造验证原业务唯一键、外键和租户隔离。
- 新自有表首次 `CREATE TABLE` 包含四个审计字段和准确中文列注释：账号 `BINARY(16)`、时间 `TIMESTAMP(6)`、数据库 UTC 时间；主体可信、历史未知值保持 NULL、更新与业务同事务。
- Flyway 历史迁移保持校验和，新版本全仓唯一；不修改第三方上游原始表来套用自有表要求。
- 同步维护标准中文文档注释、Java 包说明、重要参数与系统配置说明；严格 JSON 的参数说明放同目录或设计文档并明确入口。
- 前端复用当前 vue-pure-admin、既有增强组件和 Element Plus，满足主题、国际化、移动端及真实状态反馈要求，不引入模拟成功或浏览器 Token 存储。

## 3. 验证与交付

每次交付必须执行[功能交付门禁要求](功能交付门禁要求.md)，使用其逐项记录模板完成适用性、状态和证据判定。本文负责过程安排，交付结论及阻断规则以该门禁为统一入口；所有专项要求仍须满足。适用检查失败或未验证只能交付待审结果，不得宣称功能验收完成。

按改动影响选择并完成适用验证，不以测试名称替代实际结果：

| 检查 | 必须提供的证据 |
|---|---|
| 编译与装配 | 受影响模块构建及组合依赖可解析，无循环或核心默认构造技术实现 |
| 包与架构 | `PackageDocumentationTest` 及适用架构检查；新增/改造生产包真实被扫描，跨模块和向内依赖成立 |
| 业务规则与用例 | 关键规则、状态、协调及失败路径的有效测试，不为简单委托编写镜像测试 |
| 数据与安全 | 受影响的真实数据库 SQL、事务回滚、版本/并发、越权与跨租户反向验证 |
| 表设计与审计 | 审查首次建表定义及租户归属，并运行 `GlobalRecordAuditTest.ownedTablesHaveSingleIdPrimaryKey` 和 `ownedTablesHaveAllFourColumns` 的真实数据库检查，不增加排除绕过新表 |
| 标准左树 | 检查220px默认宽度、48px收起栏、统一树头/节点/主题焦点和触屏，检索局部treeWidth及深层覆盖；业务例外有具体理由及范围 |
| 前端布局继承 | 每次前端代码交付前执行 UI 规范13.1.1清单；从真实路由检查 main-content 实际宿主与属性透传，留存全局边框/圆角/内外边距/gap的计算值和规则来源；验证全局区块间距0/8/24px、适用树展开/收起及普通/全屏、多视口和主题，记录实际页面证据和未验范围；静态检查或构建不能替代 |
| 前端 | 适用的类型检查、构建、操作引用检查及真实页面流程；覆盖错误、无权、主题、语言和窄屏 |
| 文档 | 注释、配置默认值、实现、公开边界及迁移状态一致；规范变更同步入口 |

适用命令应从当前模块 POM、前端脚本及验证说明中确认，不从旧目录或历史产物推断。前端操作引用检查入口为 `node frontend/scripts/check-operation-bindings.mjs`，其静态结果不能代替实际授权验证。

全局数据权限检查先运行 `node scripts/audit-data-access.mjs` 同时枚举生产数据库访问和全部 Controller，再逐入口追踪唯一对象、准入、行范围、字段保护和真实执行。只遍历已声明的 Provider、DataAccessCatalog 或 Executor 会漏掉完全未登记的功能，不能作为全站覆盖证据。清单中的文本标记不是检查通过结论，必须在验证记录关联调用链和正反向测试。

交付记录至少说明：修改范围、执行命令和结果、未验证项及原因、存量差距和运行/部署状态。环境不足时明确未验证的边界，不宣称已通过；禁止删除断言、缩小扫描、扩大排除或重生成例外来获得表面通过。

本目录建立的是必须遵循的开发规则，不代表已新增全量自动门禁，也不代表存量系统已符合全部要求。

后端命名与分包执行[后端类型命名与分包规范](后端类型命名与分包规范.md)。检查真实 Controller、MyBatis Mapper、仓储端口与实现的命名、落位及依赖，核对资源 namespace、组件扫描、反射和声明类型绑定；检查失败或适用验证未完成阻断交付。
