# 后端标准工程结构与 AI 生成约束

日期：2026-11-19。状态：新增代码与本次改造代码的强制基线。本文定义本仓库的工程标准，不声称六边形架构存在唯一行业目录，也不表示存量系统已完成合规改造。

## 1. 适用范围与规范关系

适用于 `backend` 内自有后端代码的生成、修改和审查。采用 DDD 业务边界、模块化单体部署与六边形依赖原则；只有确有独立发布需求时才拆物理服务。

本文负责目录、职责、依赖及生成流程；业务契约执行[业务服务统一开发规范](业务服务统一开发规范.md)，数据权限执行[业务对象数据权限声明标准](业务对象数据权限声明标准.md)，注释执行根目录 AGENTS.md。本文细化并更新[后端工程详细设计](../design/后端工程详细设计.md)中的工程结构约定；其他业务、安全与数据要求继续有效。存量进展以[业务服务六边形分层改造](../design/业务服务六边形分层改造.md)及实际源码、测试为准。

新代码必须符合本文。修改存量时迁移受影响的完整用例边界，保持对外协议、安全和事务语义；无关历史问题登记差距，不要求借一次功能修改重构全仓。不能因旧类不合规而复制旧结构，也不能仅移动或重命名旧类宣布完成。

## 2. 顶层工程标准

```text
backend/
├─ pom.xml                         统一依赖、插件与模块聚合
├─ building-blocks/                无具体业务归属的最小稳定构件
├─ contracts/                      需要独立版本的跨进程契约及客户端
├─ services/
│  ├─ platform-service/            平台领域模块与技术适配器
│  └─ <name>-service/              有明确业务边界的服务工程
├─ applications/                   独立于业务能力的部署组合
│  └─ monolith-app/                当前组合单体启动、配置与集成测试
├─ architecture-tests/             全后端跨模块与组合产物架构检查
└─ poc-app/                        隔离技术验证，不能成为正式代码依赖
```

- Maven 模块是构建边界，不能据此推断独立部署。不得为每个对象自动生成一个服务或一组 Maven 模块。
- `building-blocks` 禁止存放账号、组织、商品等业务实体、仓储及通用业务执行器；禁止用 `common`、`utils` 掩盖归属。
- `contracts` 只承载跨进程稳定协议，不共享数据库 PO、Mapper、领域实体或服务内部实现。进程内协作优先使用领域公开 API。
- 禁止业务代码依赖 `poc-app`、测试代码或生成产物。禁止为了满足结构创建空模块、空包、空适配器和无职责的转发层。

## 3. 平台服务的固定结构

```text
platform-service/
├─ identity/                       身份、账号与认证业务
├─ tenant/                         租户业务与可信上下文契约
├─ organization/                   组织与人员
├─ authorization/                  功能权限、数据范围及字段保护
├─ configuration/                  菜单、导航、字典等业务配置
├─ localization/                   本地化相关业务模型
├─ business-object/                对象目录、能力配置与编码业务
├─ audit/                          审计模型与公开端口
├─ adapters/
│  ├─ app-api/                     第一方应用 HTTP 入口
│  ├─ platform-api/                平台管理 HTTP 入口
│  ├─ partner-api/                 合作方 HTTP 入口
│  ├─ persistence/                 MyBatis/JDBC、Mapper、PO、数据库迁移
│  ├─ security/                    安全过滤器、会话、认证与授权技术桥接
│  ├─ eventing/                    事件投递、Outbox 等技术实现
│  └─ observability/               日志、指标、链路技术接入
└─ pom.xml                         平台业务与适配器聚合
```

以上是现有平台模块的职责标准，部分模块仍只有骨架。新增普通业务 Controller 按调用对象进入对应 API 模块，不能因历史 Controller 位于 `security` 就继续堆入其中；认证协议与会话专用入口可归属安全适配器。迁移接口归属须保持 URL、安全注解、组件扫描及公开协议不变。

每个领域的 Java 根包采用 `com.appnexus.platform.<context>`，内部结构为：

```text
<context>/
├─ <公开用例接口与稳定类型>         模块间唯一业务入口
├─ port/                           供外部适配器实现的输出端口与稳定类型
└─ internal/
   ├─ application/<feature>/       用例实现、命令处理与流程协调
   └─ domain/<feature>/            聚合、实体、值对象与业务规则
```

`port` 是显式公开边界，必须记录允许的实现模块；不把应用实现或领域实体全部公开以方便适配器调用。现有根包端口可以在保持契约时渐进调整，不为改名制造重复接口。其他模块及适配器禁止导入 `internal`。输出端口用稳定快照、标识与结果类型传递数据，内部领域对象由应用侧映射。

平台领域不另建与服务级 `adapters` 重复的 `infrastructure`。公开用例实现、业务规则不能放入部署组合 `applications/monolith-app`。原 `platform-service/application` 与平台架构测试源集已分别迁入顶层部署组合及架构测试模块；旧 target 属于历史产物，不得继续按旧路径启动。

## 4. 其他业务服务的固定结构

新建业务服务默认先使用单 Maven 模块内的包边界，根包为 `com.appnexus.<context>`：

```text
<name>-service/
├─ pom.xml
└─ src/
   ├─ main/
   │  ├─ java/com/appnexus/<context>/
   │  │  ├─ api/<feature>/          对外用例接口与稳定类型
   │  │  ├─ application/<feature>/  用例实现、命令、查询及输出端口
   │  │  ├─ domain/<feature>/       领域模型与规则
   │  │  ├─ adapter/
   │  │  │  ├─ web/<feature>/      Controller、请求响应及异常映射
   │  │  │  ├─ persistence/<feature>/ 仓储、Mapper、PO 与存储映射
   │  │  │  ├─ integration/        跨模块公开能力或远程协议的桥接
   │  │  │  └─ transaction/        事务端口实现或用例事务装饰器
   │  │  └─ bootstrap/             本服务 Spring 装配与配置属性
   │  └─ resources/
   │     └─ db/migration/          本服务拥有表的 Flyway 迁移
   └─ test/                        对应生产包的规则、用例、适配器与集成测试
```

只创建本次确实使用的目录。既有 `core/adapters` 保持构建边界，持久化 Java 包统一使用 `adapter/persistence`；历史 `adapter/jdbc` 随受影响完整用例迁移，不平行复制同职责实现。简单模型可不创建聚合、工厂或领域服务，但用例与数据库访问边界仍须分离。

本结构的对外入口只有 `api`、明确公开的模块声明及跨进程 `contracts`；`application` 中输出端口只允许本模块适配器与装配访问，其他业务模块不得导入。仓库架构测试必须验证这种约束，Java 的 `public` 不等于模块公开 API。

既有多模块 `core/adapters` 服务继续保持构建布局：领域规则位于 `core`，技术实现位于 `adapters`，新增用例通过不依赖技术框架的应用包或应用模块协调。不得仅为套目录破坏现有构建或新建平行实现；具体落位及公开边界必须在功能设计中列明。

## 5. 依赖矩阵与禁止事项

| 代码位置 | 允许依赖 | 禁止依赖 |
|---|---|---|
| 领域模型 `domain` / 纯领域 `core` | JDK、经审核的纯计算构件 | 应用层、适配器、Spring、JDBC、MyBatis、Servlet、JSON 实现、Flowable、缓存客户端 |
| 公开 `api` / 平台公开根包与 `port` | JDK、稳定公开类型、必要契约 | 应用实现、内部领域实现、适配器及技术框架类型 |
| 用例 `application` / `internal/application` | 本领域模型、公开 API、输出端口 | SQL、Mapper、PO、JdbcTemplate、Spring、JSON/引擎/缓存客户端及适配器实现 |
| 入站 Web 适配器 | 公开用例、传输类型、安全入口契约 | Mapper、数据库、领域内部实现及自行编排业务事务 |
| 出站存储适配器 | 所实现的端口、稳定类型、存储技术 | Web 适配器、其他模块内部实现及其他业务模块的表 |
| 集成适配器 | 本侧端口、对侧公开 API 或版本化契约 | 对侧 Service 实现、Mapper、数据库表 |
| 装配 `bootstrap` / `applications` 启动模块 | 所需公开入口与具体实现 | 承担业务决策、状态机或提供绕过用例的执行入口 |

核心模块不能通过构造器 `new Jdbc…`、静态工厂、Service Locator 或 Spring 容器查询获取技术实现。适配器不能相互调用以绕过业务用例；确需协作通过应用端口与装配连接。安全基础设施共享依赖必须无环，禁止 API 与 security 模块互相依赖。

跨领域协作由应用用例依赖自身端口，集成适配器调用对方公开 API；避免 Maven 双向依赖。HTTP 请求 DTO、领域实体、数据库 PO 分别建模，只为实际存在的协议差异编写映射，不引入反射复制来隐式传递敏感字段。

## 6. 端口、业务规则与事务

- 输入端口表达业务操作，如 `CreateWarehouseUseCase`；输出端口表达业务需要，如 `WarehouseRepository`、`WarehouseQueries`、`ApprovalGateway`。禁止 `execute(sql)`、任意表名、任意 URL 等无边界端口。
- 领域负责状态转换、不变量与计算；应用负责调用顺序、授权协调、幂等策略和事务范围；存储适配器负责固定 SQL、锁、版本条件、映射及技术异常转换。不能把权限策略、状态机整体藏进 `Jdbc…Service`。
- 事务范围由完整业务用例定义。默认使用应用侧窄事务端口，由适配器执行事务回调；或者由装配提供事务装饰器。应用不依赖 Spring 事务类型。事务端口的泛型结果、异常回滚与嵌套行为必须有中文 Javadoc。
- 多次写入、审计字段、Outbox、幂等回执必须按业务要求在同一事务与同一数据源连接中提交。代理事务装饰器须验证调用确实经过代理，不能依赖自调用触发事务。
- 数据库时间、外部状态与随机值经必要端口输入，领域计算保持可重复；不要给每个 JDK 计算方法创建接口。数据库审计时间仍由数据库生成，不能用应用 Clock 替代。
- 认证主体与可信租户由服务端安全边界建立，应用不得接受客户端自报身份作为授权依据。授权、范围、字段、版本与状态必须在真实执行路径复核；预检不能替代执行授权。
- 缓存不能成为权限或归属的唯一可信依据；撤权、租户切换、并发更新及回滚行为须明确。跨进程事务不能沿用本地事务假设，须另行设计幂等、事件与补偿。

## 7. 对象声明、迁移与配置的归属

权限相关实现必须执行[统一权限模型强制接入](业务服务统一开发规范.md#31-统一权限模型强制接入)：业务模块只声明能力并调用统一管理、判定和公共执行入口；不得自建授权管理、策略存储或权限算法。公共能力不足先在所属 authorization 上下文及平台适配器扩展，业务特殊校验不能成为另一套授权决策。

对象、操作、数据权限在同一 `BusinessObjects.Provider` 声明中集中登记。依赖框架的声明提供器放入集成适配器或装配包，不污染纯领域。Controller 仅引用操作，声明必须连接真实执行器，禁止生成仅有目录项的能力。

迁移随表的数据所有者保存；平台当前迁移继续归属持久化适配器，其他服务迁移归属各服务资源目录。组合运行时沿用现有统一 Flyway 历史，新版本号须全仓检查唯一性，不修改历史校验和，不为每个包另建 Flyway 实例。

新自有表首次 CREATE TABLE 必须包含 `created_by`、`created_at`、`updated_by`、`updated_at` 及中文列注释；账号 `BINARY(16)`，时间 `TIMESTAMP(6)`，其可信主体、UTC、事务、历史 NULL 与只读展示约束执行业务规范。不能通过第三方表排除规则隐藏新表。

Spring 配置属性、Bean、技术客户端配置放装配或对应技术适配器；业务默认规则归属业务模型或受控业务配置。所有新增或修改的系统配置遵守相邻中文注释、单位、默认值、必填、安全及联动说明要求，敏感值只使用环境引用或占位符。

## 8. AI 生成代码的固定执行流程

每个实际包含自有 Java 源码的包（正式、测试与 PoC）必须维护中文 `package-info.java`，以 Javadoc 说明职责、边界、允许与禁止依赖及真实迁移状态。父级仅为命名路径且没有源文件时不创建空包。当前仍混合职责的包明确列出未完成项，迁移后同步更新；使用 `PackageDocumentationTest` 检查覆盖，不能把说明覆盖率当作架构完成率。

1. 阅读根 AGENTS.md、本文及本次业务适用规范，查找现有同类用例、公开接口、装配与测试；禁止从最接近的历史大类直接复制结构。
2. 编码前在任务设计或交付记录列出：所属上下文、业务对象与操作、输入端口、输出端口、实现包、公开边界、表所有权、事务范围、可信主体来源及涉及的依赖。简单任务可使用一张表，不要求单独创建文档。
3. 先确定稳定业务契约及规则，再实现用例、适配器、装配与声明；同步提供中文标准注释。保留现有 HTTP、错误码、安全和兼容性要求，协议变更必须明确说明。
4. 为新增生产包扩展架构规则及正向命中校验，确认构建类路径实际包含该服务；只检查目录存在或接口数量不算架构验证。
5. 执行受影响测试与必要真实数据库验证，记录命令、结果、未验证项及存量差距。出现失败修复实现，不删除断言、不扩大排除、不用新包名逃避扫描。

生成前归属表至少包含以下字段：

| 业务用例 | 上下文/公开入口 | 应用与领域位置 | 输出端口/适配器位置 | 事务与授权边界 | 验证证据 |
|---|---|---|---|---|---|
| 本次真实业务操作 | 实际模块与稳定接口 | 实际类/包 | 实际接口/实现 | 写入范围、身份及范围来源 | 测试、命令、结果或明确未验证 |

## 9. 强制验收门禁

| 门禁 | 需要证明的事实 |
|---|---|
| 编译与装配 | Maven 依赖无环，启动组合能解析实际实现，未靠核心构造默认适配器 |
| 架构测试 | 所有本次新增/改造包被生产类扫描命中；领域和应用向内依赖；跨模块仅用公开边界；Web 不访问存储 |
| 领域规则测试 | 状态、不变量、精度及关键边界正确；简单委托不编写镜像测试 |
| 用例测试 | 用端口替身验证重要协调、拒绝路径与失败处理，不依赖数据库证明纯业务规则 |
| 存储与集成测试 | 真实数据库验证 SQL、迁移、锁、版本、回滚及跨租户拒绝；涉及幂等或并发时验证重放、冲突和竞态 |
| 安全与声明 | 对象/操作唯一，功能权限、数据范围与字段限制落入执行路径，撤权与伪造上下文被拒绝 |
| 全局记录审计 | 涉及新表时执行 GlobalRecordAuditTest.ownedTablesHaveAllFourColumns；写入及回滚满足四字段规则 |
| 文档与配置 | 中文 Javadoc、配置说明与默认值一致，未把骨架或未验证功能描述为已完成 |

现有 `ArchitectureRulesTest`、`ServiceLayerBoundaryTest` 及 `PackageDocumentationTest` 是门禁入口，但它们当前的扫描与断言不等于本文已全量自动执行。每次交付须补齐本次边界的检查，不能仅引用旧测试名称宣称通过。实际代码迁移及验证状态另行记录，不以本文发布代替全仓改造。

## 10. 明确禁止的生成结果

- Controller 直接调用 Mapper/JDBC，或以 Controller 取代应用用例。
- 核心声明返回 ResultSet、数据库 PO、Spring Page、Servlet 或引擎对象。
- 为绕过边界把业务规则搬进适配器，或把技术类重命名为 domain/core。
- 跨模块导入 internal/application/domain 实现、跨模块读写表或生成双向 Maven 依赖。
- 在启动模块实现业务逻辑，或把运行配置与菜单/字典业务配置混为同一职责。
- 复制平台旧 security Controller 的分布作为新功能默认结构。
- 创建未接入执行器的权限、审批、打印入口，使用模拟成功或客户端 Token 存储完成交付。
- 通过空包、过度接口、同义 DTO、通用 SQL 执行器及例外清单代替真实边界。

只有职责、依赖、装配、安全与测试均有证据时，才能将本次范围标为符合本标准；代码生成结束或目录齐全不能作为完成依据。

类型后缀、技术前缀、Controller/Mapper/仓储端口及实现的职责落位，强制执行[后端类型命名与分包规范](后端类型命名与分包规范.md)；存量位置不构成新增或修改代码的豁免。
