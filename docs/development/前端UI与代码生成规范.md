# 前端 UI 与代码生成规范

更新日期：2026-11-19；状态：当前系统的强制执行基线。

## 1. 目标与适用范围

统一不仅是颜色相同，还包括布局、组件、信息层级、操作语义、状态反馈、权限表达、响应式、无障碍和文案。本文用于新增、修改和审查前端代码；覆盖登录、后台、个人中心及未来领域模块。用户明确提出的需求优先，例外须在实现说明中记录原因和范围。

当前技术基线为 vue-pure-admin 7.0.0、Vue 3、Element Plus、Pinia、Vue Router，以及 Iconify/Remix Icon。遵循仓库锁文件，不因生成某个页面升级或引入另一套 UI 框架。

“必须”是交付要求；“默认”用于新页面，复用已有模板组件时以其既有规格为准，不为了套数值而改写上游布局。本文是后续生成基线，不表示历史页面已完成全部一致性审计。

## 2. 组件选型与代码归属

| 场景 | 必须优先使用 | 禁止事项 |
|---|---|---|
| 后台整体布局 | 当前 admin 应用壳、侧栏、顶部导航、标签页、面包屑 | 页面重复创建顶部栏、第二个全局侧栏或路由实例 |
| 同类业务交互 | 仓库已保留的模板增强组件 | 未检查现有能力就自绘同类控件 |
| 表单与校验 | el-form、el-form-item 和相应 Element Plus 输入组件 | 手绘输入框、独立错误样式、仅靠 placeholder 作标签 |
| 按钮、菜单、选项卡 | el-button、el-menu、el-tabs、el-dropdown | 用 div/span 点击模拟已有组件 |
| 弹出框 | 统一使用 `@appnexus/ui` 的 ManagedDialog；应用壳动态弹层使用 ReDialog | 使用 Drawer，或另写弹层定位、遮罩与焦点系统 |
| 列表与分页 | ManagementTable；明细通过 @appnexus/ui 的 VxeTable/VxeColumn，分页使用 AppPagination | 为了使用已裁剪的示例而重新导入整套模板演示依赖 |
| 提示与状态 | 统一异常浮层、InfoHint、el-empty、el-skeleton、v-loading；Alert 仅用于非异常状态 | 自建 Toast 系统、以空白代替故障和空态 |
| 图标 | @appnexus/icons 的 AppIcon；模板内部继续使用既有 ReIcon | 新图标库、emoji 充当操作图标、业务深层导入模板组件 |
| 主题与语言 | ThemeToggle、模板主题入口与 i18n | 独立主题存储、重复语言实例、把身份信息写入展示偏好 |

只有现有组件确实不合适时才能新增。记录“需求、已检查组件、不适用原因、最小扩展、复用位置”；通常先组合而非重写。不存在的功能不提前建空包。

业务页面属于 frontend/modules/<领域>；启动和装配属于 apps/admin；与模板相关的适配当前在 admin 内，稳定公共能力按需提取到 infra。领域模块只能经公开入口使用跨包能力。个人中心当前属于应用壳自助设置页面，后续按领域规模调整时同步设计。

## 3. 视觉基础

| 项目 | 新页面默认标准 | 当前来源与约束 |
|---|---|---|
| 字体 | 继承全站中文无衬线字体，不另设字体 | src/style/reset.scss；不得页面级替换为衬线或装饰字体 |
| 正文/标签 | 14px，行高约 1.5–1.7；说明 12–13px | 优先 Element Plus 字号变量与组件默认值 |
| 页面标题 | 20–24px，字重 600；分组标题 16px | 一个页面只有一个主标题，不把所有字段加粗 |
| 颜色 | 主色、成功、警告、危险、文字、边框、背景分别使用语义变量 | --el-color-primary、--el-color-success/warning/danger、--el-text-color-*、--el-border-color-*、--el-bg-color/--el-fill-color-* |
| 主色 | 跟随全局配置及用户主题色 | platform-config.json 当前 EpThemeColor 为 #006BE6；业务 CSS 不复制该值 |
| 间距 | 以 4px 为步进，常用 8/12/16/24/32px | 同排工具间距 8px；页面、区块与内容留白使用第 13 节公共 Token |
| 圆角 | 使用 --el-border-radius-base/small/round | 不给普通 CRUD 页面增加登录宣传页式大圆角 |
| 阴影 | 普通内容卡片优先无阴影、轻边框 | 弹层按模板默认，不滥用悬浮效果和渐变 |
| 密度 | 后台默认组件尺寸；登录或重要独立表单可 large | 同一行控件必须尺寸一致，不全站强制放大 |

颜色不能单独表达状态，必须配文字或图标。不得使用不随主题变化的白色页面背景和黑色正文覆盖变量。登录页的双栏插画是模板登录场景延伸，不作为列表、详情和设置页的通用视觉样式。

## 4. 页面布局范式

| 页面类型 | 固定组织方式 |
|---|---|
| 登录 | 独立页面；品牌、主题/语言入口、单一凭据表单；移动端隐藏非必要插画；保留标准 CSRF 表单和 BFF 流程 |
| 查询列表 | 标题/说明 → 筛选 → 主操作工具栏 → 表格 → 分页；新增按钮在固定工具栏位置 |
| 编辑/新建 | 标题 → 分组表单 → 保存/取消；编辑默认使用统一弹出框，内容过于复杂时使用独立页，不使用抽屉 |
| 详情 | 标题和状态 → 摘要 → 业务分组/标签 → 操作；只读字段不使用可编辑输入框伪装 |
| 个人中心 | 保留外层应用壳；内部账号摘要和分区菜单 → 右侧信息/偏好/账号安全；偏好即时生效，资料显式保存 |
| 错误页 | 模板 403/404/500 页面，给出返回或重试；不展示堆栈与内部路径 |

页宽服从模板“固定/自定义页宽”能力，页面不得用任意固定宽度破坏该设置。长表格在自己的容器内滚动；页面正文不得横向溢出。

## 5. 图标与操作语义

- 新业务图标统一 Remix Icon 线性风格，构建期生成本地 SVG。主导航保留模板既有填充图标，不因本规范一次性替换上游图标。
- AppIcon 默认 20px；正文/输入框 16–18px、工具栏 18–20px、空态或头像标记可 24–40px。同一区域保持一致，不拉伸宽高比例。
- 图标名称表达业务语义，如 user、lock、settings；同一操作全站使用同一图标，不混入另一套粗细或多彩图标。
- 图标按钮必须有可访问名称；不明确的操作加 Tooltip。装饰图标 aria-hidden，不重复朗读标签。
- 同一操作组原则上一个主要按钮；主操作 primary、一般操作 default、导航/轻操作 text 或 link、破坏性操作 danger。保存、取消位置保持一致。
- 删除、停用、撤销等动作说明对象和后果并确认；确认按钮使用具体动词，不使用含糊的“确定”替代危险动作。

## 6. 表单、表格与数据展示

- 列表和页头的只读业务状态复用 Element Plus `el-tag`，使用公共 `app-status-tag` 圆角和默认 `light` 效果。启用使用 `success`、停用使用 `info`，其他状态按实际业务严重程度选用语义类型。详情表单网格中的只读状态使用 `el-form-item` 和公共 `detail-status-value`，与相邻字段对齐。各场景保留状态文案，筛选器、可编辑控件、编码和分类标签沿用各自的样式。

- 普通业务表单使用 el-form 统一校验；凭据页允许原生 form 承载标准服务端 POST，但输入和按钮仍使用 Element Plus，不能改变安全流程。
- 普通业务维护表单复用第 13 节恒显边框标签；特殊表单沿用对应场景布局，移动端确保标签可见，不以 placeholder 代替标签。
- 必填标识由组件产生；说明写在字段旁，错误放在对应字段并定位首个错误。不把所有字段错误合并为一个 Toast。
- 控件类型匹配数据；选择用 Select/TreeSelect，日期用 DatePicker，开关只用于明确的二元状态。开关必须标明是否即时保存，失败回滚。
- 提交期间按钮 loading、防止重复提交；失败保留非敏感输入。密码不进日志、URL、持久存储；完成、取消或离开分区时清空。
- 校验前后端一致；前端校验用于体验，服务端为最终权威。长度、金额精度、日期时区必须有契约，不擅自转换业务语义。
- 表格左对齐文本，数值/金额右对齐；列宽、空值占位和操作列一致。默认空值显示“—”，0 不当作空值；长文本按需省略并可查看全文。
- 表格操作统一位置，尽可能将操作按钮横向平铺展示，按按钮数量和中英文文案预留操作列宽度，避免同组按钮换行；仅操作过多且明显挤占数据阅读空间时将低频操作收进更多菜单。窄屏优先使用表格内部横向滚动，保留完整操作。筛选更新重置页码；删除当前页最后一项后修正分页；默认分页参数服从 API 契约，不硬造总数。
- 时间、数字、币种经统一国际化规则格式化；金额不用浮点重算后端结果，标识按字符串处理。日期与时间点不得混淆。

## 7. 请求状态、错误与会话

业务异常的展示与接入统一执行[全局统一异常处理方案](全局统一异常处理方案.md)：使用脱离文档流的浮动图层，不向页面或弹窗插入挤压内容的业务错误 Alert。字段输入校验、原数据区域内的不可用状态及静态说明按方案边界处理。该约束是后续开发与迁移基线，不表示所有页面均已完成验收。

每个读写功能必须明确：首次加载、刷新、无数据、筛选无结果、错误、无权限、保存中、成功。已有内容刷新不闪成空白；失败提供可执行的重试入口，不能显示成功假数据。

| 结果 | 统一处理 |
|---|---|
| 401 | 使用现有 sessionLifecycle 清理展示状态、菜单与标签，回登录页给出失效原因；不循环重定向 |
| 403 | 提示权限或安全凭据问题，不能伪装成空数据或重试至成功 |
| 409 | 提示数据/凭据已变化；需要时引导重新加载，不盲目覆盖 |
| 429 | 提示频繁操作，按 Retry-After 提供等待语义，不自动连续重试写请求 |
| 网络/5xx | 保留页面与安全的用户输入，提示服务不可用并提供重试，不自动注销 |
| 字段错误 | 映射稳定业务码/字段错误并在字段旁展示，不依赖翻译后句子判断结果 |
| 成功 | 一次操作一次适当反馈；刷新受影响内容，不重复 Toast/弹窗 |

现有入口为 utils/http、api/session 和 utils/sessionLifecycle，新增页面复用这些能力。安全配置、Cookie、CSRF 和真实认证协议不得因 UI 统一而退回模板模拟 Token 方案。

跨业务穿透导航统一使用应用内上下文切换：服务端上下文更新成功后，清理受影响的标签与页面缓存，通过 Vue Router 定位目标菜单并重建内容区；禁止用 `window.location.reload` 代替内容刷新。目标路由不同则直接导航，目标相同则通过模板 redirect 路由中转重建组件。OAuth 登录等必须离开 SPA 的协议跳转不受此限制。

## 8. 权限与功能真实性

- 权限相关界面执行[统一权限模型强制接入](业务服务统一开发规范.md#31-统一权限模型强制接入)：复用统一授权中心、操作准入及服务端字段限制契约，不为业务对象自行建立平行授权页面/API，不在浏览器按角色名、人员或组织关系自行推断访问权。

- 菜单/按钮可见性只改善体验，所有接口权限、租户和数据边界由后端校验。登录不自动产生角色或管理员业务权限。
- 无权限字段的原值不得先到浏览器再隐藏；禁用、隐藏、脱敏由业务契约决定，不自行猜测。
- 只提供已接通的功能。个人中心当前不提供模拟安全日志、无后端头像上传和未经验证的联系方式绑定；偏好不提供未接入通知系统的开关。
- 默认账号 UUID 不作为主要业务文案，放次级只读信息；生产页面不显示框架版本、数据库配置或内部调试信息。

## 9. 主题、国际化、响应式与无障碍

- 浅色/深色/跟随系统共用模板主题状态；ThemeToggle 是已有主题能力的薄适配。状态提示、图标、输入、禁用、悬浮、弹层均需验证深色模式。
- 用户可见文案进入 zh-CN.yaml/en.yaml；错误优先通过稳定码映射语言，不以中文字符串判断业务。英文变长不得截断必要操作。
- 验收视口至少包括桌面 1440×900、窄屏 1024×768、手机 390×844；移动端主要触控区域尽量达到 44×44px，小按钮通过容器扩大命中区。
- 窄屏多列表单转单列；内部导航可折行/切换为适合窄屏的布局；页面无横向溢出。不能简单隐藏核心功能来通过响应式检查。
- 使用语义标题、真实标签、按钮和链接；支持 Tab、Enter、Space 操作及可见焦点。弹窗复用组件的焦点管理，不手动破坏焦点恢复。
- 正文对比度以 WCAG AA 为目标（普通文字至少 4.5:1，大字至少 3:1），重要状态不能仅靠颜色；动画尊重 reduced-motion。

## 10. 生成代码的固定流程

1. 阅读 AGENTS.md、本文、对应领域/API 设计，并检查仓库现有相似页面及可用模板组件。
2. 明确页面类型、路由和权限、字段契约、组件选型、交互及状态；资料不全时优先检查代码与契约，不编造 API。
3. 实现最小可用功能，使用模板组件及主题变量；跨包只用公开入口，中文注释遵守仓库规则。
4. 有自定义组件时记录理由；新增配置须说明用途、单位、默认值、环境和安全影响。严格 JSON 的参数说明写入配套文档，不破坏语法。
5. 完成类型检查、构建和适当功能测试；浏览器验证主流程、错误、主题与响应式。使用独立测试账号，不修改现有管理员凭据。
6. 同步设计文档与验收证据，清理测试数据。未验证项明确列出，不用“构建成功”代替界面验收。

可复用的生成任务约束：

> 按 AGENTS.md 和《前端 UI 与代码生成规范》实现本功能。先检查当前 vue-pure-admin 相似页面与已保留组件，优先模板增强组件，其次 Element Plus；不得引入其他 UI/图标体系。复用应用壳、@appnexus/icons、主题与 i18n、HTTP/CSRF/会话入口。覆盖加载/空态/错误/权限/提交状态，保持中英文、深浅主题及移动端一致。重要参数中文注释。完成类型检查、构建、浏览器主流程和错误验证；如必须新增组件，记录现有组件不适用的原因，并同步文档。

## 11. 交付门槛

- 组件与模板同类页面一致，无平行布局、主题或图标体系；例外有明确记录。
- 页面层级、间距、按钮语义和表单/表格对齐一致，无未接通入口或模拟业务数据。
- 加载、空态、字段错误、权限、冲突、服务故障和提交反馈齐全，密码等敏感信息不落入浏览器存储或日志。
- 键盘可操作、标签可识别、焦点可见，桌面/窄屏/手机无正文溢出，深浅主题及英文可读。
- 前端 typecheck/build 通过；重要流程有真实浏览器证据；影响接口或权限的变更有相应后端验证。
- 本文作为人工及代码生成审查门槛；目前未实现自动 UI 一致性 lint，不宣称全部要求已经自动执行。

顶部快捷入口统一规范：主题与语言均使用 Element Plus Dropdown + text Button，18px 图标、40×48px 点击区域，无胶囊分组、常驻底色或阴影。当前主题用单一图标表达，点击菜单选择浅色/深色/系统；登录页与三种后台导航使用同一组件。设置页需要快捷主题入口时也使用相同组件。

内容容器一致性：普通内容页及个人中心外框统一使用 el-card shadow=never，保留组件的边框与圆角；页面外边距由模板 main-content 的 12px 统一提供（按用户确认从 24px 经 16px 缩小），页面不得另设外框圆角或重复外边距。个人中心仅覆盖卡片 body 的内部排布与 padding，不覆盖外框视觉。验收须对比相邻路由的内容左上角坐标、边框和圆角。

登录页同样遵循全站基础圆角：外框使用 --el-border-radius-base、无额外阴影，输入框与按钮不覆盖组件原生圆角；不得将独立登录场景解释成允许 28px 外框或 9px 控件圆角。移动端全宽无外框时可取消外框边界。

## 12. 已确认的内容区参考模板与选用规则

用户提供的三个 pure-admin 页面参考确认为后续管理页面的内容布局基线。新增或改造页面必须根据管理对象与任务选择以下模板，沿用当前 pure-admin、Element Plus 组件和交互；不得仅因视觉偏好重新组织一套布局。

| 模板 | 适用场景 | 内容组织与选择依据 |
|---|---|---|
| 标准列表（系统日志参考） | 用户、租户、日志等平面数据的查询和维护 | 顶部独立筛选容器；下方数据容器按工具栏、表格、底部分页组织。不需要层级导航时优先采用。 |
| 左树右表（部门与用户参考） | 先选择组织或分类，再管理其关联成员或其他数据 | 左侧独立树容器提供树内搜索和展开、收起；右侧上方为筛选区，下方为数据区。选中节点明确限定右侧查询范围，筛选重置默认保留当前节点，查询重置页码。 |
| 树形表格（菜单管理参考） | 维护具有真实父子关系的对象，同时比较其多列属性 | 首列缩进并支持节点展开、收起，其余属性按列对齐；对象操作固定在操作列。新增下级等动作仅在真实业务契约支持时提供。完整树不得直接按普通行分页而拆散父子关系。 |

### 12.1 共用布局与操作约束

- 所有业务页面先定义 `BusinessWorkspace` 的业务身份，再组织导航、查询和数据/详情区。标准列表、左树右表、租户选择和个人中心不重复应用壳面包屑；纯展示标题由公共工作区横幅统一提供；`PageHeader` 仅用于详情、创建、编辑等需要对象标题、状态或页面级操作的场景。只有下级对象上下文才在工作区显示对象名称与状态。属于同一对象的 Tab、SearchPanel、DataPanel 必须共享一个工作区表面与外边界，内部用背景层次、间距和轻分隔线表达层级；不得表现为三个互不关联的卡片。
- 业务导航位于工作区顶部；切换后工作区说明、查询标题、列表标题、数据、主操作和状态必须同步。查询标题应体现对象，如“租户查询”，不能只写无归属的“查询条件”。
- 工作区内部嵌入公共表格时使用无重复卡片边界的模式；弹出框或全屏仍保留独立表面。全站禁止业务抽屉；弹出框统一使用浅色标题栏、最大化和关闭图标，普通状态沿用 Element Plus 初始打开位置且不得在打开动画后进行二次定位，并允许拖动标题栏移动；最大化占据完整浏览器视口并覆盖应用壳。桌面端允许右下角手动调节宽高，普通状态下移动与调节不得把标题栏或关闭按钮移出内容区，移动端自动适配视口。该原则同样适用于左树右表、上下联动、详情表单、左右详情、Tab 详情、卡片网格和数据概览。

- 筛选区与数据区分为两个清晰容器；筛选条件左对齐，“查询 / 重置”按钮组统一靠筛选区右侧。窄屏换行后按钮组仍在可用行内右对齐，不隐藏必要条件和操作。
- 数据区工具栏左侧显示列表或任务标题，右侧依次放业务主操作、刷新、密度、列设置、全屏。避免在内容顶部重复大标题、长说明与相同列表标题。
- 调整布局不得减少已有业务操作或表格工具能力。原有新增、编辑、删除、成员管理、授权等入口按对象归属保留；权限校验、危险操作确认及真实接口契约保持有效。
- 刷新、密度、列设置、全屏作为表格工具标准能力，优先复用当前模板组件。列设置按模板支持列显隐、排序、固定和重置；已存在的能力不得在改版时丢失，尚未接入的能力必须实现后才展示有效入口，不以无响应按钮交付。
- 分页放在数据容器底部右侧，顺序与模板一致。桌面列表数据区可撑满可用高度，表格滚动与底部分页配合；移动端按内容自然排列，不以固定高度造成遮挡或正文横向溢出。
- 左树用于选择右侧数据范围，树形表格用于维护层级对象自身，二者不得混淆。仅有平面组织接口时不得编造层级、父子关系或新增下级能力。
- 实现前在对应前端设计说明中记录选用模板及业务理由；验收同时检查布局、查询按钮右对齐、完整业务操作、表格工具、请求状态、主题、国际化及响应式。

本节细化第 4 节的查询列表布局；列表创建入口统一归入数据工具栏右侧。截图中的演示说明、模拟数据和未接通功能不属于生产交付内容。

## 13. 当前公共视觉与布局规则

### 13.1 主题、密度与公共 Token

字体与中性色由 `apps/admin/src/style/index.scss`、`reset.scss` 的全局变量提供，保留当前已采纳的系统字体和中性灰配色；布局、交互和组件仍以 vue-pure-admin / Element Plus 为唯一基线。不在业务页面复制旧版浅蓝、深蓝背景色或另建主题。主题主色继续由模板管理，缺省 EpThemeColor 为 #006BE6，已有用户偏好不强制覆盖。

| 参数 | 当前默认值与范围 | 用途及修改影响 |
|---|---|---|
| --app-page-gap | 8px | 路由内容外边距，与可用高度计算联动。 |
| --app-content-padding | 8px | 普通公共容器内边距；不能用区块间距控制内容留白。 |
| --app-section-gap / configure.sectionGap | 默认 8px，允许 0–24px，步进 2px；非法值回退 8px | 系统设置中的区块间距；沿用模板显示偏好持久化，即时生效。只改变独立区域之间的间隔，不改变导航留白、字段行距或边框。 |
| --app-card-radius | 8px | 公共卡片圆角；控件另用 --app-control-radius。 |
| --app-category-width | 220px；显式 treeWidth 限制 220–360px | TreeListTemplate 左分类缺省宽度。 |
| configure.hidePageBanner | false | 隐藏纯展示横幅；标记 data-page-banner，不得隐藏导航、查询、必需操作或详情操作区。 |

以上均为展示参数，单位为 px（布尔项除外），适用于浅色、深色和系统主题，不参与身份、安全或业务数据。BusinessWorkspace 及树表右侧分区用 `row-gap: var(--app-section-gap)`，间隔采用页面底色，内容内边距保持独立。字典和菜单继承全局间距，不保留旧 12px 局部密度例外。

公共横幅沿用字典样板：20px 标题、13px 辅助说明、主题轻装饰、桌面 44px 图标，移动端 40px 并去除非必要装饰。查询标题与表单间距 4px，工具栏与表格间距 8px；查询/重置按钮统一 8px gap，清除重复按钮 margin。

### 13.1.1 全局布局规则强制继承

- 所有新增、修改和重构页面必须继承全局布局、密度和公共组件规则；使用公共组件不等于已合规，必须检查最终容器叠加、CSS 优先级及实际渲染。不得以 scoped、`:deep()`、内联样式或宽泛 `:has()` 选择器覆盖公共布局来形成页面专属密度。
- 路由页面必须明确承接应用壳传入的 `main-content` 等布局属性，并保持到实际内容宿主的传递链。标准管理页使用已有单根管理容器；使用 Fragment、多根组件或 `inheritAttrs: false` 时必须显式将布局属性绑定到唯一的页面内容宿主，不能依赖 Vue 自动透传。弹窗和 Teleport 内容不作为页面边距宿主。
- 独立区块间距只用 `--app-section-gap`，公共内容内边距只用 `--app-content-padding`，页面外边距只用 `--app-page-gap`；缺省分别为 8px。不得混用 Token、固定区块间距，或同时叠加 gap、margin、分隔线 padding 形成重复留白。字段、工具按钮及专业画布内部间距按对应规范，不将所有像素值一律替换成区块 Token。
- 查询、工具栏、表格、分页和树容器的公共密度由公共组件维护；嵌入工作区必须声明 embedded，移除重复横幅、外框及容器留白。上下主从列表使用公共 business-workspace-stack 组合，保持一层内容 padding；自然高度与视口填满能力由公共模式提供，不允许业务页深层改写表体、全屏和焦点结构。
- 全局装配样式只能作用于明确宿主，不得因子孙包含工作区而把左右 grid、树表、上下主从或专业画布改为纵向 flex。修复共性问题优先调整公共能力，并检查受影响页面；不复制局部补丁。
- 业务确需偏离时，实施前记录需求、适用页面、已检查公共能力、不适用原因和最小差异；将共性能力回收至公共组件。用户已授权范围内无需重复请求批准，但未经说明的历史覆盖不能作为新增模板。
- 交付前必须验证全局区块间距 0/8/24px、树展开/收起、普通/全屏、桌面/窄屏/手机及主题；确认无重复留白、横向溢出、列表压缩和核心操作丢失。在 docs/validation 逐项记录证据与未验项；静态扫描候选必须人工判断，不能将所有固定字段间距误报为违规，也不能将未命中视为视觉通过。

#### 每次代码交付前的全局布局验证（强制）

每次新增、修改或重构前端页面、组件、路由装配或公共样式，必须在交付代码前完成以下检查；公共组件变更同时验证受影响的代表性页面。后续修改影响布局时必须重验，不能沿用修改前证据。

1. **检查实际宿主**：从真实路由进入页面，检查渲染 DOM，确认 `main-content` 落在预期内容宿主，Fragment、多层组件及属性透传未使布局类丢失；没有属性无法继承的 Vue 警告。
2. **检查计算样式与边界**：记录页面外边距、工作区和嵌入表格的边框/圆角、内容 padding、区块 gap 的实际计算值及规则来源。页面外边距使用 `--app-page-gap`，内容 padding 使用 `--app-content-padding`，区块 gap 使用 `--app-section-gap`；边框及圆角来自公共模板和主题变量。确认未被局部样式覆盖，无重复外框和叠加留白，并与同类模板页面对照。
3. **检查动态继承**：切换全局区块间距 0/8/24px，验证区块间距实际随设置变化且内容 padding、页面外边距不被误改；覆盖桌面1440×900、窄屏1024×768、手机390×844、浅色/深色/系统主题，及适用的普通/全屏、树展开/收起。无树等不适用场景说明理由。
4. **保存证据并判定**：在 `docs/validation/` 记录最终代码依据、页面路由、验证身份、视口、主题、设置值、实际结果及截图或 DOM/计算样式证据，按交付门禁 C07 逐项判定。类型检查、构建成功、静态解析单根节点或仅使用公共组件均不能替代上述实际页面验证；失败或未验证不得宣称前端交付完成，只能明确提供待验收代码及阻断原因。

### 13.2 工作区、表格与查询

- 公共工作区共用外框，嵌入表格取消重复边框和卡片留白；全屏表格保留独立表面。独立 TreeListTemplate 横幅与内容间隔同样响应区块间距。
- 标准管理页在 viewport-page-host 内传递 flex/min-height:0；横幅、导航、工具栏、分页不收缩，分类独立滚动，表体占剩余高度。弹窗、非标准页面和专用画布按各自场景布局。
- 全部业务表格采用 VxeTable：主列表复用 ManagementTable；明细、展开行、编辑表格经 @appnexus/ui 公开入口使用 VxeTable/VxeColumn。保留模板工具、树层级、真实授权和分页契约，不新增直接 el-table 实现。展开内容使用 content 插槽，编辑行使用 rowIndex，列宽拖动由 column-config.resizable 控制，默认 true，仅影响展示。
- 工具顺序为业务操作、刷新、密度、列设置、最大化/还原。列设置保留显隐、重置、排序和左右固定，至少保留一个业务列；展示偏好不得绕过字段授权或跨账号/租户混用。
- 业务列表默认将主要业务状态作为第一数据列，已有业务编码或单号紧随其后。保留选择、展开及用户列设置，引用编码和附加状态按业务顺序呈现。
- search 插槽由公共 SearchPanel 包装，默认展开，v-show 收起保留条件与表单实例，不触发请求。标题由业务名或 searchTitle 提供，页面不重复创建折叠入口与同义标题。
- 分页统一 AppPagination，默认小尺寸、右对齐及真实总数。可切换容量的列表默认 20/50/100 条；固定容量接口隐藏容量选项。ManagementTable 仅在持有完整平面数据且未提供分页插槽时自动本地分页，默认每页 20 条；树不拆散层级，服务端分页由调用方提供总数。
- 查询与表格标题标记统一为 4px × 18px 主题色竖条、8px 标题间距。横向页签保持 44px 标题高度、选中加粗及原生活动条；保留窄屏滚动、卡片页签边框与纵向导航。
- 字典对象摘要及操作放 TreeListTemplate header，查询标题为“字典项查询”，嵌入适配器使用 embedded（默认 false）。菜单不恢复仅重复选中节点名称与编码的摘要栏，保留真实节点操作。

### 13.2.1 左树样式与默认布局（强制）

- 标准范围导航统一复用公开 `TreeListTemplate` 与模板已采用的 Element Plus Tree；不得为单页复制树头、折叠、节点悬停/选中或宽度样式。平面分类使用模板已有菜单组合，不伪造层级。
- 桌面与窄屏（大于760px）左栏默认宽度统一 `--app-category-width: 220px`，右栏 `minmax(0,1fr)`；收起栏48px。页面默认不得传 treeWidth 或重写 grid-template-columns。确需宽树时，先记录具体内容、默认宽度不适用原因和影响页面，经公共 treeWidth 参数使用220–360px范围；禁止仅为视觉偏好设置局部宽度。当前标准业务树无宽度例外。
- 树头最小高度44px、border-box、内边距6px 8px，折叠按钮36×36px；树内容内边距6px。标题与操作在同一行，长标题允许省略并保留完整可访问名称。普通节点36px、13px字号，圆角使用主题small变量；悬停为主题轻填充，当前节点用主题浅主色、主色文字和2px内侧标记，键盘焦点必须可见。
- 节点内容过长单行省略，不撑大侧栏；业务插槽负责真实名称、编码、状态和操作，不重定义节点视觉。粗指针节点和折叠按钮至少44px；760px及以下继承统一上下排列、树区最大高度280px，不强行维持220px左右分栏导致手机溢出。所有主题使用同一公共规则。
- 多行角色说明等确有业务需要的节点可用自然高度并记录适用范围；当前 AuthorizationCenter 的角色树为多行角色说明，保留48px最小高度。这不是其他普通树的扩展模板。专业设计器画布内的结构树须说明场景，不得混入标准业务左树例外。
- 交付检查左栏默认/收起宽度、节点/树头尺寸、长名称、焦点、触屏和三个视口；同时检查所有业务页是否仍有 treeWidth、深层公共样式覆盖或硬编码左右列宽。静态无覆盖不等于实际视觉通过。

### 13.3 详情与普通维护表单

无专项布局要求的业务详情、新建与编辑，以客商管理详情页（`frontend/modules/master-data/src/PartnerEditor.vue`）为全局布局与 UI 样板，复用 `TabbedDetailTemplate master-data`：`PageHeader` → 分组业务信息 → 只读系统信息 → 明细页签。页头左侧显示对象标题和真实状态，右侧集中页面操作。复杂表单沿用同一页面壳，无真实明细时不创建空页签。

- 对象具备已接通且获授权的变更记录读取操作时，须在 `PageHeader` 的 `trailing` 插槽提供「变更记录」按钮。按钮贴齐页头右端，隐藏标题横幅时仍保持右对齐。用户点击后才通过既有读取操作加载，并使用公共 `ManagedDialog` 展示、分页及反馈失败。历史不占用详情正文或明细页签。没有记录读取能力或当前账号无权时不展示入口。打开、翻页与重试只读取已授权的当前档案，失败保留详情及未保存输入。

- 单一页头标题，编码和状态置于 meta，编辑态右侧仅一组返回/保存；操作不能被横幅偏好隐藏。页头上下 padding 为 0，最小行高 32px，手机操作命中区至少 44px。
- 查询详情及编辑详情的基本信息区域，已有业务状态紧随业务编码或单号。状态只读时使用公共状态标签和已经授权返回的真实值；已有状态编辑保留原有操作和权限。
- 查看与编辑共用详情模板时按实际表单容器宽度分列：1320px 及以上六列、720–1319px 四列、480–719px 两列、480px 以下单列，列距 16px；备注可跨列。不得恢复先前按窗口宽度强制四列的规则。
- 显式查看态按分组顺序展示无边框的只读标签和值。业务状态标签按内容宽度展示。独立摘要或详情弹窗可使用单列字段清单。隐藏修改类按钮和表格工具栏，保留与编辑态同侧的返回按钮、获授权的变更记录、弹窗关闭、页签和分页等导航。
- 人员基础/详细资料使用 detail-border-label-form，标签恒显于控件边框，保留 label 关联、必填星号和校验。控件最小高 36px、手机 40px，标签 12px，不缩小正文。该人员样板限定不自动扩展为全站六列。
- 普通业务维护表单使用 business-border-label-form 复用公共恒显边框标签，保留各页列数。只作用于输入、选择、日期、文本域；开关、操作及说明保持原布局。登录、账号安全/MFA/密码、inline 查询、流程和打印画布除外；其他特殊字段通过 data-form-style="special" 明确退出。
- 详情外层单一纵向滚动，业务卡片不 flex-shrink 压缩、不另设纵向滚动；表格仅横向滚动，全屏例外。区块标题上下留白 6px、内容 10px/12px、字段底间距 10px。短详情末卡片填充剩余空间，底部引用 --app-page-gap，长详情自然增高。
- 详细信息折叠使用 v-show 保留草稿与校验，原子保存由同一个 el-form 管理。已保存编码只读、单行省略，Tooltip 支持悬停和键盘聚焦，长值浮层在视口内换行。
- 系统信息独立只读显示四项真实审计字段，查看和编辑布局一致，标签后直接显示值，使用公共时间格式化，历史未知值明确提示；审计字段不进入提交。只读用户用标签和值展示详情，不能用禁用输入框伪装。
- 明细复用 ManagementTable、ManagedDialog、AppPagination、InfoHint 与操作准入；不增加虚构头像上传、字典选项或业务入口。

### 13.4 提示与图标

静态说明与能力边界复用 InfoHint，通过信息图标点击或键盘激活 Element Plus Popover。业务异常执行[统一异常方案](全局统一异常处理方案.md)；任务状态、设计器校验和成功反馈按对应组件展示，不能将动态失败重新放回布局内 Alert。

分区展开/收起使用 AppIcon：展开态显示 arrowUp，收起态显示 arrowDown，18px；保留国际化 aria-label、aria-expanded 和必要的 aria-controls。左右面板沿用 collapsePanel/expandPanel，方向随位置；模板树、菜单与折叠组件保留原适配。下拉用 arrowDown，不拼接 Unicode 箭头。纵向侧栏展开箭头保持 14px、垂直居中、距右侧 20px，并保留原旋转及折叠行为。
