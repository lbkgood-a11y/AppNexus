# 业务对象数据权限声明标准

更新日期：2026-11-19。本文为新增及改造业务对象的数据权限接入标准；客商示例仅说明接入约束。历史测试和部署证据见[历史记录](../design/业务对象数据权限声明标准历史记录.md)，不能代替当前版本验收。

数据权限是完整对象声明的一部分。每个功能同时执行[业务对象完整声明规范](业务对象完整声明规范.md)的 D01–D12，不能以仅完成权限资源登记替代工作流、编码、打印、数据契约和真实运行接入的适用性检查。

## 1. 唯一来源与模块边界

所有未来新增功能创建时即接入统一权限模型，具体执行[业务服务统一开发规范](业务服务统一开发规范.md#31-统一权限模型强制接入)；适用的数据权限必须真实执行，能力不足先扩展公共模型。存量和新增的单据、非单据及引用入口统一纳入本规范。技术形态、调用来源和交付批次不得形成独立权限通道。

权限管理与执行必须遵守[统一权限模型强制接入](业务服务统一开发规范.md#31-统一权限模型强制接入)。业务对象适配器只连接统一决策和公共执行能力、固定映射及业务约束，不得自行实现权限管理、范围合并或平行策略存储；现有公共模型不支持的场景应先扩展公共能力，再接入对象。

新建或改造对象统一通过 BusinessObjects.Provider 唯一登记；Controller仅通过OperationBinding(reference=true)引用。未迁移对象的既有注解暂时保留，不能为同一对象再叠加Provider。数据权限是统一对象的dataAccess部分，只按operationCode声明支持范围，不复制对象身份或另建功能权限。统一对象标准位于 business-object-contracts 的 BusinessObjects.Descriptor；对象身份、版本、操作、交互与 dataAccess 共同在一份 Descriptor 中声明，业务模块只实现 BusinessObjects.Provider。platform-authorization 的 DataAccessDeclaration 仅为派生只读投影，已删除独立 Provider 入口。平台从同一对象声明生成 DataAccessCatalog。业务执行器实现 Executor 并实际消费公开 AccessPlanning / FieldProtection / DataAccessReferences，不跨模块查询组织、角色或成员表。

单据的提交、审核、撤销、过账，及非单据的查询、写入、引用、导入导出、汇总、回调与任务等实际入口，分别绑定真实操作、可信主体与数据资源。需要行范围时，统一生成权限计划、使用公共执行器，并在写入前复核实际涉及的原记录与目标资源。跨对象引用须按声明验证来源操作的可读范围与目标操作的业务资格；后台和外部调用使用平台认可的委托或机器身份。业务适配器只维护固定列、关联关系、业务状态与事务规则。公开、自助、平台管理和机器调用按统一模型选择相应的准入类型，逐项记录适用的数据边界。

能力声明由代码发布，不提供管理员编辑入口。授权策略由授权中心保存至现有 access_role_data_policy、access_member_authorization*、access_role_field_security；access_permission_scope_type 作为代码目录的数据库投影，既有数据库外键继续约束策略。平台装配期校验声明和真实MVC操作、权限目录、执行适配器；缺失或冲突阻止启动。字段目录仅从统一BusinessObjects.Provider派生；已删除旧响应字段注解和类路径扫描。自动响应执行通过同一资源的responseType绑定真实record，业务显式执行器缺省不设置该绑定。

## 2. 声明参数和校验

| 参数 | 规则与缺省行为 |
| --- | --- |
| objectType | 已登记业务对象标识，大写开头字母数字；对象唯一，必填 |
| version | 正整数声明版本；修改安全语义必须递增，删除已被策略引用的字段前必须迁移 |
| scope | TENANT或PLATFORM，必填，不允许跨管理域授权；业务行范围按已实现的租户能力声明，不能据管理域枚举推断平台行范围已支持 |
| resources | 首项为主资源，后续为子资源；资源编码全局唯一、小写点分段，不是表名 |
| parentResource | 主资源为空串，子资源明确引用同声明主资源；当前仅支持直接主从继承，禁止暗中拼接独立行策略 |
| resource.nameZh/nameEn | 中英文业务名称必填，授权中心直接消费，不能以客户端传入名称作为目录来源 |
| operations | 唯一操作清单声明operationCode、operationId、permissionCode、页面和交互；权限码必须属于已接通的主资源 |
| dataAccess.operationScopes | 以同对象已声明operationCode为键，值为受控范围集合；不再重复操作标识或权限码，未知键拒绝 |
| scopes | 仅声明实际执行的范围；当前实现ALL、ORGANIZATION、ORGANIZATION_SUBTREE及已接通操作的RULES；拒绝DENY和无明确含义的SELF；不支持的条件不展示 |
| dataAccess.dimensions | 条件声明包括业务字段、值类型、运算符、选值来源和适用操作。可用来源为 TEXT、ORGANIZATION（同租户组织 UUID）与 DICTIONARY（声明的字典编码）；服务端保存时复核组织和字典值。operationCodes 为空表示所有支持 RULES 的操作，指定时只开放对应操作。 |
| fields.field | 资源内唯一、字母开头的稳定业务字段键；不能是任意属性路径或SQL列名 |
| fields.kind | PHONE、EMAIL、PERSON_NAME、IDENTIFIER、BANK_ACCOUNT、TEXT，使用统一服务端算法 |
| fields.modes | READ_ONLY、MASKED、HIDDEN中已执行的集合，不能为空；只读不意味着额外读取授权 |

无能力目录、无功能权限、缺少行策略、上下文异常默认拒绝；不得用ALL作故障回退。目录版本令牌为按管理域/对象排序的声明版本，角色配置读取返回dataAccessVersion，业务数据权限Web保存必须原样回传，冲突要求重新加载。已有组织管理旧调用保留原契约，不将其例外扩展到新对象。

RULES是统一组合授权：主体匹配且具备本角色操作功能权限后，同条规则指定记录与全部字段条件取AND，多条规则及有效角色分支取OR。主体为ROLE_MEMBERS、指定租户MEMBER或指定ORGANIZATION的有效成员；人员访问身份使用租户成员UUID，不使用全局账号UUID或人员档案UUID。组织主体通过organization公开端口读取启用人员、组织及有效期内的权威归属，不回退旧成员主组织。当前无被代表人员上下文，成员关联多个有效人员时以其有效组织集合匹配，不把此结果作为单据业务组织资格。

指定记录为空表示不增加记录条件；条件为空表示不增加字段条件；两者都为空必须显式allRecords=true，其他情况下allRecords必须为false，空规则列表拒绝。每策略1–20条、每条最多8条件、记录500个、主体500个、条件值100个、文本200字符；跨角色执行最多100条及10000个记录/条件值，超限拒绝不截断。条件维度从同一DataAccess.dimensions声明，只支持已接通的EQ/IN、UUID/TEXT类型，EQ恰好一个值；UUID须规范格式，TEXT沿用业务列比较语义，NULL不匹配。SQL固定映射不能来自管理配置。

规则保存于原角色和成员策略行rules_json，继承读取角色当前规则，成员自定义独立保存，恢复继承清除自定义值。指定主体只缩小本角色分支，不替代角色分配或功能授权；其他有效分支ALL仍会扩大可见结果。客商查询支持编码、名称、归属组织和客商类型条件；仓库查询支持归属组织、仓库类型与经营模式条件；仓库修改与启停支持归属组织条件及指定仓库 UUID。归属组织与物流组织文本独立，历史未知归属保留 NULL；库区、库位沿用根仓库范围。组合授权不提供任意嵌套条件树、字段排序/聚合权限或导出/打印声明。后续维度和对象必须增加真实执行、界面及正反向测试，再允许声明；不能只增加枚举或下拉框。

「指定记录」是统一授权中心的独立配置入口，适用于有记录授权执行能力的现有记录操作。它保存为现有 RULES 协议中的一条 ROLE_MEMBERS 规则，只包含 recordIds。已有同结构规则可直接回显为指定记录，有条件、其他主体或多规则的授权继续回显为组合授权。新增操作只允许目标范围，隐藏指定记录。记录名称的回显继续执行业务读取权限，无权读取时使用已保存的记录 UUID。

### 动态条件参数

条件由业务字段、运算符和参数组成。固定参数继续使用已有 `values`；动态条件保存 `parameter` 标识及空 `values`，不得将配置人的身份写入策略。每一条件维度按业务语义声明允许的动态参数，并继续限定实际接通的操作。前端按该声明显示选择项，不根据表字段名称推断能力。

| 参数 | 声明和执行 |
| --- | --- |
| CURRENT_ACCOUNT | 仅用于审计创建账号字段 createdBy，服务端以有效认证账号比较 created_by。历史空值不匹配。 |
| CURRENT_PERSON | 仅用于已接通的人员字段，取当前请求复核通过的业务人员，不使用账号或租户成员冒充。 |
| CURRENT_ORGANIZATION | 用于已接通的组织字段，取当前请求复核通过的业务组织。 |
| CURRENT_ORGANIZATION_SUBTREE | 用于支持组织层级的字段，从当前业务组织按可信租户实时展开本组织及下级。 |
| CURRENT_WAREHOUSE | 预留枚举，用户上下文和业务执行接通前不得声明、配置或执行。 |

动态条件使用 EQ 表达身份匹配，组织及下级在执行时转换为受控集合。上下文缺失时整条规则分支不匹配，其他有效分支继续取 OR。固定值和既有范围策略继续按原协议解析。纯后端调用缺省没有当前人员或组织，不能从角色或全量组织关系推断。

新增操作的范围以目标业务归属为授权条件。新增前没有业务记录 UUID，授权中心隐藏指定记录控件，保存和运行校验拒绝携带 recordIds 的新增规则。目标组织从请求意图取得，经服务端校验为可信租户启用组织并符合权限计划才写入。既有显式 ALL 的兼容语义按对象声明保留。组织新增按目标上级组织授权，新增根组织没有目标上级，因此必须具备显式 ALL。

## 3. 运行时合并与事务

功能权限持续跟随角色。每个角色的功能和范围必须在同分支匹配，多角色可合并同一操作的有效行范围，租户谓词始终独立强制；组织子树在平台公开端口按可信租户解析，消除重复和环。成员分支支持继承或自定义，恢复继承清除自定义值，有效期/停用/撤权继续参与判定。

权限模块保持内聚：组合主体匹配由authorization的DataGrantRules统一拥有，持久化适配器只提供本次权威身份事实和策略编解码，不复制业务服务或前端中的授权算法。角色/成员保存统一使用公共目录和主体校验，主体标识跨规则去重后每500个一批验证，不改变各规则记录及条件的AND/OR语义；运行时组织身份仅在需要时读取，同次解析复用，不引入跨请求缓存。架构检查约束权限纯模型不得依赖Spring、SQL、JSON或具体业务实现。

字段为强制限制：HIDDEN > MASKED > READ_ONLY；任何限制都禁止修改对应字段，不可通过另一个普通角色解除。原文展示并不授予功能或行访问权。当前模型采取跨有效角色的保守收口，不提供“角色A放行字段、借角色B行范围”的允许规则，未来增加字段允许规则必须携带授权分支。

列表、COUNT、详情与主从读取使用同一受控行条件和事务；写入事务先锁定授权范围内原记录，再验证版本及目标归属。数据库故障拒绝，不缓存旧授权。SQL列名和关联由业务固定白名单编译，管理员不能填写SQL、SpEL、脚本或任意URL。

公共行范围执行通过 `RowAccessControl` 接口与平台持久化适配器中的 `MySqlRowAccessControl` 连接。当前编译已解析的 ORGANIZATION 集合、ALL及已匹配主体的RULES；旧组织集合与组合规则混合时取OR，未解析子树及不支持范围失败关闭；组织列映射由业务存储代码固定，禁止来自请求或策略配置。返回条件不包含租户谓词，业务 SQL 必须独立强制可信租户；标准范围和规则AND/OR编译必须复用公共实现，业务锁定、目标归属真实性及主从约束仍由业务执行器负责。该接口不是自动 SQL 拦截器，新增对象仍须接通列表、总数和写入路径。实现范围和检查见[公共执行层抽象](../design/数据权限公共执行层抽象.md)。

## 4. 客商实例

BusinessPartnerDeclaration提供BusinessPartner版本2的唯一完整声明，Controller仅使用reference=true引用操作，已删除原BusinessPartnerDataAccessProvider及Controller的重复对象/操作定义。主资源masterdata.partner，子资源masterdata.partner.contact、masterdata.partner.bank；子资源继承主档行范围，但独立声明字段。引用BusinessPartner.list/create/update/setStatus，对应既有masterdata.partner:*权限。list支持RULES，条件维度为 code、name、organizationId 和 partnerType；指定记录使用客商UUID，条件与指定记录可组合，查看不授予新增、编辑、启停。V124扩展原策略存储和约束，V125增加名称授权条件索引，旧策略效果保持不变。

客商新增organization_id BINARY(16)，为数据归属而不是审计创建人。新增必须选择当前租户启用组织；修改缺省保留历史归属，不允许空字符串清除；指定组织读取归属相等记录，组织及下级先解析精确集合，ALL只表示当前租户。旧客商归属NULL保持未知，旧组织范围中只有ALL可访问；明确指定该记录或按已声明其他字段匹配的RULES也可访问，不推断为创建人所在组织。改变归属同时验证原记录的修改范围和目标组织范围。

V121将旧客商角色授权原有的租户全部行为显式迁移为ALL；新配置不能缺少范围。历史成员自定义分支保留模式，原无数据范围的客商权限迁移为ALL；V120的角色继承语义不改变。V122只为已有客商表添加归属字段和索引，无新建业务表，不修改历史迁移。

字段能力覆盖主档可保护属性及联系人/银行账户文本；必填分类和结构布尔字段不开放隐藏。电话、证件和账号使用统一语义算法，其余文本全遮盖。服务端响应隐藏字段不返回原值，提供只读fieldRestrictions用于页面显隐和编辑提示；原文不进入浏览器后再遮盖。客商查询目前只支持公开编码和名称，不能通过受限电话或账号搜索推断原文；未提供任意排序或统计。

修改采用缺省保留的字段合并：受限字段不提交则保留原值，主动提交变化返回DATA_FIELD_WRITE_DENIED，遮盖值不能写回。明细null保留，显式数组维护集合；有受限字段的明细禁止通过删除整行清除内容，新增/修改仍经过原业务必填和字典校验。任何失败整笔主从、版本和审计回滚。

## 5. 页面复用

所有接入对象须遵守[强制声明与真实执行](业务服务统一开发规范.md#31-统一权限模型强制接入)。授权交互以对象功能与范围摘要表达业务意图，采用对象默认范围及操作覆盖的目标模型；不得要求用户通过重复配置来弥补执行遗漏。默认继承、显式覆盖和恢复继承须有可追溯语义；创建使用目标归属表述，不能机械复制查询 RULES 到尚未支持的写操作。当前策略仍按操作保存，页面改造前须完成公共继承契约和迁移，具体边界见[梳理记录](../design/授权配置与权限接入门禁梳理.md)。

授权中心继续复用BusinessWorkspace、现有角色/成员范围编辑器和Element Plus；组合规则通过共享DataGrantRuleEditor编辑主体、记录UUID及目录条件，不建立业务私有授权入口；数据范围页按已选择且已声明的操作显示，平台无范围目录时隐藏该页签。字段页资源名来自声明，支持原文只读/脱敏/隐藏，批量设置仅作用于支持模式的字段。

客商编辑器沿用现有主数据详情模板，增加归属组织选择；隐藏字段不展示，只读/脱敏字段展示只读值，提交剔除受限字段。明细受限时禁用新增和删除等无法安全完成的操作，后端仍独立校验。未新增公共UI组件或UI库。归属目录经原业务读取权公开端口读取，授权中心组织目录经自身管理权限读取，不借用组织管理权限。

## 6. 交付门禁

新增对象必须同时提交统一BusinessObjects.Provider、执行适配器、迁移、配置界面接入及真实数据库越权测试。必须验证跨租户同ID、列表总数、详情直读、修改/启停直调、归属移动、明细ID归属、受限字段回传/清空/整行删除、版本冲突、成员自定义与恢复继承，以及无功能/无策略/过期拒绝。同时验证组合规则AND/OR、条件缺项拒绝、跨租户主体拒绝、组织关系失效、继承/自定义切换以及列表COUNT/详情一致；影响查询的维度需提供真实EXPLAIN证据。只声明目录不算接入。

所有新增自有表须首次CREATE TABLE直接具备四审计字段及中文列注释，账号BINARY(16)、时间TIMESTAMP(6)、UTC。必须保留 GlobalRecordAuditTest 的真实全表检查。

## 7. 自动响应字段保护

Account、TenantMember、PersonDirectory 同样使用唯一 BusinessObjects.Provider；Controller 仅 reference=true 引用。资源键、字段键及保护模式属于策略契约，改名或删除前须迁移存量策略。

DataResource.responseType 可选，填写完整 record 类名；空串表示业务显式执行。仅由构建代码声明，不由管理接口设置。绑定时必须验证类型、String 字段及重复资源；执行时使用可信主体的有效角色，管理域不符、深度超限或数据库异常均不得回退原文。DTO 不重复声明字段算法，禁止恢复独立字段注解扫描或独立数据权限 Provider。字段写保护仍在业务事务内执行。


## 对象通用能力执行

工作流、直接受理和打印的公共对象执行必须在关联解析及能力写入前，按同一对象dataAccess声明复核记录组织范围与字段限制。平台桥接使用AccessPlanning、RowAccessControl及FieldProtection，不在业务对象中复制范围合并或脱敏算法。业务记录的租户、组织、版本仍由对象运行端口真实重读；客户端提交的快照不能作为范围事实。

能力专属对象权限不得借用工作流中心或打印中心的管理/基础设施权限。LeaveRequest的submit/print与ProductApproval.submit使用各自对象资源。新资源缺少数据策略默认拒绝，不将旧权限自动转换为ALL；具体切换以受控迁移和本轮检查为准。

审批任务准入与字段保护分别执行：当前任务可以提供该记录的受限办理资格，但重读审批依据仍须使用FieldProtection，不能忽略后来生效的隐藏限制；必填依据不可见时停止办理，不伪造默认值。可靠终态交付属于已启动执行的受控落地，复核可信实例、依据版本及幂等，不要求原申请人持续拥有新提交权。

进程内定时入口在领取、维护及调度前，使用唯一对象声明中的固定 SCHEDULE 操作和系统准入键。队列记录必须重读其可信租户与权威业务对象，审批结果使用发布版本、已结束实例及原依据复核。打印代理回传状态与产物时，任务必须属于同一租户，并绑定原领取时的认证主体及代理标识；原领取主体未知的旧任务按原租约到期处理，不推断领取权。

### 标准对象的受控 CRUD

标准主档使用固定租户、主键及权限依据字段映射。组织归属对象使用已声明的归属组织；人员档案以主键对应人员档案身份，适用操作可使用当前人员动态条件。平台公共用例负责生成计划、绑定值及出具写入许可；涉及组织归属变更时还负责校验目标组织。业务继续校验状态、版本、字典和主从事务。字段到列的固定映射由适配器提供，不能以客户端值或任意 SQL 充当映射。

登记受控读取/锁定语句必须带入公共谓词，即使 ALL 也生成明确的受控条件。MyBatis 门禁发现未绑定就拒绝执行；租户隔离仍独立强制。受控写入必须在同一事务中持有匹配租户、资源、记录和操作的许可。创建的许可在目标授权后出具，修改和启停在范围内锁定原记录后出具；改变归属时写入前仍需校验目标。许可随事务结束销毁，不缓存跨请求身份。标准语句的登记和门禁不等于复杂专用入口已迁移，后者须单独评估和验证。

业务对象目录的数据权限页以契约为来源展示归属依据、操作范围、可用条件及受控接入。接入说明以实际覆盖为准，不把登记状态写成所有入口均已运行验证。权限规则回归集中验证，具体对象仍须验收正常入口、负向越权和事务无副作用。

### 新功能的最小接入

每个新增入口应按「对象与操作 → 数据依据 → 固定映射 → 实际门禁」一次接通。先在原有或新建的唯一 Provider 中声明操作与数据能力，再让 Controller 引用其完整操作标识。业务只写归属与引用约束、可信列映射、状态和版本校验；策略解析、参数绑定及拒绝默认行为由平台处理。

| 类型 | 最小实现 | 执行证据 |
| --- | --- | --- |
| 标准主档 | 声明查询和编辑操作，使用 organizationId 作为权限依据。固定映射为租户 UUID、记录 ID 与 organization_id。列表和 COUNT 使用同一个 StandardCrudScope 计划，写入用同一范围约束原记录锁并出具更新许可。修改归属再验证目标组织。 | 参考 [客商声明](../../backend/services/master-data-service/src/main/java/com/appnexus/masterdata/adapter/integration/partner/BusinessPartnerDeclaration.java) 与 [固定查询 Mapper](../../backend/services/master-data-service/src/main/java/com/appnexus/masterdata/adapter/persistence/MasterReadMapper.java)。 |
| 单据 | 声明入仓签发操作，权限依据为已登记的租户全部策略，以及仓库、货主、商品引用。按操作取得平台计划，通过目标业务公开入口复核引用，再在事务内对本次单据 ID 出具写许可。固定 INSERT 绑定租户及单据 ID。对支持组织等细粒度范围的单据，仍按其原对象契约产生和使用范围谓词。 | 参考 [入仓唯一声明](../../backend/services/bulk-warehousing-service/src/main/java/com/appnexus/bulkwarehousing/adapter/integration/InboundReceivingDeclaration.java)、[入仓用例](../../backend/services/bulk-warehousing-service/src/main/java/com/appnexus/bulkwarehousing/application/InboundReceivingService.java) 与 [固定写 Mapper](../../backend/services/bulk-warehousing-service/src/main/java/com/appnexus/bulkwarehousing/adapter/persistence/InboundReceivingMapper.java)。 |

标准主档读语句需要以 GuardedScope 声明可信租户、资源及谓词参数路径，并在实际 SQL 中使用 ScopedSql.bind。记录写语句需要声明可信租户、资源、真实操作及记录参数路径。固定全租户的复合单据只在已有策略支持且引用均已复核时，允许声明可接受的完整单据操作权限；不得以该模式代替细粒度受控读写。

主档查询接线片段：

```java
// 固定映射绑定记录 ID 和 organizationId，Mapper 独立约束可信租户。
var plan = standardScope.plan(subject, "read");
var predicate = standardScope.predicate(plan);
mapper.list(tenantId, predicate);
```

对应 Mapper 使用 `@GuardedScope(predicate="access", resource="masterdata.partner", tenant="tenant", actions="read")`，SQL Provider 对同一 `access` 参数调用 `ScopedSql.bind`。写入以原记录锁、目标授权和标准写许可为前置条件。

单据签发接线片段：

```java
// plan 来自已声明的 issue 操作。入仓引用通过各自公开的受控读入口复核。
source.requireWarehouse(context, notice.warehouseId());
source.owner(context, notice.ownerPartnerId());
source.identity(context, notice.item());
writes.authorize(plan, UUID.fromString(notice.id()));
store.issue(context, notice);
```

该片段在原命令事务中执行，写 Mapper 使用 `@GuardedScope(resource="warehousing.inbound", tenant="__verifiedTenant", recordId="n.id", actions="issue")`。入仓完整用例同时校验商品基础单位和单据数量。

### 构建门禁

组合应用 Maven validate 阶段先执行 AccessBuildGate。新增或改动的 HTTP 入口须引用 Provider 中明确声明的对象操作；新增或改动的 Java 注解及 XML Mapper 语句须具有完整统一门禁；读谓词还必须接入公共 SQL 绑定。新增单条语句必须有无条件执行的门禁；历史枚举共用语句以精确签名留档。新增直接数据库入口阻断构建。可在仓库根运行 java scripts/AccessBuildGate.java . 预检。

已有技术入口及尚待复核的存量语句按精确指纹留档。该清单是实现边界，不是授权能力证明；CI 使用 Git 基准禁止补录新的例外。公共装配继续复核操作、对象、范围及执行器绑定，运行时拦截器仍以实际 SQL 和同事务许可为准。结构检查不能证明权限策略及业务约束正确，正常交付须执行实际调用的正反向测试。
