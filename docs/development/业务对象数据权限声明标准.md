# 业务对象数据权限声明标准

更新日期：2026-11-19。本文为新增及改造业务对象的数据权限接入标准；客商示例仅说明接入约束。历史测试和部署证据见[历史记录](../design/业务对象数据权限声明标准历史记录.md)，不能代替当前版本验收。

## 1. 唯一来源与模块边界

新建或改造对象统一通过 BusinessObjects.Provider 唯一登记；Controller仅通过OperationBinding(reference=true)引用。未迁移对象的既有注解暂时保留，不能为同一对象再叠加Provider。数据权限是统一对象的dataAccess部分，只按operationCode声明支持范围，不复制对象身份或另建功能权限。统一对象标准位于 business-object-contracts 的 BusinessObjects.Descriptor；对象身份、版本、操作、交互与 dataAccess 共同在一份 Descriptor 中声明，业务模块只实现 BusinessObjects.Provider。platform-authorization 的 DataAccessDeclaration 仅为派生只读投影，已删除独立 Provider 入口。平台从同一对象声明生成 DataAccessCatalog。业务执行器实现 Executor 并实际消费公开 AccessPlanning / FieldProtection / DataAccessReferences，不跨模块查询组织、角色或成员表。

能力声明由代码发布，不提供管理员编辑入口。授权策略由授权中心保存至现有 access_role_data_policy、access_member_authorization*、access_role_field_security；access_permission_scope_type 作为代码目录的数据库投影，既有数据库外键继续约束策略。平台装配期校验声明和真实MVC操作、权限目录、执行适配器；缺失或冲突阻止启动。字段目录仅从统一BusinessObjects.Provider派生；已删除旧响应字段注解和类路径扫描。自动响应执行通过同一资源的responseType绑定真实record，业务显式执行器缺省不设置该绑定。

## 2. 声明参数和校验

| 参数 | 规则与缺省行为 |
| --- | --- |
| objectType | 已登记业务对象标识，大写开头字母数字；对象唯一，必填 |
| version | 正整数声明版本；修改安全语义必须递增，删除已被策略引用的字段前必须迁移 |
| scope | TENANT或PLATFORM，必填，不允许跨管理域授权；业务行范围按已实现的租户能力声明，不能据管理域枚举推断平台行范围已支持 |
| resources | 首项为主资源，后续为子资源；资源编码全局唯一、小写点分段，不是表名 |
| parentResource | 主资源为空串，子资源明确引用同声明主资源；当前仅支持直接主从继承，禁止暗中拼接独立行策略 |
| resource.nameZh/nameEn | 中英文业务名称必填，授权中心直接消费，不能以客户端传入名称作为目录来源 |
| operations | 唯一操作清单声明operationCode、operationId、permissionCode、页面和交互；权限码必须属于已接通的主资源 |
| dataAccess.operationScopes | 以同对象已声明operationCode为键，值为受控范围集合；不再重复操作标识或权限码，未知键拒绝 |
| scopes | 仅声明实际执行的范围；当前标准实现ALL、ORGANIZATION、ORGANIZATION_SUBTREE，拒绝DENY和无明确含义的SELF；不支持的条件不展示 |
| fields.field | 资源内唯一、字母开头的稳定业务字段键；不能是任意属性路径或SQL列名 |
| fields.kind | PHONE、EMAIL、PERSON_NAME、IDENTIFIER、BANK_ACCOUNT、TEXT，使用统一服务端算法 |
| fields.modes | READ_ONLY、MASKED、HIDDEN中已执行的集合，不能为空；只读不意味着额外读取授权 |

无能力目录、无功能权限、缺少行策略、上下文异常默认拒绝；不得用ALL作故障回退。目录版本令牌为按管理域/对象排序的声明版本，角色配置读取返回dataAccessVersion，业务数据权限Web保存必须原样回传，冲突要求重新加载。已有组织管理旧调用保留原契约，不将其例外扩展到新对象。

当前契约不提供任意条件树、人员/负责人范围、动态本人组织、字段查询/排序/聚合权限、记录级共享或导出/打印声明。未来扩展需要增加受控契约、参数存储、真实执行器、界面和正反向测试，再允许Provider声明；不能只增加枚举或下拉框。

## 3. 运行时合并与事务

功能权限持续跟随角色。每个角色的功能和范围必须在同分支匹配，多角色可合并同一操作的有效行范围，租户谓词始终独立强制；组织子树在平台公开端口按可信租户解析，消除重复和环。成员分支支持继承或自定义，恢复继承清除自定义值，有效期/停用/撤权继续参与判定。

字段为强制限制：HIDDEN > MASKED > READ_ONLY；任何限制都禁止修改对应字段，不可通过另一个普通角色解除。原文展示并不授予功能或行访问权。当前模型采取跨有效角色的保守收口，不提供“角色A放行字段、借角色B行范围”的允许规则，未来增加字段允许规则必须携带授权分支。

列表、COUNT、详情与主从读取使用同一受控行条件和事务；写入事务先锁定授权范围内原记录，再验证版本及目标归属。数据库故障拒绝，不缓存旧授权。SQL列名和关联由业务固定白名单编译，管理员不能填写SQL、SpEL、脚本或任意URL。

## 4. 客商实例

BusinessPartnerDeclaration提供BusinessPartner版本1的唯一完整声明，Controller仅使用reference=true引用操作，已删除原BusinessPartnerDataAccessProvider及Controller的重复对象/操作定义。主资源masterdata.partner，子资源masterdata.partner.contact、masterdata.partner.bank；子资源继承主档行范围，但独立声明字段。引用BusinessPartner.list/create/update/setStatus，对应既有masterdata.partner:*权限。

客商新增organization_id BINARY(16)，为数据归属而不是审计创建人。新增必须选择当前租户启用组织；修改缺省保留历史归属，不允许空字符串清除；指定组织读取归属相等记录，组织及下级先解析精确集合，ALL只表示当前租户。旧客商归属NULL保持未知，只有ALL范围可访问，不推断为创建人所在组织。改变归属同时验证原记录的修改范围和目标组织范围。

V121将旧客商角色授权原有的租户全部行为显式迁移为ALL；新配置不能缺少范围。历史成员自定义分支保留模式，原无数据范围的客商权限迁移为ALL；V120的角色继承语义不改变。V122只为已有客商表添加归属字段和索引，无新建业务表，不修改历史迁移。

字段能力覆盖主档可保护属性及联系人/银行账户文本；必填分类和结构布尔字段不开放隐藏。电话、证件和账号使用统一语义算法，其余文本全遮盖。服务端响应隐藏字段不返回原值，提供只读fieldRestrictions用于页面显隐和编辑提示；原文不进入浏览器后再遮盖。客商查询目前只支持公开编码和名称，不能通过受限电话或账号搜索推断原文；未提供任意排序或统计。

修改采用缺省保留的字段合并：受限字段不提交则保留原值，主动提交变化返回DATA_FIELD_WRITE_DENIED，遮盖值不能写回。明细null保留，显式数组维护集合；有受限字段的明细禁止通过删除整行清除内容，新增/修改仍经过原业务必填和字典校验。任何失败整笔主从、版本和审计回滚。

## 5. 页面复用

授权中心继续复用BusinessWorkspace、现有角色/成员范围编辑器和Element Plus；数据范围页按已选择且已声明的操作显示，平台无范围目录时隐藏该页签。字段页资源名来自声明，支持原文只读/脱敏/隐藏，批量设置仅作用于支持模式的字段。

客商编辑器沿用现有主数据详情模板，增加归属组织选择；隐藏字段不展示，只读/脱敏字段展示只读值，提交剔除受限字段。明细受限时禁用新增和删除等无法安全完成的操作，后端仍独立校验。未新增公共UI组件或UI库。归属目录经原业务读取权公开端口读取，授权中心组织目录经自身管理权限读取，不借用组织管理权限。

## 6. 交付门禁

新增对象必须同时提交统一BusinessObjects.Provider、执行适配器、迁移、配置界面接入及真实数据库越权测试。必须验证跨租户同ID、列表总数、详情直读、修改/启停直调、归属移动、明细ID归属、受限字段回传/清空/整行删除、版本冲突、成员自定义与恢复继承，以及无功能/无策略/过期拒绝。只声明目录不算接入。

所有新增自有表须首次CREATE TABLE直接具备四审计字段及中文列注释，账号BINARY(16)、时间TIMESTAMP(6)、UTC。必须保留 GlobalRecordAuditTest 的真实全表检查。

## 7. 自动响应字段保护

Account、TenantMember、PersonDirectory 同样使用唯一 BusinessObjects.Provider；Controller 仅 reference=true 引用。资源键、字段键及保护模式属于策略契约，改名或删除前须迁移存量策略。

DataResource.responseType 可选，填写完整 record 类名；空串表示业务显式执行。仅由构建代码声明，不由管理接口设置。绑定时必须验证类型、String 字段及重复资源；执行时使用可信主体的有效角色，管理域不符、深度超限或数据库异常均不得回退原文。DTO 不重复声明字段算法，禁止恢复独立字段注解扫描或独立数据权限 Provider。字段写保护仍在业务事务内执行。
