# 仓库授权人员与登录选仓检查

日期为 2026-11-25。范围为仓储库存总览的授权入口、租户授权中心的成员数据范围、登录后顶栏选仓，以及已选仓库的会话回读。

本记录保留 V212 的历史验收路径。入口迁移后的路径与验收见[仓库人员授权独立菜单检查](仓库人员授权独立菜单检查.md)。

## 使用路径

1. 管理员在授权中心为角色启用「登录选仓」，并配置仓库记录范围。该权限独立登记，新迁移不会自动为现有角色或成员分配仓库。新租户的管理员初始化也跳过无法自动提供完整范围的权限。
2. 从「仓储 → 库存总览 → 仓库授权人员」打开授权中心的成员数据权限页签。选择角色及成员，切换为自定义数据范围，在「登录选仓」下选择指定仓库并保存。授权人须具备现有成员授权管理权和仓库目录读取权。
3. 成员登录并进入租户后，有候选时打开选仓弹窗，也可通过顶栏重新选择。服务端在当前登录会话保存已选仓库，读回时重新校验。工作台与库存等业务接口继续使用各自操作的授权策略。

## 验证结果

- 后端 `mvnw.cmd -pl applications/monolith-app -am -DskipTests compile` 通过。访问入口扫描没有违规。
- 管理端在仓库内置 Node 24 下运行 `pnpm.cmd --filter @appnexus/admin typecheck` 和 `pnpm.cmd --filter @appnexus/admin build`，两条命令退出码均为 0。
- 首次数据库集成命令执行了 V212，但默认构建目录中已有的附件实现字节码含未解析接口，导致应用上下文启动失败，2 个测试均未执行断言。使用独立构建目录重新验证。
- `pnpm.cmd --filter @appnexus/authorization test` 通过，5 个文件共 17 项用例通过。
- `GlobalRecordAuditTest.ownedTablesHaveAllFourColumns` 在独立构建和真实 MySQL 上通过，1 项通过。
- `StorageHierarchyIntegrationTest.loginWarehouseSelectionUsesEffectiveRecordScope` 在独立构建、真实 MySQL 与 Valkey 上通过，1 项通过。角色默认分配 B 仓库，成员自定义仅分配 A，候选仅返回 A。匿名访问、无权限、直提 B、缺少 CSRF、停用 A 和撤销角色权限均按预期处理。
- MySQL 真实权限目录中，启用租户权限缺少 ALL 范围的只有新选仓操作。初始化 SQL 缩小了原权限分配条件，已同步更新两条受审查 SQL 指纹并通过访问入口扫描。
- 隔离 MySQL 在同一事务加入样本后执行 EXPLAIN ANALYZE，最后回滚。租户共 1,000 个仓库，其中 901 个启用。三个指定 UUID 使用 PRIMARY 范围扫描读取 3 行，启用条件保留 2 行再排序。按已授权 ID 查得 1 行，指定范围外 ID 返回 0 行。该证据对应指定记录查询形态。
- 使用 Edge、实际构建产物、真实测试会话和接口验证。1440×900、1024×768、390×844 均可打开弹窗，弹窗边界在视口内。工作区通过 `.viewport-page-host .main-content` 定位，边框 1px、圆角 8px，工作区外边距和根内边距均为 0px，区块间距默认 8px。根变量动态调整为 0、8、24px 时，三种视口的实际区块计算值依次为 0、8、24px。浅色、深色、系统主题及中英文切换通过。
- 浏览器验证只有授权仓库出现在候选，键盘确认触发真实 PUT，刷新后恢复会话选择，仓储入口打开成员数据权限页签。启用的跨租户仓库直提返回 403。
- 在真实成员数据权限页签切换为自定义，选中 B 仓库并填写原因保存。成员授权 PUT 返回 200，随后同一会话的候选包含 A 与 B。库存总览全屏后仍可使用授权入口。
- 同一会话并发提交两个已授权仓库，两次 PUT 均返回 200，回读保留其中一个已授权仓库。隔离测试使授权分支过期后，同一会话选仓接口返回 403。
