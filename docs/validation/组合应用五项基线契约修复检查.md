# 组合应用五项基线契约修复检查

日期：2026-11-22。对已有个人中心、商品 OpenAPI、主数据和对象装配契约复核。关注现有操作的真实页面、接口及权限绑定。

## 根因与改动

| 失败项 | 根因 | 修复与验证 |
|---|---|---|
| BusinessValueDictionaryTest | 正、反商品用例缺少当前必填的归属组织，校验在访问计量单位之前失败；跨租户客商用例也缺对方归属和可信请求。 | 为两租户提供实际启用组织，装配各自可信上下文。单位反例命中 PRODUCT_V1_INPUT_INVALID，拒绝后分别核对实际目标租户无写入，保留停用与历史引用验证。 |
| BusinessObjectPageRegistrationTest | 自助个人中心静态路由散落在功能目录和两个启动校验的专门分支；测试误用可发布菜单目录，并假定所有专用 API 都有页面。 | 固定路由由 NavigationPages 统一查询，保留原可配置菜单白名单。测试对主页面与别名精确核对，也对真实无页面专用 API 做明确分类。HTTP 验证功能目录包含个人中心、菜单候选排除个人中心。 |
| ObjectExecutionAssemblyTest | 旧的 50 对象数量断言缺少 8 个已真实装配的仓储对象。 | 断言启用工作流时实际契约的完整对象编码集合，覆盖 8 个仓储对象，继续检查重复和已退役编码。 |
| ApiContractTest | 真实 GET 已有但商品 OpenAPI 自定义器未登记新增和修改两个归属组织候选方法，导致 app 契约生成失败。 | 为原接口登记独立 SDK operationId，并校验正式三组契约生成、两个 GET 路径及 operationId。审批、权限、URL 和运行语义不变。 |
| MasterDataIntegrationTest | 旧的商品基础 27 项数量断言未收录配置版本列表及两项归属组织查询。 | 按完整稳定操作编码验证 30 项基础契约。依据引擎配置校验审批读取的 3 项增量，保持既有权限与菜单登记断言。 |

涉及对象 Account、AuditEvent、TenantInvitation 的个人中心页面关联继续使用原页面键和路径。NavigationMenu 功能目录从共享路由声明读取，菜单发布、运行时导航和候选目录继续使用原菜单白名单。Product 的两个组织候选操作继续使用原 Product Provider、Controller、create/update 准入及组织范围。没有新增权限、数据库迁移或授权配置。
