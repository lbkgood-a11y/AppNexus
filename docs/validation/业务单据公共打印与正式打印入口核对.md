# 业务单据公共打印与正式打印入口核对

## 业务单据接入

`POST /api/business-object-executions` 现在支持 `PrintDocument.print`。公共分发使用已登记操作和原权限 `print.job:submit`，然后将命令参数绑定为原 `DocumentPrintRequest`。保存的单据没有修改入口，当前请求版本为 0。调用方只提供单据 UUID、打印输出类型、份数及适用的设备 UUID。

公共和专用入口调用同一个 `PrintSceneService.print`。用例从真实租户和申请账号查询本人已保存的单据，再读取该单据的启用场景、现行发布模板、场景数据契约和已保存数据。两条入口共用新增的契约存在性及数据验证，随后由原运行时校验冻结契约、选择设备、创建任务并处理同请求重放。公共路径没有额外对象关联配置，也不接受调用方提交场景、模板或打印数据。缺端口由装配或调用拒绝，缺场景、模板、契约或设备由原打印用例拒绝。原专用路由、事务、输出类型和返回仍保留。

## 正式打印入口逐项核对

下表保留本次核对时点。随后 PrintOutput.create、PrintOutput.confirm 和 PrintJob.reprint 的接入见[打印输出确认与补打公共命令验收](打印输出确认与补打公共命令验收.md)。

人员预检与状态查询后续接入见[人员打印预检及状态公共只读命令验收](人员打印预检及状态公共只读命令验收.md)。

数据契约与场景后续接入见[打印数据契约与场景公共命令验收](打印数据契约与场景公共命令验收.md)。

用户账号域的下一批打印执行入口主要是 PrintOutput.create、PrintOutput.confirm 和 PrintJob.reprint。当前业务单据命令已经把 PrintOutput.create 所复用的本人单据取数链接入，但输出请求和确认两步仍有各自独立的契约。外部、代理、二进制协议应维持各自独立的安全入口。

## 运行结果

- 权限构建门禁退出 0，待复核 0 项、留档 582 项。未新增例外。33 个正式 PrintController 操作标识与清单逐项比对通过。
- 公共执行单测 12 项和装配校验 7 项通过。未导入命令端口的中间构建被真实启动校验拒绝，登记命令但无运行端口不会进入服务。
- 用最终源码与隔离构建类路径运行真实 MySQL/Valkey 测试，库迁移到 V216，2 项通过。业务单据用例验证实际 HTTP 公共与专用入口同键只生成一个任务，数据库记录的来源、模板、契约及数据对应已保存单据。缺权限、同租户非本人、同账号跨租户、提交新场景字段、缺命令、无效版本、无设备、场景停用及契约缺失均拒绝，任务计数不增加。原类型化打印运行回归继续验证冻结模板契约及原公共 PRINT 场景执行。
- 未启动物理打印或渲染设备，未部署、未改可视化页面或请假 PoC。
