# 业务对象前置权限全量统一检查

本次差异以生产 Controller 的 EndpointOperation 为起点。Java 语法树按实际方法关联原权限注解与同方法 OperationBinding，得到 20 个 Controller、127 个操作引用及 22 个归属对象。平台代管以原 platformPermission 为准，其他入口使用原 value。原组织类型 3 个迁移入口继续复用相同机制。

## 适用检查

| 编号 | 适用性和证据 |
|---|---|
| D01–D02 | 原对象和操作标识由唯一 Provider 提供，按实际 MVC 方法反查。 |
| D03–D04 | 验证原路由管理域和单一权限。平台代管测试按平台目录权限核对，租户端点按租户目录权限核对。 |
| D05–D06 | 原记录范围、字段规则及查询和写入适配器继续执行。真实授权、隔离和撤权结果以运行证据为准。 |
| D07–D09 | 沿用各对象既有交互、字段和编码契约，前置门禁不接入新能力。 |
| D10–D11 | 已有用例继续执行原归属、范围、状态、事务、版本及审计。 |
| D12 | 运行证据记录真实组合应用、迁移前后权限对照及 HTTP 正反向覆盖。 |
| C01 | 适用，核对同一声明的目录与真实功能准入。 |
| C02–C03、C05 | 权限入口变化涉及回归，原范围、字段和事务实现继续执行。未逐对象覆盖的用例记为未验证。 |
| C04、C06–C08、C10 | 不适用。本次保留数据库、查询、前端、包和模块结构以及专业能力执行。 |

## 运行证据

- 通过。独立构建目录 `target/object-declaration-check` 使用正式组合应用、MySQL、Valkey，成功完成 215 个数据库迁移。构建权限门禁核对 587 项既有审查记录，无新增问题。
- 通过。一次性对照测试将迁移前 Java AST 清单的 127 个操作及生效权限码与迁移后的实际 MVC 和操作目录逐项比对，全部一致。用例在本轮验证后移除，避免把历史权限快照作为长期声明来源。
- 通过。租户与平台逐入口无权拒绝回归、撤权后准入即时收回、账号敏感操作正反向用例、登记唯一性及组织类型 MVC 测试均通过。此次组合运行共 14 项，包含上述一次性用例。附件上传反向用例按真实 consumes 构造请求，覆盖门禁而非提前结束于媒体类型判定。
- 命令主体为 `mvn -B -f backend/pom.xml -pl :monolith-app -am -Dappnexus.build.directory=target/object-declaration-check -Dtest=AllOperationAuthorizationTest,OperationRegistryTest,OrganizationErrorHttpTest -Dsurefire.failIfNoSpecifiedTests=false test`，一次性对照使用本地 AST 清单。结果为 BUILD SUCCESS。
- 未验证。未逐对象复测有权写入、跨租户记录隔离、各字段限制、并发和事务回滚，C02、C03、C05 及对应 D05、D06、D11、D12 尚有验收缺口。当前环境仅执行测试构建，尚未发布。
