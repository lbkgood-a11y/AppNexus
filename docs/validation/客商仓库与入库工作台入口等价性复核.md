# 客商、仓库与入库工作台入口等价性复核

日期：2026-11-27。工作区基准 `b6f9a0c` 及当前未提交代码。本轮先按实际用例判定能否迁移。角色、成员默认范围及授权解释沿用前一批实现，既有客商公共启停调用在本轮未调整。

## D01–D12

| 项 | 核查内容 |
|---|---|
| D01 | 客商由 `BusinessPartnerDeclaration` 声明，仓库由 `WarehouseDeclaration` 声明；入库作业和质检、计量、收货卡片分别归各自对象。 |
| D02 | 客商核对列表、详情、字典、地理、权限提示、创建、更新；仓库核对同类主档入口并单查选仓、历史和地图；工作台核对队列、作业列表、聚合详情、实时读数及四种分区块。 |
| D03 | 固定页面与 API 使用原操作标识；公共命令额外核查页面关系的禁用覆盖。入口差异需要实测并保留。 |
| D04 | 功能准入用可信账号和成员。客商候选组织创建/更新模式另行校验对应功能权。仓库选仓与主档读取不同准入。 |
| D05 | 客商、仓库主档范围使用原受控计划。工作台队列、列表和卡片使用各自操作权限，每个卡片的记录范围不能由作业摘要权限替代。 |
| D06 | 客商字段限制以及联系人和银行账户原值使用原保护逻辑；工作台盲检和卡片字段按现有业务约束过滤。 |
| D07 | 客商已有公共命令。仓库和工作台读取并未装配对应类型化命令；入库打印已有专门的公共执行契约，不能从打印端口推断通用查询。 |
| D08 | 固定客商和仓库读取经 `RecordAuditResponseAdvice` 补齐审计人员与引用名称。公共响应以 `output.result` 包装，公共控制器 POST 不经过固定 GET 的补全契约。 |
| D09 | 客商编码、发号、长度及唯一性规则不变。仓库与入库编码未调整。 |
| D10 | 客商公共命令与固定写入复用原应用端口。仓库和入库工作台的业务用例、可信上下文和事务接线各自核对。 |
| D11 | 审计字段由数据库、认证账号和原事务形成。平台页面控制有独立版本与启停审计。选仓还绑定会话及身份版本。 |
| D12 | 隔离环境测试按实际正反向结果记证。迁移必须同时保证准入、响应与审计一致。 |

## 逐入口核查

| 入口 | 实际调用链及待核对差异 |
|---|---|
| 客商列表和详情 | `BusinessPartnerController.list` 与 `BusinessPartnerCommandRuntime` 均调用 `MasterDataManagement.list`。固定入口另做组织、字典、地理和审计名称补全。 |
| 客商字典 | 固定 `options=true` 与公共 OPTIONS 均调用 `dictionaryOptions`。 |
| 客商地理 | 固定 `geography=true` 与公共 GEOGRAPHY 均调用 `geographyCatalog`。 |
| 客商权限提示 | 固定 `dataAccess=true` 与公共 DATA_ACCESS 均调用 `partnerAccess`。逐一覆盖 read、create、update，后两者另核查对应权限。 |
| 客商创建 | 两者调用同一 `create`，公共返回经结果包裹且附加公共关系校验。 |
| 客商更新 | 两者调用同一 `update`。公共命令要求对象 UUID 及内外两个版本一致，仍按原事务核对原记录、数据范围和字段。 |
| 仓库列表、详情 | `WarehouseController.list` → `MasterDataManagement.list`，固定入口附加审计、组织、仓库类型、运营模式和地理名称。 |
| 仓库候选、地理、字典、字段限制 | 原查询分支分别调用 `warehouseOrganizations`、`geographyCatalog`、`warehouseOptions`；字段限制独立调用 `warehouseFieldRestrictions`，空仓库时仍可返回当前成员限制。 |
| 仓库创建、更新、启停 | 各有原操作及主档写事务。Warehouse 目前未声明这些类型化命令。 |
| 仓库启停历史 | `MasterStatusHistoryController` 已复用共用历史用例，沿用授权记录和操作者审计展示。 |
| 仓库地图配置和资源 | `AmapProxyController` 已由平台拥有，两条独立操作启用声明前置准入。保留地图代理响应契约，本轮未调用外部服务。 |
| 登录仓库候选、会话选择 | `Warehouse.selectLogin` 单独准入，固定写入口重新校验候选并写当前会话，需保留租户、成员、人员、组织、身份版本和仓库的绑定。 |
| 入库队列、作业列表 | `ReadInboundWorkbenchUseCase.queue/listTasks` 各自有操作与游标契约，队列还有按状态计数和未开单筛选。 |
| 入库详情、实时读数 | 详情用 `details.detail` 聚合；实时读数用 `site.read` 复核鲜度、盲检和读数权限。二者入口虽引用同一作业详情操作，业务语义各异。 |
| 入库身份、质检、计量和收货卡片 | `details.card` 接受固定卡片类型，四条入口分别引用声明操作；后三者归属独立对象，不能用作业自身授权取代。 |

## 实测结果

隔离宿主由 `ProductBrowserFixtureTest#partnerPageExportBrowserHost` 启动，用隔离的 MySQL 8.4、Valkey、管理员与只读成员会话测试；未访问主运行环境。复核脚本和输出为 `.local/object-entry-parity/check.py`、`check.log`，宿主日志为 `.local/object-entry-parity/host.log`。

- 客商分页记录 ID 与总数相同。详情固定响应补全 `audit.createdByName`、客商类型名称、可授权的组织名称，以及联系人和银行账户引用或审计展示。公共查询缺相应补全。两条路径仍保护只读成员的敏感原值。
- 页面关系启用时，字典、地理及三种候选组织查询的状态与成功响应相同。只读成员对创建、更新候选均返回 403，读取候选返回 200。
- 公共创建返回对象 ID，公共更新保留原版本及数据库审计，过期更新返回 409。固定与公共创建均拒绝只读成员。
- 对查询、创建、更新逐个启用平台禁用覆盖后，同一身份与同一权限下，固定入口各返回 200，公共调用各返回 403 `BUSINESS_OBJECT_PAGE_RELATION_DISABLED`。每轮终止前恢复隔离环境原配置。将剩余入口直接切到公共执行会改变可执行操作，客商三类本轮保留固定调用。
- 仓库列表和字段限制的真实固定入口返回 200，对应公共命令返回 403 `BUSINESS_OBJECT_COMMAND_UNAVAILABLE`。隔离初始成员也缺独立登录选仓授权，不能把普通仓库读取当作选仓。入库队列、作业列表固定入口返回 200，对应公共命令返回同样的未装配错误。

迁移存在两项实测边界。首先需明确独立的页面入口禁用配置对固定 API 与公共执行的预期语义。随后需让公共查询使用授权后的引用名称和审计名称补全，再以原字段模板复验。仓库与入库作业域还需要各自真实命令端口，其中登录选仓的会话写入、入库盲检和逐卡片授权须保留。未添加公共入口绕过、未关闭固定入口。

组合应用回归命令为 `mvn -B -ntp -f backend/pom.xml -pl applications/monolith-app -am test "-Dtest=BusinessPartnerDataAccessTest#typedPartnerCommandsReuseRealAuthorization,WarehouseDictionaryIntegrationTest,InboundWorkbenchHttpTest" "-Dsurefire.failIfNoSpecifiedTests=false" "-Dappnexus.build.directory=target-member-object-scope"`，退出 0。客商 1 项、仓库 3 项、入库工作台 3 项，共 7 项通过，无失败、错误或跳过。仓库回归验证字段保护、归属限制和字典隔离；工作台回归验证作业列表授予、队列投影、跨租户及处理流程，还有公共打票使用已授权场景。证据在 `.local/object-entry-parity.log`。

`node scripts/audit-data-access.mjs --strict` 退出 0。覆盖 75 个 Controller 和 96 个 Mapper，0 个独立旧操作声明线索。目录和 SQL 静态校验不能替代上面的真实差异判定。


仓储专项执行 `mvn -B -ntp -f backend/pom.xml -pl applications/monolith-app -am test "-Dtest=StorageHierarchyIntegrationTest#loginWarehouseSelectionUsesEffectiveRecordScope+selectedWarehouseScopeControlsStorageReadsAndWrites" "-Dsurefire.failIfNoSpecifiedTests=false" "-Dappnexus.build.directory=target-member-scope-browser"`。首次已有测试把范围目录固定断言为 16 项，当前目录只暴露 4 个操作各自的 ALL 和 RULES。依现行规范改成对八个明确条目的精确断言，仍拒绝多余、退役、缺失或错误配对，原范围、版本和越权断言均保留。重跑 2 项通过，无失败、错误或跳过。验证了仓库/库区/库位范围、查询总数、跨范围更新拒绝，以及独立登录选仓和撤权。失败及复测证据分别为 `.local/object-entry-parity/storage.log` 与 `storage-rerun.log`。

最终对同一工作区组合应用共 9 项业务回归通过，另有隔离 HTTP 对照脚本退出 0。本轮变更只有仓库范围目录断言及验证记录，没有切换业务入口。继续迁移需先确认页面禁用是否应统一约束固定 API 与公共执行，并补齐公共读取的授权后投影。固定 API 继续沿用现有语义。
