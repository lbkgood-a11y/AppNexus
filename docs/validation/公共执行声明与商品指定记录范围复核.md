# 公共执行声明与商品指定记录范围复核

本批处理全仓核对中发现的公共执行声明失真，以及商品公共执行拒绝已授权指定记录的问题。

| 对象和操作 | 修正 | 声明与版本处理 |
|---|---|---|
| Account、TenantMember、OrganizationUnit、PersonDirectory、BusinessPartner、CodingEncoder、CodingRule 共 32 个原申报 BUSINESS 的操作 | 原专用 HTTP 入口继续调用其类型化用例。公共输入协议无法表达分页、创建、编辑和管理命令，清除与实际调用链不符的能力声明。公共配置发布按原能力校验拒绝这些绑定。 | 保持对象、操作、权限码、路由、字段和规则。过去这些公共命令运行时即被拒绝；已有绑定不自动重写，重新发布须满足当前契约。对象数据契约与真实专用命令的安全语义不变，无需数据库迁移或策略迁移。 |
| Product 的公共记录操作 | 公共执行先由原商品运行端口经受控 SQL 重读，再核对快照的真实记录键与请求目标一致。宿主按同一操作的 AccessPlan 复核指定记录分支，并保持字段投影。 | 原 Provider 已声明 RULES 的读取操作无需新增授权选项。既有版本和授权记录沿用。无字段比较依据时，带字段条件的分支失败关闭。 |
| 组合应用装配 | 业务对象声明公共能力却未装配运行端口时，装配校验拒绝启动。 | 适用于所有 Provider；仅走专用 API 的操作保留原入口和授权。 |

## 声明同步复核

| 项目 | 影响和证据 |
|---|---|
| D01 | 七个对象及商品继续由原唯一 Provider 登记。 |
| D02 | 32 条专用操作的操作标识完整保留。商品公共操作列表不变。 |
| D03 | 原路由、页面入口、别名与 Controller 引用保持。组合应用校验真实路由。 |
| D04 | 仍按原操作功能准入、可信成员、所属租户和管理域处理。 |
| D05 | 商品复用原业务受控 SQL 和同一操作的公共计划，补齐记录键复核。指定记录和别的记录走真实数据库断言。 |
| D06 | 字段保护仍由统一投影负责。无字段比较依据时，组合规则整支拒绝。 |
| D07 | 七个对象的运行声明与专用能力一致。商品沿用原 BUSINESS 驱动。 |
| D08 | 对外命令和事实契约保持。商品内部快照补充服务端实际读取的记录键。 |
| D09 | 编码字段、绑定、规则版本和发号入口无影响。 |
| D10 | 装配期校验运行端口；商品公共调用真实经过记录锁、范围及原用例。 |
| D11 | 现有关系、旧绑定回执与审计保留，无物理迁移。历史无执行端口的绑定继续不能执行或发布。 |
| D12 | 构建门禁、真实 MySQL 与权限正反向验证见运行结果。 |
