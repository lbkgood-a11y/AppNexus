# 旧顶层范围执行残留清理

| 实际差异 | 受影响对象与操作 | 声明同步、版本与迁移 |
|---|---|---|
| 角色和成员授权只保存 ALL/RULES，删除旧组织明细 INSERT 及选择控件 | PlatformRole、TenantRole、TenantMember 的配置与代管入口 | 保留现有操作标识、权限码及对象版本。公开范围已在前次统一，无需修改 Provider。历史记录保留供解释和审计，不转换、不产生授权。 |

历史 Flyway 枚举和策略读模型仍保留旧值用途，当前授权写入及执行没有旧组织集合分支。成员快捷「指定记录」保存为 RULES。

## 运行结果

Maven 隔离 Reactor 构建及权限构建门禁通过。MySQL 客商专项通过：角色 ALL 返回本租户两条记录且排除外租户记录；成员改为 RULES 后只返回指定记录；三个旧值分别在角色和成员写入被拒绝，已保存的 RULES 继续生效。RowAccessControlTest 和 DataGrantCohesionTest 通过，验证旧组织集合不进入 SQL，也不会和 RULES 合并。前端授权模块类型检查及 17 项 Vitest 通过。

命令为 `mvn -B -f backend/pom.xml -pl :monolith-app -am -Dappnexus.build.directory=target/object-declaration-check -Dtest=BusinessPartnerDataAccessTest#allAndRulesAreTheOnlyEffectiveTopLevelScopes,RowAccessControlTest,DataGrantCohesionTest -Dsurefire.failIfNoSpecifiedTests=false test`。旧测试仍有期望历史策略成功的场景，本轮未运行整个历史测试套件。未发布。
