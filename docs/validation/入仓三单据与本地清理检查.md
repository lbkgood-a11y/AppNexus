## 本地清理

本地 Flyway V166 实例，按租户名称限定为「畅链」或包含「验收」的租户。当前匹配 25 个租户，31 张 bw_ 仓储业务表清除 319 行。先做权限为 0600 的完整数据库备份，再按外键反向顺序同事务清理，保留数据库外键检查。账号、租户成员、角色分配和数据权限、商品、SKU、客商、仓库、库区、库位行数前后相等。未执行应用迁移。

备份：`.local/before-local-warehouse-reset-20261122-233457.sql`。执行与复核结果：`.local/local-warehouse-reset.log`。

## 主从结构与声明同步

| 原对象 | 本次实际变更 |
|---|---|
| BulkInboundReceipt | 保留通知主表/通知行，新增 record_entry 和 confirm_document 两个专用操作，分别沿用 warehousing.inbound:take_custody 与 warehousing.inbound:receive。新增入场头、实收头和实收确认判定明细。现有接管表扩展为入场明细，保留旧接管 UUID。只允许在同通知下选行、同入场范围下确认。合格实收继续走原库存过账，拒收不写库存。 |
| BulkWarehouseStockBalance | 原 Provider 新增 read_entry 与 read_receipt_document，同用原 warehousing.coil.stockbalance:read 和已有范围计划。入仓通知可追到入场和实收，旧入仓确认查询可回退原实收查法。 |

新业务表均在 CREATE TABLE 中声明可信账号和数据库 UTC 审计四字段。入场、接管及正实收事务从同一来源锁定，失效、超限或失败时整单回滚，重复 UUID 以结构化摘要复核。本轮确定每个接管行最多确认一次；同车通过选取仍待确认的接管行分批形成多个实收单。全拒收明细保存原因及数量，保持通知行的可收额度，后续可重新安排新批次。

页面复用 BusinessWorkspace、ManagementTable、Element Plus 表单与现有安全会话。单行整卷履约表单无法表示同车多行和选择部分接管确认，因此新增批次表单宿主。
