# 打印输出确认与补打公共命令验收

三个操作沿用 `POST /api/business-object-executions` 的类型化公共命令协议，`basisVersion` 为 0，`Idempotency-Key` 使用 UUID。会话主体由现有认证链提供。所有原专用 HTTP 入口、处理方法及原用例保留。

| 操作 | operationId 与目标 | 命令参数 | 原用例 |
|---|---|---|---|
| PrintOutput.create | PrintOutput.create，objectId 为本人已保存单据 UUID | 原 DocumentOutputRequest，mode 为 PREVIEW 或 SILENT，copies 为 1 至 99，适用时传 deviceId | PrintOutputService.document |
| PrintOutput.confirm | PrintOutput.confirm@entry1，objectId 为输出请求 UUID | 可空 deviceId，缺省沿用输出请求保存的设备 | PrintOutputService.confirm |
| PrintJob.reprint | PrintJob.reprint，objectId 为原打印任务 UUID | 必填 reason，去首尾空白后 1 至 500 字符 | PrintRuntimeService.reprint |

确认命令使用原人员入口别名 `PrintOutput.confirm@entry1`，对应 `/api/printing/outputs/{id}/confirm`。外部主入口的 `PrintOutput.confirm` 标识及其专用 API 保持原状。人员公共命令拒绝该外部入口标识。所有操作都经真实功能权限及已登记页面关系校验，再调用原事务。启动时声明与固定命令输入类型表不匹配会阻止装配。

## 权限和事务

- 输出创建需要原打印提交权限及原业务单据、场景、契约和输出状态读取边界。使用原输出请求及请求摘要，同键同参重用，同键异参冲突。
- 确认复核原打印提交及输出读取权限，锁定输出请求。只有成功预览才按已保存版本、契约和数据复制实体任务，设备缺失或不可用时拒绝。确认重试返回已确认任务。
- 补打需要原补打权限，使用原任务、原模板版本、原契约与原数据快照。请求方只能提供原因，不能替换快照。原请求幂等键、任务关联及原因审计继续生效。
