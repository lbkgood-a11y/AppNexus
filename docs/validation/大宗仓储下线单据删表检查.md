# 大宗仓储下线单据删表检查

日期 2026-11-23。依据当前工作区与 Flyway V182。V181 负责此前的代码和登记下线，V182 删除同一批 13 项单据的表和专用支撑表。

| 范围 | 表及处理 |
|---|---|
| 入场接管和实收确认 | 删除入场头、接管行、实收确认主从及旧实收记录 |
| 入仓货权、质量放行、监管与过户 | 删除独立登记、放行、限制、过户单、过户明细和版本支撑表 |
| 出仓通知、授权、车次、确认与冲销 | 删除出仓主表、授权、车次、占用、配货、计量复核、交接及冲销表 |
| 返仓发运及确认 | 删除发运主从、返仓确认和明细、在途改仓、短损和重开记录 |
| 保留 | 入仓通知及明细、现有实物库存账 `bw_stock_receipt`。库存账继续提供库存总览 |

迁移按可信租户键从原关联回填仓库、货主、货权生效时间、商品身份、单位、批次和卷号。先约束必填维度以阻断不完整回填，再解除库存账指向旧实收的外键。余额、待检量、审计和通知累计量均沿用原值。在途循环外键只解除将删除的关系，其余按从表到主表的顺序删除。历史迁移校验和保持不变。

## 执行记录

仓库根目录运行 `git diff --check`。隔离 MySQL 验证命令为 `mvn -B -f backend/pom.xml -pl applications/monolith-app -am -Pcontainer-tests '-Dappnexus.build.directory=target-warehouse-v182' '-Dtest=InboundNoticeLineMigrationTest,MasterDataIntegrationTest,GlobalRecordAuditTest#ownedTablesHaveAllFourColumns' '-Dsurefire.failIfNoSpecifiedTests=false' test`，日志 `.local/warehouse-drop-v182-final.log`。

测试结果为 7 项中 6 项通过。库存总览相关的 `MasterDataIntegrationTest#referenceNamesBatchIsTenantAndPermissionScoped` 通过。唯一失败是同类中的 `masterDataIsInstalledAndDeclaredExactlyOnce`，第 172 行仍预期国别地区、库区等对象只有 4 个操作，运行目录已有第 5 个启停历史操作。

结论：完整交付门禁仍有未验证项。已按用户指示部署到本机开发环境。
