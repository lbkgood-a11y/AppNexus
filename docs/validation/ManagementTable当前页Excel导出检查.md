# ManagementTable 当前页 Excel 导出检查

2026-11-27，工作区代码待验收，未部署。变更范围为 `@appnexus/ui` 的列表组件、公开类型、中英文文案和 XLSX 依赖。现有业务页面均未传入导出配置。

## 验证证据

- 在 `frontend` 运行 `pnpm install --frozen-lockfile --offline`，退出码 0。锁文件相对改动前只新增 `write-excel-file@4.1.1` 及其对现有 `fflate@0.8.3` 的引用。
- 在 `frontend/apps/admin` 使用 Node.js 24.15.0 执行 `node_modules/.bin/vue-tsc.cmd --noEmit --skipLibCheck`，退出码 0。在 `frontend` 执行 `pnpm --filter @appnexus/admin build`，退出码 0，XLSX 写入器单独生成异步包。构建环境为 Node.js 22.18.0，pnpm 提示低于工作区声明的 Node.js 范围。
- 从仓库根目录执行 `node frontend/scripts/check-operation-bindings.mjs`，退出码 1，按日志统计 50 条既有操作绑定问题，涉及仓储、附件和菜单等页面。公共按钮的静态例外仅描述无固定对象的浏览器转换入口，业务页面接入时须绑定实际操作并执行真实授权，未修改扫描算法。
- 在 `frontend` 运行 `pnpm --filter @appnexus/ui sbom --sbom-format cyclonedx --prod --out <临时路径>`、`pnpm licenses list --prod --json` 和 `pnpm audit --prod --json`。组件 SBOM 已生成，两项 XLSX 依赖均为 MIT，生产依赖报告未列出这两个包的漏洞。全工作区扫描退出码 1，报告有既有漏洞 66 项，含严重 2 项、高危 20 项。
- 使用 Chromium 打开本地 Vite 隔离装配页，复用真实 `BusinessWorkspace`、`ManagementTable` 和分页组件，通过浏览器下载并以 openpyxl 读回工作簿。此环境无业务身份，使用自造记录，不能代替真实路由布局或业务授权验收。openpyxl 读取时提示工作簿无默认样式，应用读取器默认样式。
- 浏览器脚本退出码 0。23 条记录的本地分页分别下载 20 行和 3 行，外部分页传入的 3 条记录全部下载。检查了文件名、标题、中文、数值、公式形态文本、未配置的字段、操作列和手动隐藏列。空页和加载态按钮禁用，缺省配置及树数据不显示入口，取值回调异常触发统一提示。验证三个标准视口的按钮可见性及全屏下载。
