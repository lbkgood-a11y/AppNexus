# 入仓三单独立页面验收

验收范围为「仓储管理 → 入仓管理」下的质检单、计量单（磅单）和入库单，以及既有入库工作台回归。

| 门禁 | 本次处理与证据 |
|---|---|
| G01/G02 | 三单使用现有仓储入库执行上下文。各对象增加自己的独立读取，提交调用既有命令。应用宿主组装会话与路由，仓储前端模块使用公共工作区、表格、弹窗、审计组件。 |
| G03/G05、C01–C03 | 统一声明分别提供列表与详情。平台授权计划、事务许可及 Mapper 可信租户谓词共同约束列表、数量、详情及入库明细。检验查询不投影司机、车牌、供应商及附件原文。迁移仅继承符合条件的系统租户管理员既有读取范围；分岗角色仍由原授权中心分配。 |
| G04/C05 | 字段转为现有命令入参；详情带入服务端版本。相同过账或冲红请求重试使用同一幂等键。事务、锁、审计和业务前置条件由原用例执行。 |
| G06/G08 | Maven、前端类型检查及 Vite 构建日志位于本机 `.local/inbound-doc-*`，共享数据库部署以及隔离测试证据分开记录。 |
| G07/C09 | 六个独立 GET 路径，详情与列表使用独立操作；旧路径及请求契约保留。聚合工作台不新增写入口。 |
| G09 | D01–D12 对照见下。 |
| C04 | V206 新增导航和权限元数据，无新业务表；审计沿用已有列和公共响应投影。盲检质检投影不显示操作人员。 |
| C06 | 列表支持精确单号过滤和同一读取快照内的计数。现有租户、单号与明细索引可用；按创建时间的宽范围查询和大数据量容量单独验证。 |
| C07 | 新页面共享容器，因为三个现有工作台卡片依赖工作台查询权限和作业上下文，不能承担独立列表、详情与授权菜单。使用公共 `BusinessWorkspace`、`ManagementTable`、`ManagedDialog`、`CodingInput` 和 Element Plus 控件。 |
| C08 | 新类落在现有入库执行 API、应用及对应适配器包，无新 Maven 模块或 Java 包。 |
| C10 | 保留实际单据编号规则和既有异步批次质量处理。此次未加入审批或打印入口。 |

## 运行记录

- 本机 `127.0.0.1:8848` 首页返回 HTTP 200，静态包生成三个单据页面分块。前端执行 `pnpm --filter @appnexus/admin typecheck` 和 `pnpm --filter @appnexus/admin build`，均通过。
- 本机 `127.0.0.1:8080` 已通过组合应用启动验证。共享 MySQL 的 Flyway 记录 V206 成功。数据库中三张单据和工作台属于同一入仓目录，迁移为符合条件的一个系统管理员角色补齐了六个读取权限。匿名调用三个列表和工作台队列均返回 401。
- 本机业务主表三单各为零条。使用同一 MySQL 实例的连接级临时表复制真实结构与索引，每类生成 5 万条、其中主测试租户 4 万条，连接结束自动删除。实测三单首屏排序获取 20 条约 60–80 ms，精确单号各返回 1 条。入库单偏移 3 万条时约 229 ms，计数约 108 ms。列表使用租户索引过滤并排序，关联作业使用复合主键等值查找；明细使用单据范围索引。结果是本机单连接 SQL 证据，未测生产并发容量。原始计划见 `.local/inbound-doc-explain.log`。
- 当前新建操作使用作业 ID 和版本作为上下文，磅票、指标及 LPN 等嵌套输入使用与 API 同结构的表单项。实际业务主键和版本仍由服务端重新校验。
- 串行回归通过 5 个用例，失败、错误和跳过均为 0。覆盖 `ApiContractTest`、`GlobalRecordAuditTest#ownedTablesHaveAllFourColumns`、`InboundWorkbenchHttpTest` 和 `MenuManagementTest#tenantNavigationFollowsRealPermissionDecisions`。此前并行打包覆盖正在使用的中间文件，产生的类文件与 ZIP 读取错误已由串行回归排除。
- 隔离 MySQL 实际生成 8 张质检单、5 张计量单和 4 张入库单。对实际单号执行 `EXPLAIN ANALYZE` 返回 1 行。浏览器使用同一隔离后端的真实会话，验证三单列表、详情、可操作按钮、盲检字段和工作台路由。截图位于本机 `.local/inbound-doc-{quality,metering,receipt}.png`。
- 分页复验按 `page=2&pageSize=1` 读取精确单号。三类单据均返回空的第二页，且总数保持 1。六个生成路径及 `InboundDocumentPage` 已同步到第一方 OpenAPI 快照。
- 在 1440×900、1024×768、390×844 下记录 27 组浏览器计算样式。真实页面宿主与工作区继承 0、8、24 px 区块间距，边框为 1 px，圆角、外边距和数据内边距为 8 px，页面无横向溢出。另覆盖浅色、深色、跟随系统和中英文切换，见 `.local/inbound-doc-release.log`。
- 更新后的本机前端入口及三单工作区资源返回 200；经 8848 反向代理访问六个独立读接口，匿名均返回 401。共享库的三张业务表仍为空，测试单据仅位于隔离库。
- 发布后复验执行 `mvn -f backend/pom.xml -pl applications/monolith-app,contracts/partner-api-spec -am -Dtest=InboundWorkbenchHttpTest,ApiContractChecksTest -Dsurefire.failIfNoSpecifiedTests=false`，启用本机隔离浏览器脚本。仓储集成测试 1 个、契约检查 2 个均通过，零失败、错误和跳过。实测按钢铁质检单号检索，详情隐藏采样单专属的化验和复检动作。证据见 `.local/inbound-doc-publish-acceptance.log`。
- 浏览器验证入口、字段呈现和操作显隐，业务写入通过命令 HTTP 集成链验证。发布后未逐项从浏览器提交每种写命令。
