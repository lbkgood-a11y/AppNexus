# 入库作业票公共打印接入验收

公共入口沿用 `POST /api/business-object-executions`，操作为 `BulkInboundTask.print_site_ticket`，输入真实作业 UUID、当前作业版本和 UUID 请求键。场景、模板及取数均由服务器处理。现有专用 `POST /api/bulk-inbound-workbench/tasks/{id}/site-commands/print` 继续使用原现场设备通道及回执。该通道没有可复用的公共打印数据契约和场景绑定。

| 执行环节 | 实际路径 |
|---|---|
| 主体与功能准入 | ObjectExecutionController → ObjectExecutionService → 原作业票操作、页面关系、活跃租户成员检查 |
| 业务授权及取数 | InboundTaskPrintRuntime → InboundSiteCommandService.lockPrintableTicket → 同时复核原打印权限及原详情权限 → InboundWorkbenchDetailMapper.lockTicket 按可信租户和作业主键加锁 |
| 数据契约 | 同一 BulkInboundTask Provider 注册 warehousing.inbound.task-slip v1，只有必填 TEXT 作业单号 taskNo；不读取车牌、司机、货主等字段 |
| 绑定与输出 | 公共执行核对记录、版本及字段投影，经原已发布对象配置选择同契约场景，走原 PRINT 驱动、print.job:submit 权限及公共预览生产线 |
| 事务与重试 | 作业锁、配置解析和输出写入位于同一 REQUIRED 事务。沿用原打印请求幂等键。无有效绑定或场景、无权限、错租户、非活动作业、陈旧版本均不会形成输出 |

上线时由租户按原打印模板、场景及对象配置流程发布匹配契约。代码没有预置模板、设备连接或默认场景。此次只生成公共预览，不更改原专用现场打印流程。
