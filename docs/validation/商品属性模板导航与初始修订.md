# 商品属性模板导航与初始修订

日期 2026-11-21。目标路由为 `/#/master-data/product-attribute`。左树用于切换「商品属性」「属性模板」及具体模板。选择模板根节点展示有模板归属的属性，选择具体模板时使用其绑定修订名称与类型。模板归属以最新发布版为准，未发布时采用最新草稿。全量列表优先展示最新发布属性修订，其次为最新草稿，再回退到历史修订。无修订的存量对象保持可见，名称及类型留空。新建保存后切回全量列表。

页面复用 TreeListTemplate、Element Plus Tree、ManagementTable 和 ManagedDialog。模板和选项数据始终来自已有真实接口。按模板分组只改变页面查询范围，属性加入模板沿用模板版本维护。

## 声明同步复核

| 对象 | 差异与处理 |
|---|---|
| ProductAttribute | `ProductAttributeDeclaration` 更新 create 的操作说明。字段来源从同租户修订读取，创建仅可随新聚合写入初始修订和选项。既有 POST 和 GET 契约为附加字段，授权键、已有聚合的可变范围、已发布版本与策略均无变化，未新增策略迁移。 |

## 全量入口与编辑回归

根据截图将左侧全量入口显示为「全部属性」。它包含已配置到模板的属性和未配置到模板的属性。列表「编辑」使用既有修订读取、选项读取及草稿写入操作，优先续写最新草稿。没有草稿时，使用最新发布修订（或最近的历史修订）预填，保存新增草稿。原属性分组关系仍通过行内「属性分组」维护。ProductAttribute 的专用操作、资源及权限键未增删，已发布修订及现有策略无迁移。D01–D12 继续使用上表，D02/D03/D08/D11 的变化是这两个界面入口对应原有不同操作，真实写入只影响草稿。

- 复跑时工作区的 InvitationUseCases 工厂已接收与 InvitationConfiguration 一致的第四个参数 `InvitationFieldAccess`。组合应用主源码和测试源码均通过编译，Spring 启动并运行测试。邀请对象的 Provider、操作、权限键与字段保护语义在本轮未调整。
- 首轮整机与浏览器夹具均在创建商品档案时遇到 `PRODUCT_ORGANIZATION_REQUIRED`。在隔离库准备启用的组织，夹具把组织标识传入真实商品创建用例。组合应用仍执行真实授权与归属检查。
- 编辑回归变更后，管理端 `pnpm.cmd run typecheck` 与 `pnpm.cmd run build` 退出码均为 0。
- 使用 `ProductBrowserFixtureTest#isolatedBrowserHost` 在隔离 MySQL/Valkey 启动监听 18109 的真实应用，通过回环 18869 加载管理端构建，浏览器以一次性商品验收账号进入属性管理。测试宿主用例 1 条通过。
