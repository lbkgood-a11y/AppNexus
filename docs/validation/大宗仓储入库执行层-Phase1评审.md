用本地 `mysql:8.4` 镜像启动隔离实例（实际版本 8.4.11），先加载 V136/V167 中通知头及明细的原始建表语句，再加载本次六表草案。使用 Unix socket 执行 `mysql -uroot phase1`，从 `information_schema.tables` 和 `information_schema.columns` 核对结构，退出码为 0，分别返回 8 张表和 32 个审计列。这个检查覆盖六表 DDL 的解析和索引、外键建表，未覆盖完整迁移链和业务写入。

## 过账与冲红应用事务编排

新增内部 `ExecuteReceiptService` 及 `ReceiptExecutionRepository`。适用的声明差异为 ReceiptOrder 的 D02、D04–D06、D08、D10、D11。运行声明、权限版本、迁移和已有 HTTP 契约未变。应用每次请求调用公共 `AccessPlanning`，确认返回的主体、权限、资源及范围，仓储必须先锁作业并校验对象范围。已有回执在版本校验前核对摘要，首次命令按作业及单据版本和状态推进，再写事务回执。

扩展 `InboundExecutionMigrationTest`，用测试仓储和权限计划驱动真实 MySQL 事务，验证版本变化后仍可重放原请求、同键异请求冲突、撤权拒绝重放，以及回执数量不增长。G03–G05、G09、C01–C03、C05 和 D12 的生产执行链仍未验证。测试授权不代表真实 Provider 接入，测试库存效果只更新目标单据状态，实际库存过账和事件未验证。Phase 4 仍待业务整体验收。

组合应用 Maven 定向回归通过。公共 `AccessPlanning` 接口调整后，以同一 Surefire 类路径用 `javac --release 21` 重新编译应用包和测试，并直接运行同一测试方法，隔离 MySQL 迁移至 V186，退出码 0，输出 `RECEIPT_REPLAY_TEST_PASSED`。
