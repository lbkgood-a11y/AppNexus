# 仓储角色范围恢复全量检查

日期：2026-11-22。范围为全量运行中的角色范围恢复问题，沿用现有授权规则。基线失败单列。

## 根因与修复

同一测试 JVM 原本通过 DatabaseTestSupport 共享 MySQL 和 Valkey。工作流启用的 ObjectCapabilityAuthorizationTest、ObjectExecutionAssemblyTest、WorkflowSecurityTest、ProductApprovalWorkflowIntegrationTest 装配了 LeaveRequest 和 ProductApproval。DataAccessIntegration 启动时把这些 Provider 的范围投影登记在 access_permission_scope_type。随后工作流关闭的装配仍使用同一 MySQL。它初始化新的测试租户时，管理员角色带入三个 ALL 策略。

- leave.request:submit / leave.request
- leave.request:print / leave.request
- masterdata.product.approval:submit / masterdata.product.approval

在诊断轮中，临时缩小仓库范围便已触发 DATA_SCOPE_UNSUPPORTED；finally 恢复原策略时再次触发相同异常，掩盖了前一次失败。三项的 SQL 元数据均存在，工作流关闭的 DataAccessCatalog 均没有对应支持项。证据为 .local/warehouse-role-diagnostic.log 中 WAREHOUSE SCOPE ORIGINAL 和 WAREHOUSE SCOPE RESTORE。

改动只在组合测试夹具。四个工作流启用测试使用独立 MySQL/Valkey，默认测试共享原默认容器。同类装配继续共享夹具及登录协议。仓储测试通过原授权接口覆盖和恢复，增加恢复后的策略集合相等断言。生产 Provider、范围规则、数据库迁移和角色授权逻辑没有改动。
