# 仓库字段保护与商品回归

| 检查 | 实现与实际验证范围 |
| --- | --- |
| D01–D03 | 复用 `Warehouse` 的唯一 Provider 和原列表、详情、创建、修改和启停入口。描述符升级至 3，操作 ID 和路由不变。 |
| D04–D06 | 原功能权限和可信租户条件继续执行。仓库声明联系人、电话、邮件、权属证明和个人担保，支持隐藏、遮盖及只读。读取每页复核一次策略；隐藏从响应去除。显式提交任何受限字段会失败，省略时保留原存储值；失败不会更新版本和审计。配置范围仍为原固定租户边界。 |
| D07–D11 | 共用平台字段算法和已有事务；无新数据库结构、存量策略迁移、流程或打印能力。前端详情读取已有字段限制，隐藏字段不呈现，受限字段不进入保存请求。受限创建字段由服务端拒绝，新增表单的策略预加载仍待补齐。 |
| D12、G03–G06、C01–C03、C05 | 真实 MySQL 仓库测试覆盖无策略原值、遮盖和隐藏、显式回传原值及新建拒绝、失败后版本和审计保持，以及正常修改保留受限原值。仓库集成 2 项和 full Provider 装配 3 项全部通过，退出码 0。各字段的 HTTP 策略设定与撤销仍待端到端验证。 |
| 商品回归 | 在子分类配置夹具中绑定有效的已发布 BASIC 模板，并提交对应必填属性。未修改运行时发布规则。隔离 `ProductCatalogMySqlTest` 1 项通过，退出码 0。 |
| C07、G08 | 管理端 `typecheck` 和生产构建均通过。浏览器全局布局、字段和有效角色的实际页面验收未完成。人员及其他对象的字段接入和逐对象证据待补充。本次未部署，运行实例目录未核对。 |

仓库验证命令为 `mvn -q -f backend/pom.xml -pl applications/monolith-app -am -Dtest=WarehouseDictionaryIntegrationTest,ObjectExecutionAssemblyTest -Dsurefire.failIfNoSpecifiedTests=false test`。商品验证命令为 `mvn -q -f backend/pom.xml -pl services/master-data-service -am -Dtest=ProductCatalogMySqlTest -Dsurefire.failIfNoSpecifiedTests=false test`。两者运行于隔离源码副本，在真实 MySQL 8.4 验证。前端在 Node 24 下执行 `pnpm --filter @appnexus/admin typecheck`、`pnpm --filter @appnexus/admin build`。
