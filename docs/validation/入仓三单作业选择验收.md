# 入仓三单作业选择验收

独立新建表单使用可搜索的入库作业选择器，显示作业号。提交时携带所选作业 ID、作业版本和入库草稿所需的计量版本。单据详情触发的复检、皮重、过账和冲红继续使用详情版本。

| 门禁 | 范围与证据 |
|---|---|
| G01/G02 | 复用仓储入库执行上下文和现有前端工作区、ManagedDialog 与 Element Plus 远程选择器，无新增业务组件、表、包或构建模块。 |
| G03/G05、C01–C03 | 七个候选 GET 分别绑定现有写操作权限；应用服务申请同命令范围，事务许可和 Mapper 验证可信租户。候选不读取车牌、司机、供应商、货主、运单、附件和质检结果。测试覆盖同岗允许、跨岗拒绝、异租户排除和搜索通配符转义。 |
| G04/C05 | 候选按有效通知、模板、作业状态和单据占用筛选。品类条件使用已有配置策略值。写命令仍在锁内复核权限、版本、卡控和冲红重开条件。版本冲突时清空选择并刷新候选，不自动重试写入。 |
| G06/G08 | 前端类型检查、构建和后端集成运行证据记录在下文。 |
| G07/C09 | 生成契约为原七条新建路由追加 GET，原 POST 路由及请求保持兼容。GET 默认最多 20 项，输入按作业号前缀匹配、最多 64 字符，响应禁止缓存。 |
| G09 | D01–D12 对照见下。 |
| C04/C08 | 无业务迁移、表结构或 Java 包变更，沿用原表的租户索引与审计。 |
| C06 | 通过同实例连接级临时表模拟 5 万条作业，其中一个租户 4 万条。毛重候选以 `T20` 为前缀，走 `uk_bw_exec_task_no` 租户和编号范围索引，实际扫描 198 项，返回 20 项约 9.3 ms。该结果来自本机单连接，证据见 `.local/inbound-task-selection-explain.log`。 |
| C07 | 浏览器复用现有入仓页面宿主，测量三种尺寸和区块间距继承。选择器按真实后端查询结果和岗位控制，检查自动版本绑定、字段显隐及空态。 |
| C10 | 沿用原编号、库存过账和异步质量事件。候选查询不发号、不写库存、不发布业务事件。 |

## 声明同步

| 编号 | 对照 |
|---|---|
| D01–D03 | 沿用质检单、计量单和入库单的唯一 Provider。现有七种新建操作各增加候选 GET 别名；Controller 引用同一操作。平台注册器只合并声明明确且元数据一致的方法与路径。 |
| D04–D06 | 沿用各租户命令的 ALL 数据范围、公共授权计划和事务许可。候选按固定投影只返回作业号、ID、版本和适用计量版本。 |
| D07–D10 | 无新增工作流、打印或事件契约。沿用原命令与编码运行入口，候选的数据库投影通过受控持久化适配器取得。 |
| D11–D12 | 新增读别名复用原授权代码，无新权限或角色迁移。状态、乐观锁和事务最终由原写用例复核。正反向测试及本机运行记录见下。 |

## 运行证据

- 前端使用 `pnpm --filter @appnexus/admin typecheck` 和 `pnpm --filter @appnexus/admin build`，日志见 `.local/inbound-task-selection-final-{types,ui}.log`。
- `ApiContractTest` 两个用例通过，生成的七个 GET 已同步到第一方 OpenAPI 快照。`ApiContractChecksTest` 两个用例通过，见 `.local/inbound-task-selection-{release,contract}.log`。
- 本机 8080 已加载新组合应用并验证既有 206 版迁移，8848 首页和三单工作区资源返回 200。通过前端代理访问七个候选入口，匿名均返回 401。前一版服务包和首页文件均已备份。
- 部署后 `InboundWorkbenchHttpTest` 通过，失败、错误和跳过均为 0。逐项断言采样、钢铁核验、毛重、外部计量、钢铁双计量、散货草稿、钢铁草稿的候选和版本，并回归过账、冲红及异步质量处理。
- Playwright 在实际隔离业务会话中选择三单作业，确认表单没有作业 ID 或作业版本手工项，实际提交质检，并比对请求中的 ID 和版本与候选响应。计量和入库的命令提交由同一 HTTP 集成用例覆盖。浏览器覆盖桌面、窄屏和手机共 27 组布局计算，检查 0、8、24 px 区块间距、边框、圆角、内外边距以及主题与中英文切换。证据见 `.local/inbound-task-selection-acceptance.log`。
