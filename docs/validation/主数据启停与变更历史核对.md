# 主数据启停与变更历史核对

目标为所有具备启停状态的主数据对象提供实际操作和可查询的变更历史。

## 实施前核对

| 对象 | 已接通的操作 | 当前历史证据及缺口 |
| --- | --- | --- |
| 客商、仓库、库区、库位、国家地区、行政区划 | 公共 `Management.vue` 启停按钮，分别绑定对象的 `setStatus` | `MasterDataService.setStatus` 原事务执行 CAS 与最后修改审计。缺少逐次状态事件写入和授权查询。 |
| 商品 | `Product.setStatus`，启用受审批及结构完整性约束 | `ProductLifecycleService.status` 提交 `STATUS`，`ProductHistoryMapper` 按原商品范围读取。本次查看页也可在原授权下打开该历史。 |
| SKU、商品规格、商品组件 | `Product.setStructureState`，由商品结构统一准入。组件的现有业务约束只允许停用。 | 商品聚合记录 `STRUCTURE_STATE`。尚未验证逐子记录定位、变更值和列表入口。 |
| 商品分类、计量单位、商品属性组、商品属性、商品模板、单位换算 | 目录或换算页面的启停入口 | 未发现这些启停入口使用独立的逐次状态历史。属性修订和模板版本清单仅能证明其版本生命周期，需补启停历史写入及授权读取。 |

## 变更、声明及门禁

商品查看入口改用已接通的 `Product.readChanges`，未添加 API、权限或业务操作。D01–D02 复用原对象定义及操作，D03 扩展既有详情的渲染条件，D04–D06 仍用原商品读取准入、行范围与字段投影，D07–D11 无能力、数据契约、编码、运行端口、迁移和事务变化。D12 登录态页面的正反向回归待验证。

G01–G02 的统一要求见[开发规范](../development/业务服务统一开发规范.md#主数据启停与变更历史)。G03、G05、G09 的商品入口使用原 `Product.readChanges`，静态操作绑定已通过，真实授权回归仍待验证。G04、G08 商品详情真实登录态未验、全量功能未交付；G06 静态检查见本轮运行结果；G07 更新开发规范入口、前端 UI 规范及业务服务规范。

C01、C02、C03 涉及既有历史读取准入及数据，未调整其实现，实际正反向回归待验证。C04、C05、C06、C08、C09、C10 对当前差异不适用，未改持久化事务、查询、工程边界、接口或业务能力。C07 查看态变更记录入口已静态绑定，真实页面布局门禁待验证。

全量交付阻断项为上表存量对象的事件写入和查询适配、各对象授权验证、并发及失败无历史验证、真实页面布局验收。

## 全量补齐实施

- 客商、仓库、库区库位、国别地区、行政区划、商品分类、计量单位、属性及属性组、模板、单位换算共 12 类独立启停记录。V176 新增 `md_master_status_change`，复用每类对象原有状态 CAS 并在同一事务追加，拒绝旧版本和重复目标状态。原状态由 CAS 不等谓词确认。历史时间由数据库生成，操作者从可信上下文传给原状态写入和历史写入，旧数据不生成补造记录。
- 商品、SKU、规格及组件沿用商品聚合变更历史，商品详情和子资源入口复用 `Product.readChanges`。子资源按 SKU、规格 ID 或所属组件商品 ID 提取前后状态。
- 独立历史启用 12 条固定 API。客商、仓库、库区库位和两类地理档案先复用原主档读取路径验证行范围，商品目录沿用原租户级读取权限；查询和总数同时绑定可信租户、固定资源和目标记录。历史只投影启停字段、结果版本、操作者与时间。
- UI 复用公共 `ManagedDialog`、分页以及已存在的商品历史 API。独立对象的历史字段与商品快照差异结构不同，因此使用统一的精简历史入口；SKU 和规格/组件复用商品历史组件。列表和具备页头的仓库、客商详情均绑定独立历史读取操作。
- 后续新增主数据启停时适用同样规则。组合应用测试从实际主数据状态路由核对历史入口，仓库验收继续核对声明、真实写入和回滚。
