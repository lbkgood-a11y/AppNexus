# 业务对象顶层范围统一检查

## 声明同步复核

| 对象 | 实际差异及声明 | 原操作与版本 |
|---|---|---|
| BusinessPartner | BusinessPartnerDeclaration 的查询、新增、修改、历史、启停移除旧组织范围 | 保留 ALL、RULES 及原操作标识 |
| Warehouse | WarehouseDeclaration 的查询、新增、修改、启停移除旧组织范围 | 保留 ALL、RULES；登录选仓继续只声明 RULES |
| OrganizationUnit | OrganizationUnitDeclaration 的领域及平面操作按原映射移除旧组织范围 | 各操作保留原 ALL 或 ALL、RULES |
| Product | ProductDeclaration 在主档和附属资源的范围移除旧组织值 | 主档保留 ALL、RULES，原仅额外支持旧组织值的操作保留 ALL |
| ProductApproval | ProductApprovalDeclaration 的提交移除旧组织范围 | 保留 ALL 和原审批契约 |
| LeaveRequest | LeaveDeclaration 的提交和打印移除旧组织范围 | 保留 ALL 和原审批、打印契约 |

以上为实际受影响的六个 Provider。顶层旧策略在改动前已由运行解析器忽略，授权中心元数据也已过滤。此次消除声明与运行差异，使用原对象与契约版本及存量授权标识，无 Flyway 数据变更。历史旧策略不可转换为 ALL。

| 项 | 适用性及证据 |
|---|---|
| D01 | 原对象身份、归属及版本复核 |
| D02 | 原操作集合、稳定标识和引用复核 |
| D03 | 无路由、菜单及操作声明入口变更 |

| D06 | 字段保护和读写映射继续使用原实现 |

| D09 | 无编码字段或发号配置变化 |

| C03–C10 | 本轮后端差异未改字段保护、数据库结构、事务、查询 SQL、前端、包/依赖、外部 API 或专业能力。展示的上轮验收另有记录。 |

旧值仍见于历史 Flyway/数据库枚举约束、已有策略解码、部分旧测试和内部组织范围执行类型。内部组织集合供已授权查询适配器使用。它与可供选择的顶层操作范围是不同的数据。组合授权的组织/人员主体或条件另有生效边界，现有执行器对退役条件按整条规则拒绝。

## 运行结果

隔离 Maven Reactor 构建通过，共 12 项。DataAccessDeclarationTest 4 项，DataGrantCohesionTest 7 项，PermissionCatalogTest 的公开范围目录集成测试 1 项。集成测试使用正式装配及 MySQL/Valkey，验证所有公开元数据均可在对应声明查到且只公开 ALL/RULES。运行用例验证旧分支单独出现时拒绝、有有效 ALL 时继续生效、诊断返回 DATA_SCOPE_UNSUPPORTED。

命令为 `mvn -B -f backend/pom.xml -pl :monolith-app -am -Dappnexus.build.directory=target/object-declaration-check -Dtest=PermissionCatalogTest#exposesOnlyRegisteredStructuredDataPolicyMetadata,DataAccessDeclarationTest,DataGrantCohesionTest -Dsurefire.failIfNoSpecifiedTests=false test`。全库写入及行范围回归未验证。BusinessPartnerDataAccessTest、ObjectCapabilityAuthorizationTest、RoleManagementTest 中仍有历史场景断言旧范围可保存或生效，未纳入本轮专项结果。尚未发布。
