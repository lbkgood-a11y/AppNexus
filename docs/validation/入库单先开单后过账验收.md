# 入库单先开单后过账验收

工作台默认显示无有效入库单的到场作业。选择作业后打开入库草稿，转至入库单详情。质检、计量、监卸与钢铁核验沿用原专用命令，按作业汇总。计量确认后，库位批次或 LPN 明细补到同一入库单。操作员提交入账时复核完整事实后才写库存。

| 门禁 | 阶段及边界 |
|---|---|
| G01/G02 | 复用仓储收货记录、作业锁、独立操作和工作台投影，兼容已保存的草稿及原命令调用。 |
| G03/G05、C01–C03 | 开单权限 `warehousing.receipt:open_draft` 独立。工作台、详情、质检、计量、明细齐套和过账继续分别授权。候选和明细读取保持可信租户绑定，盲检投影沿用原安全接口。 |
| G04/C05 | 按作业行锁复用有效草稿槽位。V208 允许待收集时计量引用为空。收集完成在原草稿补写计量快照和明细并推进版本。原过账事务复核实物事实、额度、库存记账和 Outbox。 |
| G06/G08 | 构建及真实验证结果记录在下文。 |
| G07/C09 | 新开单入口仅接收作业和版本，队列参数 `unopened` 缺省保持原查询。已有散货及钢铁草稿请求继续兼容。 |
| G09、D01–D06 | 复用原入库单、质检单、计量单和作业声明。入库单新增 `open_draft`，其 Provider 登记工作台路由并沿用数据范围。 |
| D07–D10 | 不增加工作流、打印或异步事件。开单号由服务端主键派生，其他单据原编码能力保留。 |
| D11–D12、C04 | 迁移只放开既有入库表计量引用的空值并声明新操作。旧值、外键和有效槽位约束保留。 |
| C06–C08 | 待开单以租户和有效作业槽位排除已开记录。页面复用现有文档工作区、工作台和标准弹出框。无新增 Java 包。 |
| C10 | 创建和补齐草稿不发库存事件。原过账和煤炭异步质量处理沿用原事务接线。 |

现有玉米公式扣重仍未接通正式过账。页面上的提前开单不会绕过该能力限制。库位及 LPN 明细目前沿用既有表单契约。

## 验证记录

- 使用本机 MySQL 连接级临时表复制 5 万条作业，一个租户 4 万条且一半已开单。待开单用有效槽位索引做反连接，限定为同一租户，取首屏 20 条。该单连接计划约 340 ms，不代表生产并发能力。证据见 `.local/receipt-first-explain.log`。
- 历史兼容回归和应用 API 契约已执行。最终浏览器和业务链见 `.local/receipt-first-acceptance.log`，前端类型检查和构建见 `.local/receipt-first-publish-{types,ui}.log`。
- 首轮仓储链路、API 契约、全局记录审计和菜单授权共 5 项通过。契约已同步并通过第一方快照检查 2 项。实测同车次重复打开返回同草稿，无明细时提交返回 409，通知实收保持为零。采样和计量后补齐原单，提交后通知实收入账 100 kg。
- 本机应用已部署 V208，8080 服务恢复，8848 发布入口与最终构建哈希一致。共享业务库尚无已发布品类模板，本轮真实写命令使用隔离租户数据。
- 发布后仓储集成用例通过，失败、错误和跳过均为 0。实际浏览器从待开单队列用键盘打开草稿，跳转入库单，显示采样入口并隐藏未齐套单据的提交按钮。验证 1440×900、1024×768、390×844 三种视口和 0、8、24 px 区块间距继承，以及浅色、深色、跟随系统和中英文切换。浏览器覆盖开单与操作显隐，采样、计量、补齐及过账实际提交由 HTTP 用例覆盖。证据见 `.local/receipt-first-installed.log` 和 `.local/receipt-first-workflow.png`。
