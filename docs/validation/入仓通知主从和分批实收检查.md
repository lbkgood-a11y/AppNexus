# 入仓通知主从和分批实收检查

日期：2026-11-22。目标：一张通知多个品规、逐行接管及实收，旧 UUID 与关联保留，行锁及数据库条件保护实收上限。沿用原操作及权限。

## 契约和迁移

- V167 保留通知、接管、实收、库存等现有 UUID。每张旧通知回填第 1 行，保留数量、版本、原审计和实收历史。旧通知号沿用 UUID 文本。接管复合外键绑定可信租户、通知和明细。
- 原单行签发与无明细编号的接管请求继续兼容。仅一行时由后端选唯一行；多行请求必须显式指定行。新签发可填写唯一文本编号，缺省仍使用 UUID。已有仓储查询路径保持可用，入仓通知额外支持文本单号。
- 通知状态和各行限额持续记录。服务器按行确定 SKU、单位和版本，锁定主单及来源行，实收确认、待检库存和累计量同事务提交。签发采用的流程版本不因迁移切换。
- 主表保留旧聚合列的单行兼容镜像，所有新履约和库存品规读取从明细取值。部署窗口需先停旧写入，再应用 V167 并启动新版本。旧二进制不能消费新增的非空单号及接管行约束；开出多行单据后不提供旧二进制回退路线。
- 查询页返回 100 条接管和 100 条通用关联记录，超出时明确提示。编号查询、签发、接管和实收复用当前租户权限。此轮未新增独立入场单和草稿、关闭或撤销的页面及动作。
