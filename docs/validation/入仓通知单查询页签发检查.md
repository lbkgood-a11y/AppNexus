## 实际证据

- 组合应用以 `-Pcontainer-tests -Dtest=MenuManagementTest,ProductV1IntegrationTest` 运行 15 项，0 失败、错误或跳过，见 `.local/inbound-new-backend.log`。admin 的 `vue-tsc --noEmit --skipLibCheck`、`vite build`、`vitest run`、根目录操作绑定检查与 `git diff --check` 通过。
- Chrome 在本机隔离 MySQL/Valkey 与真实组合应用上验证。查询页「新建」可进入同页表单，取消回到查询，未填字段时提交不可用，批准上限 0 显示校验且没有发出 POST。提交 200 后原签发端点返回 HTTP 204，页面自动按 UUID 展示批准量 200、实收量 0，刷新仍可见。整卷履约保留原履约卷数和作业页签。英文能显示 New 和 Issue inbound notice。日志 `.local/inbound-new-positive.log`。
- 同租户真实只读角色通过原授权管理配置，只授予仓储单据查询。浏览器能通过导航打开查询页，「新建」不渲染，直调原 POST 返回 403。日志 `.local/inbound-new-reader.log`。
- 两态均有唯一 `.management-page.main-content`，Vue 无属性透传警告。1440×900、1024×768、390×844 下默认外边距 8px、边框 1px、圆角和搜索内边距 8px。全局间距调整 0、8、24px 时 `.business-workspace` 的实际 row-gap 随之变化，内外边距保持，页面不溢出。规则来自应用壳与公共模板 Token。浅色、深色、系统主题在三个视口均正常。查询表嵌入边框 0px，全屏边框 1px，可退出并保留单据。无左树。日志 `.local/inbound-new-positive.log`、`.local/inbound-new-table.log`。

结论：通过本轮适用验收。验证使用独立本地测试服务，常驻本地后端未重启。
