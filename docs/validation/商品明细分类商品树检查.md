# 商品明细分类商品树检查

2026-11-22。本次修改 `/master-data/product-sku`。页面沿用商品管理的 `TreeListTemplate`、Element Plus 懒加载树和公共表格。分类下展示子分类及直属商品。选中商品后读取原商品、结构及固定配置，切回分类清空旧明细及筛选条件。「全部商品」覆盖无分类草稿。缺少分类读取权限时，拥有商品查询权限的用户仍可按商品选择。无新增自定义组件、表、接口或部署动作。

## 实际证据

- 使用 `ProductBrowserFixtureTest#warehouseTitleBrowserHost`，在隔离 MySQL/Valkey、本机后端 18089 和前端 18848 验证。租户管理员展开「仓储验收分类」，商品列表请求带该分类 ID，选择「验收热卷」显示货号 `TITLE-SKU`。切回分类出现选商品提示，再经「全部商品」分支重新选中同一商品，明细恢复。浏览器仅拦截一次分类 HTTP 500，单一树栏错误提示出现，点击重试后由真实接口恢复。
- 1440×900、1024×768、390×844 的真实 `.management-page.main-content` 外边距均为 8px，公共树表面边框 1px、圆角 8px，查询区内边距 8px。切换 `--app-section-gap` 为 0/8/24px 时查询表单计算间距同步变化，页面横向溢出均为 0。两种桌面宽度的左栏为 220px，键盘 Enter 折叠为 48px，空格展开。390px 下树与列表上下排列，树栏宽 372px。表格全屏后可用 Escape 回到原页面。
- 桌面浏览器用真实工具栏切换浅色、深色和跟随系统，系统主题随浏览器深浅偏好往返。切换英语后树标题显示 `Categories and products`，中文标题为「商品分类与商品」。
- 前端运行 `npm_config_manage_package_manager_versions=false pnpm --filter @appnexus/admin typecheck`、`pnpm --filter @appnexus/admin build` 和 `pnpm --filter @appnexus/admin test src/locales.test.ts`，后两项同样设置该环境变量。后端运行 `mvn test -pl services/master-data-service -am -Dtest=ProductDeclarationAssemblyTest -Dsurefire.failIfNoSpecifiedTests=false`，1 项通过。仓库根目录 `node frontend/scripts/check-operation-bindings.mjs` 退出 1，失败均来自工作区已有的库存总览改动。

当前结论为待验收，未满足全部交付门禁。
