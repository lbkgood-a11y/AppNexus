## 运行证据

- 独立构建使用 `-Dappnexus.build.directory=target/object-declaration-check`，排除默认输出目录中旧 `AttachmentRecordMapper.class` 引起的应用启动失败。独立构建已启动正式组合应用并执行 MySQL 迁移。
- `OperationRegistryTest` 与 `OrganizationErrorHttpTest` 共 7 个用例通过。独立 MVC 以真实 Controller 映射和 Provider 验证 3 个操作登记，组织类型列表覆盖缺少租户上下文、无权限及具备权限三条路径。业务端口替身用于观察调用与拒绝，授权策略数据库由组合测试另行验证。
- `OrganizationSummaryTest` 的 3 个真实 MySQL 用例通过，覆盖组织范围和跨租户隔离回归。组织类型获权后的新增、修改和冲突回滚未逐项实测，D05、D10、D11、D12 和 C02、C05 仍有未验证项。
- 最终专项构建通过，11 个用例全部通过。`AllOperationAuthorizationTest#organizationTypeOperationsDenyMemberWithoutDeclaredPermission` 使用真实 MVC、MySQL、Valkey 和已选择租户的会话，确认列表、新增和修改均拒绝仅有成员资格的账号。实际启动校验通过。命令为 `mvn -B -f backend/pom.xml -pl :monolith-app -am -Dappnexus.build.directory=target/object-declaration-check -Dtest=AllOperationAuthorizationTest#organizationTypeOperationsDenyMemberWithoutDeclaredPermission,OrganizationSummaryTest,OrganizationErrorHttpTest,OperationRegistryTest -Dsurefire.failIfNoSpecifiedTests=false test`。
- 扩大回归发现两处失败：全租户端点测试用 JSON 请求附件上传，映射返回 415；固定范围目录测试期望 11 项，组合应用返回 10 项且仍含 OrganizationType。两处分别记录，不调整其他对象或放宽断言。全仓迁移与交付门禁未关闭。
