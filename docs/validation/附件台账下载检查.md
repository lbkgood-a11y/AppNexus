# 附件台账下载检查

2026-11-27 · `/platform/attachments` · 工作区待验收

平台附件台账在可用记录的操作列展示「下载」。浏览器以原文件名保存，服务端仅根据已授权记录的固定存储键读取原件。

## 声明同步复核

| 项 | 差异与证据 |
| --- | --- |
| D01 | `AttachmentDeclaration` 是 `ManagedAttachment` 唯一 Provider，声明因增加下载操作由版本 1 升为 2。 |
| D02 | 新增 `ManagedAttachment.download`，上传与查询操作沿用原声明。 |
| D03 | 平台台账按钮与 GET `/bff/platform/attachments/{id}/download` 使用同一操作，Controller 引用声明并开启统一前置准入。 |
| D04 | 下载归平台管理域，沿用 `configuration.attachmentledger:read`。租户附件操作权限不能准入。 |
| D05 | 附件 UUID 只定位资料，Mapper 仍执行原平台台账门禁，额外限制为 AVAILABLE。 |
| D06 | 下载响应只发送授权原件、文件名及长度，存储连接凭据和原始对象键不随下载响应发送。 |
| D07 | 私有存储实际接入本机、S3/OSS 兼容和 OBS 读取；下载不产生工作流、打印或消息。 |
| D08 | 请求只接受附件 UUID，响应以标准附件头和 UTF-8 文件名提供原件。不存在或不可用资料返回 404，存储启动读取失败返回 503。 |
| D09 | 无发号或新记录，沿用附件 UUID。 |
| D10 | Controller 调用专用附件用例，授权资料读取和存储访问经既有端口。 |
| D11 | 新查询使用现有主键，无数据库迁移。原件流在资料查询事务外读取并由响应转换器关闭。 |
| D12 | 静态操作绑定通过。新增集成验证覆盖 401、403、404 和原件字节，执行状态见门禁。 |
