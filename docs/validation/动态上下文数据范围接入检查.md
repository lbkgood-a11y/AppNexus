# 动态上下文数据范围接入检查

规范入口和《业务对象数据权限声明标准》新增动态条件参数约定。旧固定值仍以 values 表达，动态条件将参数标识与空 values 一并保存。当前仓库保留协议编码，所有声明和保存均拒绝该参数。

| 实际差异 | 对象、声明及版本处理 |
| --- | --- |
| 客商查询支持创建账号、当前归属组织、当前组织及下级 | BusinessPartner.list，声明 3→4。createdBy 绑定审计 created_by，organizationId 保留既有固定组织与 EQ/IN 条件。未声明人员字段，故界面不展示当前人员。 |
| 动态条件按字段来源及操作显示和保存 | 权限目录、角色与成员范围编辑复用原操作，不新增 HTTP 路由、功能权限或配置入口；权限目录直接投影字段能力。 |
| 当前人员和组织从可信请求取值，动态条件匹配前解析 | 既有租户过滤器复核可代表身份后写入请求上下文，客商授权适配器传递给统一权限计划；当前人员解析在公共层可用，不借用账号或成员标识。 |
| 层级查询保持原组织树语义 | 复用 DataScopeMapper 可信租户下级展开；动态组织不存在则该规则分支不匹配。已发布固定策略无需迁移，旧客商声明版本的授权草稿会要求刷新。 |

| D 项 | 复核 |
| --- | --- |
| D01–D04 | 原对象和操作唯一来源，角色、成员和接口准入不变；当前人员与组织由可信身份端口复核。 |
| D05–D06 | 列表及总数同谓词，详情按 ID 走同一范围。创建账号读取审计列，仅参与查询条件。字段展示和脱敏契约无变化。 |
| D07–D09 | 无编码、打印、审批或其他专业契约接入；原业务事实和 DTO 语义保持。 |
| D10–D11 | 组合规则先经声明校验，再从当前上下文解析；未解析参数拒绝、缺身份丢弃整条 AND 分支，SQL 绑定固定。老 values 规则和原 JSON 存储保持，未新增迁移。 |
| D12 | 隔离 MySQL 和浏览器实测见下；当前人员是公共参数单测，尚无客商业务字段使用。 |
