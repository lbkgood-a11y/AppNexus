# 入库质检公式扣重验收

本轮接通散货入库的质检公式扣重。已发布模板须配置 `deduction_strategy=QUALITY_LINEAR`、`quality_gate_strategy=QUALIFIED_AND_UNLOADED`、`stock_granularity=BULK`，计量策略须为 `SCALE` 或 `SCALE_DIFFERENCE`。沿用原入库草稿及提交过账操作。

模板的 `definition.deductionFormula` 声明版本及 `moisture`、`impurity` 两项规则。每项需要化验指标代码 `metric`、基准百分数 `baseline` 和每超一个百分点对应的扣量百分点 `multiplier`。两个指标须不同，数据来自现行合格化验快照，单位须为 `pct` 或 `%`。配置使用租户正式批准值。

每项扣量按物理净重乘以超出基准的百分点、再乘系数并除以 100。扣水和扣杂分别用 HALF_UP 保留四位小数。现场扣重来自监卸凭证且只计一次。库存账面重量为物理净重减总扣重，必须大于零。

| 门禁 | 本次处理 |
|---|---|
| G01–G03、C01–C03 | 库存域既有入库单、质检单、计量单和车次事实。权限及可信租户执行路径不变。表单只看授权后的结果，用户不能提交扣量或公式。 |
| G04、C05 | 作业、来源与计量在原事务内锁定。过账重新比对模板、合格质检、皮重门禁版本及同车次关联的监卸凭证。过账消耗扣重后的库存单位额度。 |
| G05、D04–D06 | 三项扣量只进入已授权入库单详情。完整公式、质检快照与凭证 ID 写入库存业务快照，未加入公开响应。 |
| G06–G08、C06–C09 | 构建及真实集成证据记录在下文。查询沿用现有通知、单据和作业索引。无新库表、迁移、模块或端点。 |
| G09、D01–D03 | 同一入库单 Provider 与原入口处理待收集、已齐套和过账。原操作码、页面绑定、权限与版本保留。 |
| D07–D10、C10 | 不增加工作流或打印。称重净重、扣水、扣杂和现场扣量分别留存，保留原库存事件和编码接口。 |
| D11–D12 | 输入来自既有已发布模板和锁内事实。缺少公式、合格化验、同版过皮或有效监卸证据时不入账。 |

本机业务模板的配置发布入口和正式参数仍是独立上线条件。本轮以隔离测试模板验证计算和库存事务，测试参数不能作为实际收货标准。

## 运行证据

- 后端仓储完整回归与应用 API 契约共 3 项通过。隔离库先开同一张草稿，地磅净重 70 kg，扣水 1.05 kg、扣杂 0.70 kg、现场扣重 1.50 kg，过账后库存为 66.75 kg。同一单据补齐后版本递增，提交前模拟模板变更得到 409，恢复原模板后用同一幂等键成功提交。证据见 `.local/quality-deduction-acceptance.log`。
- 前端类型检查与构建通过。浏览器以真实隔离租户会话读取已过账单据并逐项比对扣量，在 1440×900、1024×768、390×844 三个视口验证 0、8、24 px 区块间距继承、边框、圆角和无横向溢出。浅色、深色、跟随系统及中英文标签切换通过。截图位于 `.local/quality-deduction-receipt.png`。
- 新构建已部署本机。8848 首页返回 200，8080 和 8848 代理的匿名单据请求均返回 401。共享业务库未发现已发布模板，验收数据位于隔离库。
