## 场景结果

A 的 51 t 钢卷在冻结或活动占用时不能过户。解除冻结及撤配后，模拟转入分录失败，转出及过户记录同时回滚，活动货主仍为 A。重试成功后，A 转出 51 t、B 转入 51 t，库存和库位保持。相同键重放不增加分录。原 A 的旧授权不能配货或放行，B 在过户前签发的旧授权因代次不匹配也不能配该卷。B 重新签发后可配。

A 的实物余额无该卷，旧授权可查询到自身 53 t 单据额度。B 有 51 t 可提量，冻结及活动占用均将该卷可提量降为零而保持在库货权。增加 3 t 待检后，在库货权 54 t、可提 51 t。按授权页可查看 51 t 占用或实发和 2 t 单据余额。B 实发 51 t 后，实物仍有独立 3 t 待检。

## 执行记录

两阶段均从隔离源码副本运行，排除工作区原 target。Maven 3.9.15、Java 21，使用已缓存的 MySQL 8.4 和 Valkey 镜像。

第一阶段执行并通过 2 项组合数据库测试，退出码 0。完成后才接入余额查询。

```sh
TESTCONTAINERS_RYUK_DISABLED=true mvn -f backend/pom.xml -pl applications/monolith-app -am -Pcontainer-tests -Dtest='ProductV1IntegrationTest#warehouseReferencesUseExistingProductAndConversionReadBoundary,GlobalRecordAuditTest#ownedTablesHaveAllFourColumns' -Dsurefire.failIfNoSpecifiedTests=false test
```
