# 事件工作台交付检查

范围：平台事件工作台、事务内多消费者投递、独立回执与失败恢复、原任务 API 兼容、真实 MySQL 迁移验证。生产部署未执行。切换前须同时暂停旧生产方和旧 Worker，确认无在途事务，再应用 V203 并启动新版本。

## 业务对象声明同步

| 声明项 | 适用性及变更 |
|---|---|
| D01 对象归属 | 沿用平台管理域唯一的 `PlatformTaskDeclaration`，描述符版本 2 → 3。事件工作台是独立菜单。 |
| D02 操作 | 新增 `listEvents`、`readEvent`、`retryDelivery`。原 `list`、`retry`、`processEvents` 保留。 |
| D03 页面及入口 | `/platform/events` 通过平台导航装配。新旧 Controller 均引用同一 Provider。Worker 通过固定 SCHEDULE 操作。 |
| D04 功能准入 | 平台读、重试仍分别使用 `platform.task:read` 和 `platform.task:retry`，不迁移原角色授权。调度保持系统准入。 |
| D05 范围 | 平台固定联表投影按可信平台账号授权，租户 ID 是平台列表筛选条件。执行侧回执校验投递租户、事件和消费者。 |
| D06 字段 | 返回业务引用、受控失败码、尝试与审计元数据。租约令牌、堆栈、业务正文和重试原因不出现在读接口。 |
| D07 能力 | 专用 API 和统一 SCHEDULE 入口适用。同库事件由 `TransactionalBusinessEvents` 接通，工作流、打印、外部消息和回放不适用。 |
| D08 契约 | 事件 UUID、投递 UUID 区分使用，投递状态和尝试历史独立。旧接口保留事件 UUID。工作台页面及 API 仅通过授权真实数据源获取状态。 |
| D09 编码 | 技术 UUID 由服务端生成，无业务编号或发号入口。 |
| D10 运行 | 平台公开用例执行查询和单投递恢复。Worker 执行领取、回执与业务回调。专用操作无公共命令能力。 |
| D11 生命周期 | 同事务扇出。同库消费事务包含回执、业务效果和投递完成。重试保持回执与累计历史，写管理审计。迁移记录依旧回执决定成功，缺失进入对账。 |
| D12 证据 | 真实 MySQL 回归见下表。浏览器矩阵、容量和部署核查按实际证据判定。 |

入库业务对象继续复用原 Provider 与原质检投影操作。当前代码增量改变事件投递技术状态，未新增入库业务动作、字段准入或对外协议。权限失效事实保留原同步权威事务和原消费者。权限及入库事件都保留原事件 ID 和回执键，新订阅声明应用于新业务事件。

| G07、C09 | 新接口、旧事件 ID 映射、迁移顺序见《统一事件模型详细设计》。平台 OpenAPI 契约测试 2 项通过。新接口文档从正式 Controller 导出，旧路由标记 deprecated，运行参数和权限保持原语义。 |

- 本次未执行生产部署、生产负载容量测试或生产 MFA 启用配置的端到端验证。浏览器隔离夹具关闭 MFA，生产仍沿用现有默认平台策略。全量仓储工作台回归未在最终组合中运行。
