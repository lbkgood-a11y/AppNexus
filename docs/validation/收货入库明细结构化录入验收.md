# 收货入库明细结构化录入验收

散货和钢铁在原入库单表单选择通知单行、库区和库位，自动使用来源仓库、库存单位、千克单位和授权引用版本。库存单位与千克不同时，须采用已启用且方向匹配的换算规则。钢铁逐卷编辑卷包号、炉批号、规格、材质、理重和批次，支持增删与重复校验。复用原明细保存和库存过账接口。

| 门禁 | 本轮处理 |
|---|---|
| G01/G02、D01/D02 | 复用原仓储入库和主数据边界，新增入库明细组合字段。通用表格没有联动多个受权单位和位置层级的字段组，本次使用已有 Element Plus 字段组和弹窗宿主。 |
| G03/G05、C01–C03、D03–D06 | 候选仅在入库用途中返回来源通知 UUID。通知、仓库、库区、库位、单位及换算沿用各自真实授权接口。权限不足或引用不可用时不提供可提交的替代值。质检、计量候选不返回来源通知 ID。 |
| G04、C05、D11 | 结构化字段组装原命令输入。后台继续复核同通知、位置层级、角色权限、版本、额度、件数、理重合计和正式过账条件。 |
| G06/G08、C07、D12 | 构建、真实浏览器、集成和部署证据记录如下。 |
| G07/C09、D08 | 入库候选契约新增可选来源通知引用。原草稿保存及过账结构保留，无新命令。 |
| C04/C06/C08 | 无新迁移、Java 包或构建模块。只在现有授权查询投影添加字段。仓库下按父级编码搜索原库区、库位接口。 |
| G09、D07/D09/D10、C10 | 原 Provider、业务操作、编码、能力及事件接线保留。本轮没有增加工作流、打印或消息。 |

**范围边界**：本轮处理入库明细录入。化验指标表单、MTC 附件选择、冲红原单引用、模板发布入口和真实设备联调仍是完整现场验收的缺口。

## 运行证据

- 前端类型检查和构建通过，日志为 `.local/receiving-lpn-{types,ui}.log`。后端仓储回归和 API 契约共 3 项通过，第一方契约检查 2 项通过。
- 隔离浏览器实际从独立钢铁入库单选择已计量车次。空引用无法提交，手工输入的大小写重复卷包号被拦截。实际选择三卷对应的通知行、库区、库位和批次后提交，服务端随后对同一张入库单过账，账面重量为 100.0001 kg。浏览器请求中引用 UUID 和版本均来自已授权选项。
- 含三行编辑的真实弹窗在 1440×900、1024×768、390×844 下均可见。浏览器测得 0、8、24 px 间距按应用壳传递，边框、圆角、外边距、数据内边距可查询，且无页面横向溢出。浅色、深色、跟随系统和英文入口切换通过。见 `.local/receiving-lpn-acceptance.log`、`.local/receiving-lpn-form.png`。
- 散货使用同一组来源和库位字段，原散货写入及过账在仓储集成回归中通过。没有另行在浏览器提交散货。跨单位换算的浏览器用例仍待验证。
- 最终构建已部署本机，首页返回 200，后端和前端代理的匿名入库请求按预期返回 401。验收业务数据留在隔离库。
