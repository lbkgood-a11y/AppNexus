# 人员字段保护与仓库策略预加载

## 声明与执行

| 核对 | 实现及适用性 |
| --- | --- |
| D01–D03 | 复用 `Person` 与 `Warehouse` 唯一 Provider。描述符分别升至 3、4。两者均新增 `fieldRestrictions` 只读操作，在原可信租户读取域中返回当前成员的字段模式。原路径、原操作 ID 与已存在的策略键保留。 |
| D04–D06 | 人员主档声明电话、邮箱、证件号、紧急联系人及电话，明细声明联系方式、详细地址和证书编号。列表和详情使用同一字段目录和原租户准入。受限主档及明细字段显式提交即拒绝，省略时保留旧值。某明细分类含受限字段时拒绝整行删除。仓库、人员新增表单在读取策略后装配控件，失败时禁止编辑。 |
| D07–D11 | 专用用例继续执行原业务权限、父版本和事务。无新表、字段、流程、编码或打印能力。新增的人员响应策略元数据不含原值。原策略没有改名，授权编辑版本令牌随描述符更新，需刷新后保存。 |
| G01–G07、C01–C03、C05、C09 | 真实 MySQL、Valkey、Spring 装配验证原角色路径、读取投影、写入拒绝及父版本保持。前端类型检查和生产构建通过。无 SQL 查询条件或数据库结构变更。 |
| D12、G08–G09 | 本次证据覆盖人员及仓库的测试场景。其他对象的字段保护和逐对象正反向验收未完成。没有切换运行实例，发布后的目录尚未核对。 |

集成验证在隔离源码副本执行 `mvn -q -f backend/pom.xml -pl applications/monolith-app -am -Dtest=WarehouseDictionaryIntegrationTest,PersonnelIntegrationTest,MasterDataIntegrationTest,ObjectExecutionAssemblyTest -Dsurefire.failIfNoSpecifiedTests=false test`。人员 6 项、仓库 2 项、主数据组合 3 项、Provider 组合 3 项，共 14 项通过，退出码 0。隔离库迁移至 V133。前端在 Node 24 下执行 `pnpm --filter @appnexus/admin typecheck` 和 `pnpm --filter @appnexus/admin build`，均退出 0。

## 浏览器实测

在隔离的 Spring 应用、MySQL、Valkey 和管理端生产产物上测试。账号只关联测试租户。在没有人员和仓库记录的情况下，新增入口通过真实 API 加载策略，无代理模拟业务响应。首次打开仓库表单显示数据暂不可用，重试后正常显示。代理侧随后确认仓库预加载及选项请求均返回 200。

| 场景 | 观察结果 |
| --- | --- |
| 仓库新增 | 空目录进入新增页。配置为只读的电话显示只读文本、无编辑控件；隐藏的邮件无标签和输入控件；无策略的联系人仍可编辑。 |
| 人员新增 | 空目录进入新增页。配置为只读的电话仍展示、无编辑控件；隐藏的证件号无显示。隶属业务表单在同一应用壳内。 |
| 1440×900、1024×768、390×844 | 两个表单均位于真实 `.main-content` 宿主，三种尺寸可见宿主宽度内无横向溢出；仓库的电话只读与邮箱隐藏在三种尺寸保持。宿主计算 margin 为 8px、padding 为 0px、顶部边框宽度 0px、圆角 0px。 |
| 区块间距 | 人员实际系统设置中用键盘将间距切到 0、24、8。人员详情计算 gap 对应为 0px、24px、8px，恢复至 8px。 |

C07 已留存上述实际检查结果，但仓库动态间距、浅色/深色/系统主题组合、人员明细编辑与删除在浏览器中的场景仍未覆盖。无部署动作。本次专用浏览器宿主和代理生命周期均限定为临时验收。
