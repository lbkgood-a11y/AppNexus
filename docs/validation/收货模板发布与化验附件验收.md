# 收货模板发布与化验附件验收

范围为入库品类模板配置、保存草稿与按版本发布，化验按模板录入，以及同车次的 MTC 与外观附件选择。浏览器场景为已签发散货通知到库存入账，覆盖千克到库存吨的真实换算。正式业务阈值由租户配置。

| 门禁 | 本次处理 |
|---|---|
| G01/G02、D01–D03 | 新增唯一配置对象 `BulkCommodityTemplate`，使用原仓储表和入库上下文。化验输入元数据仍归原质检操作，附件选择沿用平台附件权限。 |
| G03/G05、C01–C03、D04–D06 | 查询、草稿维护与发布分权。模板事务按可信租户绑定，商品通过原主数据权限复核。化验输入只返回现行样品绑定的指标代码和单位，省略判定区间。MTC 列表限制同车次已就绪附件，服务端复核归属、类型及相互独立。 |
| G04、C05、D11 | 草稿编辑按行版本。发布按逻辑编码锁住各版本，发布更高版本并停用原版，历史作业保留原模板。库存写入仍由原入库事务执行。 |
| G06/G08、C07、D12 | 测试、浏览器及本机证据见下。 |
| G07/C09、D08 | 模板命令使用明确字段和已支持策略。化验原请求保留。附件选择用原作业业务关联 ID 和附件响应。 |
| G09、D07/D09/D10、C10 | 不新增工作流、打印或事件，模板编码由批准配置维护。化验、附件、收货及库存保留原运行入口。 |
| C04/C06/C08 | 使用既有模板表及四个审计字段。V209 声明权限、数据范围及菜单。列表和版本发布使用租户及模板编码索引，不新增 Java 包。 |

## 运行证据

- 本机旧库的授权来源列不可为空。首次 V209 整体回滚后，确认模板权限与菜单均未写入，修复为继承原有授权来源。预演在现有表和数据上成功并回滚。仅清理未成功的 V209 记录，重新部署后 V209 成功，首页 200，匿名模板查询按预期返回 401。
- 在本机连接级临时表按既有索引构造 5,000 个模板版本，主测试租户 4,000 条。模板分页首 20 条实测约 13.5 ms，发布定位按租户和编码走 `uk_bw_exec_template_version`，读取 5 个版本约 0.125 ms。见 `.local/receiving-template-explain.log`。
- 默认 Maven 输出目录包含 IDE 增量编译留下的类，造成组合应用回归启动失败。正式复验使用单独构建目录 `target-receiving-template-qa`。
- 前端类型检查和构建通过。隔离构建中的正式仓储回归通过，零失败、错误和跳过。原应用 API 契约 2 项通过，生成快照同步后第一方契约检查 2 项通过。日志见 `.local/receiving-template-{isolated,certified,contract}.log`。
- 在已部署版本的隔离验收环境中，浏览器新建散货采样模板、选择商品、保存草稿并发布。打开已签发通知，自动采用已发布模板，登记车次，从工作台开入库单，采样并填写自动生成的化验指标，登记外部净重 1,250 kg，选择库区库位、确认批次和换算规则，再提交同一入库单。数据库确认库存单位为测试吨，数量为 1.2500。
- 浏览器从同车次选择 PDF 质保书和 PNG 外观照片。外观照片选项排除了 PDF，提交后钢铁核验为 PASS。测试使用已扫描就绪的附件记录，实际扫描服务未在此用例发起。截图为 `.local/receiving-mtc-picker.png` 和 `.local/receiving-cross-unit-result.png`。
- 模板弹窗在 1440×900、1024×768、390×844 下可操作。浏览器实测 0、8、24 px 区块间距继承、边框、圆角、内外边距且无页面横向溢出。此次弹窗未单独复测全部主题、语言和快捷键。
- 最终验收构建已部署到本机，首页与 API 代理检查通过。共享业务库仍没有已发布的正式模板。验收模板、换算关系、附件与库存均属于隔离租户。
