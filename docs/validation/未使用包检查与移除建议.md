## 4. 已排除的误报

- business-object-client 无仓库内业务消费，但它是对外 Java SDK，有公开接入说明和独立测试，不应按内部依赖图删除。
- partner-api-spec 是契约与兼容检查工程；backend-architecture-tests 和 workflow-architecture-tests 是构建门禁，入口是 Maven reactor/CI，无业务消费者是正常情况。
- poc-app 是隔离技术验证工程，CI 包含 PoC 验证；leave-poc 更被 monolith-app 真实依赖，不能因名称含 poc 直接删除。
- printing/agent 是独立可执行打印代理，提供 start 入口与实际后端领取/回执流程，不需要被其他 npm 包依赖。
- persistence.identity 包通过 MyBatis 扫描和 Spring 实现装配；未出现其他包对内部类型的直接导入不能作为删除依据。
- vue-tsc、TypeScript、Vitest、@types/* 等分别由脚本或类型解析使用；@vue/compiler-sfc 与 @vue/compiler-dom 被操作绑定检查脚本使用，不能按业务 import 判断为闲置。admin 的动画、Tippy、Sortable、版本检测等也查到实际入口。
