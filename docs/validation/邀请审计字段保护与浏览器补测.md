## 浏览器及真实 HTTP 证据

使用单独的 Spring Boot、MySQL 8.4、Valkey 和管理端生产产物。测试账号及记录均为一次性隔离夹具。首次仓库页面在冷启动时显示暂不可用，刷新后加载成功，之后出入口请求返回 200。

| 场景 | 实际结果 |
| --- | --- |
| 仓库全局间距 | 通过浏览器的系统设置将区块间距切为 0、24、8，仓库表单计算 gap 分别为 0px、24px、8px。实际 `.main-content` 的 margin 为 8px，观察中未横向溢出。最后恢复默认 8。 |
| 仓库主题 | 浅色显示 `color-scheme:light`，深色显示 `color-scheme:dark` 且根节点带 `dark`，系统主题在当前环境解析为浅色。三种主题均保留电话只读、邮箱隐藏。 |
| 人员受限明细编辑 | 联系方式列表没有受保护的联系值列。打开编辑，仅提交合规的备注修改。保存后表格重新读取得到测试备注；删除按钮保持禁用。 |
| 人员删除交互 | 普通培训明细的删除按钮可用，打开确认后取消，列表中的明细保留。此步骤仅检查 UI 对确认与取消的处理。 |
| 人员真实删除请求 | 对同一隔离数据用应用签发的 CSRF 和可信会话调用原 DELETE API。受保护联系方式返回 403 与 `DATA_FIELD_WRITE_DENIED`，人员版本不动；无字段限制的培训明细删除成功，重新读取确认培训已移除、受限联系方式仍在。 |

浏览器验收后的隔离会话已终止。上述场景补充[人员字段保护与仓库策略预加载](人员字段保护与仓库策略预加载.md)的实测，范围限于仓库、人员及所列操作。

## 回归证据

运行于独立源码和构建目录，命令为 `mvn -q -f backend/pom.xml -pl applications/monolith-app -am -Dtest=TenantInvitationTest,UnifiedAuditTest,ObjectExecutionAssemblyTest -Dsurefire.failIfNoSpecifiedTests=false test`。首轮 8 项执行 6 项通过，新增的两个用例因夹具角色编码含短横线触发数据库约束，未执行到断言。夹具改为与原约束相符的下划线和十六进制编码，生产权限行为未改。将 `-Dtest` 改为 `TenantInvitationTest#inviteeFieldRuleBlocksDisclosureAndWrite,UnifiedAuditTest#auditTargetIsProtectedInEachActorDomain` 后两项均通过，退出码 0。隔离真实 MySQL 迁移至 V133。

邀请用例验证原权限下显示受邀账号、授予隐藏策略后的投影及写入拒绝、存量邀请保持待接受、移除字段策略后恢复原允许读取。审计用例验证无策略原值、平台代查隐藏、租户不继承平台隐藏和独立租户隐藏。两个对象的字段权限仍受对应原有功能准入限制。
