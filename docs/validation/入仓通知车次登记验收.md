# 入仓通知车次登记验收

入口位于「仓储管理 → 入仓管理 → 入仓通知单 → 详情 → 入库车次」。登记表示车辆或非车辆批次已到场，初始节点为待质检。车次号由服务端生成。

来源通知由详情路径确定。系统优先使用通知已固定的模板版本，也兼容历史单一模板的车次。通知未绑定时，已发布模板定义中的 `noticeProductIds` 以小写商品 UUID 数组关联通知全部商品。只有一个匹配版本时自动采用，多个匹配版本可从匹配项选择。缺少商品关联时，授权人员可首次选择适用的已发布通用模板。首个成功登记会锁定来源并固定模板版本，后续登记自动继承。

## 门禁与声明

| 门禁 | 本次处理 |
|---|---|
| G01/G02 | 通知详情增加到场登记，复用现有仓储执行、任务主表、工作台和单据选择器。没有新增业务包或构建模块。 |
| G03/G05、C01–C03 | 由 `BulkInboundTask.create_from_notice` 准入，服务端同时检查来源通知读权限和两个租户范围。通知、模板和车次 SQL 都绑定可信租户。车辆字段权限从统一模型读取，列表不返回车牌或现场识别号。 |
| G04/C05 | 事务先锁通知。模板绑定、版本推进、作业记录及 UTC 审计同事务写入。相同请求 UUID 只对应相同内容，不同输入冲突。创建后按已有写权限和业务状况进入三单候选。 |
| G06/G08 | 构建、HTTP、浏览器及本机运行证据记录在下文。 |
| G07/C09 | GET 和 POST 共用通知任务资源路径。原通知和三单契约保留。新响应使用禁止缓存和稳定错误码。 |
| G09、D01–D06 | 唯一登记归属为 `InboundTaskDeclaration`。Provider 明确登记通知详情 GET 和 POST 入口。无第二套授权策略，模板、车次列表和车辆输入按已授权投影展示。 |
| D07–D10 | 沿用现有作业流程和三单命令。车次号是由 UUID 派生的服务器标识，未增加可配置编码规则和发号入口。此操作不增加打印、工作流或消息契约。 |
| D11/D12、C04 | V207 为已存在的通知表增加租户复合外键及新增操作权限。历史通知列保留 NULL，登记时检查旧车次是否使用同一模板。无新表。 |
| C06 | 登记上下文按通知主键读取，最近车次使用现有租户和通知索引并限 20 条。 |
| C07 | 页面使用现有通知详情宿主、PageHeader、ManagedDialog 和 Element Plus 控件。车次预览只展示编号和阶段。 |
| C08/C10 | 沿用现有包和通用事务许可。登记不改变原库存过账、冲红和异步化验事件。 |

## 运行证据

- 初始本机共享数据库只有一张通知、没有已发布品类模板。真实业务模板的发布由租户配置，隔离验收模板用于验证实际命令和库存账。
- 首轮 Maven 回归通过 5 项，覆盖应用 API 契约、全局记录审计、仓储完整链路和导航权限。日志见 `.local/inbound-arrivals-release.log`。
- 本机 MySQL 临时表复制 5 万条车次，其中主测试租户 4 万条，目标通知 80 条。最近 20 条走 `idx_bw_exec_notice_tasks` 逆向索引访问，单连接实测约 0.17 ms。历史模板歧义检查同索引限定通知且达到两种模板即停止。证据见 `.local/inbound-arrivals-explain.log`。
- 本机 8080 已启动新组合应用，Flyway V207 成功。8848 首页返回 200，经过同端口代理调用车次上下文的匿名请求返回 401。已有通知编辑全范围的一个系统租户管理员角色获得登记授权。共享数据库已发布模板数仍为 0。
- 前端类型检查和构建通过，日志见 `.local/inbound-arrivals-final-{types,ui}.log`。
- 部署后 `ApiContractTest` 与 `InboundWorkbenchHttpTest` 共 3 项通过。隔离租户通过真实 HTTP 签发通知，自动匹配模板，登记两辆车次，并验证同一请求重试、不同输入冲突、模板越权替换拒绝及分岗准入。第一车次从工作台和三单候选进入采样、计量、生成入库单及暂估过账，通知明细累计实收为 100.0000 kg。
- 实际浏览器在通知详情创建第三车次，确认来源及固定模板自动带入，并核对工作台队列。检验三种视口和 0、8、24 px 区块间距继承，均无横向溢出。证据见 `.local/inbound-arrivals-acceptance.log` 和 `.local/inbound-arrivals-notice.png`。这一轮对新增弹窗未单独重测主题和键盘导航。
- 已同步第一方 OpenAPI 的车次 GET、POST 和命令及响应结构。`ApiContractChecksTest` 共 2 项通过，见 `.local/inbound-arrivals-contract.log`。
