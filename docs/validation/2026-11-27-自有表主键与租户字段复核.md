# 自有表主键与租户字段复核

日期 2026-11-27。复核正式组合应用迁移和独立 PoC 测试库。生产环境尚未执行本次迁移。

## 迁移差异与归属

- 本地 MySQL 8.4 的 V217 快照含 149 张自有基础表，55 张缺少 `id`，31 张以 `id` 参与复合主键。另有 V220 新增的平台事件订阅状态表，其首次建表已声明单列 `id`。
- V221 保留每张表现有的业务键列及其顺序，以独立唯一索引维护原外键、幂等和重复检查。已有 `id` 原值与原类型继续使用，新增存量行主键由 MySQL 分配 `BIGINT UNSIGNED AUTO_INCREMENT`。对已有复合主键先按全表唯一性检查 `id`。本地 V217 实例的 31 张表均无重复 `id`。
- V222 将策略模板中实际保存租户归属的 `owner_id` 改名为 `tenant_id`，保留原值和索引。角色权限、数据策略和字段保护三张表从父角色获得租户，平台角色子行使用 NULL。复合外键同时约束写错租户和将租户行写成 NULL。投递尝试从父投递取得范围并通过复合外键验证，平台投递沿用当前零 UUID 约定。集成客户端审计保存客户端归属，回填无法追溯的历史记录保留 NULL。
- 平台或全局无租户字段的表按用途复核。账号与认证包含 `identity_account`、`identity_bootstrap`、`identity_account_mfa`、`identity_mfa_recovery`、`identity_password_recovery`、`identity_refresh_history`、`account_security_log`。平台管理员包含 `platform_administrator`、`platform_administrator_bootstrap`、`access_account_role`。共享目录和配置包含 `platform_tenant`、`platform_menu`、`platform_menu_resource`、`platform_menu_audit`、`access_permission`、`access_permission_scope_type`、`business_object_type`、`business_object_page_relationships`、`business_object_entry_control_audit`、`platform_attachment_upload_policy`、`platform_event_subscription_state`。平台菜单的适用范围表示可见对象类型。
- Flyway 历史、框架原始表和第三方引擎表采用现有自有表门禁边界。PoC 的独立 V4 迁移统一 Outbox、消费回执和令牌族的记录主键，保留原业务键，消费回执使用父事件的 `tenant_id`。

## 声明同步复核

| 业务归属 | 既有入口与事务 | 持久化变化 |
| --- | --- | --- |
| 平台授权与组织初始化 | 角色授权用例和首位管理员初始化从可信管理域进入，持有角色或租户锁 | 原授权适配器从所属角色读取 `tenant_id`，数据库校验父角色归属 |
| 权限策略模板 | 模板保存、应用及列表由现有角色管理权限校验进入 | 原模板适配器改用 `tenant_id` 过滤，沿用原值与索引 |
| 集成客户端 | 平台管理员变更客户端，同事务记录审计 | 审计从不透明客户端标识关联其租户绑定 |
| 平台事件投递 | 平台任务 Worker 在领取事务内记录尝试 | 尝试继承父投递范围，数据库校验归属 |
| 主数据、仓储、打印、工作流及其他存量表 | 沿用各自入口、端口、业务键及事务 | 使用组合应用的统一迁移，只调整物理主键，业务键保留唯一约束 |

| 条目 | 实际差异与处理 |
| --- | --- |
| D01 对象身份 | 沿用各表原业务归属，新增数据库行 ID 供持久化使用，原业务标识与对外身份延续。 |
| D02 操作 | 角色授权、组织初始化、策略模板、集成客户端和平台任务沿用现有操作。未增删操作。 |
| D03 入口 | 现有 Controller、页面、回调和后台入口的绑定延续。 |
| D04 准入 | 角色写入沿用原有角色锁和管理域复核。平台任务尝试记录仍使用既有 worker 操作。 |
| D05 行范围 | 策略模板仍同时按标识和可信管理域查询。角色关系与投递尝试增加数据库归属约束，父角色与父投递提供范围。 |
| D06 字段保护 | 现有字段规则及公共执行器继续使用原角色键，新列仅用于持久化与完整性校验。 |
| D07 通用能力 | 工作流、打印与事件契约沿用当前版本。事件投递尝试存储的租户取自父投递。 |
| D08 数据契约 | 对外 DTO、审计来源映射及已声明业务字段延续。原记录引用键保留唯一约束，新增行 ID 无对外投影。 |
| D09 编码 | 编码及幂等表的原业务键组合保留唯一。 |
| D10 真实运行 | 组合应用 Mapper 继续在原调用链写入，补齐持久化租户列。SQL 门禁仅更新对应固定语句的精确指纹及复核说明。 |
| D11 生命周期与事务 | 原事务、版本和发布关联延续。新增 V221、V222 前向迁移和独立 PoC V4，无公开声明版本变化。 |
| D12 验收 | 在真实 MySQL 扫描全表，验证迁移、原业务唯一键与归属约束。测试结果见下表。 |

## 交付门禁

| 条目 | 适用性、证据与结果 |
| --- | --- |
| C01 | 授权持久化验证通过。SQL 门禁扫描 577 项，0 项异常。策略模板集成测试 2 项通过，其中包含真实角色授权保存。实际开通测试租户后核对 136 条系统角色授权、64 条数据策略均记录正确租户。角色管理扩展回归未跑完。 |
| C02 | 涉及数据归属。隔离 MySQL 验证角色字段限制接受正确租户及平台 NULL，并拒绝错误租户和租户行 NULL。 |
| C03 | 字段保护持久化验证通过。字段限制的原业务唯一键、父角色归属及跨租户反向断言通过。审计界面相关的扩展回归未执行。 |
| C04 | 通过。MySQL 8.4 空库应用 222 个 Flyway 迁移，150 张自有基础表的单列 `id` 和四审计列检查通过。V217 隔离结构副本的 149 张表也通过主键检查。带数据样本验证 V222 六项归属迁移、平台角色 NULL 和未知历史审计 NULL。人员历史迁移测试验证 V76 带数据升级后保留原账号、人员关系和历史审计，并确认再次执行迁移为零。PoC Outbox 和令牌轮换容器测试共 6 项通过。 |
| C05 | 适用。真实 MySQL 复核重复字段限制被拒绝，撤销角色权限时原数据策略级联删除仍有效。 |
| C06 | 适用。真实 MySQL `EXPLAIN` 验证按角色读取字段限制命中 `uk_access_role_field_security_previous_pk`，类型 `ref`，合成样本估算 1 行。未进行生产数据量和迁移锁耗时验证。 |
| C07 | 无前端代码或界面差异，无布局或浏览器验收项。 |
| C08 | 未新增 Java 包、模块或跨模块依赖。受影响 Mapper 在隔离 Maven 构建中编译，并随组合应用装配。 |
| C09 | 涉及迁移发布。目标环境部署前先备份，在写入停止后复核 31 张表是否存在跨租户重复 ID，再按顺序运行 V221、V222。MySQL DDL 会隐式提交。遇失败检查已完成 DDL，按迁移前备份恢复或经独立评审后继续修复。 |
| C10 | 通过。可靠事件集成测试 11 项通过，并在测试数据库检查到 15 条执行尝试与父投递归属一致。 |

组合回归已列入结果的 31 项中，30 项通过，1 项人员状态历史路由断言失败。当前人员启停入口缺少该断言要求的 `/api/master-data/person/{id}/status-history` 路由。本次迁移与 Mapper 差异未改动人员路由或其声明。角色管理扩展测试反复执行全量地理目录初始化，完成本次数据库及受影响写入验证后停止该扩展运行，后续统一审计与包说明测试未执行。独立 PoC 容器测试共 8 项通过。
